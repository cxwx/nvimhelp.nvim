1. 跳转到标签					*tag-commands*

							*tag* *tags*
标签是出现在 "tags" 文件中的标识符。它是一种可以跳转到的标记。例如：在 C
程序中每个函数名都可以用作标签。"tags" 文件必须在使用标签命令之前由 ctags
等程序生成。

使用 ":tag" 命令，光标将定位在标签上。使用 CTRL-] 命令，光标所在的关键字
将作为标签。如果光标不在关键字上，则使用光标右边第一个关键字。

":tag" 命令对 C 程序非常有效。如果你看到一个函数调用并想知道该函数做什么，
将光标移到函数名内部并按 CTRL-]。这会带你到函数定义处。一种简便的返回方式
是使用 CTRL-T 命令。另请阅读下面关于标签栈的内容。

						*:ta* *:tag* *E426* *E429*
:[count]ta[g][!] {name}
			跳转到 {name} 的定义处，使用标签文件中的信息。
			将 {name} 放入标签栈。[!] 参见 |tag-!|。
			{name} 可以是正则表达式模式，参见 |tag-regexp|。
			当有多个匹配 {name} 的标签时，跳转到第 [count] 个。
			省略 [count] 时跳转到第一个。
			参见 |tag-matchlist| 了解跳转到其他匹配标签。

g<LeftMouse>						*g<LeftMouse>*
<C-LeftMouse>					*<C-LeftMouse>* *CTRL-]*
CTRL-]			跳转到光标下关键字的定义处。与 ":tag {name}"
			相同，其中 {name} 是光标下或光标后的关键字。
			当有多个匹配 {name} 的标签时，跳转到第 [count]
			个。没有给出 [count] 时跳转到第一个。
			参见 |tag-matchlist| 了解跳转到其他匹配标签。

							*v_CTRL-]*
{Visual}CTRL-]		与 ":tag {name}" 相同，其中 {name} 是高亮的文本。

							*telnet-CTRL-]*
CTRL-] 是默认的 telnet 转义键。当你按 CTRL-] 跳转到标签时，你会得到 telnet
提示符。大多数版本的 telnet 允许更改或禁用默认转义键。参见 telnet 手册页。
你可以用 `telnet -E {Hostname}` 来禁用转义字符，或用
`telnet -e {EscapeCharacter} {Hostname}` 来指定另一个转义字符。
如果可能，尝试使用 "ssh" 代替 "telnet" 来避免此问题。

							*tag-priority*
当有多个匹配标签时，使用以下优先级：
1. "FSC"  当前文件的完全匹配静态标签。
2. "F C"  当前文件的完全匹配全局标签。
3. "F  "  其他文件的完全匹配全局标签。
4. "FS "  其他文件的完全匹配静态标签。
5. " SC"  当前文件的忽略大小写匹配静态标签。
6. "  C"  当前文件的忽略大小写匹配全局标签。
7. "   "  其他文件的忽略大小写匹配全局标签。
8. " S "  其他文件的忽略大小写匹配静态标签。

注意当当前文件改变时，优先级列表大多不变，以避免使用 ":tnext" 时产生混淆。
使用 ":tag {name}" 时会改变。

在以下情况下，":tag" 命令不会找到忽略大小写的匹配：
- 'tagcase' 为 "followic" 且 'ignorecase' 选项关闭
- 'tagcase' 为 "followscs" 且 'ignorecase' 选项关闭，同时 'smartcase'
  选项关闭或模式包含大写字符。
- 'tagcase' 为 "match"
- 'tagcase' 为 "smart" 且模式包含大写字符。

在以下情况下会找到忽略大小写的匹配：
- 使用了模式（以 "/" 开头）
- 用于 ":tselect"
- 当 'tagcase' 为 "followic" 且 'ignorecase' 开启
- 当 'tagcase' 为 "followscs" 且 'ignorecase' 开启，或 'smartcase' 选项
  开启且模式不包含大写字符
- 当 'tagcase' 为 "ignore"
- 当 'tagcase' 为 "smart" 且模式不包含大写字符

注意使用忽略大小写的标签搜索会禁用标签文件中的二分搜索，导致速度变慢。
可以通过对标签文件进行大小写折叠排序来避免。参见 'tagbsearch' 选项的说明。

2. 标签栈				*tag-stack* *tagstack* *E425*

标签栈记住了你跳转到的标签，以及从哪里跳转的。只有在 'tagstack' 选项
开启时，标签才会被压入栈中。

g<RightMouse>						*g<RightMouse>*
<C-RightMouse>					*<C-RightMouse>* *CTRL-T*
CTRL-T			跳转到标签栈中第 [count] 个旧条目（默认 1）。

						*:po* *:pop* *E555* *E556*
:[count]po[p][!]	跳转到标签栈中第 [count] 个旧条目（默认 1）。
			[!] 参见 |tag-!|。

:[count]ta[g][!]	跳转到标签栈中第 [count] 个新条目（默认 1）。
			[!] 参见 |tag-!|。

							*:tags*
:tags			显示标签栈的内容。活动条目用 '>' 标记。

":tags" 的输出如下所示：

   # TO tag      FROM line  in file/text
   1  1 main		 1  harddisk2:text/vim/test
 > 2  2 FuncA		58  i = FuncA(10);
   3  1 FuncC	       357  harddisk2:text/vim/src/amiga.c

此列表显示你跳转到的标签以及跳转前的光标位置。较旧的标签在上方，
较新的在下方。

'>' 指向活动条目。这是下一个 ":tag" 命令将使用的标签。CTRL-T 和
":pop" 命令将使用活动条目上方的位置。

"TO" 下面的数字是匹配列表中当前匹配的序号。注意使用 ":pop" 或
":tag" 时此数字不变。

行号和文件名被记住以便能回到标签命令前的位置。行号是正确的，即使
删除/插入了行，除非是由另一个程序（如另一个 Vim 实例）完成的。

对于当前文件，"file/text" 列显示该位置处的文本。缩进被移除，长行
被截断以适应窗口。

你可以用几个命令跳转到之前使用过的标签。一些示例：

	":pop" 或 CTRL-T	到前一个标签之前的位置
	{count}CTRL-T		到第 {count} 个旧标签之前的位置
	":tag"			到新标签
	":0tag"			到最后使用的标签

使用此功能最明显的方式是在浏览程序的调用图时。考虑以下调用图：

	main  --->  FuncA  --->  FuncC
	      --->  FuncB

（说明：main 调用 FuncA 和 FuncB；FuncA 调用 FuncC）。
你可以通过在 FuncA 的调用上使用 CTRL-] 从 main 到达 FuncA。然后你可以
CTRL-] 到达 FuncC。如果你现在想回到 main，可以使用两次 CTRL-T。然后你
可以 CTRL-] 到 FuncB。

如果你执行 ":ta {name}" 或 CTRL-] 命令，此标签将插入到栈的当前位置。
如果栈满了（最多可容纳 20 个条目），最旧的条目被删除，较旧的条目向上
移动一个位置（它们的索引号减一）。如果最后使用的条目不在底部，最后使用
的条目下面的条目将被删除。这意味着调用图中的旧分支会丢失。经过上述命令
后，标签栈将如下所示：

   # TO tag	FROM line  in file/text
   1  1 main		1  harddisk2:text/vim/test
   2  1 FuncB	       59  harddisk2:text/vim/src/main.c

|gettagstack()| 函数返回指定窗口的标签栈。
|settagstack()| 函数修改窗口的标签栈。

							*tagstack-examples*
像 `:tag` 一样写入标签栈，但使用用户自定义的 jumper#jump_to_tag 函数： >
	" 在跳转前存储跳转出发点。
	let tag = expand('<cword>')
	let pos = [bufnr()] + getcurpos()[1:]
	let item = {'bufnr': pos[0], 'from': pos, 'tagname': tag}
	if jumper#jump_to_tag(tag)
		" 跳转成功，将先前位置写入标签栈。
		let winid = win_getid()
		let stack = gettagstack(winid)
		let stack['items'] = [item]
		call settagstack(winid, stack, 't')
	endif
<
设置标签栈的当前索引为 4： >
	call settagstack(1005, {'curidx' : 4})
<
向标签栈压入新条目： >
	let pos = [bufnr('myfile.txt'), 10, 1, 0]
	let newtag = [{'tagname' : 'mytag', 'from' : pos}]
	call settagstack(2, {'items' : newtag}, 'a')
<
							*E73*
当标签栈为空时尝试使用它会得到错误消息。

3. 标签匹配列表			*tag-matchlist* *E427* *E428*

当有多个匹配标签时，可以使用以下命令在它们之间跳转。注意这些命令不改变
标签栈，它们保持同一条目。

							*:ts* *:tselect*
:ts[elect][!] [name]	列出匹配 [name] 的标签，使用标签文件中的信息。
			当未给出 [name] 时，使用标签栈中最后的标签名。
			[!] 参见 |tag-!|。
			第一列中的 '>' 表示列表中的当前位置（如果有）。
			[name] 可以是正则表达式模式，参见 |tag-regexp|。
			优先级参见 |tag-priority|。
			输出示例：

>
	  # pri kind tag		file
	  1 F	f    mch_delay		os_amiga.c
			mch_delay(msec, ignoreinput)
	> 2 F	f    mch_delay		os_msdos.c
			mch_delay(msec, ignoreinput)
	  3 F	f    mch_delay		os_unix.c
			mch_delay(msec, ignoreinput)
	Type number and <Enter> (empty cancels):
<
			"pri" 列参见 |tag-priority|。注意这取决于当前文件，
			因此使用 ":tselect xxx" 可能产生不同结果。
			"kind" 列给出标签的类型，如果这包含在标签文件中。
			"info" 列显示在标签文件中可以找到的信息。它取决于
			生成标签文件的程序。
			当列表很长时，你可能会得到 |more-prompt|。
			如果你已经看到想使用的标签，可以输入 'q' 然后
			输入编号。

							*:sts* *:stselect*
:sts[elect][!] [name]	执行 ":tselect[!] [name]" 并为选定的标签分割窗口。

							*g]*
g]			类似 CTRL-]，但使用 ":tselect" 而不是 ":tag"。

							*v_g]*
{Visual}g]		与 "g]" 相同，但使用高亮的文本作为标识符。

							*:tj* *:tjump*
:tj[ump][!] [name]	类似 ":tselect"，但当只有一个匹配时直接跳转到标签。

							*:stj* *:stjump*
:stj[ump][!] [name]	执行 ":tjump[!] [name]" 并为选定的标签分割窗口。

							*g_CTRL-]*
g CTRL-]		类似 CTRL-]，但使用 ":tjump" 而不是 ":tag"。

							*v_g_CTRL-]*
{Visual}g CTRL-]	与 "g CTRL-]" 相同，但使用高亮的文本作为标识符。

							*:tn* *:tnext*
:[count]tn[ext][!]	跳转到第 [count] 个下一个匹配标签（默认 1）。
			[!] 参见 |tag-!|。

								*]t*
]t			映射到 |:tnext|。 |default-mappings|

							*:tp* *:tprevious*
:[count]tp[revious][!]	跳转到第 [count] 个上一个匹配标签（默认 1）。
			[!] 参见 |tag-!|。

								*[t*
[t			映射到 |:tprevious|。 |default-mappings|

							*:tN* *:tNext*
:[count]tN[ext][!]	与 ":tprevious" 相同。

							*:tr* *:trewind*
:[count]tr[ewind][!]	跳转到第一个匹配标签。如果给出 [count]，跳转到
			第 [count] 个匹配标签。[!] 参见 |tag-!|。

								*[T*
[T			映射到 |:trewind|。 |default-mappings|

							*:tf* *:tfirst*
:[count]tf[irst][!]	与 ":trewind" 相同。

							*:tl* *:tlast*
:tl[ast][!]		跳转到最后一个匹配标签。[!] 参见 |tag-!|。

								*]T*
]T			映射到 |:tlast|。 |default-mappings|

							*:lt* *:ltag*
:lt[ag][!] [name]	跳转到标签 [name] 并将匹配标签添加到当前窗口的
			新位置列表。[name] 可以是正则表达式模式，参见
			|tag-regexp|。当未给出 [name] 时，使用标签栈中
			最后的标签名。搜索标签行的搜索模式以 "\V" 为前缀
			以转义所有特殊字符（very nomagic）。显示匹配标签
			的位置列表独立于标签栈。
			[!] 参见 |tag-!|。

当没有其他消息时，Vim 显示跳转到的是哪个匹配标签，以及匹配标签的数量： >
	tag 1 of 3 or more
"or more" 用于表示 Vim 尚未尝试所有标签文件。使用 ":tnext" 几次，
或使用 ":tlast" 可能会找到更多匹配。

当你因为其他消息没有看到此消息，或只是想知道你在哪里时，此命令会
再次显示它（并跳转到与上次相同的标签）： >
	:0tn
<
							*tag-skip-file*
当找到一个匹配标签但其文件不存在时，此匹配被跳过并使用下一个匹配标签。
Vim 会报告此情况以通知你缺少文件。当到达匹配列表末尾时，会给出错误消息。

							*tag-preview*
标签匹配列表也可以在预览窗口中使用。命令与上面相同，前面加 "p"。

							*:pts* *:ptselect*
:pts[elect][!] [name]	执行 ":tselect[!] [name]" 并在 "预览" 窗口中
			显示新标签。更多信息参见 |:ptag|。

							*:ptj* *:ptjump*
:ptj[ump][!] [name]	执行 ":tjump[!] [name]" 并在 "预览" 窗口中
			显示新标签。更多信息参见 |:ptag|。

							*:ptn* *:ptnext*
:[count]ptn[ext][!]	在预览窗口中执行 ":tnext"。参见 |:ptag|。

								*]_CTRL-T*
]_CTRL-T		映射到 |:ptnext|。 |default-mappings|

							*:ptp* *:ptprevious*
:[count]ptp[revious][!]	在预览窗口中执行 ":tprevious"。参见 |:ptag|。

								*[_CTRL-T*
[_CTRL-T		映射到 |:ptprevious|。 |default-mappings|

							*:ptN* *:ptNext*
:[count]ptN[ext][!]	与 ":ptprevious" 相同。

							*:ptr* *:ptrewind*
:[count]ptr[ewind][!]	在预览窗口中执行 ":trewind"。参见 |:ptag|。

							*:ptf* *:ptfirst*
:[count]ptf[irst][!]	与 ":ptrewind" 相同。

							*:ptl* *:ptlast*
:ptl[ast][!]		在预览窗口中执行 ":tlast"。参见 |:ptag|。

4. 标签详情						*tag-details*

							*static-tag*
静态标签是为特定文件定义的标签。在 C 程序中，这可能是一个 static 函数。

在 Vi 中跳转到标签会设置当前搜索模式。这意味着跳转到标签后 "n" 命令不会
搜索跳转前的相同模式。Vim 不这样做，因为我们认为这是一个 bug。如果你确实
想要旧的 Vi 行为，在 'cpoptions' 中设置 't' 标志。

							*tag-binary-search*
Vim 使用二分搜索在标签文件中快速找到所需标签。但这只在标签文件按 ASCII
字节值排序时才有效。因此，如果没有找到匹配，会用线性搜索再试一次。如果
你只想使用线性搜索，重置 'tagbsearch' 选项。或者更好的做法：排序标签文件！

注意当不按特定名称查找标签时，二分搜索会被禁用。这发生在忽略大小写时
以及使用不以固定字符串开头的正则表达式时。标签搜索此时可能会慢很多。
前者可以通过对标签文件进行大小写折叠排序来避免。
详情参见 'tagbsearch'。

							*tag-regexp*
":tag" 和 ":tselect" 命令接受正则表达式参数。参见 |pattern| 了解
可以使用的特殊字符。
当参数以 '/' 开头时，它用作模式。如果参数不以 '/' 开头，则按字面意义
作为完整标签名。
示例： >
    :tag main
<	跳转到优先级最高的标签 "main"。 >
    :tag /^get
<	跳转到以 "get" 开头的优先级最高的标签。 >
    :tag /norm
<	列出所有包含 "norm" 的标签，包括 "id_norm"。
当参数既字面存在又作为正则表达式匹配时，字面匹配具有更高优先级。
例如，":tag /open" 匹配 "open" 优先于 "open_file" 和 "file_open"。
使用模式时忽略大小写。如果你想匹配大小写，在模式中使用 "\C"。

							*tag-!*
如果标签在当前文件中，这总是有效的。否则执行的操作取决于当前文件是否
已更改、命令是否添加了 !、以及 'autowrite' 和 'winfixbuf' 选项：

  标签在     文件	    winfixbuf	autowrite		~
当前文件  已更改	!   选项	选项	      操作	~
 -----------------------------------------------------------------------------
    是		x	x      关	  x	    跳转到标签
    否		否	x      关	  x	    读取其他文件，跳转到标签
    否		是	是     关	  x	    放弃当前文件，
						    读取其他文件，跳转到标签
    否		是	否     关	  开	    写入当前文件，
						    读取其他文件，跳转到标签
    否		是	否     关	  关	    失败
    是		x	是     x	  x	    跳转到标签
    否		否	否     开	  x	    失败
    否		是	否     开	  x	    失败
    否		是	否     开	  开	    失败
    否		是	否     开	  关	    失败
 -----------------------------------------------------------------------------

- 如果标签在当前文件中，命令总是有效。
- 如果标签在另一个文件且当前文件未更改，另一个文件将成为当前文件并读入
  缓冲区。
- 如果标签在另一个文件，当前文件已更改且命令添加了 !，当前文件的更改将
  丢失，另一个文件将成为当前文件并读入缓冲区。
- 如果标签在另一个文件，当前文件已更改且 'autowrite' 选项开启，当前文件
  将被写入，另一个文件将成为当前文件并读入缓冲区。
- 如果标签在另一个文件，当前文件已更改且 'autowrite' 选项关闭，命令将
  失败。如果你想保存更改，使用 ":w" 命令然后使用不带参数的 ":tag"。
  这有效是因为标签已经被放入栈中。如果你想丢弃更改可以使用 ":tag!" 命令。
- 如果标签在另一个文件且窗口包含 'winfixbuf'，命令将失败。如果标签在
  同一文件中则可能成功。

							*tag-security*
注意 Vim 出于安全原因禁止某些命令。这类似于在当前目录中使用 exrc/vimrc
文件的 'secure' 选项。参见 |trojan-horse| 和 |sandbox|。
当 {tagaddress} 更改缓冲区时，你会得到警告消息：
	"WARNING: tag command changed a buffer!!!"
在未来版本中将不允许更改缓冲区。这一切都是出于安全原因：有人可能在标签
文件中隐藏恶意命令，否则会被忽视。例如： >
	:$d|/tag-function-name/

在 Vi 中 ":tag" 命令在搜索标签时设置最后的搜索模式。在 Vim 中不这样做，
之前的搜索模式仍然被记住，除非 'cpoptions' 中有 't' 标志。

							*tags-option*
'tags' 选项是一个文件名列表。每个文件都会被搜索标签。这可以用来使用
不同于默认文件 "tags" 的标签文件。也可以用来访问公共标签文件。

在以下情况下不使用列表中的下一个文件：
- 找到了当前缓冲区的匹配静态标签。
- 找到了匹配的全局标签。
这也取决于是否忽略大小写。在以下情况下忽略大小写：
- 'tagcase' 为 "followic" 且 'ignorecase' 被设置
- 'tagcase' 为 "ignore"
- 'tagcase' 为 "smart" 且模式只包含小写字符。
- 'tagcase' 为 "followscs" 且 'smartcase' 被设置且模式只包含小写字符。
如果不忽略大小写，而标签文件只有不匹配大小写的匹配，则搜索下一个标签文件
以寻找匹配大小写的匹配。如果没有找到匹配大小写的标签，则使用第一个不匹配
大小写的匹配。如果忽略大小写，找到了有或无匹配大小写的全局标签，则使用它，
不再搜索更多标签文件。

当标签文件名以 "./" 开头时，'.' 被替换为当前文件的路径。这使得可以使用
当前文件所在目录中的标签文件（不管当前目录是什么）。使用 "./" 的思想是
你可以定义先搜索哪个标签文件：在当前目录中（"tags,./tags"）还是在当前
文件的目录中（"./tags,tags"）。

例如： >
	:set tags=./tags,tags,/home/user/commontags

在此示例中，首先在当前文件所在目录中的 "tags" 文件中搜索标签。然后是
当前目录中的 "tags" 文件。如果没找到，则在 "/home/user/commontags"
文件中搜索标签。

通过在 'cpoptions' 中包含 'd' 标志可以关闭此功能，使其与 Vi 兼容。
"./tags" 此时将是当前目录中的标签文件，而不是当前文件所在目录中的
标签文件。

可以使用空格代替逗号。此时需要反斜杠使空格包含在字符串选项中： >
	:set tags=tags\ /home/user/commontags

要在文件名中包含空格使用三个反斜杠。要在文件名中包含逗号使用两个
反斜杠。例如，使用： >
	:set tags=tag\\\ file,/home/user/common\\,tags

表示文件 "tag file" 和 "/home/user/common,tags"。'tags' 选项的值将是
"tag\ file,/home/user/common\,tags"。

如果 'tagrelative' 选项开启（这是默认设置），并且使用另一个目录中的
标签文件，则该标签文件中的文件名是相对于标签文件所在目录的。

5. 标签文件格式				*tags-file-format* *E431*

						*ctags*
标签文件可以用外部命令创建，例如 "ctags"。它将为每个函数创建一个标签。
某些版本的 "ctags" 也会为每个 "#defined" 宏、typedef、enum 等创建标签。

一些生成标签文件的程序：
ctags			大多数 Unix 系统上都有。仅支持 C。只做基本工作。
universal ctags		基于 exuberant ctags 的维护版本。
			参见 https://ctags.io。
							*Exuberant_ctags*
exuberant ctags		适用于 C、C++、Java、Fortran、Eiffel 等。
			参见 https://ctags.sourceforge.net。自 2009 年以来
			没有新版本。
|:helptags|		用于 Vim 的 |help| 文件
ptags.py		用于 Python，用 Python 编写。在你的 Python 源代码
			目录的 Tools/scripts/ptags.py 中可以找到。
ptags			用于 Perl，用 Perl 编写。可在
			https://metacpan.org/pod/Vim::Tag 找到


标签文件中的行必须是以下两种格式之一：

1.  {tagname}		{TAB} {tagfile} {TAB} {tagaddress}
2.  {tagname}		{TAB} {tagfile} {TAB} {tagaddress} {term} {field} ..

以前支持一种旧格式，参见 |tag-old-static|。

第一种格式是普通标签，完全兼容 Vi。它是传统 ctags 实现产生的唯一格式。
这通常用于全局函数，也在其他文件中被引用。

标签文件中的行可以以 <NL> 或 <CR><NL> 结尾。在 Macintosh 上 <CR> 也有效。
<CR> 和 <NL> 字符不能出现在行内。

第二种格式是新的。它在每行末尾的可选字段中包含额外信息。它向后兼容 Vi。
它只被新版本的 ctags（如 Universal ctags 或 Exuberant ctags）支持。

{tagname}	标识符。通常是函数名，但可以是任何标识符。不能包含 <Tab>。
{TAB}		一个 <Tab> 字符。注意：以前版本允许这里使用任何空白字符。
		为了允许 {tagfile} 中有空格，这已被废弃。
{tagfile}	包含 {tagname} 定义的文件。可以有绝对或相对路径。可以包含
		环境变量和通配符（尽管使用通配符的用处不大）。不能包含
		<Tab>。
{tagaddress}	将光标定位在标签上的 Ex 命令。可以是任何 Ex 命令，尽管有
		限制（参见 |tag-security|）。Posix 只允许行号和搜索命令，
		这是最常用的。
{term}		;" 分号和双引号两个字符。这被 Vi 解释为注释的开始，使得
		后面的内容被忽略。这是为了与 Vi 向后兼容，它忽略后面的
		字段。示例： >
			APP	file	/^static int APP;$/;"	v
<		当 {tagaddress} 不是行号或搜索模式时，{term} 必须是
		`|;"`。这里竖线结束命令（不包括竖线），`;"` 用于让 Vi
		忽略行的其余部分。示例： >
			APP	file.c	call cursor(3, 4)|;"	v

{field} ..	可选字段列表。每个字段的形式为：

			<Tab>{fieldname}:{value}

		{fieldname} 标识字段，只能包含字母字符 [a-zA-Z]。
		{value} 可以是任何字符串，但不能包含 <Tab>。
		以下字符是特殊的：
			"\t" 代表 <Tab>
			"\r" 代表 <CR>
			"\n" 代表 <NL>
			"\\" 代表单个 '\' 字符

		有一个字段没有 ':'。这是标签的类型。它被处理为前面有
		"kind:"。在上面的示例中，这是 "kind:v"（通常表示变量）。
		参见 ctags 文档了解它产生的类型，使用 ctags 可以运行
		`ctags --list-kinds`。

		Vim 当前识别的另一个字段是 "file:"（值为空）。
		它用于静态标签。


标签文件的前几行可以包含以
	!_TAG_
开头的行。这些被排序到前面，只有少数以 "!" 开头的标签可以排在它们之前。
Vim 识别两个项目。第一个是指示文件是否已排序的行。当找到此行时，Vim
对标签文件使用二分搜索：
	!_TAG_FILE_SORTED<Tab>1<Tab>{anything} ~

标签文件可以进行大小写折叠排序，以避免在忽略大小写时进行线性搜索。
（当 'ignorecase' 被设置且 'tagcase' 为 "followic" 时，或当 'tagcase'
为 "ignore" 时忽略大小写。）详情参见 'tagbsearch'。
此时应使用值 '2'：
	!_TAG_FILE_SORTED<Tab>2<Tab>{anything} ~

Vim 识别的另一个标签是标签文件的编码：
	!_TAG_FILE_ENCODING<Tab>utf-8<Tab>{anything} ~
这里 "utf-8" 是标签使用的编码。Vim 将在搜索标签时将被搜索的标签从
'encoding' 转换为标签文件的编码。列出标签时进行反向转换。转换失败时
使用未转换的标签。

							*tag-search*
命令可以是任何 Ex 命令，但通常是搜索命令。
示例：
	tag1	file1	/^main(argc, argv)/ ~
	tag2	file2	108 ~

命令总是在 'magic' 未设置的情况下执行。搜索模式中唯一的特殊字符是
"^"（行首）和 "$"（<EOL>）。参见 |pattern|。注意你必须在搜索文本中
的每个反斜杠前放一个反斜杠。这是为了与 Vi 向后兼容。

							*E434* *E435*
如果命令是普通搜索命令（以 "/" 或 "?" 开头和结尾），会进行一些特殊处理：
- 搜索从文件的第 1 行开始。
  "/" 的搜索方向是向前，"?" 是向后。
  注意 'wrapscan' 无关紧要，整个文件总是被搜索。
- 如果搜索失败，忽略大小写再试一次。如果也失败了，搜索： >
	"^tagname[ \t]*("
<  （标签前加 '^' 后加 "[ \t]*("）。当使用函数名时，这将在函数名位于
  第 0 列时找到函数名。这在函数的参数自标签文件生成以来已更改时有帮助。
  如果此搜索也失败，再用以下模式搜索： >
	"^[#a-zA-Z_].*\<tagname[ \t]*("
<  这意味着：以 '#' 或标识符开头并包含标签后跟空白和 '(' 的行。这将
  找到带有类型前缀的宏名和函数名。


							*tag-old-static*
直到 2019 年 3 月（补丁 8.1.1092），支持一种过时的格式：
    {tagfile}:{tagname} {TAB} {tagfile} {TAB} {tagaddress}

此格式仅用于静态标签。它现在已过时，被第二种格式取代。它只被
Elvis 1.x、旧版 Vim 和少数版本的 ctags 支持。静态标签通常用于
局部函数，只在 {tagfile} 文件中被引用。注意对于静态标签，两次出现的
{tagfile} 必须完全相同。另见下面的 |tags-option|，了解如何使用静态标签。

此支持已被移除，因为当你可以更新到新版 Vim 时，你也应该能够更新 ctags
到支持第二种格式的版本。

6. 包含文件搜索		*include-search* *definition-search*
							*E387* *E388* *E389*

这些命令在当前文件和所有遇到的包含文件中（递归地）查找字符串。这可以
用来查找变量、函数或宏的定义。如果你只想在当前缓冲区中搜索，使用
|pattern-searches| 中列出的命令。

当遇到包含另一个文件的行时，在继续当前缓冲区之前先搜索该文件。被
包含文件所包含的文件也会被搜索。当无法找到包含文件时，它被静默忽略。
使用 |:checkpath| 命令发现哪些文件找不到，可能是你的 'path' 选项
设置不正确。注意：搜索的是包含文件，不是可能正在编辑该文件的缓冲区。
只有对当前文件使用缓冲区中的行。

字符串可以是任何关键字或已定义的宏。对于关键字，任何匹配都会被找到。
对于已定义的宏，只有与 'define' 选项匹配的行才会被找到。默认是
"^#\s*define"，适用于 C 程序。对于其他语言你可能需要更改此设置。
参见 'define' 了解 C++ 的示例。字符串不能包含行尾，只能找到行内匹配。

当为已定义的宏找到匹配时，如果行以反斜杠结尾，则继续显示下一行。

以 "[" 开头的命令从当前文件的开头开始搜索。以 "]" 开头的命令从当前
光标位置开始。

'include' 选项用于定义包含另一个文件的行。默认是 "\^#\s*include"，
适用于 C 程序。注意：Vim 不识别 C 语法，如果 'include' 选项匹配了
"#ifdef/#endif" 内部或注释内部的行，它仍然会被搜索。'isfname' 选项
用于识别匹配模式后的文件名。

'path' 选项用于查找没有绝对路径的包含文件的目录。

'comments' 选项用于显示单行或跳转到某行的命令。它定义可能开始注释的
模式。这些行在搜索时被忽略，除非使用了 [!]。一个例外：当行匹配模式
`"^# *define"` 时，它不被视为注释。

如果你想列出匹配然后选择一个跳转，可以使用映射来实现。这里有一个
示例： >

  :map <F4> [I:let nr = input("Which one: ")<Bar>exe "normal " .. nr .. "[\t"<CR>

7. 使用 'tagfunc'					*tag-function*

可以为 Vim 提供一个函数来生成标签列表，用于 |:tag|、|:tselect| 等命令、
普通模式标签命令如 |CTRL-]| 以及 |taglist()| 函数。

用于生成标签列表的函数通过设置 'tagfunc' 选项来指定。该函数将以三个
参数被调用：
   pattern	标签搜索期间使用的标签标识符或模式。
   flags	包含控制函数行为的标志的字符串。
   info		包含以下条目的字典：
		    buf_ffname	  完整文件名，可用于优先级。
		    user_data	  自定义数据字符串，如果之前由 tagfunc
				  存储在标签栈中。

注意使用时需要在参数名前加 "a:"。

当前最多可以传递三个标志给标签函数：
  'c'		函数被正在处理的普通命令调用（助记：标签函数可以使用
		光标周围的上下文来更好地生成标签列表。）
  'i'		在插入模式下，用户正在补全标签（使用 |i_CTRL-X_CTRL-]|
		或 'complete' 包含 "`t`" 或 "`]`"）。
  'r'		tagfunc 的第一个参数应被解释为 |pattern|
		（参见 |tag-regexp|），例如使用时： >
		  :tag /pat
<		在插入模式下补全时也会给出。
		如果此标志不存在，参数通常按字面意义作为完整标签名。

注意当设置 'tagfunc' 时，|tag-priority| 中描述的标签优先级不适用。
相反，优先级与函数返回的列表中元素的顺序完全一致。
								*E987*
函数应返回字典条目的列表。每个字典必须至少包含以下条目，且每个值
必须是字符串：
	name		标签名。
	filename	定义标签的文件名。它是相对于当前目录的路径
			或完整路径。
	cmd		用于在文件中定位标签的 Ex 命令。可以是
			Ex 搜索模式或行号。
注意格式类似于 |taglist()| 的格式，这使得可以使用其输出来生成结果。
以下字段是可选的：
	kind		标签的类型。
	user_data	存储在标签栈中的自定义数据字符串，可用于
			在操作之间消除标签歧义。

如果函数返回 |v:null| 而不是列表，将执行标准标签查找。

不允许从 'tagfunc' 内部更改标签栈。  *E986*
不允许从 'tagfunc' 内部关闭窗口或切换窗口。
*E1299*

以下是用于 'tagfunc' 的函数的假设示例。它使用 |taglist()| 的输出来
生成结果：按文件名逆序排列的标签列表。
>vim
	function CompareFilenames(item1, item2)
	  let f1 = a:item1['filename']
	  let f2 = a:item2['filename']
	  return f1 >=# f2 ? -1 : f1 <=# f2 ? 1 : 0
	endfunction

	function TagFunc(pattern, flags, info)
	  let result = taglist(a:pattern)
	  call sort(result, "CompareFilenames")

	  return result
	endfunc
	set tagfunc=TagFunc
<
注意：执行 |taglist()| 时 'tagfunc' 函数不会被递归调用。
