编辑文件						*edit-files*

                                      输入 |gO| 查看目录。

==============================================================================
1. 简介						*edit-intro*

用 Vim 编辑文件意味着：

1. 将文件读入缓冲区
2. 用编辑器命令修改缓冲区
3. 将缓冲区写入文件

							*current-file*
只要你不写入缓冲区，原始文件就保持不变。如果你开始编辑一个文件（将文件读入
缓冲区），文件名会被记住作为"当前文件名"。这也被称为当前缓冲区的名称。它可以
在命令行上用 "%" 使用 |:_%|。

							*alternate-file*
如果已经有一个当前文件名，那么它会变成备用文件名。它可以在命令行上用 "#" 使用
|:_#|，你也可以使用 |CTRL-^| 命令在当前文件和备用文件之间切换。但是，使用
|:keepalt| 时不会更改备用文件名。每个窗口会记住一个备用文件名。

							*:keepa* *:keepalt*
:keepa[lt] {cmd}	执行 {cmd} 同时保持当前备用文件名不变。注意间接调用的
			命令（例如通过函数）仍然可能设置备用文件名。

所有文件名都会记住在缓冲区列表中。当你输入文件名进行编辑（例如用
":e filename"）或写入（例如用 ":w filename"）时，文件名会被添加到列表中。
你可以使用缓冲区列表来记住你编辑过哪些文件，并使用 |CTRL-^| 命令快速在
文件之间切换（例如复制文本）。先输入文件编号，然后按 CTRL-^。


CTRL-G		或				*CTRL-G* *:f* *:fi* *:file*
:f[ile]			打印当前文件名（按输入时的样子，除非使用了 ":cd"）、
			光标位置（除非设置了 'ruler' 选项）和文件状态
			（只读、已修改、读取错误、新文件）。参见 'shortmess'
			选项了解如何使此消息更短。

:f[ile]!		类似 |:file|，但即使 'shortmess' 指示也不截断名称。

{count}CTRL-G		类似 CTRL-G，但打印带完整路径的当前文件名。如果计数
			大于 1，还会给出当前缓冲区编号。

					*g_CTRL-G* *word-count* *byte-count*
g CTRL-G		以五种方式打印光标的当前位置：列、行、单词、字符和
			字节。如果字符数和字节数相同，则省略字符位置。

			如果行中有在屏幕上占据多个位置的字符（<Tab> 或
			特殊字符），或每列使用多个字节的字符（'encoding'
			为 utf-8 时大于 0x7F 的字符），则同时显示字节列和
			屏幕列，用短横线分隔。

			另见 'ruler' 选项和 |wordcount()| 函数。

							*v_g_CTRL-G*
{Visual}g CTRL-G	类似 "g CTRL-G"，但显示可视选区的单词、字符、行和
			字节计数。
			在块状模式中，还会显示列计数。（关于 {Visual}
			参见 |Visual-mode|。）

							*:file_f*
:f[ile][!] {name}	将当前文件名设置为 {name}。可选的 ! 避免截断消息，
			与 |:file| 相同。
			如果缓冲区已有名称，该名称会变成 |alternate-file|
			名称。会创建一个未列出的缓冲区来保存旧名称。

			参见 |nvim_buf_set_name()| 以避免文件名转义。

							*:0file*
:0f[ile][!]		移除当前缓冲区的名称。可选的 ! 避免截断消息，
			与 |:file| 相同。

:buffers
:files
:ls			列出所有当前已知的文件名。参见 |windows.txt|
			|:files| |:buffers| |:ls|。

Vim 会记住你输入的文件名的完整路径名。在大多数情况下，显示文件名时只显示
你输入的名称，但如果你使用了 ":cd" 命令 |:cd|，则使用完整路径名。

							*home-replace*
如果环境变量 $HOME 已设置，且文件名以该字符串开头，通常会用 "~" 替换 HOME
来显示。这样做是为了保持文件名简短。在读写文件时仍使用完整名称，"~" 仅在
显示文件名时使用。当替换文件名后结果只是 "~" 时，会使用 "~/" 代替（以避免
与设置为 $HOME 的选项和 'backupext' 设置为 "~" 时混淆）。

写入缓冲区时，默认使用当前文件名。因此当你执行 "ZZ" 或 ":wq" 命令时，原始
文件会被覆盖。如果你不想这样，可以通过给 ":write" 命令一个文件名参数来将
缓冲区写入另一个文件。例如： >

	vim testfile
	[用编辑器命令修改缓冲区]
	:w newfile
	:q

这会创建一个文件 "newfile"，它是 "testfile" 的修改副本。文件 "testfile" 保持
不变。无论如何，如果 'backup' 选项已设置，Vim 在覆盖原始文件之前会重命名或
复制它。如果你发现需要原始文件，可以使用这个文件。另见 'patchmode' 选项。
备份文件的名称通常与原始文件相同，后面加上 'backupext'。默认的 "~" 有点奇怪，
是为了避免意外覆盖现有文件。如果你更喜欢 ".bak"，请更改 'backupext' 选项。
备份文件可以通过设置 'backupdir' 放在另一个目录中。

当你在没有文件名的情况下开始编辑时，消息中会显示 "No File"。如果 ":write"
命令使用了文件名参数，当前文件的文件名会被设置为该文件名。这只在 'cpoptions'
包含 'F' 标志时发生（默认包含）|cpo-F|。这在先在空缓冲区中输入文本然后写入
文件时很有用。如果 'cpoptions' 包含 'f' 标志（默认不包含）|cpo-f|，则文件名
会为 ":read file" 命令设置。这在启动 Vim 时不带参数然后执行 ":read file" 开始
编辑文件时很有用。
当文件名已设置且 'filetype' 为空时，会触发文件类型检测自动命令。
							*not-edited*
由于文件名是在没有真正开始编辑该文件的情况下设置的，你会被保护不会覆盖该文件。
这通过设置 "notedited" 标志来实现。你可以用 CTRL-G 或 ":file" 命令查看此标志
是否已设置。当 "notedited" 标志设置时，它会包含 "[Not edited]"。
将缓冲区写入当前文件名（用 ":w!"）时，"notedited" 标志会被重置。

							*abandon*
Vim 会记住你是否修改了缓冲区。你受到保护不会丢失所做的更改。如果你尝试退出
而不写入，或想开始编辑另一个文件，Vim 会拒绝。要覆盖此保护，在命令后面加
'!'。更改将会丢失。例如：":q" 在缓冲区已更改时不起作用，但 ":q!" 可以。
要查看缓冲区是否已更改，请使用 "CTRL-G" 命令。如果缓冲区已更改，消息中会
包含 "[Modified]"，或者如果 'shortmess' 中有 'm' 标志则包含 "+"。

如果你想自动保存更改而不询问，请开启 'autowriteall' 选项。'autowrite' 是
与之对应的 Vi 兼容选项，但不适用于所有命令。

如果你想保留更改的缓冲区但不保存它，请开启 'hidden' 选项。参见 |hidden-buffer|。
有些命令即使 'hidden' 未设置也会这样工作，请查看命令的帮助。

2. 编辑文件					*edit-a-file*

							*:e* *:edit* *reload*
:e[dit][!] [++opt] [+cmd]
			编辑当前文件。这在当前文件在 Vim 之外被更改时很有用，
			可以重新编辑当前文件。
							*:edit!* *discard*
			如果给出 [!]，当前缓冲区中未保存的更改会被丢弃。
			不带 [!] 时，如果有未保存的更改命令会失败，除非
			'autowriteall' 已设置且文件可以写入。
			另见 |++opt| 和 |+cmd|。

							*:edit_f*
:e[dit][!] [++opt] [+cmd] {file}
			编辑 {file}。
							*:edit!_f*
			如果给出 [!]，当前缓冲区中未保存的更改会被丢弃。
			不带 [!] 时，如果有未保存的更改命令会失败，除非
			'hidden' 已设置或 'autowriteall' 已设置且文件可以
			写入。
			另见 |++opt| 和 |+cmd|。

							*:edit_#* *:e#*
:e[dit] [++opt] [+cmd] #[count]
			编辑第 [count] 个缓冲区（如 |:files| 所示）。
			此命令与 [count] CTRL-^ 相同。但 ":e #" 在备用缓冲区
			没有文件名时不起作用，而 CTRL-^ 仍然可以。
			另见 |++opt| 和 |+cmd|。

							*:ene* *:enew*
:ene[w]			编辑一个新的、未命名的缓冲区。当当前缓冲区有更改时
			会失败，除非 'hidden' 已设置或 'autowriteall' 已设置
			且文件可以写入。
			如果 'fileformats' 不为空，新缓冲区使用给出的第一个
			格式。如果 'fileformats' 为空，使用当前缓冲区的
			'fileformat'。

							*:ene!* *:enew!*
:ene[w]!		编辑一个新的、未命名的缓冲区。丢弃当前缓冲区的任何
			更改。
			设置 'fileformat' 如同 |:enew|。

							*:fin* *:find*
:fin[d][!] [++opt] [+cmd] {file}
			在 'path' 中查找 {file}，然后 |:edit| 它。
			另见：'findfunc'。

:{count}fin[d][!] [++opt] [+cmd] {file}
			与 ":find" 相同，但使用 'path' 中第 {count} 个匹配。
			因此 ":2find file" 会找到 'path' 中找到的第二个
			"file"。当 'path' 中文件的匹配数少于请求的数量时，
			你会得到一个错误消息。

							*:ex*
:ex [++opt] [+cmd] [file]
			同 |:edit|。

							*:vi* *:visual*
:vi[sual][!] [++opt] [+cmd] [file]
			在 Ex 模式中使用时：离开 |Ex-mode|，返回普通模式。
			否则同 |:edit|。

							*:vie* *:view*
:vie[w][!] [++opt] [+cmd] file
			在 Ex 模式中使用时：离开 |Ex-mode|，返回普通模式。
			否则同 |:edit|，但为此缓冲区设置 'readonly' 选项。

							*CTRL-^* *CTRL-6*
CTRL-^			编辑备用文件。通常备用文件是之前编辑的文件。这是
			在两个文件之间快速切换的方式。等同于 ":e #"，但在
			没有文件名时也可以工作。

			如果 'autowrite' 或 'autowriteall' 选项开启且缓冲区
			已更改，则写入它。
			通常 ^ 字符位于 6 键上，按 CTRL 和 6 就能得到我们
			所说的 CTRL-^。但在某些非美式键盘上 CTRL-^ 以其他
			方式产生。

{count}CTRL-^		编辑缓冲区列表中第 [count] 个文件（等同于 ":e #[count]"）。
			这是在文件之间快速切换的方式。
			更多详情参见上面的 |CTRL-^|。

							*gf* *E446* *E447*
[count]gf		编辑光标下或光标后名称所指的文件。
			助记："goto file"。
			使用 'isfname' 选项来确定哪些字符应该在文件名中。
			尾部的标点字符 ".,:;!" 会被忽略。转义的空格 "\ "
			会被缩减为单个空格。
			使用 'path' 选项作为查找文件的目录名称列表。关于
			相对目录和通配符的详情参见 'path' 选项。
			使用 'suffixesadd' 选项来检查添加了后缀的文件名。
			如果找不到文件，使用 'includeexpr' 修改名称并再次
			尝试。
			如果给出了 [count]，则编辑在 'path' 中找到的第
			count 个文件。
			如果 Vim 拒绝 |abandon| 当前文件，此命令会失败。
			如果你想在新窗口中编辑文件，请使用 |CTRL-W_CTRL-F|。
			如果你确实想编辑一个新文件，请使用： >
				:e <cfile>
<			要使 gf 始终像这样工作： >
				:map gf :e <cfile><CR>
<			如果名称是超文本链接，看起来像
			"type://machine/path"，你需要 |netrw| 插件。
			对于 Unix，'~' 字符会被展开，例如 "~user/file"。
			环境变量也会被展开 |expand-env|。

							*v_gf*
{Visual}[count]gf	同 "gf"，但使用高亮文本作为要编辑的文件名。
			'isfname' 被忽略。前导空白会被跳过，其余所有空白和
			特殊字符都包含在文件名中。
			（关于 {Visual} 参见 |Visual-mode|。）

							*gF*
[count]gF		同 "gf"，但如果文件名后面跟着数字，则光标定位到
			文件中的那一行。
			文件名和数字必须由非文件名（参见 'isfname'）且非
			数字的字符分隔。也能识别 " line "，就像在
			`:verbose command UserCmd` 的输出中使用的那样。
			文件名、分隔符和数字之间的空白会被忽略。
			示例：
				eval.c:10 ~
				eval.c @ 20 ~
				eval.c (30) ~
				eval.c 40 ~

							*v_gF*
{Visual}[count]gF	同 "v_gf"。

这些命令用来开始编辑单个文件。这意味着文件被读入缓冲区且当前文件名被设置。
打开的文件取决于当前目录，参见 |:cd|。

文件读取后给出的消息的解释参见 |read-messages|。

如果你搞乱了缓冲区想重新开始，可以使用 ":e!" 命令。":e" 命令只在你更改了
当前文件名时才有用。

							*:filename* *{file}*
除了这里提到的内容外，在期望文件名的地方还有更多特殊项目，参见
|cmdline-special|。

非 Unix 系统的注意事项：当使用接受单个文件名的命令（如 ":edit file"）时，
文件名中允许有空格，但尾部空格会被忽略。这在经常在文件名中嵌入空格的系统
（如 MS-Windows）上很有用。示例：命令 ":e   Long File Name " 会编辑文件
"Long File Name"。当使用接受多个文件名的命令（如 ":next file1 file2"）时，
嵌入的空格必须用反斜杠转义。

						*wildcard* *wildcards*
{file} 中的通配符会被展开，但与文件补全一样，'wildignore' 和 'suffixes' 也
适用。支持哪些通配符取决于系统。以下是常见的：
	`?`	匹配一个字符
	`*`	匹配任意内容，包括空
	`**`	匹配任意内容，包括空，递归进入目录
	[abc]	匹配 'a'、'b' 或 'c'

要避免通配符的特殊含义，在前面加反斜杠。但在 MS-Windows 上反斜杠是路径分隔符，
"path\[abc]" 当 "[" 在 'isfname' 选项中时仍被视为通配符。避免此问题的简单
方法是使用 "path\[[]abc]"，这匹配文件 "path\[abc]"。

					*starstar-wildcard*
"**" 的展开在 Unix、Win32、macOS 和一些其他系统上可用（但在 Unix 和 macOS 上
可能取决于你的 'shell' 设置。已知在 zsh 上能正确工作；对于 bash 需要至少
bash 版本 >= 4.X）。
这允许搜索目录树。默认最深可达 100 级目录。
注意有些命令的工作方式略有不同，参见 |file-searching|。
示例： >
	:n **/*.txt
找到的文件：
	aaa.txt ~
	subdir/bbb.txt ~
	a/b/c/d/ccc.txt ~
当在 "**" 紧前或紧后使用非通配符字符时，这些字符仅在顶层目录中匹配。它们不
用于更深层的目录。例如： >
	:n /usr/inc**/types.h
找到的文件：
	/usr/include/types.h ~
	/usr/include/sys/types.h ~
	/usr/inc/old/types.h ~
注意包含 "/sys" 的路径被包含在内，因为它不需要匹配 "/inc"。因此它就像匹配
"/usr/inc*/*/*..."，而不是 "/usr/inc*/inc*/inc*"。

					*backtick-expansion* *`-expansion*
在 Unix 和一些其他系统上，你也可以在文件名参数中使用反引号，例如： >
	:next `find . -name ver\\*.c -print`
	:view `ls -t *.patch  \| head -n1`
Vim 会使用 'shell' 运行反引号中的命令，并使用标准输出作为给定 Vim 命令的
参数（shell 命令的错误消息会被丢弃）。
要查看 Vim 运行的 shell 命令，将 'verbose' 选项设置为 4。当 shell 命令返回
非零退出代码时，会显示错误消息且 Vim 命令会被中止。要避免此情况，使 shell
始终返回零，像这样： >
       :next `find . -name ver\\*.c -print \|\| true`

星号前的反斜杠是为了防止 shell 在执行 find 程序之前展开 "ver*.c"。shell
管道符号 "|" 前的反斜杠防止 Vim 将其解析为命令终止符。
这在大多数其他系统上也有效，但限制是反引号必须包围整个项目。不能在第一个
反引号之前或最后一个反引号之后直接有文本。

							*`=*
你可以让反引号作为 Vim 表达式展开，而不是外部命令，方法是在第一个反引号后
紧跟等号，例如： >
	:e `=tempname()`
表达式可以包含几乎任何内容，因此这也可以用来避免 '"'、"|"、'%' 和 '#' 的
特殊含义。但是，'wildignore' 会像其他通配符一样适用。

表达式中的环境变量在求值表达式时展开，因此这可以工作： >
	:e `=$HOME .. '/.vimrc'`
这在字符串中使用 $HOME，它会按字面意思使用，很可能不是你想要的： >
	:e `='$HOME' .. '/.vimrc'`

如果表达式返回字符串，则名称用换行符分隔。当结果是 |List| 时，每个项目用作
一个名称。换行符也分隔名称。
注意此类表达式仅在期望文件名作为 Ex 命令参数的地方支持。

							*++opt* *[++opt]*
[++opt] 参数可用于为一个命令设置某些选项，以及指定处理坏字符的行为。
形式为： >
	++{optname}
或： >
	++{optname}={value}

其中 {optname} 是以下之一：	    *++ff* *++enc* *++bin* *++nobin* *++edit*
    ff     或  fileformat   覆盖 'fileformat'
    enc    或  encoding	    覆盖 'fileencoding'
    bin    或  binary	    设置 'binary'
    nobin  或  nobinary	    重置 'binary'
    bad			    指定处理坏字符的行为
    edit		    用于 |:read|：保持选项如同编辑文件
    p			    用于 |:write|：创建文件的父目录

{value} 不能包含空白。它可以是选项的任何有效值。
示例： >
	:e ++ff=unix
这以 'fileformat' 设置为 "unix" 重新编辑同一个文件。 >

	:w ++enc=latin1 newfile
这以 latin1 格式将当前缓冲区写入 "newfile"。

当 'fileencoding' 或用 ++enc 指定的值与 'encoding' 不同时，写入文件时给出的
消息会显示 "[converted]"。

可以有多个 ++opt 参数，用空白分隔。它们必须全部出现在任何 |+cmd| 参数之前。

								*++p*
"++p" 标志在父目录不存在时创建文件的父目录。例如，如果你编辑
"foo/bar/file.txt"，":write ++p" 命令会在写入文件之前（如有必要）创建
"foo/bar/"。 >

	:edit foo/bar/file.txt
	:write ++p

如果你想让 :write（不带 "++p"）始终创建缺少的父目录，在你的配置中添加此
自动命令： >

	" 自动创建父目录（URI "://" 除外）。
	au BufWritePre,FileWritePre * if @% !~# '\(://\)' | call mkdir(expand('<afile>:p:h'), 'p') | endif
<

								*++bad*
"++bad=" 的参数指定无法转换的字符和非法字节的处理方式。可以是以下三种之一：
    ++bad=X      一个单字节字符，替换每个坏字符。
    ++bad=keep   保留坏字符不转换。注意这可能导致文本中出现非法字节！
    ++bad=drop   删除坏字符。

默认类似 "++bad=?"：用问号替换每个坏字符。在某些地方使用倒问号 (0xBF)。

注意并非所有命令都使用 ++bad 参数，即使你添加了它也不会报错。例如 |:write|。

注意在读取时，'fileformat' 和 'fileencoding' 选项会被设置为使用的格式。
在写入时不会发生这种情况，因此下次写入会使用选项的旧值。'binary' 选项同理。


							*+cmd* *[+cmd]*
[+cmd] 参数可用于在新打开的文件中定位光标，或执行任何其他命令：
	+		从最后一行开始。
	+{num}		从第 {num} 行开始。
	+/{pat}		从包含 {pat} 的第一行开始。
	+{command}	打开新文件后执行 {command}。
			{command} 是任何 Ex 命令。
要在 {pat} 或 {command} 中包含空白，在其前面加反斜杠。双倍反斜杠的数量。 >
	:edit  +/The\ book	     file
	:edit  +/dir\ dirname\\      file
	:edit  +set\ dir=c:\\\\temp  file
注意在最后一个示例中反斜杠的数量被减半了两次：一次用于 "+cmd" 参数，一次
用于 ":set" 命令。

							*file-formats*
'fileformat' 选项设置文件的 <EOL> 风格：
'fileformat'    字符		   名称			~
  "dos"		<CR><NL> 或 <NL>   DOS 格式		*DOS-format*
  "unix"	<NL>		   Unix 格式		*Unix-format*
  "mac"		<CR>		   Mac 格式		*Mac-format*

读取文件时，上述字符被解释为 <EOL>。在 DOS 格式中（Windows 的默认格式），
<CR><NL> 和 <NL> 都被解释为 <EOL>。注意以 DOS 格式写入文件时，会为每个单独
的 <NL> 添加 <CR> 字符。另见 |file-read|。

写入文件时，上述字符用于 <EOL>。对于 DOS 格式使用 <CR><NL>。另见
|DOS-format-write|。

你可以以 DOS 格式读取文件并以 Unix 格式写入。这会将所有 <CR><NL> 对替换为
<NL>（假设 'fileformats' 包含 "dos"）： >
	:e file
	:set fileformat=unix
	:w
如果你以 Unix 格式读取文件并以 DOS 格式写入，所有 <NL> 字符会被替换为
<CR><NL>（假设 'fileformats' 包含 "unix"）： >
	:e file
	:set fileformat=dos
	:w

如果你开始编辑一个新文件且 'fileformats' 选项不为空（这是默认值），Vim 会
尝试检测文件中的行是否由指定的格式分隔。当设置为 "unix,dos" 时，Vim 会检查
行是否以单个 <NL>（Unix 使用）或 <CR><NL> 对（MS-Windows）结尾。只有当所有
行都以 <CR><NL> 结尾时，'fileformat' 才设置为 "dos"，否则设置为 "unix"。
当 'fileformats' 包含 "mac" 且文件中未找到 <NL> 字符时，'fileformat' 设置为
"mac"。

如果在非 MS-Windows 系统上 'fileformat' 选项设置为 "dos"，会显示消息 "[dos]"
提醒你正在发生一些不寻常的事情。在 MS-Windows 系统上如果 'fileformat' 设置为
"unix" 会得到消息 "[unix]"。在所有系统上如果 'fileformat' 设置为 "mac" 会得到
消息 "[mac]"。

如果 'fileformats' 选项为空且使用 DOS 格式，但读取文件时某些行没有以 <CR><NL>
结尾，文件消息中会包含 "[CR missing]"。
如果 'fileformats' 选项为空且使用 Mac 格式，但读取文件时发现了 <NL>，文件
消息中会包含 "[NL missing]"。

如果新文件不存在，当 'fileformats' 为空时使用当前缓冲区的 'fileformat'。
否则使用 'fileformats' 中的第一个格式作为新文件的格式。

在编辑二进制、可执行或 Vim 脚本文件之前，应该设置 'binary' 选项。一种简单
的方法是用 "-b" 选项启动 Vim。这会避免使用 'fileformat'。否则你可能会面临
单个 <NL> 字符被意外替换为 <CR><NL> 的风险。

行尾和文件末尾				*eol-and-eof*

Vim 有几个选项来控制文件格式：
	'fileformat'	<EOL> 风格：Unix、DOS、Mac
	'endofline'	最后一行是否以 <EOL> 结尾
	'endoffile'	文件是否以 CTRL-Z 结尾
	'fixendofline'	是否修复 eol 和 eof

前三个值通常在读取文件时自动检测，并在写入文件时使用。编辑缓冲区时看起来
每一行都有行结尾且 CTRL-Z 不存在（设置了 'binary' 时例外，那时工作方式不同）。

'fixendofline' 选项可用于选择写入的内容。你也可以更改选项值以与读取时不同
的方式写入文件。

以下是一些使用示例。

如果你想要 Unix 格式的文件（每行以 NL 结尾）： >
	setl ff=unix fixeol
在任何类 Unix 系统上你可能都应该这样做。现代 MS-Windows 系统通常也能很好地
使用此格式。建议 Vim 脚本始终使用此格式。

如果你想在现代环境中使用旧的 MS-DOS 文件，修复行尾并去掉 CTRL-Z，但保留
<CR><NL> 风格的 <EOL>： >
	setl ff=dos fixeol
这对许多 MS-Windows 程序很有用，它们通常期望 <CR><NL> 行结尾。

如果你想去掉最后的 <EOL> 并添加最后的 CTRL-Z（例如用于 CP/M 等旧系统）： >
	setl ff=dos nofixeol noeol eof

如果你想完全按原样保留文件格式，包括任何最后的 <EOL> 和最后的 CTRL-Z： >
	setl nofixeol

3. 参数列表				*argument-list* *arglist*

如果在启动 Vim 时给出了多个文件名，此列表会被记住为参数列表。你可以跳转到
此列表中的每个文件。

不要将此与缓冲区列表混淆，缓冲区列表可以用 |:buffers| 命令查看。参数列表
在 Vi 中就已存在，缓冲区列表是 Vim 中的新功能。参数列表中的每个文件名也会
出现在缓冲区列表中（除非用 |:bdel| 或 |:bwipe| 删除了）。但缓冲区列表中的
名称通常不在参数列表中。

此主题在用户手册的 |07.2| 节中有介绍。

有一个全局参数列表，默认所有窗口使用。可以创建一个当前窗口本地的新参数列表，
参见 |:arglocal|。

你可以使用以下命令和表达式函数 |argc()| 和 |argv()| 来操作参数列表。这些
都作用于当前窗口的参数列表。

							*:ar* *:arg* *:args*
:ar[gs]			打印参数列表，当前文件用方括号括起来。

:ar[gs] [++opt] [+cmd] {arglist}			*:args_f*
			将 {arglist} 定义为新的参数列表并编辑第一个文件。
			当有更改且 Vim 不想 |abandon| 当前缓冲区时会失败。
			另见 |++opt| 和 |+cmd|。

:ar[gs]! [++opt] [+cmd] {arglist}			*:args_f!*
			将 {arglist} 定义为新的参数列表并编辑第一个文件。
			丢弃当前缓冲区的任何更改。
			另见 |++opt| 和 |+cmd|。

:[count]arge[dit][!] [++opt] [+cmd] {name} ...		*:arge* *:argedit*
			将 {name} 添加到参数列表并编辑它。
			不检查重复，可以将文件添加到参数列表两次
			|:argded|。
			这类似于使用 |:argadd| 然后 |:edit|（有一个小例外，
			|:edit| 不更改参数列表，因此参数列表指针不会改变）。
			文件名中的空格必须用 "\" 转义。
			[count] 的使用与 |:argadd| 相同。
			如果当前文件不能被 |abandon|，{name} 仍然会被添加
			到参数列表，但不会被编辑。不检查重复。
			另见 |++opt| 和 |+cmd|。

:[count]arga[dd] {name} ...			*:arga* *:argadd* *E479*
:[count]arga[dd]						*E1156*
			将 {name} 添加到参数列表。当 {name} 省略时，将
			当前缓冲区名称添加到参数列表。
			如果 [count] 省略，{name} 添加在参数列表中当前
			条目之后。否则添加在第 [count] 个文件之后。
			如果参数列表是 "a b c"，且 "b" 是当前参数，
			则这些命令的结果是：
				命令		新参数列表 ~
				:argadd x	a  [b]  x  c
				:0argadd x	x   a  [b] c
				:1argadd x	a   x  [b] c
				:$argadd x	a  [b]  c  x
			最后一个之后：
				:+2argadd y	a  [b]  c  x  y
			不检查重复，可以将文件添加到参数列表两次。你可以
			之后用 |:argdedupe| 修复它： >
				:argadd *.txt | argdedupe
<			当前编辑的文件不会改变。
			注意：你也可以使用此方法： >
				:args ## x
<			这会添加 "x" 项并排序新列表。

:argded[upe]					*:argded* *:argdedupe*
			从参数列表中删除重复的文件名。
			如果你的当前文件是重复的，你的当前文件会更改为
			原始文件的索引。

:argd[elete] {pattern} ...		*:argd* *:argdelete* *E480* *E610*
			从参数列表中删除匹配 {pattern} 的文件。{pattern}
			像文件模式一样使用，参见 |file-pattern|。"%" 可以
			用来删除当前条目。
			此命令保留当前编辑的文件，即使它从参数列表中被
			删除。
			示例： >
				:argdel *.obj

:[range]argd[elete]	从参数列表中删除 [range] 范围内的文件。
			示例： >
				:10,$argdel
<			删除第 10 个及之后的参数，保留 1-9。 >
				:$argd
<			只删除最后一个。 >
				:argd
				:.argd
<			删除当前参数。 >
				:%argd
<			从参数列表中删除所有文件。
			当范围中的最后一个数字太大时，会删除到最后一个
			参数。

							*:argu* *:argument*
:[count]argu[ment] [count] [++opt] [+cmd]
			编辑参数列表中的第 [count] 个文件。当 [count] 省略
			时使用当前条目。当有更改且 Vim 不想 |abandon| 当前
			缓冲区时会失败。
			另见 |++opt| 和 |+cmd|。

:[count]argu[ment]! [count] [++opt] [+cmd]
			编辑参数列表中的第 [count] 个文件，丢弃当前缓冲区
			的任何更改。当 [count] 省略时使用当前条目。
			另见 |++opt| 和 |+cmd|。

:[count]n[ext] [++opt] [+cmd]			*:n* *:ne* *:next* *E165* *E163*
			编辑下 [count] 个文件。当有更改且 Vim 不想 |abandon|
			当前缓冲区时会失败。另见 |++opt| 和 |+cmd|。

								*]a*
]a			映射到 |:next|。|default-mappings|

:[count]n[ext]! [++opt] [+cmd]
			编辑下 [count] 个文件，丢弃缓冲区的任何更改。
			另见 |++opt| 和 |+cmd|。

:n[ext] [++opt] [+cmd] {arglist}			*:next_f*
			同 |:args_f|。

:n[ext]! [++opt] [+cmd] {arglist}
			同 |:args_f!|。

:[count]N[ext] [count] [++opt] [+cmd]			*:Next* *:N* *E164*
			编辑参数列表中的前 [count] 个文件。当有更改且 Vim
			不想 |abandon| 当前缓冲区时会失败。
			另见 |++opt| 和 |+cmd|。

:[count]N[ext]! [count] [++opt] [+cmd]
			编辑参数列表中的前 [count] 个文件。丢弃缓冲区的
			任何更改。另见 |++opt| 和 |+cmd|。

:[count]prev[ious] [count] [++opt] [+cmd]		*:prev* *:previous*
			同 :Next。另见 |++opt| 和 |+cmd|。

							*:rew* *:rewind*
:rew[ind] [++opt] [+cmd]
			开始编辑参数列表中的第一个文件。当有更改且 Vim
			不想 |abandon| 当前缓冲区时会失败。
			另见 |++opt| 和 |+cmd|。

								*[A*
[A			映射到 |:rewind|。|default-mappings|

:rew[ind]! [++opt] [+cmd]
			开始编辑参数列表中的第一个文件。丢弃缓冲区的
			任何更改。另见 |++opt| 和 |+cmd|。

							*:fir* *:first*
:fir[st][!] [++opt] [+cmd]
			":rewind" 的另一个名称。

							*:la* *:last*
:la[st] [++opt] [+cmd]
			开始编辑参数列表中的最后一个文件。当有更改且 Vim
			不想 |abandon| 当前缓冲区时会失败。
			另见 |++opt| 和 |+cmd|。

								*]A*
]A			映射到 |:last|。|default-mappings|

:la[st]! [++opt] [+cmd]
			开始编辑参数列表中的最后一个文件。丢弃缓冲区的
			任何更改。另见 |++opt| 和 |+cmd|。

							*:wn* *:wnext*
:[count]wn[ext] [++opt]
			写入当前文件并开始编辑下 [count] 个文件。
			另见 |++opt| 和 |+cmd|。

:[count]wn[ext] [++opt] {file}
			将当前文件写入 {file} 并开始编辑下 [count] 个文件，
			除非 {file} 已存在且 'writeany' 选项关闭。
			另见 |++opt| 和 |+cmd|。

:[count]wn[ext]! [++opt] {file}
			将当前文件写入 {file} 并开始编辑下 [count] 个文件。
			另见 |++opt| 和 |+cmd|。

:[count]wN[ext][!] [++opt] [file]		*:wN* *:wNext*
:[count]wp[revious][!] [++opt] [file]		*:wp* *:wprevious*
			同 :wnext，但转到上一个文件而不是下一个。

上面命令中的 [count] 默认为一。某些命令可以使用两个计数。使用最后一个
（最右边的）。

如果没有 [+cmd] 参数，光标定位在文件的最后已知光标位置。如果 'startofline'
已设置，光标会定位在行的第一个非空白处，否则使用最后已知的列。如果没有最后
已知的光标位置，光标会在第一行（在 Ex 模式中是最后一行）。

							*{arglist}*
参数列表中的通配符会被展开且文件名会被排序。因此你可以使用命令 `vim *.c` 来
编辑所有 C 文件。在 Vim 中命令 `:n *.c` 做同样的事。

空白用于分隔文件名。在空格或 tab 前面加反斜杠可以将其包含在文件名中。例如，
编辑单个文件 "foo bar"： >
	:next foo\ bar

在 Unix 和一些其他系统上你也可以使用反引号，例如： >
	:next `find . -name \\*.c -print`
星号前的反斜杠是为了防止 shell 在执行 find 程序之前展开 "*.c"。

							*arglist-position*
当有参数列表时，你可以在窗口标题中看到你正在编辑哪个文件（如果有标题且
'title' 开启），以及用 "CTRL-G" 命令得到的文件消息中。你会看到类似
	(4 of 11)
如果你实际上不在参数列表当前位置编辑文件，它会是
	((4) of 11)
这意味着你在参数列表的第 4 个位置，但不在编辑参数列表中的第四个文件。
当你执行 ":e file" 时会发生这种情况。


本地参数列表

							*:arglocal*
:argl[ocal]		创建全局参数列表的本地副本。
			不会开始编辑另一个文件。

:argl[ocal][!] [++opt] [+cmd] {arglist}
			定义一个新的参数列表，它是当前窗口的本地列表。
			其他方面类似 |:args_f|。

							*:argglobal*
:argg[lobal]		为当前窗口使用全局参数列表。
			不会开始编辑另一个文件。

:argg[lobal][!] [++opt] [+cmd] {arglist}
			为当前窗口使用全局参数列表。像 |:args_f| 一样定义
			新的全局参数列表。所有使用全局参数列表的窗口都会
			看到此新列表。

可以有多个参数列表。它们可以在窗口之间共享。当它们共享时，在一个窗口中更改
参数列表也会更改另一个窗口中的参数列表。

当窗口被分割时，新窗口继承当前窗口的参数列表。两个窗口然后共享此列表，直到
其中一个使用 |:arglocal| 或 |:argglobal| 来使用另一个参数列表。


使用参数列表

						*:argdo*
:[range]argdo[!] {cmd}	对参数列表中的每个文件执行 {cmd}，或者如果指定了
			[range]，则仅对该范围内的参数执行。工作方式如同
			执行以下操作： >
				:rewind
				:{cmd}
				:next
				:{cmd}
				等等
<			当当前文件不能被 |abandon| 且未给出 [!] 时，命令
			会失败。
			当在某个文件上检测到错误时，不会继续访问参数列表
			中的后续文件。
			参数列表中的最后一个文件（或发生错误的文件）成为
			当前文件。
			{cmd} 可以包含 '|' 来连接多个命令。
			{cmd} 不能更改参数列表。
			注意：执行此命令时，Syntax 自动命令事件会被添加到
			'eventignore' 中以禁用。这大大加快了编辑每个文件
			的速度。
			另见 |:windo|、|:tabdo|、|:bufdo|、|:cdo|、|:ldo|、
			|:cfdo| 和 |:lfdo|。

示例： >
	:args *.c
	:argdo set ff=unix | update
这将 'fileformat' 选项设置为 "unix" 并在文件已更改时写入。这会对所有 `*.c`
文件执行。

示例： >
	:args *.[ch]
	:argdo %s/\<my_foo\>/My_Foo/ge | update
这将所有 "*.c" 和 "*.h" 文件中的单词 "my_foo" 更改为 "My_Foo"。"e" 标志用于
":substitute" 命令以避免在未使用 "my_foo" 的文件中出错。":update" 仅在有更改
时才写入文件。

4. 写入					*writing* *save-file*

注意：当 'write' 选项关闭时，你无法写入任何文件。

							*:w* *:write*
					*E502* *E503* *E504* *E505*
					*E512* *E514* *E667* *E949*
:w[rite] [++opt]	将整个缓冲区写入当前文件。这是保存更改到文件的
			正常方式。当 'readonly' 设置时或有其他原因文件无法
			写入（如父目录不存在，使用 |++p| 可避免）时会失败。
			关于 ++opt 参见 |++opt|，但只有 ++p、++bin、++nobin、
			++ff 和 ++enc 有效。


:w[rite]! [++opt]	类似 ":write"，但在 'readonly' 设置时或有其他拒绝
			写入的原因时强制写入。
			注意：这可能会更改文件的权限和所有权，并破坏
			（符号）链接。在 'cpoptions' 中添加 'W' 标志可避免
			此问题。

:[range]w[rite][!] [++opt]
			将指定的行写入当前文件。这不常见，因为文件将不包含
			缓冲区中的所有行。

							*:w_f* *:write_f*
:[range]w[rite] [++opt]	{file}
			将指定的行写入 {file}，除非它已存在且 'writeany'
			选项关闭。

							*:w!*
:[range]w[rite]! [++opt] {file}
			将指定的行写入 {file}。覆盖现有文件。

						*:w_a* *:write_a* *E494*
:[range]w[rite][!] [++opt] >>
			将指定的行追加到当前文件。

:[range]w[rite][!] [++opt] >> {file}
			将指定的行追加到 {file}。'!' 在文件不存在时强制
			写入。

							*:w_c* *:write_c*
:[range]w[rite] [++opt] !{cmd}
			以 [range] 行作为标准输入执行 {cmd}（注意 '!' 前面
			的空格）。{cmd} 的执行方式与 ":!{cmd}" 相同，任何
			'!' 都会被替换为上一个命令 |:!|。

":w" 命令的默认 [range] 是整个缓冲区 (1,$)。|'[| 和 |']| 标记会被设置为
写入命令使用的 [range]。如果你写入整个缓冲区，它将不再被视为已更改。
当你用 ":w somefile" 写入另一个文件时，取决于 'cpoptions' 中的 "+" 标志。
当包含时，写入命令会重置 'modified' 标志，即使缓冲区本身可能仍然与其文件
不同。

如果用 ":w" 给出了文件名，它会成为备用文件。这可以用于例如写入失败后你想
稍后用 ":w #" 再试。可以通过从 'cpoptions' 选项中删除 'A' 标志来关闭此
功能。

注意 'fsync' 选项在这里很重要。如果设置了，它可能使写入变慢（但更安全）。

							*:sav* *:saveas*
:sav[eas][!] [++opt] {file}
			以名称 {file} 保存当前缓冲区，并将当前缓冲区的
			文件名设置为 {file}。之前的名称用于备用文件名。
			需要 [!] 来覆盖现有文件。
			当 'filetype' 为空时，在写入文件之前会用新名称
			进行文件类型检测。
			写入成功后会重置 'readonly'。

							*:up* *:update*
:[range]up[date][!] [++opt] [>>] [file]
			类似 ":write"，但仅在缓冲区已修改或缓冲区表示磁盘
			上不存在的新文件时才写入。


写入多个缓冲区				*buffer-write*

							*:wa* *:wall*
:wa[ll]	[++opt]		写入所有已更改的缓冲区。没有文件名的缓冲区会导致
			错误消息。只读的缓冲区不会被写入。
			关于 ++opt 参见 |++opt|，但只有 ++p 有效，且适用于
			每个写入的文件。

:wa[ll]! [++opt]	写入所有已更改的缓冲区，包括只读的。没有文件名的
			缓冲区不会被写入且会导致错误消息。


如果你尝试覆盖在别处已被更改的文件，Vim 会发出警告（除非使用了 "!"）。
参见 |timestamp|。

			    *backup* *E207* *E506* *E507* *E508* *E509* *E510*
如果你写入一个现有文件（但不是追加）且 'backup'、'writebackup' 或
'patchmode' 选项开启，会对原始文件进行备份。文件要么被复制要么被重命名
（参见 'backupcopy'）。文件成功写入后，当 'writebackup' 选项开启且
'backup' 选项关闭时，备份文件会被删除。当 'patchmode' 选项开启时，备份
文件可能被重命名。

							*backup-table*
'backup' 'writebackup'	操作	~
   off	     off	不进行备份
   off	     on		备份当前文件，之后删除（默认）
   on	     off	删除旧备份，备份当前文件
   on	     on		删除旧备份，备份当前文件

当 'backupskip' 模式与写入文件的名称匹配时，不会创建备份文件。'backup' 和
'writebackup' 的值将被忽略。

当 'backup' 选项开启时，旧的备份文件（与新备份文件同名）会被删除。如果
'backup' 未设置但 'writebackup' 已设置，现有的备份文件不会被删除。文件写入
期间创建的备份文件会有不同的名称。

在某些文件系统上，崩溃时可能同时丢失备份和新写入的文件（文件可能在那里但
包含无效数据）。在这种情况下，请尝试恢复，因为交换文件会同步到磁盘，可能
仍然存在。|:recover|

'backupdir' 选项给出的目录用于存放备份文件（默认：与写入文件相同的目录）。

备份是新文件（原始文件的副本）还是原始文件被重命名，取决于 'backupcopy'
选项。参见那里关于何时复制何时重命名的解释。

如果备份文件的创建失败，则不执行写入。如果你想强制写入，在命令后加 '!'。

							*file-watcher*
当你注意到对缓冲区写入作出反应的程序（如 inotify、entr 或 fswatch）或
当外部应用程序执行 Vim 来编辑文件（如 git）且这些程序似乎没有注意到原始
文件已被更改时，你可能要考虑将 'backupcopy' 选项值切换为 "yes"。这确保
Vim 写入这些监视程序期望的同一文件，而不是创建新文件（这会阻止它们检测到
文件已更改）。另见 |crontab|

							*write-permissions*
写入新文件时，权限为读写。对于 unix，掩码为 0o666 并额外应用 umask。写入
已读取的文件时，Vim 会保留权限，但清除 s 位。

							*write-readonly*
当 'cpoptions' 选项包含 'W' 时，Vim 会拒绝覆盖只读文件。当 'W' 不存在时，
如果系统允许（目录必须可写），":w!" 会覆盖只读文件。

							*write-fail*
如果新文件的写入失败，你必须小心不要丢失你的更改和原始文件。如果没有备份
文件且写入新文件失败，你已经丢失了原始文件！不要退出 VIM 直到你写出文件！
如果进行了备份，它会被放回原始文件的位置（如果可能）。如果你退出 Vim 并
丢失了所做的更改，原始文件通常仍然存在。如果放回原始文件失败，会有错误
消息告诉你丢失了原始文件。

						*DOS-format-write*
如果 'fileformat' 是 "dos"，<CR><NL> 用于 <EOL>。这是 Windows 的默认值。
在其他系统上会显示消息 "[dos]" 提醒你使用了不寻常的 <EOL>。
						*Unix-format-write*
如果 'fileformat' 是 "unix"，<NL> 用于 <EOL>。在 Windows 上会显示
消息 "[unix]"。
						*Mac-format-write*
如果 'fileformat' 是 "mac"，<CR> 用于 <EOL>。会显示消息 "[mac]"。

另见 |file-formats| 和 'fileformat' 及 'fileformats' 选项。

						*ACL*
ACL 代表访问控制列表。它是一种控制文件访问权限的高级方式。它在新的
MS-Windows 和 Unix 系统上使用，但仅当文件系统支持时。
   Vim 会尝试在写入文件时保留 ACL 信息。备份文件会获得原始文件的 ACL 信息。
   ACL 信息也用于检查文件是否只读（打开文件时）。

					*xattr* *E1506* *E1508* *E1509*
xattr 代表扩展属性。它是一种在文件系统中与文件一起保存元数据的高级方式。
它取决于实际使用的文件系统，且 Vim 仅在 Linux 系统上支持它。
   Vim 会尝试在写入文件时保留扩展属性信息。备份文件会获得原始文件的扩展
属性。

						*read-only-share*
当 MS-Windows 在网络上共享驱动器时，它可以被标记为只读。这意味着即使文件的
只读属性不存在，且 NT 网络共享驱动器上的 ACL 设置允许写入文件，你仍然无法
写入文件。Win32 平台上的 Vim 会检测只读的网络驱动器并将文件标记为只读。
你将无法用 |:write| 覆盖它。

						*write-device*
当文件名实际上是设备名时，Vim 不会进行备份（那是不可能的）。你需要使用 "!"，
因为设备已经存在。
Unix 示例： >
	:w! /dev/lpt0
MS-Windows 示例： >
	:w! lpt0
对于 Unix，当名称不指向普通文件或目录时会检测为设备。fifo 或命名管道对 Vim
来说也像设备。
对于 MS-Windows，设备通过其名称检测：
	CON
	CLOCK$
	NUL
	PRN
	COMn	n=1,2,3... 等
	LPTn	n=1,2,3... 等
名称可以是大写或小写。

5. 写入和退出					*write-quit*

							*:q* *:quit*
:q[uit]			退出当前窗口。如果这是最后一个 |edit-window| 则退出
			Vim。当有更改且 Vim 拒绝 |abandon| 当前缓冲区，
			以及当参数列表中的最后一个文件未被编辑时会失败。
			如果有其他标签页且退出的是当前标签页中的最后一个
			窗口，则关闭当前标签页 |tab-page|。
			触发 |QuitPre| 自动命令事件。
			退出另一个窗口参见 |CTRL-W_q|。

:conf[irm] q[uit]	退出，但在有更改或参数列表中的最后一个文件未被编辑
			时给出提示。参见 |:confirm| 和 'confirm'。

:q[uit]!		不写入就退出，即使当前缓冲区有更改。缓冲区会被
			卸载，即使它设置了 'hidden'。
			如果这是最后一个窗口且有已修改的隐藏缓冲区，当前
			缓冲区会被放弃，第一个已更改的隐藏缓冲区成为当前
			缓冲区。
			使用 ":qall!" 始终退出。

:cq[uit]		始终退出，不写入，并返回错误代码。参见 |:cq|。

							*:wq*
:wq [++opt]		写入当前文件并关闭窗口。如果这是最后一个
			|edit-window| 则 Vim 退出。
			当文件只读或缓冲区没有名称时写入失败。当参数列表
			中的最后一个文件未被编辑时退出失败。

:wq! [++opt]		写入当前文件并关闭窗口。如果这是最后一个
			|edit-window| 则 Vim 退出。当当前缓冲区没有名称时
			写入失败。

:wq [++opt] {file}	写入到 {file} 并关闭窗口。如果这是最后一个
			|edit-window| 则 Vim 退出。当参数列表中的最后一个
			文件未被编辑时退出失败。

:wq! [++opt] {file}	写入到 {file} 并关闭当前窗口。如果这是最后一个
			|edit-window| 则退出 Vim。

:[range]wq[!] [++opt] [file]
			同上，但只写入 [range] 中的行。

							*:x* *:xit*
:[range]x[it][!] [++opt] [file]
			类似 ":wq"，但仅在有更改时才写入。
			当 'hidden' 已设置且有更多窗口时，写入文件后当前
			缓冲区变为隐藏。

							*:exi* *:exit*
:[range]exi[t][!] [++opt] [file]
			同 :xit。

							*ZZ*
ZZ			写入当前文件（如果已修改）并关闭当前窗口
			（同 ":x"）。
			如果当前文件有多个窗口，只关闭当前窗口。

							*ZQ*
ZQ			不检查更改就退出（同 ":q!"）。

多个窗口和缓冲区				*window-exit*

							*:qa* *:qall*
:qa[ll]		退出 Vim，除非有些缓冲区已被更改。（使用 ":bmod" 转到
		下一个已修改的缓冲区）。
		当 'autowriteall' 已设置时，所有已更改的缓冲区会被写入，
		像 |:wqall| 一样。

:conf[irm] qa[ll]
		退出 Vim。当有些缓冲区已被更改时给出提示。参见 |:confirm|。

:qa[ll]!	退出 Vim。缓冲区的任何更改会丢失。
		另见 |:cquit|，它做同样的事但以非零值退出。

							*:quita* *:quitall*
:quita[ll][!]	同 ":qall"。

:wqa[ll] [++opt]				*:wqa* *:wqall* *:xa* *:xall*

:conf[irm] wqa[ll] [++opt]

		写入所有已更改的缓冲区并退出 Vim。当有些缓冲区只读或因

6. 对话框					*edit-dialogs*

							*:confirm* *:conf*
:conf[irm] {command}	执行 {command}，并在需要确认操作时使用对话框。可以
			用于 |:edit|、|:restart|、|:q|、|:qa| 和 |:w| 命令
			（后者用于覆盖只读设置），以及任何可能因未保存的
			更改而失败的命令，如 |:only|、|:buffer|、|:bdelete|
			等。

示例： >
  :confirm w foo
<	当 "foo" 已存在时会请求确认。 >
  :confirm q
<	当有更改时会请求确认。 >
  :confirm qa
<	如果存在任何已修改、未保存的缓冲区，你会被提示保存或放弃每一个。
	还有"全部保存"或"全部放弃"的选择。

如果你想始终使用 ":confirm"，请设置 'confirm' 选项。

					*:browse* *:bro* *E338* *E614* *E615* *E616*
:bro[wse] {command}	为 {command} 的参数打开文件选择对话框。目前适用于
			|:e|、|:w|、|:wall|、|:wq|、|:wqall|、|:x|、|:xall|、
			|:exit|、|:view|、|:sview|、|:r|、|:saveas|、|:sp|、
			|:mkexrc|、|:mkvimrc|、|:mksession|、|:mkview|、
			|:split|、|:vsplit|、|:tabe|、|:tabnew|、|:cfile|、
			|:cgetfile|、|:caddfile|、|:lfile|、|:lgetfile|、
			|:laddfile|、|:diffsplit|、|:diffpatch|、|:pedit|、
			|:redir|、|:source|、|:update|、|:visual|、|:vsplit|
			以及在 'confirm' 设置时的 |:qall|。
			注意：仅在 Win32 GUI 中有效；在控制台中如果
			FileExplorer 自动命令组存在则 `:browse edit` 有效。
			当 ":browse" 不可能时你会得到错误消息。如果
			{command} 不支持浏览，{command} 会在没有对话框的
			情况下执行。
			":browse set" 的工作方式类似 |:options|。
			另见 |:oldfiles| 中的 ":browse oldfiles"。

语法通过一些示例最能说明： >
	:browse e $vim/foo
<		在 $vim/foo 目录中打开浏览器，编辑选择的文件。 >
	:browse e
<		在 'browsedir' 指定的目录中打开浏览器，编辑选择的文件。 >
	:browse w
<		在当前缓冲区的目录中打开浏览器，以当前缓冲区文件名为
		默认值，在选择的文件名下保存缓冲区。 >
	:browse w C:/bar
<		在 C:/bar 目录中打开浏览器，以当前缓冲区文件名为默认值，
		在选择的文件名下保存缓冲区。
另见 'browsedir' 选项。
对于不支持浏览的 Vim 版本，命令会不加修改地执行。

							*browsefilter*
对于 MS-Windows，你可以修改浏览对话框中使用的过滤器。通过设置 g:browsefilter
或 b:browsefilter 变量，你可以全局或针对缓冲区本地更改过滤器。变量设置为格式
为 "{filter label}\t{pattern};{pattern}\n" 的字符串，其中 "{filter label}" 是
出现在 "Files of Type" 组合框中的文本，{pattern} 是过滤文件名的模式。多个
模式可以用 ';' 分隔。

例如，要在对话框中只显示 Vim 文件，你可以使用以下命令： >

     let g:browsefilter = "Vim scripts\t*.vim\nVim Startup Files\t*vimrc\n"

你可以通过设置 b:browsefilter 变量来逐缓冲区覆盖过滤器设置。你通常会在
filetype 插件中设置 b:browsefilter，这样浏览对话框会包含与你当前编辑的文件
类型相关的条目。缺点是：这使得开始编辑不同类型的文件变得困难。要解决这个
问题，你可以在 Windows 上添加以下作为最后一个过滤器： >

	All Files\t(*.*)\t*\n
<
或者在其他平台上添加以下内容，以便用户仍然可以访问任何所需的文件： >

	All Files\t(*)\t*\n
<

要避免在 Vim 实际上不支持 browsefilter 时设置它，你可以使用
has("browsefilter")： >

	if has("browsefilter")
	   let g:browsefilter = "whatever"
	endif

7. 当前目录				*current-directory*

你可以使用 |:cd|、|:tcd| 和 |:lcd| 切换到另一个目录，这样就不必在文件名
前面输入目录名了。这也影响外部命令的执行，例如 ":!ls" 或 ":te ls"。

有三个当前目录"作用域"：全局、标签页和窗口。窗口本地工作目录优先于标签页
本地工作目录，标签页本地工作目录又优先于全局工作目录。如果本地工作目录
（标签页或窗口）不存在，则使用层级中下一个更高的作用域。

							*:cd* *E747* *E472*
:cd[!]			在非 Unix 系统上且 'cdhome' 关闭时：打印当前目录名。
			否则：切换当前目录到主目录。清除任何窗口本地目录。
			在所有系统上使用 |:pwd| 来打印当前目录。

:cd[!] {path}		切换当前目录到 {path}。
			如果 {path} 是相对的，则在 'cdpath' 列出的目录中
			搜索。
			清除任何窗口本地目录。
			不改变已打开文件的含义，因为它的完整路径名被记住了。
			但 |arglist| 中的文件可能会改变！
			在 MS-Windows 上这也会改变活动驱动器。
			要切换到当前文件的目录： >
				:cd %:h
<
							*:cd-* *E186*
:cd[!] -		切换到之前的当前目录（上一次 ":cd {path}" 命令之前
			的目录）。

							*:chd* *:chdir*
:chd[ir][!] [path]	同 |:cd|。

							*:tc* *:tcd*
:tc[d][!] {path}	类似 |:cd|，但只为当前标签页设置目录。当前窗口
			也会使用此目录。其他标签页中的窗口和当前标签页中
			有自己窗口本地目录的窗口的当前目录不会改变。

							*:tcd-*
:tc[d][!] -		切换到之前的当前目录（上一次 ":tcd {path}" 命令
			之前的目录）。

							*:tch* *:tchdir*
:tch[dir][!]		同 |:tcd|。

							*:lc* *:lcd*
:lc[d][!] {path}	类似 |:cd|，但只为当前窗口设置当前目录。其他窗口
			或标签页的当前目录不会改变。

							*:lch* *:lchdir*
:lch[dir][!]		同 |:lcd|。

							*:lcd-*
:lc[d][!] -		切换到之前的当前目录（上一次 ":lcd {path}" 命令
			之前的目录）。

							*:pw* *:pwd* *E187*
:pw[d]			打印当前目录名。
			另见 |getcwd()|。
							*:pwd-verbose*
			当 'verbose' 非零时，|:pwd| 还会显示当前目录是在
			什么作用域设置的。示例： >

				" 由 :cd 设置
				:verbose pwd
				[global] /path/to/current

				" 由 :lcd 设置
				:verbose pwd
				[window] /path/to/current

				" 由 :tcd 设置
				:verbose pwd
				[tabpage] /path/to/current

只要没有使用 |:lcd| 或 |:tcd| 命令，所有窗口共享同一个当前目录。使用命令
跳转到另一个窗口不会改变当前目录。

当对窗口使用了 |:lcd|，指定的目录成为该窗口的当前目录。未使用 |:lcd| 命令
的窗口仍使用全局或标签页本地目录。跳转到另一个窗口时，当前目录会更改为最后
指定的本地当前目录。如果没有指定，则使用全局或标签页本地目录。
创建新窗口时，它继承当前窗口的本地目录。

切换标签页时应用相同的行为。如果当前标签页没有本地工作目录，则使用全局工作
目录。

使用 |:cd| 命令时，当前窗口和标签页会丢失其本地当前目录，从此使用全局当前
目录。使用 |:tcd| 命令时，只有当前窗口会丢失其本地工作目录。

使用 |:cd| 后，读写文件时会使用完整路径名。在某些网络文件系统上这可能会
导致问题。使用完整路径名的结果是，当前使用的文件名将继续引用同一个文件。
示例：如果你有文件 a:test 和目录 a:vim，命令 ":e test" ":cd vim" ":w" 会
覆盖文件 a:test 而不会写入 a:vim/test。但如果你执行 ":w test"，文件
a:vim/test 会被写入，因为你给了新文件名且没有引用 ":cd" 之前的文件名。

8. 编辑二进制文件				*edit-binary*

虽然 Vim 是为编辑文本文件而设计的，但也可以编辑二进制文件。|-b| Vim 参数
（b 代表 binary）使 Vim 以二进制模式进行文件 I/O，并设置一些用于编辑二进制
文件的选项（'binary' 开启、'textwidth' 设为 0、'modeline' 关闭、'expandtab'
关闭）。设置 'binary' 选项有同样的效果。不要忘记在读取文件之前执行此操作。

编辑二进制文件时有几点需要注意：
- 编辑可执行文件时，字节数不能改变。
  只使用 "R" 或 "r" 命令来更改文本。不要用 "x" 或退格键删除字符。
- 将 'textwidth' 选项设置为 0。否则行可能会意外被分成两行。
- 当 <EOL> 不多时，行会变得很长。如果你想编辑不适合屏幕的行，请重置 'wrap'
  选项。这时会使用水平滚动。如果行变得太长（参见 |limits|），你无法编辑该行。
  读取文件时该行会被分割。也可能在读取文件时得到 "out of memory" 错误。
- 确保在加载文件之前设置 'binary' 选项。否则 <CR><NL> 和 <NL> 都会被认为
  结束一行，写入文件时 <NL> 会被替换为 <CR><NL>。
- <Nul> 字符在屏幕上显示为 ^@。你可以用 "CTRL-V CTRL-@" 或 "CTRL-V 000"
  输入它们。
- 要在文件中插入 <NL> 字符，请分割一行。写入缓冲区到文件时，<NL> 会为
  <EOL> 写入。
- Vim 通常会在文件末尾没有 <EOL> 时追加一个。设置 'binary' 选项可以防止
  此行为。如果你想添加最后的 <EOL>，请设置 'endofline' 选项。你也可以读取
  此选项的值来查看最后一行是否有 <EOL>（你在文本中看不到这一点）。

10. 时间戳					*timestamp* *timestamps*

Vim 在你开始编辑文件时会记住文件的修改时间戳、模式和大小。这用于避免你拥有
同一文件的两个不同版本（而你不知道这一点）。

在运行 shell 命令 (|:!cmd| |suspend| |:read!| |K|) 后，会比较窗口中所有
缓冲区的时间戳、文件模式和文件大小。Vim 会运行任何相关的 |FileChangedShell|
自动命令或为任何已更改的文件显示警告。在 GUI 中这在 Vim 重新获得输入焦点时
发生。

							*E321* *E462*
如果你想在文件在 Vim 之外被更改时自动重新加载，请设置 'autoread' 选项。这在
你写入文件时不起作用，只在文件没有在 Vim 内部更改时起作用。
							*ignore-timestamp*
如果你不想被询问或自动重新加载文件，你可以使用： >
	set buftype=nofile

或者，从 shell 启动 gvim 时： >
	gvim file.log -c "set buftype=nofile"

注意如果定义了 FileChangedShell 自动命令，你不会得到警告消息或提示。
自动命令应该处理此情况。

目录没有警告。但如果你开始编辑一个新文件且它后来被创建为目录，你会得到
警告。

当 Vim 注意到文件的时间戳已更改，且该文件正在缓冲区中编辑但没有更改时，
Vim 会检查文件内容是否相同。这通过再次读取文件（到一个立即删除的隐藏缓冲区
中）并比较文本来完成。如果文本相同，你不会得到警告。

如果你得到的警告不够频繁，可以使用以下命令。

							*:checkt* *:checktime*
:checkt[ime]		检查是否有任何缓冲区在 Vim 之外被更改。
			这会检查并在你最终会有文件的两个版本时发出警告。
			如果这是从自动命令、":global" 命令调用的或不是
			手动输入的，实际检查会推迟到副作用（重新加载文件）
			无害的时刻。
			检查每个已加载的缓冲区关联的文件是否已更改。如果
			文件已更改，Vim 会采取行动。如果缓冲区中没有更改
			且 'autoread' 已设置，则重新加载缓冲区。否则，
			你会被提供重新加载文件的选择。如果文件被删除，你
			会得到错误消息。
			如果文件之前不存在而现在存在，你会得到警告。
			一旦文件被检查，时间戳会被重置，你不会再次被警告。
			语法高亮、标记、diff 状态、'fileencoding'、
			'fileformat' 和 'binary' 选项不会改变。参见
			|v:fcs_choice| 来也重新加载这些（例如，如果代码
			格式化工具更改了文件）。

:[N]checkt[ime] {filename}
:[N]checkt[ime] [N]
			检查特定缓冲区的时间戳。缓冲区可以通过名称、编号
			或模式来指定。


							*E813* *E814*
如果你选择重新加载，Vim 会重新加载缓冲区。如果包含此缓冲区的窗口可见，
重新加载会在该窗口的上下文中发生。否则使用特殊窗口，以便大多数自动命令
能正常工作。你不能关闭此窗口。其他一些限制也适用。最好确保不会在当前缓冲区
之外发生任何事情。例如，设置窗口本地选项可能会在错误的窗口中生效。分割窗口、
在那里做一些事情然后关闭它应该是可以的（如果没有其他自动命令的副作用）。
关闭不相关的窗口和缓冲区会让你遇到麻烦。

在写入文件之前，会检查时间戳（除非使用了 "!"）。如果它已更改，Vim 会询问
你是否真的要覆盖文件：

	WARNING: The file has been changed since reading it!!!
	Do you really want to write to it (y/n)?

如果你按 'y'，Vim 会继续写入文件。如果你按 'n'，写入会被中止。如果你使用了
":wq" 或 "ZZ"，Vim 不会退出，你会得到另一次写入文件的机会。

该消息通常意味着在编辑会话开始后有人写入了该文件。这可能是另一个人，在这种
情况下你可能想检查你对文件的更改和另一个人的更改是否应该合并。将文件以另一个
名称写入并检查差异（可以使用 "diff" 程序）。

也有可能是你自己从另一个编辑会话或用另一个命令（例如过滤命令）修改了文件。
那么你就知道要保留文件的哪个版本。

时间检查的精度取决于文件系统。在 Unix 上通常是亚秒级。在旧的文件系统和
MS-Windows 上通常是一秒。使用 `has('nanotime')` 检查是否可用亚秒级时间戳
检查。

有一种情况你会收到该消息但实际上没有问题：在 Win32 系统上夏令时开始的那天。
Win32 库中的某些东西让 Vim 对一小时的时差产生了困惑。问题在第二天就会消失。

11. 文件搜索					*file-searching*

文件搜索目前用于 'path'、'cdpath' 和 'tags' 选项，以及 |finddir()| 和
|findfile()|。其他命令使用 |wildcards|，略有不同。

有三种不同类型的搜索：

1) 向下搜索：					*starstar*
   向下搜索使用通配符 "*"、"**" 以及可能你的操作系统支持的其他通配符。"*" 和
   "**" 在 Vim 内部处理，因此在所有操作系统上都能工作。注意 "**" 只在名称
   开头时才作为特殊通配符。

   "*" 的使用很简单：它匹配 0 个或多个字符。在搜索模式中这等同于 `.*`。
   注意 "." 不用于文件搜索。

   "**" 更复杂：
      - 它只匹配目录。
      - 默认最多匹配 30 级深的目录，因此你可以用它搜索整个目录树。
      - 匹配的最大级数可以通过在 "**" 后追加数字来指定。
	因此 '/usr/**2' 可以匹配： >
		/usr
		/usr/include
		/usr/include/sys
		/usr/include/g++
		/usr/lib
		/usr/lib/X11
		....
<	它不匹配 '/usr/include/g++/std'，因为那是三级。
	允许的数字范围是 0（"**0" 被移除）到 100。
	如果给定的数字小于 0，默认为 30；如果大于 100，则使用 100。系统对
	路径长度也有限制，通常是 256 或 1024 字节。
      - "**" 只能在路径末尾或后跟路径分隔符或后跟数字和路径分隔符。

   你可以以任何顺序组合 "*" 和 "**"： >
	/usr/**/sys/*
	/usr/*tory/sys/**
	/usr/**2/sys/*

2) 向上搜索：
   这里你可以给出一个目录，然后在目录树中向上搜索文件。你可以给出停止目录
   来限制向上搜索。停止目录用 ';' 追加到路径（对于 'path' 选项）或文件名
   （对于 'tags' 选项）。如果你想要多个停止目录，用 ';' 分隔它们。如果你
   不想要停止目录（"搜索到根目录"），只使用 ';'。 >
	/usr/include/sys;/usr
<   将在以下位置搜索： >
	   /usr/include/sys
	   /usr/include
	   /usr
<
   如果你使用相对路径，向上搜索从 Vim 的当前目录或当前文件的目录开始
   （如果相对路径以 './' 开头且 'd' 不包含在 'cpoptions' 中）。

   如果 Vim 的当前路径是 /u/user_x/work/release 而你执行 >
	:set path=include;/u/user_x
<   然后用 |gf| 搜索文件，文件会在以下位置搜索： >
	/u/user_x/work/release/include
	/u/user_x/work/include
	/u/user_x/include

<   注意：如果你的 'path' 设置包含不存在的目录，Vim 会跳过该不存在的目录，
   且在使用向上搜索时也不会在不存在目录的父目录中搜索。

3) 组合向上/向下搜索：
   如果 Vim 的当前路径是 /u/user_x/work/release 而你执行 >
	set path=**;/u/user_x
<   然后用 |gf| 搜索文件，文件会在以下位置搜索： >
	/u/user_x/work/release/**
	/u/user_x/work/**
	/u/user_x/**
<
   要小心！这可能消耗大量时间，因为搜索 '/u/user_x/**' 包含了
   '/u/user_x/work/**' 和 '/u/user_x/work/release/**'。因此
   '/u/user_x/work/release/**' 会被搜索三次，'/u/user_x/work/**' 会被
   搜索两次。

   在上面的示例中，你可能想将 path 设置为： >
	:set path=**,/u/user_x/**
<   这搜索： >
	/u/user_x/work/release/**
	/u/user_x/**
<   这搜索相同的目录，但顺序不同。

   注意 ":find"、":sfind" 和 ":tabfind" 命令的补全目前不适用于包含 URL
   或使用带深度限制的双星号 (/usr/**2) 或向上搜索 (;) 表示法的 'path' 项。

12. 信任文件					*trust*

如果启用了 'exrc'，Nvim 会执行在文件系统上找到的任意代码。为了防止执行恶意
代码，只有"信任文件"会被执行。你可以使用 |:trust| 命令或 |vim.secure.read()|
函数将文件标记为信任或不信任。

							*:trust* *E5570*
:trust [++deny] [++remove] [file]

			管理信任文件。不带 ++ 选项时，:trust 将当前缓冲区
			（或 [file]，但请看下面的警告）标记为信任，基于其
			内容的哈希值。信任列表存储在磁盘上，Nvim 会在重启
			后重新使用它。

			警告：`:trust [file]` 存在 TOCTOU 风险，因此为了
			安全，你应该查看文件、检查其内容，然后运行 `:trust`
			（不带 [file] 参数）。

			[++deny] 将当前缓冲区或 [file] 标记为不信任：它永远
			不会被执行，'exrc' 会忽略它。

			[++remove] 将当前缓冲区或 [file] 从信任列表中移除。
			当文件被 'exrc' 或 |vim.secure.read()| 发现时，
			用户会被提示信任或拒绝它。
