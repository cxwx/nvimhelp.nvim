健康检查                                              *vim.health* *health*

vim.health 是一个帮助用户排查配置问题以及插件可能关心的其他环境条件的最小框架。
Nvim 内置了针对配置、性能、python 支持、ruby 支持、剪贴板支持等的健康检查。

要运行所有健康检查，使用：>vim
    :checkhealth
<

鼓励插件作者编写新的健康检查。|health-dev|


命令                                                     *health-commands*

                                                           *:che* *:checkhealth*
:che[ckhealth]  运行所有健康检查。
                                                                       *E5009*
                Nvim 依赖 |$VIMRUNTIME|、'runtimepath' 和 'packpath' 来查找
                用于语法高亮、文件类型特定行为和标准插件（包括
                :checkhealth）的标准"运行时文件"。如果找不到运行时文件，
                这些功能将无法工作。

:che[ckhealth] {plugins}
                为一个或多个插件运行健康检查。例如，仅运行标准 Nvim
                健康检查：>vim
                        :checkhealth vim.health
<
                为 "foo" 和 "bar" 插件运行健康检查（假设它们在 'runtimepath'
                上并且已实现 Lua `require("foo.health").check()` 接口）：>vim
                        :checkhealth foo bar
<
                要为 Lua 子模块运行健康检查，使用点号表示法或
                "*" 来引用所有子模块。例如 Nvim 提供了
                `vim.lsp` 和 `vim.treesitter`：>vim
                        :checkhealth vim.lsp vim.treesitter
                        :checkhealth vim*
<

用法                                                           *health-usage*

健康检查缓冲区中的本地映射：

q               关闭窗口。

全局配置：
                                                                    *g:health*
g:health  具有以下可选键的字典：
          - `style` (`'float'|nil`) 设置为 "float" 以在浮动窗口中显示
          :checkhealth，而非默认行为。

          示例：>lua
            vim.g.health = { style = 'float' }


本地配置：

健康检查将其缓冲区文件类型设置为 "checkhealth"。你可以通过处理 |FileType|
事件来自定义缓冲区。例如，如果你不想在健康报告中显示表情符号：>vim
    autocmd FileType checkhealth :set modifiable | silent! %s/\v( ?[^\x00-\x7F])//g

创建健康检查                                              *health-dev*

健康检查是检查用户环境、配置或插件关心的任何其他先决条件的函数。Nvim 内置了
以下位置的健康检查：
• $VIMRUNTIME/autoload/health/
• $VIMRUNTIME/lua/vim/lsp/health.lua
• $VIMRUNTIME/lua/vim/treesitter/health.lua
• 以及更多...

要为你自己的插件添加新的健康检查，只需在 'runtimepath' 上创建一个
"health.lua" 模块，返回一个包含 "check()" 函数的表。然后 |:checkhealth| 将
自动找到并调用该函数。

例如，如果你的插件名为 "foo"，在以下位置之一（在 'runtimepath' 上）定义你的
健康检查模块：
• lua/foo/health/init.lua
• lua/foo/health.lua

如果你的插件还提供了一个名为 "bar" 的子模块，你想为其创建单独的健康检查，
在以下位置之一定义健康检查：
• lua/foo/bar/health/init.lua
• lua/foo/bar/health.lua

所有此类健康模块必须返回一个包含 `check()` 函数的 Lua 表。

将此示例代码复制到 `lua/foo/health.lua` 中，将路径中的 "foo" 替换为你的
插件名称：>lua
    local M = {}

    M.check = function()
      vim.health.start("foo report")
      -- make sure setup function parameters are ok
      if check_setup() then
        vim.health.ok("Setup is correct")
      else
        vim.health.error("Setup is incorrect")
      end
      -- do some more checking
      -- ...
    end

    return M
<


error({msg}, {...})                                       *vim.health.error()*
    报告一个错误。

    Parameters: ~
      • {msg}  (`string`)
      • {...}  (`string|string[]`) 可选的建议

info({msg})                                                *vim.health.info()*
    报告一条信息性消息。

    Parameters: ~
      • {msg}  (`string`)

ok({msg})                                                    *vim.health.ok()*
    报告一条"成功"消息。

    Parameters: ~
      • {msg}  (`string`)

start({name})                                             *vim.health.start()*
    开始一个新的报告。大多数插件应只调用一次，但如果你想在报告中显示不同的
    部分，每个部分调用一次。

    Parameters: ~
      • {name}  (`string`)

warn({msg}, {...})                                         *vim.health.warn()*
    报告一条警告。

    Parameters: ~
      • {msg}  (`string`)
      • {...}  (`string|string[]`) 可选的建议
