*26.1*	使用可视模式重复

可视模式对于在任意一系列行上进行修改非常方便。你可以看到高亮的文本，从而确认是
否修改了正确的行。但是选择区域需要一些输入。"gv" 命令可以重新选择相同的区域。这
样你就可以对同一段文本进行另一个操作。
   假设你有一些行需要将 "2001" 改为 "2002"，将 "2000" 改为 "2001":

	The financial results for 2001 are better ~
	than for 2000.  The income increased by 50%, ~
	even though 2001 had more rain than 2000. ~
			2000		2001 ~
	income		45,403		66,234 ~

首先将 "2001" 改为 "2002"。在可视模式下选择这些行，然后使用: >

	:s/2001/2002/g

现在使用 "gv" 重新选择相同的文本。光标在哪里并不重要。然后使用
":s/2000/2001/g" 进行第二次修改。
   显然，你可以多次重复这些修改。

*26.2*	加和减

当重复将一个数字改为另一个数字时，你经常有一个固定的偏移量。在上面的例子中，每
个年份加了一。除了为每个出现的年份输入替换命令，可以使用 CTRL-A 命令。
   使用和上面相同的文本，搜索一个年份: >

	/19[0-9][0-9]\|20[0-9][0-9]

现在按 CTRL-A。年份将加一:

	The financial results for 2002 are better ~
	than for 2000.  The income increased by 50%, ~
	even though 2001 had more rain than 2000. ~
			2000		2001 ~
	income		45,403		66,234 ~

使用 "n" 查找下一个年份，按 "." 重复 CTRL-A（"." 输入更快）。对所有出现的年份
重复 "n" 和 "."。

加大于一的数可以在 CTRL-A 前面加上数字。假设你有以下列表:

	1.  item four ~
	2.  item five ~
	3.  item six ~

将光标移到 "1." 上，输入: >

	3 CTRL-A

"1." 将变为 "4."。同样，你可以用 "." 对其他数字重复这个操作。

CTRL-X 命令以类似的方式进行减法。

CTRL-A 和 CTRL-X 的行为取决于 'nrformats' 的值。例如，如果你使用: >

        :set nrformats+=octal

在 "007" 上按 CTRL-A 将递增为 "010"，因为 "007" 会被识别为八进制数。

*26.3*	在多个文件中进行修改

假设你有一个名为 "x_cnt" 的变量，你想将它改为 "x_counter"。这个变量在你的几个
C 文件中使用。你需要在所有文件中进行修改。方法如下。
   将所有相关文件放入参数列表: >

	:args *.c
<
这会找到所有 C 文件并编辑第一个。现在你可以对所有这些文件执行替换命令: >

	:argdo %s/\<x_cnt\>/x_counter/ge | update

":argdo" 命令接受一个参数，即另一个命令。那个命令将在参数列表中的所有文件上执
行。
   后面的 "%s" 替换命令作用于所有行。它用 "\<x_cnt\>" 查找单词 "x_cnt"。"\<"
和 "\>" 用于只匹配完整的单词，而不是 "px_cnt" 或 "x_cnt2"。
   替换命令的标志包括 "g"，用于替换同一行中所有出现的 "x_cnt"。"e" 标志用于避
免在文件中没有 "x_cnt" 时出错。否则 ":argdo" 会在第一个未找到 "x_cnt" 的文件上
中止。
   "|" 分隔两个命令。后面的 "update" 命令只在文件被修改时写入文件。如果没有
"x_cnt" 被改为 "x_counter"，什么也不会发生。

还有 ":windo" 命令，在所有窗口中执行其参数。以及 ":bufdo" 在所有缓冲区上执行其
参数。使用时要小心，因为缓冲区列表中的文件可能比你想象的多。用 ":buffers" 命令
（或 ":ls"）检查。

*26.4*	在 shell 脚本中使用 Vim

假设你有很多文件需要将字符串 "-person-" 改为 "Jones" 然后打印出来。怎么做？一种
方法是大量手动输入。另一种是编写 shell 脚本来完成工作。
   Vim 编辑器在使用普通模式命令时是一个出色的面向屏幕的编辑器。然而，对于批处
理，普通模式命令不会产生清晰的、带注释的命令文件；所以这里你将使用 Ex 模式。这
种模式提供了一个友好的命令行界面，便于放入批处理文件中。（"Ex 命令" 只是命令行
(:) 命令的另一个名称。）
   你需要的 Ex 模式命令如下: >

	%s/-person-/Jones/g
	write tempfile
	quit

你将这些命令放入文件 "change.vim" 中。现在要在批处理模式下运行编辑器，使用这个
shell 脚本: >

	for file in *.txt; do
	  vim -e -s $file < change.vim
	  lpr -r tempfile
	done

for-done 循环是一个 shell 结构，用于重复中间的两行，每次 $file 变量被设为不同的
文件名。
   第二行以 Ex 模式（-e 参数）在文件 $file 上运行 Vim 编辑器，并从文件
"change.vim" 读取命令。-s 参数告诉 Vim 在静默模式下运行。换句话说，不要持续输
出 : 提示符或任何其他提示。
   "lpr -r tempfile" 命令打印生成的 "tempfile" 并删除它（这就是 -r 参数的作
用）。


从标准输入读取

Vim 可以从标准输入读取文本。由于通常是从那里读取命令，你必须告诉 Vim 改为读取
文本。这通过传递 "-" 参数来代替文件名来实现。例如: >

	ls | vim -

这允许你编辑 "ls" 命令的输出，而不需要先将文本保存到文件中。
   如果你使用标准输入读取文本，可以使用 "-S" 参数来读取脚本: >

	producer | vim -S change.vim -


普通模式脚本

如果你确实想在脚本中使用普通模式命令，可以这样使用: >

	vim -s script file.txt ...
<
	备注:
	"-s" 在不与 "-e" 一起使用时有不同的含义。这里它表示将
	"script" 作为普通模式命令来执行。当与 "-e" 一起使用时，它
	表示静默模式，不使用下一个参数作为文件名。

"script" 中的命令像你手动输入一样执行。不要忘记换行会被解释为按下 <Enter>。在
普通模式中，这会将光标移到下一行。
   要创建脚本，你可以编辑脚本文件并输入命令。你需要想象结果会是什么，这可能有些
困难。另一种方法是在手动执行命令时录制它们。方法如下: >

	vim -w script file.txt ...

所有输入的按键将被写入 "script"。如果你犯了一个小错误，可以继续操作，记得以后编
辑脚本。
   "-w" 参数会追加到已有脚本后面。当你想逐步录制脚本时这很好。如果你想从头开始
完全重新录制，使用 "-W" 参数。它会覆盖任何已存在的文件。
