*change.txt*    Nvim


		  VIM REFERENCE MANUAL	  by Bram Moolenaar


本文件描述删除或修改文本的命令。在此上下文中，修改文本意味着用一个命令
删除文本并替换为其他文本。所有这些命令都可以撤销。非 Ex 命令可以用 "."
命令重复。

关于插入文本，参见 |insert.txt|。

                                      输入 |gO| 查看目录。

1. 删除文本						*deleting* *E470*

["x]<Del>	或					*<Del>* *x* *dl*
["x]x			删除光标下和之后的 [count] 个字符
			[到寄存器 x]（非 |linewise|）。与 "dl" 相同。
			<Del> 键不接受 [count]。它会删除计数的
			最后一个字符。
			关于删除换行符（合并行）参见 'whichwrap'。

							*X* *dh*
["x]X			删除光标前的 [count] 个字符 [到寄存器 x]
			（非 |linewise|）。与 "dh" 相同。
			另见 'whichwrap'。

							*d*
["x]d{motion}		删除 {motion} 移过的文本 [到寄存器 x]。
			例外情况见下文。

							*dd*
["x]dd			删除 [count] 行 [到寄存器 x] |linewise|。

							*D*
["x]D			删除光标下直到行尾的字符以及 [count]-1 行
			[到寄存器 x]；是 "d$" 的同义词。
			（非 |linewise|）

{Visual}["x]x	或					*v_x* *v_d* *v_<Del>*
{Visual}["x]d   或
{Visual}["x]<Del>	删除高亮文本 [到寄存器 x]（关于
			{Visual} 见 |Visual-mode|）。

{Visual}["x]CTRL-H   或				*v_CTRL-H* *v_<BS>*
{Visual}["x]<BS>	在选择模式中：删除高亮文本 [到寄存器 x]。

{Visual}["x]X	或					*v_X* *v_D* *v_b_D*
{Visual}["x]D		删除高亮的行 [到寄存器 x]（关于
			{Visual} 见 |Visual-mode|）。在可视块模式中，
			"D" 删除高亮文本加上直到行尾的所有文本。

					*:d* *:de* *:del* *:delete* *:dl* *:dp*
:[range]d[elete] [x]	删除 [range] 行（默认：当前行）[到寄存器 x]。
			注意这些奇怪的缩写：
			   :dl		删除并列出
			   :dell	同上
			   :delel	同上
			   :deletl	同上
			   :deletel	同上
			   :dp		删除并打印
			   :dep		同上
			   :delp	同上
			   :delep	同上
			   :deletp	同上
			   :deletep	同上

:[range]d[elete] [x] {count}
			删除 {count} 行，从 [range] 开始（默认：当前行
			|cmdline-ranges|）[到寄存器 x]。

这些命令删除文本。你可以用 `.` 命令重复它们（`:d` 除外），也可以撤销。
使用可视模式删除文本块。关于寄存器的说明参见 |registers|。
							*d-special*
d{motion} 命令的一个例外：如果移动不是行级的，移动的起点和终点不在同一行，
且起点之前只有空白而终点之后没有非空白字符，则删除变为行级。这意味着删除
也会移除你可能期望保留的空白行。使用 |o_v| 操作符来强制移动为字符级。

尝试删除空的文本区域（例如在第一列执行 "d0"）在 'cpoptions' 包含 'E'
标志时是一个错误。

							*J*
J			合并 [count] 行，最少两行。移除缩进并插入最多
			两个空格（见下文）。在缓冲区的最后一行会失败。
			如果 [count] 太大，会减少到可用的行数。

							*v_J*
{Visual}J		合并高亮的行，最少两行。移除缩进并插入最多
			两个空格（见下文）。

							*gJ*
gJ			合并 [count] 行，最少两行。不插入或移除
			任何空格。

							*v_gJ*
{Visual}gJ		合并高亮的行，最少两行。不插入或移除
			任何空格。

							*:j* *:join*
:[range]j[oin][!] [flags]
			合并 [range] 行。与 "J" 相同，但使用 [!] 时
			合并不插入或删除任何空格。
			如果 [range] 的起始和结束值相等，此命令无操作。
			默认行为是将当前行与下一行合并。
			[flags] 参见 |ex-flags|。

:[range]j[oin][!] {count} [flags]
			合并 {count} 行，从 [range] 开始（默认：
			当前行 |cmdline-ranges|）。与 "J" 相同，
			但使用 [!] 时合并不插入或删除任何空格。
			[flags] 参见 |ex-flags|。

这些命令删除行之间的 <EOL>。其效果是将多行合并为一行。你可以重复这些命令
（`:j` 除外）并撤销。

这些命令（"gJ" 除外）用一个空格替换 <EOL>，除非有尾随空白或下一行以 ')'
开头。这些命令（"gJ" 除外）删除下一行的任何前导空白。如果 'joinspaces'
选项开启，这些命令在 '.'、'!' 或 '?' 后插入两个空格。
'formatoptions' 中的 'B' 和 'M' 标志改变在多字节字符前后插入空格的行为
|fo-table|。

|'[| 标记设置在第一个被合并行的末尾，|']| 设置在结果行的末尾。

2. 删除并插入					*delete-insert* *replacing*

							*R*
R			进入替换模式：你输入的每个字符替换一个现有字符，
			从光标下的字符开始。将输入的文本重复 [count]-1
			次。更多详情参见 |Replace-mode|。

							*gR*
gR			进入虚拟替换模式：你输入的每个字符在屏幕空间中
			替换现有字符。因此一个 <Tab> 可能一次替换多个
			字符。将输入的文本重复 [count]-1 次。更多详情
			参见 |Virtual-Replace-mode|。

							*c*
["x]c{motion}		删除 {motion} 文本 [到寄存器 x] 并开始插入。
			当 'cpoptions' 包含 'E' 标志且没有要删除的文本
			时（例如光标在 'x' 后面时执行 "cTx"），会发生
			错误且不启动插入模式（这是 Vi 兼容的）。
			当 'cpoptions' 不包含 'E' 标志时，"c" 命令
			总是启动插入模式，即使没有要删除的文本。

							*cc*
["x]cc			删除 [count] 行 [到寄存器 x] 并开始插入
			|linewise|。如果 'autoindent' 开启，保留
			第一行的缩进。

							*C*
["x]C			从光标位置删除到行尾以及 [count]-1 行
			[到寄存器 x]，并开始插入。是 c$ 的同义词
			（非 |linewise|）。

							*s*
["x]s			删除 [count] 个字符 [到寄存器 x] 并开始
			插入（s 代表 Substitute，替换）。是 "cl" 的
			同义词（非 |linewise|）。

							*S*
["x]S			删除 [count] 行 [到寄存器 x] 并开始插入。
			是 "cc" 的同义词 |linewise|。

{Visual}["x]c	或					*v_c* *v_s*
{Visual}["x]s		删除高亮文本 [到寄存器 x] 并开始插入
			（关于 {Visual} 见 |Visual-mode|）。

							*v_r*
{Visual}r{char}		用 {char} 替换所有选中的字符。
			CTRL-C 会被按原样插入。

							*v_C*
{Visual}["x]C		删除高亮的行 [到寄存器 x] 并开始插入。
			在可视块模式中工作方式不同 |v_b_C|。
							*v_S*
{Visual}["x]S		删除高亮的行 [到寄存器 x] 并开始插入
			（关于 {Visual} 见 |Visual-mode|）。
							*v_R*
{Visual}["x]R		目前与 {Visual}["x]S 相同。在未来版本中
			可能有不同的工作方式。

注意：
- 你可以用 <Esc> 结束插入和替换模式。
- 关于这些模式中的其他特殊字符，参见 "插入和替换模式" 部分
  |mode-ins-repl|。
- [count] 的效果在 Vim 退出插入或替换模式后生效。
- 当 'cpoptions' 选项包含 '$' 且更改在一行内时，Vim 继续显示将被删除的
  文本，并在最后一个删除字符处放一个 '$'。

关于寄存器的说明参见 |registers|。

替换模式与插入模式类似，除了你输入的每个字符都会删除一个字符。如果到达行尾，
Vim 会追加后续字符（与插入模式一样）。在替换模式中，退格键恢复原始文本
（如果有的话）。（参见 "插入和替换模式" 部分 |mode-ins-repl|）。

						*cw* *cW*
特殊情况：当光标在一个单词中时，"cw" 和 "cW" 不包含单词后的空白，它们只
更改到单词末尾。这是因为 Vim 将 "cw" 解释为 change-word（修改单词），
而单词不包含后面的空白。

如果你希望 "cw" 包含单词后的空格，参见 |cpo-_| 了解如何更改行为。
或者使用 "caw"（见 |aw|）。

							*:c* *:ch* *:change*
:{range}c[hange][!]	用其他文本替换若干行文本。输入仅包含 "." 的行
			来停止替换。没有 {range} 时，此命令只更改当前行。
			添加 [!] 在命令执行期间切换 'autoindent'。

3. 简单修改					*simple-change* *changing*

							*r*
r{char}			用 {char} 替换光标下的字符。如果 {char} 是 <CR>
			或 <NL>，则用换行替换该字符。要用真正的 <CR>
			替换，使用 CTRL-V <CR>。CTRL-V <NL> 替换为 <Nul>。

			如果 {char} 是 CTRL-E 或 CTRL-Y，则使用下方或
			上方行的字符，与 |i_CTRL-E| 和 |i_CTRL-Y| 类似。
			这也适用于计数，因此 `10r<C-E>` 从下方行复制
			10 个字符。

			如果你给了 [count]，Vim 用 [count] 个 {char}
			替换 [count] 个字符。但当 {char} 是 <CR> 或 <NL>
			时，Vim 只插入一个 <CR>："5r<CR>" 用一个换行替换
			五个字符。
			当 {char} 是 <CR> 或 <NL> 时，Vim 执行自动缩进。
			其工作方式类似于删除被替换的字符然后执行
			"i<CR><Esc>"。
			{char} 可以作为二合字母输入 |digraph-arg|。
			|:lmap| 映射适用于 {char}。插入模式中的 CTRL-^
			命令可以用来切换开关 |i_CTRL-^|。当 'encoding'
			为 Unicode 时，关于使用组合字符参见 |utf-8-char-arg|。

							*gr*
gr{char}		用 {char} 替换光标下的虚拟字符。这在屏幕空间
			而非文件空间中替换。更多详情参见 |gR| 和
			|Virtual-Replace-mode|。与 |r| 一样可以给出计数。
			{char} 的输入方式与 |r| 相同，但在插入模式中
			有特殊含义的字符（如大多数 CTRL 键）不能使用。

							*gr-default*
			Nvim 创建的 |lsp-defaults| 映射可能会抑制 |gr|
			的内置行为。使用以下命令恢复内置行为：>
				nnoremap <nowait> gr gr
<

普通模式命令（如 |r| 和 |t|）的参数是单个字符。当 'cpo' 不包含 'D' 标志时，
此字符也可以像 |digraphs| 一样输入。先输入 CTRL-K，然后输入两个二合字母
字符。

						*case*

LC_CTYPE 的值在这里很重要。

							*~*

			光标向右移动。如果给了 [count]，对这么多字符
			执行。

~{motion}		'tildeop' 选项：切换 {motion} 文本的大小写。

							*g~*
g~{motion}		切换 {motion} 文本的大小写。

g~g~							*g~g~* *g~~*
g~~			切换当前行的大小写。

							*v_~*
{Visual}~		切换高亮文本的大小写（关于 {Visual} 见
			|Visual-mode|）。

							*v_U*
{Visual}U		将高亮文本转为大写（关于 {Visual} 见
			|Visual-mode|）。

							*gU* *uppercase*
gU{motion}		将 {motion} 文本转为大写。
			示例：>
				:map! <C-F> <Esc>gUiw`]a

gUgU							*gUgU* *gUU*
gUU			将当前行转为大写。

							*v_u*
{Visual}u		将高亮文本转为小写（关于 {Visual} 见

							*gu* *lowercase*
gu{motion}		将 {motion} 文本转为小写。

gugu							*gugu* *guu*

							*g?* *rot13*
g?{motion}		对 {motion} 文本进行 Rot13 编码。

							*CTRL-A*
CTRL-A			将 [count] 加到光标处或之后的数字或字母字符上。

                                                       *v_CTRL-A*
{Visual}CTRL-A		将 [count] 加到高亮文本中的数字或字母字符上。

							*v_g_CTRL-A*
{Visual}g CTRL-A	将 [count] 加到高亮文本中的数字或字母字符上。
			如果高亮了多行，每行会额外增加 [count]
			（从而有效地创建一个增量为 [count] 的序列）。
			例如，如果你有这个数字列表：>
				1.
				1.
				1.
				1.
<			移到第二个 "1." 并可视选择三行，
			按 g CTRL-A 结果为：>
				1.
				2.
				3.
				4.
<
							*CTRL-X*
CTRL-X			从光标处或之后的数字或字母字符中减去 [count]。

							*v_CTRL-X*
{Visual}CTRL-X		从高亮文本中的数字或字母字符中减去 [count]。

							*v_g_CTRL-X*
{Visual}g CTRL-X	从高亮文本中的数字或字母字符中减去 [count]。
			如果高亮了多行，每个值会额外减少 [count]
			（从而有效地创建一个递减量为 [count] 的序列）。

CTRL-A 和 CTRL-X 命令适用于（有符号的）十进制数、无符号二进制/八进制/
十六进制数和字母字符。

这取决于 'nrformats' 选项：
- 当 'nrformats' 包含 "bin" 时，Vim 假设以 '0b' 或 '0B' 开头的数字为
  二进制。
- 当 'nrformats' 包含 "octal" 时，Vim 将以 '0' 开头的数字视为八进制，
  除非该数字包含 '8' 或 '9'。其他数字为十进制，可能有前置负号。
  如果光标在数字上，命令作用于该数字；否则 Vim 使用光标右边的数字。
- 当 'nrformats' 包含 "hex" 时，Vim 假设以 '0x' 或 '0X' 开头的数字为
  十六进制。数字中最右边字母的大小写决定结果十六进制数的大小写。如果
  当前数字中没有字母，Vim 使用之前检测到的大小写。
- 当 'nrformats' 包含 "alpha" 时，Vim 会更改光标下或之后的字母字符。
  这对制作带字母索引的列表很有用。

对于十进制数，递增或递减时考虑前导负号；对于二进制、八进制和十六进制值，
不考虑负号。要忽略符号，可以在使用 CTRL-A 或 CTRL-X 之前先可视选择数字。

对于有前导零的数字（包括所有八进制和十六进制数），Vim 在可能时保持数字的
字符数。对 "0077" 执行 CTRL-A 得到 "0100"，对 "0x100" 执行 CTRL-X
得到 "0x0ff"。
有一个例外：当一个以零开头的数字不是八进制（包含 '8' 或 '9'），但
'nrformats' 包含 "octal" 时，会移除前导零以避免结果被识别为八进制数。

注意当 'nrformats' 包含 "octal" 时，带前导零的十进制数会导致错误，因为
它们可能与八进制数混淆。

类似地，当 'nrformats' 同时包含 "bin" 和 "hex" 时，带前导 '0x' 或 '0X'
的二进制数可能被解释为十六进制而非二进制，因为 '0b' 是有效的十六进制数字。
对 "0x0b11" 执行 CTRL-A 得到 "0x0b12"，而不是 "0x0b100"。
当 'nrformats' 包含 "bin" 但不包含 "hex" 时，对 "0x0b11" 中的 "0b11"
执行 CTRL-A 得到 "0x0b100"。

当光标下的数字太大无法放入 64 位时，会被四舍五入到最接近的可表示数字，
并跳过加法/减法。例如对 18446744073709551616 执行 CTRL-X 得到
18446744073709551615。更大的数字也是如此，如 18446744073709551618。

CTRL-A 命令在宏中非常有用。例如：使用以下步骤制作编号列表。

1. 创建第一个列表条目，确保它以数字开头。
2. qa	     - 开始录制到寄存器 'a'
3. Y	     - 复制该条目
4. p	     - 在第一个条目下方放一个副本
5. CTRL-A    - 递增数字
6. q	     - 停止录制
7. <count>@a - 重复复制、粘贴和递增 <count> 次


左移和右移行						*shift-left-right*

							*<*
 <{motion}		将 {motion} 行向左移动一个 'shiftwidth'。

			如果 'shiftwidth' 选项设置为零，缩进量在行中
			第一个非空白字符处计算。
							*<<*
 <<			将 [count] 行向左移动一个 'shiftwidth'。

							*v_<*
{Visual}[count]<	将高亮的行向左移动 [count] 个 'shiftwidth'
			（关于 {Visual} 见 |Visual-mode|）。

							*>*
 >{motion}		将 {motion} 行向右移动一个 'shiftwidth'。

			如果 'shiftwidth' 选项设置为零，缩进量在行中
			第一个非空白字符处计算。
							*>>*
 >>			将 [count] 行向右移动一个 'shiftwidth'。

							*v_>*
{Visual}[count]>	将高亮的行向右移动 [count] 个 'shiftwidth'
			（关于 {Visual} 见 |Visual-mode|）。

							*:<*
:[range]<		将 [range] 行向左移动一个 'shiftwidth'。重复 '<'
			可移动多个 'shiftwidth'。

:[range]< {count}	将 {count} 行向左移动一个 'shiftwidth'，从
			[range] 开始（默认当前行 |cmdline-ranges|）。
			重复 '<' 可移动多个 'shiftwidth'。

:[range]le[ft] [indent]	将 [range] 中的行左对齐。将行的缩进设置为
			[indent]（默认 0）。

							*:>*
:[range]> [flags]	将 [range] 行向右移动一个 'shiftwidth'。
			重复 '>' 可移动多个 'shiftwidth'。
			[flags] 参见 |ex-flags|。

:[range]> {count} [flags]
			将 {count} 行向右移动一个 'shiftwidth'，从
			[range] 开始（默认当前行 |cmdline-ranges|）。
			重复 '>' 可移动多个 'shiftwidth'。
			[flags] 参见 |ex-flags|。

">" 和 "<" 命令对于在程序中更改缩进非常方便。使用 'shiftwidth' 选项
设置这些命令插入或删除的空白大小。通常 'shiftwidth' 选项为 8，但你可以
将其设为比如 3 以获得较小的缩进。向左移动在没有缩进时停止。向右移动
不影响空行。

如果 'shiftround' 选项开启，缩进会四舍五入到 'shiftwidth' 的倍数。

如果 'smartindent' 选项开启，或 'cindent' 开启且 'cinkeys' 包含值为零的
'#'，向右移动不影响以 '#' 开头的行（这些应该是必须保持在第 1 列的 C
预处理器行）。这可以通过 'cino' 选项更改，参见 |cino-#|。

当 'expandtab' 选项关闭时（默认），Vim 尽可能使用 <Tab> 来制作缩进。
你可以用 ">><<" 将由空格组成的缩进替换为由 <Tab>（和必要时一些空格）
组成的相同缩进。如果 'expandtab' 选项开启，Vim 只使用空格。然后你可以用
">><<" 将缩进中的 <Tab> 替换为空格（或使用 `:retab!`）。

要将一行移动多个 'shiftwidth'，使用可视模式或 `:` 命令。
例如：>
	Vjj4>		将三行向右移动 4 个缩进
	:<<<		将当前行向左移动 3 个缩进
	:>> 5		将 5 行向右移动 2 个缩进
	:5>>		将第 5 行向右移动 2 个缩进

4.1 过滤命令						*filter*

过滤器是一个程序，它接受标准输入的文本，以某种方式更改它，然后发送到标准
输出。你可以使用下面的命令将一些文本通过过滤器发送，使其被过滤器的输出
替换。过滤器的例子有 "sort"（按字母排序行）和 "indent"（格式化 C 程序
文件——你需要一个像过滤器一样工作的 indent 版本；不是所有版本都这样）。
'shell' 选项指定 Vim 用来执行过滤命令的 shell。你可以用 "." 重复过滤
命令。Vim 不识别 `:!` 命令后的注释（以 '"' 开头）。

							*!*
!{motion}{filter}	通过外部程序 {filter} 过滤 {motion} 的文本行。

							*!!*
!!{filter}		通过外部程序 {filter} 过滤 [count] 行。

							*v_!*
{Visual}!{filter}	通过外部程序 {filter} 过滤高亮的行
			（关于 {Visual} 见 |Visual-mode|）。

:{range}![!]{filter} [!][arg]				*:range!*
			关于执行外部命令参见 |:!|

			通过外部程序 {filter} 过滤 {range} 行。Vim 将
			可选的感叹号替换为上次给出的命令，并追加可选的
			[arg]。Vim 将过滤命令的输出保存到临时文件中，
			然后将文件读入缓冲区 |tempfile|。Vim 使用
			'shellredir' 选项将过滤器输出重定向到临时文件。
			但如果 'shelltemp' 选项关闭，则在可能时使用管道
			（在 Unix 上）。
			当 'cpoptions' 中包含 'R' 标志时，被过滤行中的
			标记会被删除，除非使用 |:keepmarks| 命令。
			例如：>
				:keepmarks '<,'>!sort
<			当过滤后的行数少于之前时，缺少行中的标记无论
			如何都会被删除。

							*=*
={motion}		通过 'equalprg' 选项给出的外部程序过滤 {motion}
			行。当 'equalprg' 选项为空时（默认），使用内部
			格式化函数 |C-indenting| 和 'lisp'。

			|indent-expression|。

							*v_=*
{Visual}=		像 ={motion} 一样过滤高亮的行。


						*tempdir* *tempfile* *setuid*
Nvim 使用临时文件进行过滤和生成差异。插件通常也使用 |tempname()| 来达到
自己的目的。在首次请求临时文件时，Nvim 创建一个公共目录（"Nvim 临时目录"），
作为当前会话中所有临时文件（包括 `stdpath("run")` 文件 |$XDG_RUNTIME_DIR|）
的存储。

Nvim 临时目录创建在第一个可用的系统临时目录中：
	Unix:    $TMPDIR, /tmp, current-dir, $HOME。
	Windows: $TMPDIR, $TMP, $TEMP, $USERPROFILE, current-dir。

在 unix 上临时目录以 0700 权限创建（仅当前用户可访问），以避免安全问题
（例如符号链接攻击）。退出时，Nvim 删除临时目录及其内容。
							*E5431*
如果你看到如下错误或 |log| 消息：>
	E5431: tempdir disappeared (2 times)
这意味着你系统上的外部进程删除了 Nvim 临时目录。通常这是由"杀毒软件"
或配置错误的清理服务引起的。

如果 Nvim 设置了 setuid 位，这可能会导致问题：临时文件属于 setuid 用户
所有，但过滤命令可能以原始用户身份运行。

使用表达式进行替换			*sub-replace-expression*
						*sub-replace-\=* *s/\=*
当替换字符串以 "\=" 开头时，其余部分被解释为表达式。

|sub-replace-special| 中提到的字符特殊含义不适用，除了 "<CR>"。<NL> 字符
用作换行，你可以用双引号字符串得到："\n"。在前面加反斜杠可以得到真正的
<NL> 字符（在文件中为 NUL）。

"\=" 记法也可以在 |substitute()| 函数的第三个参数 {sub} 中使用。在这种
情况下，|sub-replace-special| 中提到的字符特殊含义完全不适用。特别是
<CR> 和 <NL> 不被解释为换行，而分别被解释为回车符和换行符。

当结果是 |List| 时，项目用换行连接。因此每个项目成为一行，但它们内部
也可以包含换行。

|submatch()| 函数可用于获取匹配的文本。整个匹配文本可以用 "submatch(0)"
访问。第一对 () 匹配的文本用 "submatch(1)"。后续子匹配也类似。

要小心：分隔字符不能出现在表达式中！考虑使用 "@" 或 ":" 之类的字符。
如果表达式的结果包含分隔字符则没有问题。

示例：>
	:s@\n@\="\r" .. expand("$HOME") .. "\r"@
这将行尾替换为包含 $HOME 值的新行。>

	s/E/\="\<Char-0x20ac>"/g
这将每个 'E' 字符替换为欧元符号。更多信息参见 |<Char->|。

			其他连续的空白不会被更改。

			警告：此命令会修改 C 程序中字符串内的 <Tab>
			字符。使用 "\t" 来避免这种情况（这是个好习惯）。
			`:retab!` 也可能将一系列空格替换为 <Tab> 字符，
			这可能会弄乱 printf()。
			可以使用逗号分隔的制表位宽度列表来代替单个
			制表位。列表中的每个值表示一个制表位的宽度，
			但最后一个值适用于所有后续的制表位。

							*retab-example*
使用自动命令和 ":retab" 来编辑以 8 个制表位存储但以 4 个制表位编辑的文件
的示例。警告：字符串内的空白可能会改变！另见 'softtabstop' 选项。>

  :auto BufReadPost	*.xx	retab! 4
  :auto BufWritePre	*.xx	retab! 8
  :auto BufWritePost	*.xx	retab! 4
  :auto BufNewFile	*.xx	set ts=4

你可以使用这些命令将文本从一个地方复制到另一个地方。首先用复制、删除或
修改命令将文本放入寄存器，然后用粘贴命令插入寄存器内容。你也可以用这些
命令在文件之间移动文本，因为 Vim 在切换缓冲区时保留所有寄存器（CTRL-^
命令是在两个文件之间快速切换的方法）。

					*linewise-register* *charwise-register*
你可以用 "." 重复粘贴命令（:put 除外）并撤销。如果用于将文本放入寄存器的
命令是 |linewise|，Vim 将文本插入到光标所在行的下方（"p"）或上方（"P"）。
否则 Vim 在光标之后（"p"）或之前（"P"）插入文本。使用 ":put" 命令时，
Vim 总是将文本插入到下一行。你可以用 "xp" 命令序列交换两个字符。可以用
"ddp" 命令序列交换两行。可以用 "deep" 命令序列交换两个单词（光标在第一个
单词前的空白处开始）。你可以在粘贴命令后使用 |']| 或 |`]| 命令将光标移到
插入文本的末尾，或使用 |'[| 或 |`[| 将光标移到开头。

							     *put-Visual-mode*
在可视模式中使用 |p| 或 |P| 等粘贴命令时，Vim 会尝试用寄存器的内容替换
选中的文本。工作方式取决于选择类型和文本。对于块级选择，还取决于块的大小
以及角是否在现有字符上。（实现细节：它实际上是先在选择之后粘贴寄存器，
然后删除选择。）
									 *v_p*
可视模式中的 |p| 粘贴文本并将默认寄存器（无名、选择或剪贴板）设置为
先前选中的文本。如果你想在其他地方粘贴该文本这很有用。但你不能重复
同样的更改。
									 *v_P*
可视模式中的 |P| 粘贴文本但不设置默认寄存器。你可以重复更改，但删除的
文本不能使用。如果你确实需要它，可以用另一个寄存器使用 |p|。例如，
复制要粘贴的文本，可视选择要替换的文本，使用 "0p。你可以多次重复，
每次无名寄存器都会更改。
							*blockwise-put*
当寄存器包含一行的文本（字符级）时，使用块级可视选择粘贴该寄存器会在
每个选中的行中重复粘贴该文本，从而用寄存器文本的多个副本替换块级选择
区域。例如：
	- 用 `yw` 复制单词 "TEXT" 到寄存器
	- 选择一个可视块，在文本中用 "v" 标记：
	    aaavvaaa
	    bbbvvbbb
	    cccvvccc
	- 按 `p`，结果为：
	    aaaTEXTaaa
	    bbbTEXTbbb
	    cccTEXTccc

							*blockwise-register*
如果你使用块级可视模式命令将文本放入寄存器，文本块将插入到当前行和后续行
中光标列之前（"P"）或之后（"p"）。Vim 使整个文本块从相同列开始。因此插入
的文本看起来与复制或删除时相同。Vim 可能会将一些 <Tab> 字符替换为空格以
实现这一点。但如果块的宽度不是 <Tab> 宽度的倍数，且插入块之后的文本包含
<Tab>，该文本可能会不对齐。

使用 |zP|/|zp| 粘贴块级复制的寄存器而不添加尾随空格。

注意在字符级复制命令之后，Vim 将光标留在最接近缓冲区开头的第一个复制字符
上。这意味着 "yl" 不移动光标，但 "yh" 将光标向左移一个字符。
原因：	在 Vi 中，"y" 命令后跟一个向后移动有时不会将光标移到第一个复制字符，
	因为跳过了重新显示。在 Vim 中它始终移到第一个字符，如 Posix 所规定。
使用行级复制命令时，光标放在第一行，但列不变，因此它可能不在第一个复制
字符上。

寄存器					       *registers* *{register}* *E354*

有十种类型的寄存器：
1. 无名寄存器 ""
2. 10 个编号寄存器 "0 到 "9
3. 小删除寄存器 "-
4. 26 个命名寄存器 "a 到 "z 或 "A 到 "Z
5. 三个只读寄存器 ":、".、"%
6. 替代缓冲区寄存器 "#
7. 表达式寄存器 "=
8. 选择寄存器 "* 和 "+
9. 黑洞寄存器 "_
10. 上次搜索模式寄存器 "/

-----------------------------------------------------------------------------
1. 无名寄存器 ""				    *quote_quote* *quotequote*

Vim 用 "d"、"c"、"s"、"x" 命令删除的或用 "y" 命令复制的文本填充此寄存器，
无论是否指定了特定寄存器（例如 "xdd）。这就像无名寄存器指向上次使用的
寄存器。因此当使用大写寄存器名追加时，无名寄存器包含与命名寄存器相同的文本。
一个例外是 '_' 寄存器："_dd 不将删除的文本存储到任何寄存器。
Vim 对未指定寄存器的任何粘贴命令（p 或 P）使用无名寄存器的内容。
此外你可以用名字 '"' 来访问它。这意味着你必须输入两个双引号。
写入 "" 寄存器会写入寄存器 "0。

-----------------------------------------------------------------------------
2. 编号寄存器 "0 到 "9					*quote_number*
			 *quote0* *quote1* *quote2* *quote3* *quote4* *quote9*

Vim 用复制和删除命令的文本填充这些寄存器。
编号寄存器 0 包含最近一次复制命令的文本，除非该命令用 ["x] 指定了其他
寄存器。

编号寄存器 1 包含最近一次删除或修改命令删除的文本（即使该命令指定了
其他寄存器），除非文本少于一行（此时使用小删除寄存器）。对于使用以下
移动命令的删除操作符有一个例外：|%|、|(|、|)|、|`|、|/|、|?|、|n|、
|N|、|{| 和 |}|。

此时始终使用寄存器 "1（这是 Vi 兼容的）。如果删除在一行内，"-" 寄存器
也会被使用。注意这些字符可能被映射。例如 |%| 被 matchit 插件映射。

每次连续的删除或修改，Vim 将寄存器 1 的先前内容移到寄存器 2，2 移到 3，
依此类推，寄存器 9 的先前内容丢失。
							*yankring*
要将复制（不仅仅是删除）也存储到寄存器 1-9，试试这个：>lua
    -- Yank-ring: 将复制的文本存储到寄存器 1-9。
    vim.api.nvim_create_autocmd('TextYankPost', {
      callback = function()
        if vim.v.event.operator == 'y' then
          for i = 9, 1, -1 do -- 移动所有编号寄存器。
            vim.fn.setreg(tostring(i), vim.fn.getreg(tostring(i - 1)))
          end
        end
      end,
    })
<
-----------------------------------------------------------------------------
3. 小删除寄存器 "-                                 *quote_-* *quote-*

此寄存器包含删除少于一行的命令的文本，除非该命令用 ["x] 指定了寄存器。

-----------------------------------------------------------------------------
4. 命名寄存器 "a 到 "z 或 "A 到 "Z             *quote_alpha* *quotea*

Vim 只在你明确指定时才填充这些寄存器。用小写字母指定以替换其先前内容，
用大写字母指定以追加到其先前内容。当 'cpoptions' 中存在 '>' 标志时，
追加的文本前会插入换行。

-----------------------------------------------------------------------------
5. 只读寄存器 ":、". 和 "%

这些是 '%'、':' 和 '.'。你只能在 "p"、"P" 和 ":put" 命令以及 CTRL-R
中使用它们。

						*quote_.* *quote.* *E29*
   - ".	包含上次插入的文本（与插入模式命令 CTRL-A 和 CTRL-@ 插入的
	相同）。注意：在命令行上 CTRL-R 不能使用此寄存器。它的工作方式
	略有不同，像是插入文本而不是粘贴（'textwidth' 和其他选项会影响
	插入的内容）。
							*quote_%* *quote%*
   - "%	包含当前文件名。
						*quote_:* *quote:* *E30*
   - ":	包含最近执行的命令行。例如：使用 "@:" 重复上一个命令行命令。
	命令行只在至少输入了一个字符时才存储到此寄存器中。因此如果命令
	完全从映射执行，则保持不变。

-----------------------------------------------------------------------------
6. 替代文件寄存器 "#                               *quote_#* *quote#*

包含当前窗口的替代文件名。它会改变 |CTRL-^| 命令的工作方式。此寄存器
可写，主要是为了在插件更改它后能恢复。

它接受缓冲区编号：>
     let altbuf = bufnr(@#)
     ...
     let @# = altbuf

如果传入的缓冲区编号不存在会给出错误 |E86|。

也可以接受与现有缓冲区名匹配的值：>
     let @# = 'buffer_name'

如果有多个缓冲区匹配给定名称则给出错误 |E93|，如果没有缓冲区匹配则给出
错误 |E94|。

-----------------------------------------------------------------------------
7. 表达式寄存器 "=                              *quote_=* *quote=* *@=*

这不是一个真正存储文本的寄存器，而是在使用寄存器的命令中使用表达式的方式。
表达式寄存器可读写。

- 在 " 或 CTRL-R 之后输入 '=' 时，光标移到命令行，你可以在那里输入
  任何表达式（见 |expression|）。所有普通的命令行编辑命令都可用，包括
  表达式专用的历史记录。当你输入 <CR> 结束命令行时，Vim 计算表达式的
  结果。如果用 <Esc> 结束，Vim 放弃表达式。如果你没有输入表达式，Vim
  使用上一个表达式（类似于 "/" 命令）。
- 表达式必须求值为字符串。数字总是自动转换为字符串。对于 "p" 和 ":put"
  命令，如果结果是浮点数则转换为字符串。如果结果是列表，每个元素转为
  字符串并用作一行。字典转换为字符串。函数引用会导致错误消息（使用
  string() 来转换）。
- 如果 "=" 寄存器用于 "p" 命令，字符串在 <NL> 字符处分割。如果字符串
  以 <NL> 结尾，它被视为行级寄存器。

-----------------------------------------------------------------------------
8. 选择寄存器 "* 和 "+

使用这些寄存器为 GUI 存储和检索选中的文本。参见 |quotestar| 和 |quoteplus|。
当剪贴板不可用或不工作时，使用无名寄存器代替。对于 Unix 系统和 Mac OS X，
参见 |primary-selection|。

-----------------------------------------------------------------------------
9. 黑洞寄存器 "_					      *quote_*

写入此寄存器时，什么都不会发生。这可以用于删除文本而不影响普通寄存器。
从此寄存器读取时，什么都不会返回。

-----------------------------------------------------------------------------
10. 上次搜索模式寄存器 "/			    *quote_/* *quote/*

包含最近的搜索模式。用于 "n" 和 'hlsearch'。可以用 `:let` 写入，你可以
更改它以使 'hlsearch' 高亮其他匹配而无需实际搜索。不能复制或删除到此
寄存器。搜索方向可在 |v:searchforward| 中获得。注意从函数返回时值会被
恢复 |function-search-undo|。

							*@/*
你可以用 `:let` 命令写入寄存器 |:let-@|。例如：>
	:let @/ = "the"

如果你使用粘贴命令而不指定寄存器，Vim 使用上次填充的寄存器（这也是
无名寄存器的内容）。如果你搞混了，使用 `:dis` 命令查看 Vim 会粘贴
什么（此命令显示所有命名和编号寄存器；无名寄存器标记为 '"'）。

以下三个命令总是作用于整行。

:[range]co[py] {address}				*:co* *:copy*
			将 [range] 给出的行复制到 {address} 给出的行
			下方。

							*:t*
:t			copy 的同义词。

:[range]m[ove] {address}			*:m* *:mo* *:move* *E134*
			将 [range] 给出的行移动到 {address} 给出的行
			下方。

6. 格式化文本						*formatting*

:[range]ce[nter] [width]				*:ce* *:center*
			将 [range] 中的行在 [width] 列之间居中
			（默认 'textwidth'，'textwidth' 为 0 时为 80）。

:[range]ri[ght] [width]					*:ri* *:right*
			将 [range] 中的行在 [width] 列处右对齐
			（默认 'textwidth'，'textwidth' 为 0 时为 80）。

							*:le* *:left*
:[range]le[ft] [indent]
			将 [range] 中的行左对齐。将行的缩进设置为
			[indent]（默认 0）。

							*gq*
gq{motion}		格式化 {motion} 移过的行。
			格式化使用以下三种方法之一：
			1. 如果 'formatexpr' 不为空，求值该表达式。
			   这可以因缓冲区而异。
			2. 如果 'formatprg' 不为空，使用外部程序。
			3. 否则使用内部格式化。

			第三种情况下，'textwidth' 选项控制每个格式化行
			的长度（见下文）。
			如果 'textwidth' 选项为 0，格式化行的长度为
			屏幕宽度（最大宽度为 79）。
			'formatoptions' 选项控制格式化的类型 |fo-table|。
			光标停留在最后一个格式化行的第一个非空白字符上。

gqgq							*gqgq* *gqq*
gqq			格式化当前行。带计数时格式化多行。

							*v_gq*
{Visual}gq		格式化高亮的文本。（关于 {Visual} 见
			|Visual-mode|）。

							*gw*
gw{motion}		格式化 {motion} 移过的行。类似于 |gq| 但将
			光标放回文本中的相同位置。但不使用 'formatprg'
			和 'formatexpr'。

gwgw							*gwgw* *gww*
gww			像 "gw" 一样格式化当前行。

							*v_gw*
{Visual}gw		像 "gw" 一样格式化高亮的文本。（关于
			{Visual} 见 |Visual-mode|）。

示例：要格式化当前段落使用：				*gqap*  >
	gqap

"gq" 命令将光标留在移动命令将光标带到的行上。这允许你用 "." 重复格式化。
这与 "gqj"（格式化当前和下一行）和 "gq}"（格式化到段落末尾）配合得很好。
注意：当设置 'formatprg' 时，"gq" 将光标留在第一个格式化行上（与使用
过滤命令时类似）。

如果你想格式化当前段落并继续在你所在的位置，使用：>
	gwap
如果你想始终保持段落格式化，可以将 'a' 标志添加到 'formatoptions'。
参见 |auto-format|。

如果 'autoindent' 选项开启，Vim 使用第一行的缩进用于后续行。

格式化不改变空行（但它会改变只有空白的行！）。

合并行时使用 'joinspaces' 选项。

你可以将 'formatexpr' 选项设置为表达式，或将 'formatprg' 选项设置为
外部程序名供 Vim 用于文本格式化。'textwidth' 和其他选项对外部程序
格式化无效。

                                                        *format-formatexpr*
'formatexpr' 选项可以设置为执行缓冲区重新格式化的 Vim 脚本函数。这通常
应该在 |ftplugin| 中进行，因为格式化高度依赖于文件类型。使用 |autoload|
脚本是有意义的，这样相应的脚本只在实际需要时加载，脚本应命名为
<filetype>format.vim。

例如，Vim 在 $VIMRUNTIME/ftplugin 目录中分发的 XML 文件类型插件将
'formatexpr' 选项设置为：>

   setlocal formatexpr=xmlformat#Format()

这意味着你会在文件 `$VIMRUNTIME/autoload/xmlformat.vim` 中找到定义
xmlformat#Format() 函数的对应脚本。

以下是一个从选中文本中删除尾随空白的示例脚本。将其放在你的 autoload
目录中，例如 ~/.vim/autoload/format.vim：
>vim
  func! format#Format()
    " only reformat on explicit gq command
    if mode() != 'n'
      " fall back to Vim's internal reformatting
      return 1
    endif
    let lines = getline(v:lnum, v:lnum + v:count - 1)
    call map(lines, {key, val -> substitute(val, '\s\+$', '', 'g')})
    call setline('.', lines)

    " do not run internal formatter!
    return 0
  endfunc

然后你可以通过执行以下命令启用格式化：>
  setlocal formatexpr=format#Format()

注意：此函数从插入模式调用时显式返回非零值（基本上意味着文本被插入到
超过 'textwidth' 限制的位置）。这导致 Vim 回退到使用内部格式化程序
重新格式化文本。

但如果使用 |gq| 命令重新格式化文本，函数将接收选中的行，修剪这些行的
尾随空白并将它们放回原位。如果你打算将单行分成多行，注意不要覆盖任何
内容。

如果你想允许从插入或替换模式重新格式化文本，需要非常小心，因为函数可能
被递归调用。调试时设置 'debug' 选项会有帮助。

							*right-justify*
Vim 中没有右对齐文本的命令。你可以用外部命令来完成，例如 "par"
（如：`:.,}!par` 格式化到段落末尾），或将 'formatprg' 设置为 "par"。

							*format-comments*
注释格式化的概述在用户手册的 |30.6| 节中。

Vim 可以以特殊方式自动插入和格式化注释。Vim 通过行首（忽略空白）的特定
字符串识别注释。可以使用三种类型的注释：

- 在每行开头重复的注释字符串。例如 shell 脚本中使用的以 "#" 开头的注释。
- 仅在第一行出现的注释字符串，后续行中不出现。例如此处带破折号的列表。
- 三段式注释，有开始字符串、结束字符串和可选的中间行。开始、中间和结束
  的字符串各不相同。例如 C 风格注释：>
	/*
	 * this is a C comment
	 */

'comments' 选项是逗号分隔的部分列表。每个部分定义一种注释字符串类型。
一个部分由以下组成：
	{flags}:{string}

{string} 是必须出现的字面文本。

{flags}：
  n	嵌套注释。允许混合部分的嵌套。如果 'comments' 是 "n:),n:>"，
	则以 "> ) >" 开头的行是注释。

  b	{string} 后需要空白（<Space>、<Tab> 或 <EOL>）。

  f	仅第一行有注释字符串。不在下一行重复注释，但保留缩进
	（例如项目符号列表）。

  s	三段式注释的开始

  m	三段式注释的中间

  e	三段式注释的结束

  l	左对齐。与 's' 或 'e' 一起使用时，开始或结束的最左字符与中间
	的最左字符对齐。这是默认值，可以省略。更多详情见下文。

  r	右对齐。与上面类似，但使用最右字符而不是最左字符。更多详情见
	下文。

  O	"O" 命令不考虑此注释。

  x	允许在新行上仅输入结束注释字符串的最后一个字符来结束三段式注释，
	前提是中间注释字符串已被自动插入。更多详情见下文。

  {digits}
	与 's' 或 'e' 一起使用时：为自动插入的中间或结束注释引导符
	添加 {digit} 偏移量。偏移量从左对齐开始。更多详情见下文。

  -{digits}
	类似 {digits} 但减少缩进。这仅在开始或结束部分有一些可以移除的
	缩进时有效。

当一个字符串没有 'f'、's'、'm' 或 'e' 标志时，Vim 假设注释字符串在
每行开头重复。{flags} 字段可以为空。

{string} 前后文本中的任何空白都是 {string} 的一部分，所以不要包含
前导或尾随空白，除非空白是注释字符串的必需部分。

当一个注释引导符是另一个的一部分时，在完整的后面指定部分。例如，要同时
包含 "-" 和 "->"，使用 >
	:set comments=f:->,f:-

三段式注释必须始终以开始、中间、结束的形式给出，中间没有其他部分。
三段式注释的例子是 >
	sr:/*,mb:*,ex:*/
用于 C 注释。为了避免将 "*ptr" 识别为注释，中间字符串包含 'b' 标志。
对于三段式注释，Vim 在开始和中间字符串之后检查文本中的结束字符串。
如果 Vim 找到结束字符串，注释不会在下一行继续。三段式注释必须有中间
字符串，否则 Vim 无法识别中间行。

注意上面三段式注释定义中 "x" 标志的使用。当你在 C 注释中按回车时，
Vim 会为新行插入中间注释引导符：" * "。要关闭这个注释，你只需在新行上
输入任何内容之前输入 "/"。这会将中间注释引导符替换为结束注释引导符并
应用任何指定的对齐，只留下 `" */"`。不需要先按退格键。

当既有中间部分匹配，又有更长的结束部分匹配时，使用结束部分。这使得
C 风格注释无需中间部分以空格结尾也能工作。

以下是对齐标志工作的示例，使注释突出（看起来有点像数字 1）。
考虑注释字符串：>vim
	:set comments=sr:/***,m:**,ex-2:******/
>
                                   /***
                                     **<--"r" 标志的右对齐
                                     **
 "-2" 标志偏移 2 个空格-->          **
                                   ******/
在这个例子中，第一个注释被输入，然后按了 4 次回车，然后按 "/" 结束注释。

以下是三段式注释的一些细节。有三个时机考虑对齐和偏移标志：在开始注释
后开新行、在结束注释前开新行，以及自动结束三段式注释。结束对齐标志
有反向视角；结果是 "s" 和 "e" 使用相同的对齐标志时，开始和结束部分
的缩进相同。每个注释部分只应使用一个对齐，但偏移数字会覆盖 "r" 和
"l" 标志。

启用 'cindent' 在很多情况下会覆盖对齐标志。使用不同的方法（如 |gq|
或 |=|）重新缩进也不会参考对齐标志。相同的行为可以在那些其他格式化
选项中定义。一个考虑因素是 'cindent' 有基于上下文的注释缩进附加选项，
但不能复制许多三段式缩进对齐。但 'indentexpr' 有能力更好地处理
三段式注释。

其他示例：>
   "b:*"	包含以 "*" 开头的行，但如果 "*" 后跟非空白则不包含。
		这避免了像 "*str" 这样的指针解引用被识别为注释。
   "n:>"	包含以 ">"、">>"、">>>" 等开头的行。
   "fb:-"	格式化以 "- " 开头的列表。

默认包含 "b:#"。这意味着以 "#include" 开头的行不被识别为注释行。
但以 "# define" 开头的行被识别。这是一个折中。

且包含 "*/" 的行之后开新行，不会插入注释引导符，新行的缩进取自包含注释

    /*
     * Your typical comment.

    comment.

	:set fo=tcrq

自动格式化					*auto-format* *autoformat*

当 'formatoptions' 中存在 'a' 标志时，插入或删除文本时文本会自动格式化。
这对于编辑文本段落非常方便。一些使用提示：

- 你需要正确定义段落。最简单的是用空行分隔段落。当没有分隔空行时，
  考虑使用 'w' 标志并在段落中每行末尾（除最后一行外）添加空格。

- 你可以基于文件类型 |filetype| 或使用 |modeline| 为特定文件设置
  'formatoptions'。

- 将 'formatoptions' 设置为 "aw2tq" 可以使带缩进的文本如下：

	    bla bla foobar bla
	bla foobar bla foobar bla
	    bla bla foobar bla
	bla foobar bla bla foobar

- 添加 'c' 标志以仅自动格式化注释。对源代码有用。

- 将 'textwidth' 设置为所需宽度。如果为零则使用 79，或如果屏幕较小
  则使用屏幕宽度。

以及一些警告：

- 当部分文本没有正确分隔成段落时，修改此文本会导致它被格式化。
  考虑执行 >

	:set fo-=a

- 当使用 'w' 标志（尾随空格表示段落继续）并用 |dd| 删除段落的最后一行时，
  该段落将与下一个段落合并。

- 更改的文本会保存用于撤销。格式化也是一种更改。因此每次格式化操作都会
  保存文本用于撤销。这可能消耗相当多的内存。

- 格式化长段落和/或复杂缩进可能会很慢。

7. 排序文本						*sorting*

Vim 有排序函数和排序命令。排序函数参见：|sort()|、|uniq()|。
另见 |:uniq|。

							*:sor* *:sort*
:[range]sor[t][!] [b][f][i][l][n][o][r][u][x] [/{pattern}/]
			排序 [range] 中的行。没有给出范围时排序所有行。

			使用 [!] 时顺序反转。

			使用 [i] 时忽略大小写。
							*:sort-l*
			使用 [l] 时排序使用当前排序规则区域设置。
			实现细节：使用 strcoll() 比较字符串。
			参见 |:language| 检查或设置排序规则区域设置。
			示例：>
				:language collate en_US.UTF-8
				:%sort l
<			|v:collate| 也可用于检查当前区域设置。
			使用区域设置排序通常忽略大小写。
			这在 Mac 上不能正常工作。

			选项 [n][f][x][o][b] 互斥。

			使用 [n] 时，按行中第一个十进制数排序
			（在 {pattern} 匹配之后或内部）。
			包含一个前导 '-'。

			使用 [f] 时，按行中的浮点数排序。
			浮点数的值的确定类似于将文本（在 {pattern} 匹配
			之后或内部）传给 str2float() 函数。

			使用 [x] 时，按行中第一个十六进制数排序
			（在 {pattern} 匹配之后或内部）。
			前导 "0x" 或 "0X" 被忽略。
			包含一个前导 '-'。

			使用 [o] 时，按行中第一个八进制数排序
			（在 {pattern} 匹配之后或内部）。

			使用 [b] 时，按行中第一个二进制数排序
			（在 {pattern} 匹配之后或内部）。
							*:sort-u* *:sort-uniq*
			使用 [u]（u 代表 unique，唯一）时，只保留一系列
			相同行中的第一行（使用 [i] 时忽略大小写）。
			不使用此标志时，一系列相同行将保持原始顺序。
			注意前导和尾随空白可能导致行不同。
			如果你只想去重，使用 |:uniq|。

			当指定 /{pattern}/ 且没有 [r] 标志时，跳过
			与 {pattern} 匹配的文本，从而按匹配之后的内容排序。
			'ignorecase' 适用于模式，但不使用 'smartcase'。
			可以使用任何非字母字符代替斜杠。
			例如，按第二个逗号分隔的字段排序：>
				:sort /[^,]*,/
<			按虚拟列 10 处的文本排序（从而忽略制表符和
			空格的差异）：>
				:sort /.*\%10v/
<			按行中第一个数字排序，无论前面有什么：>
				:sort /.\{-}\ze\d/
<			（说明：".\{-}" 匹配任意文本，"\ze" 设置匹配
			的结束，\d 匹配数字。）
			使用 [r] 时，按匹配的 {pattern} 排序，而不是
			跳过它。
			例如，只按每行的前三个字母排序：>
				:sort /\a\a\a/ r

<			如果使用了 {pattern}，任何没有 {pattern} 匹配
			的行保持当前顺序，但与有 {pattern} 匹配的行
			分开。如果是反向排序，它们会在排序行之后以
			反向顺序出现，否则它们以原始顺序出现在排序行
			之前。

			如果 {pattern} 为空（例如指定 //），使用上次
			搜索模式。这允许先试验模式。

注意将 `:sort` 与 `:global` 一起使用不会排序匹配行，这是没什么用的。

`:sort` 不使用当前区域设置，除非使用 l 标志。
Vim 执行 "稳定" 排序。

排序可以被中断，但如果你中断得太晚，可能会出现重复行。这也取决于使用的
系统库函数。

==============================================================================
8. 去重文本					*deduplicating* *unique*

Vim 有去重函数和去重命令。去重函数参见：|uniq()|。
另见 |:sort-uniq|。

							*:uni* *:uniq*
:[range]uni[q][!] [i][l][r][u] [/{pattern}/]
			移除 [range] 中相邻的重复行。没有给出范围时
			处理所有行。

			使用 [i] 时比较行时忽略大小写。

			使用 [l] 时比较使用当前排序规则区域设置。
			更多详情参见 |:sort-l|。

			使用 [r] 时，在匹配 /{pattern}/ 的文本上进行
			比较，而不是整行。

			使用 [u] 时，只保留不重复的行（即后面没有紧跟
			相同行的行）。

			使用 [!] 时，只保留后面紧跟有重复行的行。

			如果同时给出 [!] 和 [u]，[u] 被忽略，[!] 生效。

			当指定 /{pattern}/ 且不使用 [r] 时，跳过与
			{pattern} 匹配的文本，在匹配之后的内容上进行
			比较。
			'ignorecase' 适用于模式，但不使用 'smartcase'。
			可以使用任何非字母字符代替斜杠。

			例如，基于第二个逗号分隔的字段移除相邻的重复行：>
				:uniq /[^,]*,/
<			或只保留忽略前 5 个字符后的唯一行：>
				:uniq u /.\{5}/
<			如果 {pattern} 为空（例如使用 //），使用上次
			搜索模式。

			注意前导和尾随空白可能导致行被视为不同。
			要移除所有重复行而不管位置，使用 |:sort-u| 或
			外部工具。
