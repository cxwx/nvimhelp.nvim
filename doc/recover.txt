崩溃后恢复						*crash-recovery*

你花了几个小时输入的文本明天早上就要用了，然后灾难发生了：你的电脑崩溃了。

			不要惊慌！

你可以从 Vim 用来存储文件内容的文件中恢复大部分更改。通常你只需要一个命令就可以
恢复你的工作:
	vim -r filename

                                      输入 |gO| 查看目录。

==============================================================================
1. 交换文件						*swap-file*

Vim 将你的更改存储在交换文件中。使用你开始编辑的原始文件加上交换文件，
你可以恢复大部分工作。

你可以用以下命令查看当前使用的交换文件名:

	:sw[apname]					*:sw* *:swapname*

或者你可以使用 |swapname()| 函数，它还允许查看其他缓冲区的交换文件名。

交换文件的名称通常与你正在编辑的文件相同，扩展名为 ".swp"。
- 在 Unix 上，在同一目录下的交换文件名前会加上 '.'。这样做是为了让交换文件
  不显示在目录列表中。
- 如果此文件已经存在（例如，当你从崩溃中恢复时），会给出警告并使用另一个
  扩展名，如 ".swo"、".swn" 等。
- 已存在的文件永远不会被覆盖。
- 当 Vim 停止编辑文件时，交换文件会被删除。

								*E326*
技术细节: 如果 ".swp" 文件名已经存在，最后一个字符会递减，直到找到不存在
	   该名称的文件或到达 ".saa"。如果到达最后一个情况，则不创建交换文件。

通过设置 'directory' 选项，你可以将交换文件放在编辑文件之外的其他地方。
优点:
- 你不会用 ".swp" 文件污染目录。
- 当 'directory' 在另一个分区时，可以降低损坏文件所在文件系统的风险（在崩溃时）。
缺点:
- 你可能会因为不同目录中相同名称的文件而产生名称冲突（虽然 Vim 会通过比较路径名
  来尝试避免这种情况）。这会导致虚假的 ATTENTION 警告消息。
- 当你使用你的主目录，而别人试图编辑同一个文件时，那个用户将看不到你的交换文件，
  也不会收到 ATTENTION 警告消息。

如果你想把交换文件放在固定位置，在你的 vimrc 中添加类似以下的命令:
	:set dir=~/tmp		(Unix)
	:set dir=c:\\tmp	(Win32)
当编辑软盘上的文件时这也非常方便。当然你必须先创建 "tmp" 目录才能工作！

对于只读文件，不会立即使用交换文件。只有在进行更改时才会创建交换文件。

可以重置 'swapfile' 选项以避免创建交换文件。而 |:noswapfile| 修饰符可用于
不为新缓冲区创建交换文件。

:nos[wapfile]   {command}			*:nos* *:noswapfile*
		执行 {command}。如果它包含加载新缓冲区的命令，该缓冲区将在
		不创建交换文件的情况下加载，并且 'swapfile' 选项将被重置。
		如果缓冲区已经有交换文件，则不会被删除，'swapfile' 也不会被重置。


检测已存在的交换文件 ~

你可以在用户手册的 |11.3| 节找到相关内容。

									*W325*
默认的 |SwapExists| 处理器 (|default-autocmds|) 会跳过 |E325| 提示（并自动选择
"(E)dit"），如果交换文件的所有者进程仍在运行且属于当前用户。这假设你通常不希望
仅仅因为碰巧从多个 Nvim 实例编辑同一文件就被 |ATTENTION| 消息打扰。在最坏的
情况下（系统崩溃），该文件会有多个交换文件；使用 |:recover| 来检查它的所有
交换文件。


更新交换文件 ~

在输入 200 个字符或 4 秒内没有输入任何内容后，交换文件会被更新。这只在缓冲区
被更改时发生，而不是在你只是移动时。不实时更新的原因是这样做会过多地减慢正常
工作速度。你可以用 'updatecount' 选项更改 200 字符的计数。你可以用 'updatetime'
选项设置时间。时间以毫秒为单位给出。写入交换文件后，Vim 会将文件同步到磁盘。

如果不需要写入交换文件，可以通过将 'updatecount' 选项设置为 0 来关闭。
用 "-n" 选项启动 Vim 也会这样做。可以通过将 'updatecount' 选项设置为非零值来
重新打开写入。执行此操作时将为所有缓冲区创建交换文件。但是将 'updatecount'
设置为零时，现有的交换文件不会被删除，它只影响此后打开的文件。

如果你想确保你的更改在交换文件中，请使用以下命令:

					*:pre* *:preserve* *E313* *E314*
:pre[serve]		将当前缓冲区的所有文本写入其交换文件。恢复时不再
			需要原始文件。

Vim 交换文件可以通过前六个字符 "b0VIM " 来识别。之后是版本号，例如 "3.0"。


链接和符号链接 ~

在 Unix 上，同一个文件可以有两个名称。这可以通过硬链接和符号链接（symlinks）
来实现。

对于硬链接，Vim 不知道文件的另一个名称。因此，交换文件的名称将基于你用来编辑
文件的名称。不会检查是否通过其他名称编辑同一文件，因为 Vim 无法找到另一个交换
文件（除非搜索整个硬盘，那会非常慢）。

对于符号链接，Vim 会解析链接以找到实际文件的名称。交换文件名基于该名称。因此，
无论你用什么名称编辑文件，交换文件名通常是相同的。但是有例外:
- 当实际文件的目录不可写时，交换文件会放在其他地方。
- 当符号链接以某种方式创建了循环时，你会收到 *E773* 错误消息，并使用未修改的
  文件名。你将无法正常保存文件。

2. 恢复					*recovery* *E308* *E311*

基本文件恢复在用户手册中有解释: |usr_11.txt|。

另一种恢复方法是启动 Vim 并使用 ":recover" 命令。当你启动 Vim 编辑文件并收到
"ATTENTION: Found a swap file ..." 消息时，这很容易。在这种情况下，单个命令
":recover" 就可以完成工作。你也可以给 recover 命令指定文件名或交换文件名:
					*:rec* *:recover* *E305* *E306* *E307*
:rec[over] [file]	尝试从交换文件恢复 [file]。如果未给出 [file]，则使用
			当前缓冲区的文件名。缓冲区的当前内容将丢失。
			如果缓冲区已被修改，此命令会失败。

:rec[over]! [file]	与 ":recover" 类似，但当前缓冲区的任何更改都将丢失。

						*E312* *E309* *E310* *E1364*
Vim 对于交换文件在某些方面损坏时有一定的智能。如果 Vim 对发现的内容有疑问，
它会给出错误消息并在文本中插入 "???" 行。如果在恢复过程中看到错误消息，
请在文件中搜索 "???" 以查看出了什么问题。你可能需要剪切和粘贴来获取所需文本。

最常见的提示是 "???LINES MISSING"。这意味着 Vim 无法从原始文件读取文本。
这可能发生在系统崩溃且原始文件的部分内容未写入磁盘时。

在覆盖原始文件或删除交换文件之前，请确保恢复成功。最好的做法是将恢复的文件
写入其他位置，并运行 'diff' 来检查恢复的文件中是否包含你想要的更改。
或使用 |:DiffOrig|。

一旦你确认恢复没问题，就删除交换文件。否则，你将继续收到 ".swp" 文件已存在的
警告消息。
