Treesitter 集成                                 *treesitter*

Nvim 集成了 `tree-sitter` 库，用于对缓冲区进行增量解析：
https://tree-sitter.github.io/tree-sitter/

警告：Treesitter 支持仍处于实验阶段，可能会频繁变化。本文档可能也未
完全反映最新的更改。

                                      Type |gO| to see the table of contents.

==============================================================================
解析器文件                                              *treesitter-parsers*

解析器是 treesitter 的核心。它们是 treesitter 会在 `parser` 运行时
目录中搜索的库。

Nvim 包含以下解析器：

- C
- Lua
- Markdown
- Vimscript
- Vimdoc
- Treesitter 查询文件 |ft-query-plugin|

你可以手动安装更多解析器，或使用插件如
https://github.com/nvim-treesitter/nvim-treesitter 。

解析器在任何 'runtimepath' 目录中以 `parser/{lang}.*` 搜索。如果找到
同一语言的多个解析器，使用第一个。（注意：这通常意味着优先级为
"用户配置 > 插件 > 内置"。）

从文件路径加载解析器：>lua

    vim.treesitter.language.add('python', { path = "/path/to/python.so" })
<
如果文件系统区分大小写，解析器名称假定为小写。

要将某些 |filetypes| 与 treesitter 语言（解析器名称）关联，使用
|vim.treesitter.language.register()|。例如，要对文件类型为 `svg` 或
`xslt` 的缓冲区使用 `xml` treesitter 解析器，使用：>lua

    vim.treesitter.language.register('xml', { 'svg', 'xslt' })
<
                                                    *treesitter-parsers-wasm*

如果 Nvim 构建时启用了 `ENABLE_WASMTIME`，还可以加载 wasm 解析器：>lua

    vim.treesitter.language.add('python', { path = "/path/to/python.wasm" })
<

TREESITTER 查询                                          *treesitter-query*

Treesitter 查询是从已解析的 |TSTree| 中提取信息的方式，例如用于高亮。
简而言之，`query`（查询）由一个或多个模式组成。`pattern`（模式）定义在
语法树中的节点类型上。`match`（匹配）对应语法树中匹配模式的特定元素。
模式可以选择性地定义捕获和谓词。`capture`（捕获）允许你将名称与模式中
的特定节点关联。`predicate`（谓词）为匹配添加任意元数据和条件数据。

查询用类 lisp 语言编写，文档在
https://tree-sitter.github.io/tree-sitter/using-parsers/queries/1-syntax.html
注意：其中列出的谓词与 Nvim 支持的不同。参见 |treesitter-predicates|
了解 Nvim 支持的完整谓词列表。

Nvim 在 `runtimepath` 下的 `queries` 目录中查找 `*.scm` 文件形式的
查询，其中每个文件包含特定语言和用途的查询，例如
`queries/lua/highlights.scm` 用于高亮 Lua 文件。
默认使用 `runtimepath` 上的第一个查询（通常意味着用户配置优先于插件，
插件优先于 Nvim 内置查询）。如果查询应扩展其他查询而非替换它们，
使用 |treesitter-query-modeline-extends|。

Lua 接口在 |lua-treesitter-query| 中描述。


TREESITTER 查询谓词                            *treesitter-predicates*

谓词是特殊的 scheme 节点，用于条件性地捕获节点。例如，`eq?` 谓词
可以如下使用：>query

    ((identifier) @variable.builtin
      (#eq? @variable.builtin "self"))
<
仅匹配对应 `"self"` 文本的标识符。此类查询可用于以不同方式高亮
内置函数或变量。

以下谓词是内置的：

    `eq?`                                            *treesitter-predicate-eq?*
        将字符串与节点对应的文本匹配：>query
            ((identifier) @variable.builtin (#eq? @variable.builtin "self"))
            ((node1) @left (node2) @right (#eq? @left @right))
<
    `any-eq?`                                    *treesitter-predicate-any-eq?*
        类似 `eq?`，但对量化模式只需一个捕获的节点匹配。

    `match?`                                      *treesitter-predicate-match?*
    `vim-match?`                              *treesitter-predicate-vim-match?*
         将 |regexp| 与节点对应的文本匹配：>query
            ((identifier) @constant (#match? @constant "^[A-Z_]+$"))
<
         注意：`^` 和 `$` 锚点将匹配节点文本的开头和结尾。

    `any-match?`                              *treesitter-predicate-any-match?*
    `any-vim-match?`                      *treesitter-predicate-any-vim-match?*
        类似 `match?`，但对量化模式只需一个捕获的节点匹配。

    `lua-match?`                              *treesitter-predicate-lua-match?*
         将 |lua-pattern| 与节点对应的文本匹配，类似 `match?`

    `any-lua-match?`                      *treesitter-predicate-any-lua-match?*
         类似 `lua-match?`，但对量化模式只需一个捕获的节点匹配。

    `contains?`                                *treesitter-predicate-contains?*
        将字符串与节点对应文本的部分匹配：>query
            ((identifier) @foo (#contains? @foo "foo"))
            ((identifier) @foo-bar (#contains? @foo-bar "foo" "bar"))
<
    `any-contains?`                        *treesitter-predicate-any-contains?*
        类似 `contains?`，但对量化模式只需一个捕获的节点匹配。

    `any-of?`                                    *treesitter-predicate-any-of?*
        将给定字符串中的任意一个与节点对应的文本匹配：>query
            ((identifier) @foo (#any-of? @foo "foo" "bar"))
<
        这是检查节点是否匹配多个关键字之一的推荐方式，因为已为此
        进行了优化。

    `has-ancestor?`                        *treesitter-predicate-has-ancestor?*
        将给定节点类型与节点的所有祖先匹配：>query
            ((identifier) @variable.builtin
              (#any-of? @variable.builtin "begin" "end")
              (#has-ancestor? @variable.builtin range_expression))
<
    `has-parent?`                            *treesitter-predicate-has-parent?*
        将给定节点类型与节点的直接祖先匹配：>query
            (((field_expression
                 (field_identifier) @method)) @_parent
             (#has-parent? @_parent template_method function_declarator))
<
                                                    *treesitter-predicate-not*
每个谓词都有一个 `not-` 前缀的谓词，即该谓词的否定。

                                                    *treesitter-predicate-all*
                                                    *treesitter-predicate-any*
查询可以使用量词来捕获多个节点。当捕获包含多个节点时，谓词仅在捕获
包含的所有节点都匹配谓词时才匹配。某些谓词（`eq?`、`match?`、
`lua-match?`、`contains?`）接受 `any-` 前缀，改为在捕获包含的任意
节点匹配谓词时匹配。

例如，考虑以下 Lua 代码：>lua

  -- TODO: This is a
  -- very long
  -- comment (just imagine it)
<
使用以下带谓词的查询：
>query
    (((comment)+ @comment)
     (#match? @comment "TODO"))
<
此查询不会匹配，因为不是所有被 @comment 捕获的节点都匹配谓词。
改为使用：
>query
    (((comment)+ @comment)
     (#any-match? @comment "TODO"))
<

可以通过 |vim.treesitter.query.add_predicate()| 添加更多谓词。
使用 |vim.treesitter.query.list_predicates()| 列出所有可用谓词。


TREESITTER 查询指令                            *treesitter-directives*

Treesitter 指令为节点或匹配存储元数据并执行副作用。例如，`set!`
指令在匹配或节点上设置元数据：>query

        ((identifier) @foo (#set! type "parameter"))
<
以下指令是内置的：

    `set!`                                          *treesitter-directive-set!*
        为特定匹配或捕获设置键/值元数据。值可以通过
        `metadata[key]`（匹配特定）或
        `metadata[capture_id][key]`（捕获特定）访问。

        参数: ~
            {capture_id}（可选）
            {key}
            {value}

        示例：>query
            ((identifier) @foo (#set! @foo kind "parameter"))
            ((node1) @left (node2) @right (#set! type "pair"))
            ((codeblock) @markup.raw.block (#set! priority 90))
<
    `offset!`                                      *treesitter-directive-offset!*
        获取捕获节点的范围并应用偏移。这将为具有 `capture_id` 的捕获
        节点设置形如 { {start_row}, {start_col}, {end_row}, {end_col} }
        列表的新范围作为 `metadata[capture_id].offset`。此偏移将应用于
        |vim.treesitter.get_range()| 返回的范围。对
        |treesitter-language-injections| 很有用。

        参数: ~
            {capture_id}
            {start_row}
            {start_col}
            {end_row}
            {end_col}

        示例：>query
            ((identifier) @constant (#offset! @constant 0 1 0 -1))
<
    `gsub!`                                          *treesitter-directive-gsub!*
        使用 |lua-pattern| 转换节点内容。这将设置新的
        `metadata[capture_id].text`。

        参数: ~
            {capture_id}
            {pattern}
            {replacement}

        示例：>query
            (#gsub! @_node ".*%.(.*)" "%1")
<
    `trim!`                                          *treesitter-directive-trim!*
        修剪节点中的空白。设置新的 `metadata[capture_id].range`。接受
        捕获 ID，以及可选的四个整数来自定义修剪行为（`1` 表示修剪，
        `0` 表示不修剪）。仅给出捕获 ID 时，修剪节点末尾的空行
        （仅包含空白或为空的行）（为向后兼容）。如果给出参数，可以
        修剪节点两侧的所有空白。

        示例：>query
            ; only trim blank lines from the end of the node
            ; (equivalent to (#trim! @fold 0 0 1 0))
            (#trim! @fold)

            ; trim blank lines from both sides of the node
            (#trim! @fold 1 0 1 0)

            ; trim all whitespace around the node
            (#trim! @fold 1 1 1 1)
<
        参数: ~
            {capture_id}
            {trim_start_linewise}
            {trim_start_charwise}
            {trim_end_linewise}（仅给出 {capture_id} 时默认 `1`）
            {trim_end_charwise}

可以通过 |vim.treesitter.query.add_directive()| 添加更多指令。
使用 |vim.treesitter.query.list_directives()| 列出所有可用指令。


TREESITTER 查询模式行                          *treesitter-query-modeline*

Nvim 支持使用一组"模式行"来自定义查询的行为，即查询中以 `;` 开头的
注释。以下是当前支持的模式行替代方案：

    `inherits: {lang}...`                     *treesitter-query-modeline-inherits*
        指定此查询应继承 {lang} 的查询。这将递归地深入到 {lang} 的
        查询中，除非用括号包裹：`({lang})`。
        注意：这旨在用于包含另一语言的查询。如果你想让查询扩展
        同一语言的查询，使用 `extends`。

    `extends`                                  *treesitter-query-modeline-extends*
        指定此查询应作为查询的扩展使用，即应与其他查询合并。
        注意：扩展的顺序和用作基础的查询取决于你的 'runtimepath' 值。

注意：这些模式行注释必须在查询顶部，但可以重复，例如以下两个模式行
块都是有效的：
>query
    ;; inherits: typescript,jsx
    ;; extends
<
>query
    ;; extends
    ;;
    ;; inherits: css
<

TREESITTER 语法高亮                          *treesitter-highlight*

语法高亮通过名为 `highlights.scm` 的查询指定，这些查询将已解析的
|TSTree| 中的 |TSNode| 匹配到可以分配高亮组的 `capture`（捕获）。
例如，查询 >query

    (parameters (identifier) @variable.parameter)
<
将函数 `parameters` 节点内的任何 `identifier` 节点匹配到名为
`@variable.parameter` 的捕获。例如，对 Lua 代码 >lua

    function f(foo, bar) end
<
将被解析为（参见 |:InspectTree|）：>query

    (function_declaration ; [1:1 - 24]
      name: (identifier) ; [1:10 - 10]
      parameters: (parameters ; [1:11 - 20]
        name: (identifier) ; [1:12 - 14]
        name: (identifier))) ; [1:17 - 19]
<
上述查询将 `foo` 和 `bar` 高亮为 `@variable.parameter`。

也可以匹配字面表达式（前提是解析器返回它们）：
>query
    [
      "if"
      "else"
    ] @keyword.conditional
<
假设在 runtimepath 中找到了合适的解析器和 `highlights.scm` 查询，
只需通过 |vim.treesitter.start()| 即可启用当前缓冲区的 treesitter
高亮。

                                                 *treesitter-highlight-groups*
捕获名称加 `@` 前缀后可直接用作高亮组。对于许多常用捕获，对应的
高亮组默认链接到 Nvim 的标准 |highlight-groups|（例如 `@comment`
链接到 `Comment`），但可以在配色方案中覆盖。

实现了回退系统，使更具体的组回退到更通用的组。例如，在有单独文档
注释的语言中（如 c、java 等），可以使用 `@comment.documentation`。
如果此组未定义，则使用普通 `@comment` 的高亮。这样，现有配色方案
已经开箱即用，但可以为提供它们的查询添加更具体的变体。

作为附加规则，捕获高亮始终可以通过在额外点后附加语言名来针对特定
语言进行特化。例如，按语言不同方式高亮注释：>vim

    hi @comment.c guifg=Blue
    hi @comment.lua guifg=DarkBlue
    hi link @comment.documentation.java String
<

                                                  *treesitter-highlight-spell*
特殊的 `@spell` 捕获可用于指示节点应由 Nvim 的内置 |spell| 检查器
进行拼写检查。例如，以下捕获将注释标记为需要检查：>query

    (comment) @spell
<

还有 `@nospell` 可以在 `@spell` 区域内禁用拼写检查。

                                                *treesitter-highlight-conceal*
Treesitter 高亮通过 `conceal` 和 `conceal_lines` 元数据支持 |conceal|。
按惯例，要隐藏的节点捕获为 `@conceal`，但可以使用任何捕获。例如，
以下查询可用于隐藏 Markdown 中的代码块分隔符：>query

    ((fenced_code_block_delimiter) @conceal (#set! conceal ""))
<
也可以用单个字符替换节点，该字符（与传统语法不同）可以赋予自定义
高亮。例如，以下（不明智的）查询将 `!=` 运算符替换为 Unicode 字形，
仍然像其他运算符一样高亮：>query

    "!=" @operator (#set! conceal "≠")
<
要隐藏整行（完全不绘制），可以使用带 `conceal_lines` 元数据的查询：
>query

    ((comment) @comment @spell
      (#set! conceal_lines ""))
<
以这种方式指定的隐藏遵循 'conceallevel' 和 'concealcursor'。

注意虽然你可以为 `conceal` 使用任何字符串，但只使用第一个字符：>query

    ; identifiers will be concealed with 'f'.
    ((identifier) @conceal (#set! conceal "foo"))
<

                                               *treesitter-highlight-priority*
Treesitter 使用 |nvim_buf_set_extmark()| 设置高亮，默认优先级为 100。
这使插件可以设置低于或高于 treesitter 的高亮优先级。也可以通过设置
`"priority"` 元数据属性手动更改单个查询模式的优先级：>query

    ((super_important_node) @superimportant (#set! priority 105))
<

                                          *treesitter-highlight-commentstring*
Treesitter 高亮支持更细粒度的 'commentstring'，由内置 |commenting|
插件使用。当光标在设置了 `bo.commentstring` 元数据属性
（|treesitter-directive-set!|）的节点内时，该属性定义注释分隔符
（"最内层优先"）。这对于像 `JSX` 这样根据代码区域有不同注释语法的
语言很有用，例如：>query

    ((jsx_element) @_tag (#set! @_tag bo.commentstring "{/* %s */}"))
<
当多个捕获在一个区域上设置此元数据时，只有最内层（最具体的）应用于
给定区域。

TREESITTER 语言注入                *treesitter-language-injections*

注意以下信息改编自：
https://tree-sitter.github.io/tree-sitter/3-syntax-highlighting.html#language-injection

某些源文件包含用多种不同语言编写的代码。示例包括：

    • HTML 文件，可在 `<script>` 标签内包含 JavaScript，在 `<style>`
      标签内包含 CSS
    • ERB 文件，在 `<%` `%>` 标签内包含 Ruby，在这些标签外包含 HTML
    • PHP 文件，可在 `<php` 标签之间包含 HTML
    • JavaScript 文件，在正则字面量中包含正则表达式语法
    • Ruby，可在 heredoc 字面量中包含代码片段，其中 heredoc 分隔符
      通常指示语言
    • Lua，可在 |vim.cmd()| 调用中包含 Vimscript 片段。
    • Vimscript，可在 |:lua-heredoc| 块中包含 Lua 片段。

所有这些示例都可以用父语法树和一个或多个注入语法树建模，注入语法树
位于父树的某些节点内。语言注入查询允许你使用以下捕获指定这些"注入"：

    • `@injection.content` - 表示捕获的节点应使用另一种语言重新解析其
      内容。如果一个模式中有多个 `@injection.content` 捕获，所有范围
      将被收集并解析为一棵树。这允许查询作者使用注入查询量词创建
      "作用域"注入。
    • `@injection.language` - 表示捕获节点的文本可能包含应用于重新
      解析 `@injection.content` 的语言名称。
    • `@injection.filename` - 表示捕获节点的文本可能包含文件名；通过
      |vim.filetype.match()| 查找对应的文件类型，并将其作为应用于
      重新解析 `@injection.content` 的语言名称。

语言注入行为也可以通过与模式关联的一些属性进行配置：

    • `injection.language` - 可用于硬编码特定语言的名称。
    • `injection.combined` - 表示树中所有匹配节点的内容应作为一个
    嵌套文档解析。
    • `injection.include-children` - 表示 `@injection.content` 节点
    的整个文本应重新解析，包括其子节点的文本。默认情况下，子节点
    的文本将从注入文档中排除。
    • `injection.self` - 表示节点的文本应使用与节点的 LanguageTree
      相同的语言解析。
    • `injection.parent` - 表示捕获节点的文本应使用与节点的父
      LanguageTree 相同的语言解析。

注入查询当前在整个缓冲区上运行，对大缓冲区可能较慢。要禁用特定语言
（如 `c`）的注入，只需在你的 'runtimepath' 中放置一个空的
`queries/c/injections.scm` 文件。

Lua 模块: vim.treesitter.languagetree              *treesitter-languagetree*

*LanguageTree* 包含解析器树：{lang} 的根 treesitter 解析器和任何
"注入"语言解析器，这些解析器本身可能注入其他语言，递归进行。例如，
包含一些 Vimscript 命令的 Lua 缓冲区需要多个解析器才能完全理解其内容。

要为给定缓冲区和语言创建 LanguageTree（解析器对象），使用：>lua
    local parser = vim.treesitter.get_parser(bufnr, lang)
<

（其中 `bufnr=0` 表示当前缓冲区）。`lang` 默认为 'filetype'。注意：
目前解析器在缓冲区的生命周期内保留，但这可能会改变；如果插件需要
增量更新，应保留对解析器对象的引用。

每当需要访问当前语法树时，解析缓冲区：>lua
    local tree = parser:parse({ start_row, end_row })
<

这返回表示缓冲区当前状态的不可变 |treesitter-tree| 对象表。当插件想在
（可能的）编辑后访问状态时，必须再次调用 `parse()`。如果缓冲区未编辑，
将返回相同的树而无额外工作。如果缓冲区之前已解析，将对更改的部分进行
增量解析。

注意：要在 |nvim_buf_attach()| Lua 回调中直接使用解析器，必须在注册
回调之前调用 |vim.treesitter.get_parser()|。但最好不要直接在变更回调
中进行解析，因为它们会非常频繁。执行任何树分析的插件应使用计时器来
限制过于频繁的更新。

    使用对应语言的 |treesitter-parsers| 递归解析语言树中的所有区域，

Query:iter_captures({node}, {source}, {start_row}, {end_row}, {opts})
    迭代 {node} 中所有匹配的所有捕获。

    如果查询包含谓词，{source} 是必需的；调用者必须确保使用与缓冲区
    当前文本一致的新解析树（如果相关）。{start} 和 {stop} 可用于限制
    行范围内的匹配（通常与根节点作为 {node} 一起使用，即获取当前
    视口中的语法高亮匹配）。省略时，使用给定节点的 {start} 和 {stop}
    行值。

    迭代器返回四个值：
    1. 标识捕获的数字 id

    2. 捕获的节点

    3. 来自处理匹配的任何指令的元数据

    4. 匹配本身

    示例：如何按名称获取捕获：>lua
        for id, node, metadata, match in query:iter_captures(tree:root(), bufnr, first, last) do
          local name = query.captures[id] -- name of the capture in the query
          -- typically useful info about the node:
          local type = node:type() -- type of the captured node
          local row1, col1, row2, col2 = node:range() -- range of the capture
          -- ... use the info here ...
        end
<

    注意: ~
      • 仅当特定捕获的查询模式包含谓词时才返回捕获。

    参数: ~
      • {node}       (`TSNode`) 搜索将在其下进行
      • {source}     (`integer|string`) 从中提取文本的源缓冲区或字符串
      • {start_row}  (`integer?`) 搜索的起始行。默认为 `node:start()`。
      • {end_row}    (`integer?`) 搜索的停止行（末尾包含，除非提供
                     `stop_col`）。默认为 `node:end_()`。

Query:iter_matches({node}, {source}, {start}, {stop}, {opts})
    迭代 self 在给定范围上的匹配。

    迭代 {node} 内的所有匹配。参数与 |Query:iter_captures()| 相同，
    但迭代的值不同：查询中模式的（基于 1 的）索引、将捕获索引映射
    到节点列表的表，以及来自处理匹配的任何指令的元数据。

            for _, node in ipairs(nodes) do
              -- `node` was captured by the `name` capture in the match

              local node_data = metadata[id] -- Node level metadata
              -- ... use the info here ...
            end
          end
        end

      • {source}  (`integer|string`) 要搜索的源缓冲区或字符串
      • {start}   (`integer?`) 搜索的起始行。默认为 `node:start()`。
      • {stop}    (`integer?`) 搜索的停止行（末尾不包含）。默认为

      • {opts}    (`table?`) 可选关键字参数：

                  • match_limit (integer) 设置进行中匹配的最大数量

        (`fun(): integer, table<integer, TSNode[]>, vim.treesitter.query.TSMetadata, TSTree`)

set({lang}, {query_name}, {text})                 *vim.treesitter.query.set()*
    为 {lang} 设置名为 {query_name} 的运行时查询

    这允许用户覆盖或扩展插件设置的任何运行时文件和/或配置。

    例如，你可以用以下代码启用 `C` 标识符的拼写检查：>lua
        vim.treesitter.query.set(
          'c',
          'highlights',
          [[;inherits c
          (identifier) @spell]]
        )
<

    参数: ~
      • {lang}        (`string`) 查询使用的语言
      • {query_name}  (`string`) 查询名称（如 "highlights"）
      • {text}        (`string`) 查询文本（未解析的）。
