                            NVIM REFERENCE MANUAL


诊断框架                                     *vim.diagnostic*

Nvim 提供了一个框架，用于显示来自外部工具的错误或警告，也称为"诊断"。
这些诊断可以来自各种来源，如 linter 或 LSP 服务器。诊断框架是对现有
错误处理功能（如 |quickfix| 列表）的扩展。

                                      Type |gO| to see the table of contents.

==============================================================================
快速入门                                              *diagnostic-quickstart*

下文中将报告诊断的任何工具称为"诊断生产者"。诊断生产者只需遵循几个简单步骤
来报告诊断：

1. 创建一个命名空间 |nvim_create_namespace()|。注意命名空间必须有名称。
   匿名命名空间不会工作。
2. （可选）为诊断命名空间配置选项 |vim.diagnostic.config()|。
3. 生成诊断。
4. 为缓冲区设置诊断 |vim.diagnostic.set()|。
5. 从步骤 3 重复。

总体而言，API 分为面向诊断生产者的函数和面向诊断消费者（即想要读取和查看
缓冲区诊断的最终用户）的函数。生产者的 API 需要 {namespace} 作为第一个参数，
而消费者的通常不需要命名空间（尽管通常可以选择性地提供）。一个好的经验法则是，
如果方法旨在修改缓冲区的诊断（如 |vim.diagnostic.set()|），则需要命名空间。

                                *vim.diagnostic.severity* *diagnostic-severity*
诊断中的 "severity" 键是 `vim.diagnostic.severity` 中定义的值之一：>

    vim.diagnostic.severity.ERROR
    vim.diagnostic.severity.WARN
    vim.diagnostic.severity.INFO
    vim.diagnostic.severity.HINT

接受 severity 作为可选参数的函数（如 |vim.diagnostic.get()|）接受三种形式之一：

1. 单个 |vim.diagnostic.severity| 值：>lua

    vim.diagnostic.get(0, { severity = vim.diagnostic.severity.WARN })

2. 带有 "min" 或 "max" 键（或两者都有）的表。此形式允许用户指定严重性
   范围：>lua

    vim.diagnostic.get(0, { severity = { min = vim.diagnostic.severity.WARN } })
3. 列表式表。此形式允许过滤特定严重性：>lua

    vim.diagnostic.get(0, { severity = {
        vim.diagnostic.severity.WARN,
        vim.diagnostic.severity.INFO,
    } })
<

默认值                                              *diagnostic-defaults*

当 Nvim 启动时无条件创建以下诊断键映射：
- `]d` 跳转到缓冲区中的下一个诊断。|]d-default|
- `[d` 跳转到缓冲区中的上一个诊断。|[d-default|
- `]D` 跳转到缓冲区中的最后一个诊断。|]D-default|
- `[D` 跳转到缓冲区中的第一个诊断。|[D-default|
- `<C-w>d` 在浮动窗口中显示光标处的诊断。|CTRL-W_d-default|

处理器                                                *diagnostic-handlers*

诊断通过 |vim.diagnostic.show()| 向用户显示。诊断的显示通过处理器管理。
处理器是一个包含 "show" 和（可选）"hide" 函数的表。"show" 函数的签名为
>
    function(namespace, bufnr, diagnostics, opts)
<
负责显示或以其他方式处理给定的诊断。"hide" 函数负责"清理" "show" 函数
执行的任何操作，签名为
>
    function(namespace, bufnr)
<
处理器可以通过 |vim.diagnostic.config()| 配置，通过在 `vim.diagnostic.handlers`
中创建新键来添加（参见 |diagnostic-handlers-example|）。

传递给处理器的 {opts} 表是完整的配置选项集（即不限于处理器本身的选项）。
表中的值已经被解析（即如果用户为配置选项指定了函数，该函数已被求值）。

如果诊断处理器配置了 "severity" 键，则传递给该处理器的诊断列表将使用该键的
值进行过滤（参见下面的示例）。

Nvim 默认提供这些处理器："virtual_text"、"virtual_lines"、"signs" 和
"underline"。

                                                *diagnostic-handlers-example*
下面的示例创建了一个新的处理器，使用 |vim.notify()| 通知用户诊断信息：>lua

    -- It's good practice to namespace custom handlers to avoid collisions
    vim.diagnostic.handlers["my/notify"] = {
      show = function(namespace, bufnr, diagnostics, opts)
        -- In our example, the opts table has a "log_level" option
        local level = opts["my/notify"].log_level

        local name = vim.diagnostic.get_namespace(namespace).name
        local msg = string.format("%d diagnostics in buffer %d from %s",
                                  #diagnostics,
                                  bufnr,
                                  name)
        vim.notify(msg, level)
      end,
    }

    -- Users can configure the handler
    vim.diagnostic.config({
      ["my/notify"] = {
        log_level = vim.log.levels.INFO,

        -- This handler will only receive "error" diagnostics.
        severity = vim.diagnostic.severity.ERROR,
      }
    })
<
在此示例中，隐藏诊断时无需执行任何操作，因此我们省略了 "hide" 函数。

可以覆盖现有处理器。例如，使用以下代码仅为给定行上严重性最高的诊断
显示标记：>lua

    -- Create a custom namespace. This will aggregate signs from all other
    -- namespaces and only show the one with the highest severity on a
    -- given line
    local ns = vim.api.nvim_create_namespace("my_namespace")

    -- Get a reference to the original signs handler
    local orig_signs_handler = vim.diagnostic.handlers.signs

    -- Override the built-in signs handler
    vim.diagnostic.handlers.signs = {
      show = function(_, bufnr, _, opts)
        -- Get all diagnostics from the whole buffer rather than just the
        -- diagnostics passed to the handler
        local diagnostics = vim.diagnostic.get(bufnr)

        -- Find the "worst" diagnostic per line
        local max_severity_per_line = {}
        for _, d in pairs(diagnostics) do
          local m = max_severity_per_line[d.lnum]
          if not m or d.severity < m.severity then
            max_severity_per_line[d.lnum] = d
          end
        end

        -- Pass the filtered diagnostics (with our custom namespace) to
        -- the original handler
        local filtered_diagnostics = vim.tbl_values(max_severity_per_line)
        orig_signs_handler.show(ns, bufnr, filtered_diagnostics, opts)
      end,
      hide = function(_, bufnr)
        orig_signs_handler.hide(ns, bufnr)
      end,
    }
<

                                          *diagnostic-toggle-virtual-lines-example*
诊断处理器也可以切换。例如，你可能想通过以下键映射切换 `virtual_lines`
处理器：>lua

    vim.keymap.set('n', 'gK', function()
      local new_config = not vim.diagnostic.config().virtual_lines
      vim.diagnostic.config({ virtual_lines = new_config })
    end, { desc = 'Toggle diagnostic virtual_lines' })
<

                                            *diagnostic-on-jump-example*
你可以使用 |vim.diagnostic.jump()| 的 `on_jump` 选项来使用特定处理器显示
跳转到的诊断。例如，以下代码在跳转到诊断时使用 `virtual_lines` 处理器：>lua

  --- @param diagnostic? vim.Diagnostic
  --- @param bufnr integer
  local function on_jump(diagnostic, bufnr)
    if not diagnostic then return end

    vim.diagnostic.show(
      diagnostic.namespace,
      bufnr,
      { diagnostic },
      { virtual_lines = { current_line = true }, virtual_text = false }
    )
  end

  vim.diagnostic.config({ jump = { on_jump = on_jump } })
<
                                          *diagnostic-loclist-example*
每当打开 |location-list| 时，以下 `show` 处理器将显示最新的诊断：>lua

  vim.diagnostic.handlers.loclist = {
    show = function(_, _, _, opts)
      -- Generally don't want it to open on every update
      opts.loclist.open = opts.loclist.open or false
      local winid = vim.api.nvim_get_current_win()
      vim.diagnostic.setloclist(opts.loclist)
      vim.api.nvim_set_current_win(winid)
    end
  }
<

该处理器接受与 |vim.diagnostic.setloclist()| 相同的选项，可以通过
|vim.diagnostic.config()| 配置：>lua

  -- Open the location list on every diagnostic change (warnings/errors only).
  vim.diagnostic.config({
    loclist = {
      open = true,
      severity = { min = vim.diagnostic.severity.WARN },
    }
  })
<

高亮                                              *diagnostic-highlights*

所有为诊断定义的高亮以 `Diagnostic` 开头，后跟高亮类型（如 `Sign`、
`Underline` 等）和严重性（如 `Error`、`Warn` 等）。

默认情况下，标记、浮动窗口和虚拟文本的高亮链接到对应的默认高亮。
下划线高亮不链接，使用自己的默认高亮组。

例如，|hl-DiagnosticSignError| 的默认高亮链接到 |hl-DiagnosticError|。
要更改默认值（从而更改链接的高亮），使用 |:highlight| 命令：>vim

    highlight DiagnosticError guifg="BrightRed"

标记                                                   *diagnostic-signs*

为每个诊断严重性定义了标记。每个标记的默认文本是严重性名称的首字母
（例如，ERROR 为 "E"）。标记可以通过 |vim.diagnostic.config()| 自定义。
示例：>lua

    -- Highlight entire line for errors
    -- Highlight the line number for warnings
    vim.diagnostic.config({
        signs = {
            text = {
                [vim.diagnostic.severity.ERROR] = '',
                [vim.diagnostic.severity.WARN] = '',
            },
            linehl = {
                [vim.diagnostic.severity.ERROR] = 'ErrorMsg',
            },
            numhl = {
                [vim.diagnostic.severity.WARN] = 'WarningMsg',
            },
        },
    })

当设置了 "severity_sort" 选项时（参见 |vim.diagnostic.config()|），每个
标记的优先级取决于相关诊断的严重性。否则，所有标记具有相同的优先级
（|vim.diagnostic.config()| 中 "signs" 表的 "priority" 选项值，未设置时
为 10）。

                                                        *DiagnosticChanged*
DiagnosticChanged       诊断更改后触发。从 Lua 使用时，新的诊断通过
                        自动命令回调的 "data" 表传递。按缓冲区触发。

示例：>lua

    vim.api.nvim_create_autocmd('DiagnosticChanged', {
      callback = function(ev)
        local diagnostics = ev.data.diagnostics
        vim.print(diagnostics)
      end,
    })

*vim.Diagnostic*
    继承: |vim.Diagnostic.Set|

                                                        *diagnostic-structure*

    诊断使用与 Nvim API 其余部分相同的索引（即基于 0 的行和列）。
    |api-indexing|

    字段: ~
      • {bufnr}       (`integer`) 缓冲区编号
      • {end_lnum}    (`integer`) 诊断的结束行（基于 0 索引）
      • {col}         (`integer`) 诊断的起始列（基于 0 索引）
      • {end_col}     (`integer`) 诊断的结束列（基于 0 索引）
      • {severity}    (`vim.diagnostic.Severity`) 诊断的严重性
                      |vim.diagnostic.severity|
      • {namespace}?  (`integer`)

*vim.Diagnostic.Set*
    诊断使用与 Nvim API 其余部分相同的索引（即基于 0 的行和列）。
    |api-indexing|

    字段: ~
      • {lnum}        (`integer`) 诊断的起始行（基于 0 索引）
      • {col}?        (`integer`, 默认: `0`) 诊断的起始列
                      （基于 0 索引）
      • {end_lnum}?   (`integer`, 默认: `lnum`) 诊断的结束行
                      （基于 0 索引）
      • {end_col}?    (`integer`, 默认: `col`) 诊断的结束列
                      （基于 0 索引）
      • {severity}?   (`vim.diagnostic.Severity`, 默认: `vim.diagnostic.severity.ERROR`)
                      诊断的严重性 |vim.diagnostic.severity|
      • {message}     (`string`) 诊断文本
      • {source}?     (`string`) 诊断来源
      • {code}?       (`string|integer`) 诊断代码
      • {user_data}?  (`any`) 插件可添加的任意数据

*vim.diagnostic.GetOpts*
    包含以下键的表:

    字段: ~
      • {namespace}?  (`integer[]|integer`) 限制诊断到一个或多个命名空间。
      • {lnum}?       (`integer`) 限制诊断到跨越指定行号的诊断。
      • {severity}?   (`vim.diagnostic.SeverityFilter`) 参见
                      |diagnostic-severity|。
      • {enabled}?    (`boolean`, 默认: `nil`) 限制诊断到仅启用或禁用的。
                      如果为 nil，忽略启用状态。参见
                      |vim.diagnostic.enable()|

*vim.diagnostic.JumpOpts*
    继承: |vim.diagnostic.GetOpts|

    包含以下键的配置表。某些参数可以通过 |vim.diagnostic.config()| 更改
    默认值。

    字段: ~
      • {diagnostic}?  (`vim.Diagnostic`) 要跳转到的诊断。与 {count}、
                       {namespace} 和 {severity} 互斥。
                       参见 |vim.Diagnostic|。
      • {count}?       (`integer`) 从 {pos} 开始移动的诊断数量。正整数
                       向前移动 {count} 个诊断，负整数向后移动 {count}
                       个诊断。与 {diagnostic} 互斥。
      • {pos}?         (`[integer,integer]`) 光标位置，为 `(row, col)` 元组。
                       参见 |nvim_win_get_cursor()|。在使用 {count} 时用于
                       查找最近的诊断。仅在 {count} 非 nil 时使用。默认为
                       当前光标位置。
      • {wrap}?        (`boolean`, 默认: `true`) 是否在文件中循环。类似于
                       'wrapscan'。
      • {severity}?    (`vim.diagnostic.SeverityFilter`) 参见
                       |diagnostic-severity|。
      • {on_jump}?     (`fun(diagnostic:vim.Diagnostic?, bufnr:integer)`)
                       跳转到诊断时调用的可选回调。
      • {winid}?       (`integer`, 默认: `0`) 窗口 ID

*vim.diagnostic.NS*

    字段: ~
      • {name}       (`string`)
      • {opts}       (`vim.diagnostic.Opts`) 参见 |vim.diagnostic.Opts|。
      • {user_data}  (`table`)
      • {disabled}?  (`boolean`)

*vim.diagnostic.Opts*
    下面的许多配置选项接受以下之一：
    • `false`：禁用此功能
    • `true`：启用此功能，使用默认设置。
    • `table`：启用此功能并覆盖设置。使用空表可使用默认值。
    • `function`：签名为 (namespace, bufnr) 的函数，返回上述任意值。

    字段: ~
      • {underline}?         (`boolean|vim.diagnostic.Opts.Underline|fun(namespace: integer, bufnr:integer): vim.diagnostic.Opts.Underline`, 默认: `true`)
                             为诊断使用下划线。
      • {virtual_text}?      (`boolean|vim.diagnostic.Opts.VirtualText|fun(namespace: integer, bufnr:integer): vim.diagnostic.Opts.VirtualText`, 默认: `false`)
                             为诊断使用虚拟文本。如果为一个命名空间设置了
                             多个诊断，则显示每个诊断的一个前缀加上最后
                             一个诊断的消息。
      • {virtual_lines}?     (`boolean|vim.diagnostic.Opts.VirtualLines|fun(namespace: integer, bufnr:integer): vim.diagnostic.Opts.VirtualLines`, 默认: `false`)
                             为诊断使用虚拟行。
      • {signs}?             (`boolean|vim.diagnostic.Opts.Signs|fun(namespace: integer, bufnr:integer): vim.diagnostic.Opts.Signs`, 默认: `true`)
                             为诊断使用标记 |diagnostic-signs|。
      • {float}?             (`boolean|vim.diagnostic.Opts.Float|fun(namespace?: integer|integer[], bufnr:integer): vim.diagnostic.Opts.Float`)
                             浮动窗口选项。参见
                             |vim.diagnostic.Opts.Float|。
      • {status}?            (`vim.diagnostic.Opts.Status`) 状态栏组件选项。
                             参见 |vim.diagnostic.Opts.Status|。
      • {update_in_insert}?  (`boolean`, 默认: `false`) 在插入模式中更新
                             诊断（如果为 `false`，诊断在 |InsertLeave|
                             时更新）
      • {severity_sort}?     (`boolean|{reverse?:boolean}`, 默认: `false`)
                             按严重性排序诊断。这影响标记、虚拟文本和
                             高亮的显示顺序。当为 true 时，较高严重性
                             显示在较低严重性之前（例如 ERROR 显示在
                             WARN 之前）。选项：
                             • {reverse}? (boolean) 反转排序顺序
      • {jump}?              (`vim.diagnostic.Opts.Jump`)
                             |vim.diagnostic.jump()| 的默认值。参见
                             |vim.diagnostic.Opts.Jump|。

*vim.diagnostic.Opts.Float*
    继承: |vim.lsp.util.open_floating_preview.Opts|


    字段: ~
      • {bufnr}?          (`integer`, 默认: 当前缓冲区) 显示诊断的
                          缓冲区编号。
      • {namespace}?      (`integer|integer[]`) 限制诊断到给定的命名空间。
      • {scope}?          (`'line'|'buffer'|'cursor'|'c'|'l'|'b'`, 默认:
                          `line`) 显示整个缓冲区（`buffer`）、当前光标行
                          （`line`）或当前光标位置（`cursor`）的诊断。
                          也接受简写版本（`c` 代表 `cursor`，`l` 代表
                          `line`，`b` 代表 `buffer`）。
      • {pos}?            (`integer|[integer,integer]`) 如果 {scope} 为
                          "line" 或 "cursor"，使用此位置而非光标位置。
                          如果是数字，解释为行号；否则为 (row, col) 元组。
      • {severity_sort}?  (`boolean|{reverse?:boolean}`, 默认: `false`)
                          按严重性排序诊断。覆盖 |vim.diagnostic.config()|
                          中的设置。
      • {severity}?       (`vim.diagnostic.SeverityFilter`) 参见
                          |diagnostic-severity|。覆盖 |vim.diagnostic.config()|
                          中的设置。
      • {header}?         (`string|[string,any]`) 用作浮动窗口标题的字符串。
                          如果是表，解释为 `[text, hl_group]` 元组。覆盖
                          |vim.diagnostic.config()| 中的设置。
      • {source}?         (`boolean|'if_many'`) 在消息中包含诊断来源。
                          使用 "if_many" 仅在缓冲区中有多个诊断来源时
                          显示来源。否则，任何真值表示始终显示诊断来源。
                          覆盖 |vim.diagnostic.config()| 中的设置。
      • {format}?         (`fun(diagnostic:vim.Diagnostic): string?`) 接受
                          诊断作为输入并返回字符串或 nil 的函数。如果
                          返回值为 nil，处理器不显示该诊断。否则输出文本
                          用于显示诊断。覆盖 |vim.diagnostic.config()|
                          中的设置。
      • {prefix}?         (`string|table|(fun(diagnostic:vim.Diagnostic,i:integer,total:integer): string, string)`)
                          在浮动窗口中为每个诊断添加前缀：
                          • 如果是 `function`，{i} 是正在求值的诊断的
                            索引，{total} 是窗口中显示的诊断总数。函数
                            应返回一个 `string`，作为窗口中每个诊断的
                            前缀，以及一个（可选的）高亮组用于高亮前缀。
                          • 如果是 `table`，解释为 |nvim_echo()| 中的
                            `[text, hl_group]` 元组
                          • 如果是 `string`，作为每个诊断的前缀，无高亮。
                            覆盖 |vim.diagnostic.config()| 中的设置。
      • {suffix}?         (`string|table|(fun(diagnostic:vim.Diagnostic,i:integer,total:integer): string, string)`)
                          与 {prefix} 相同，但将文本追加到诊断而非前置。
                          覆盖 |vim.diagnostic.config()| 中的设置。

*vim.diagnostic.Opts.Status*

    字段: ~
      • {format}?  (`table<vim.diagnostic.Severity,string>|(fun(counts:table<vim.diagnostic.Severity,integer>): string)`)
                   可以是：
                   • 将 |diagnostic-severity| 映射到每个现有严重性部分
                     使用的文本的表。
                   • 接受 |diagnostic-severity| 到对应严重性的诊断数量
                     （仅那些至少有 1 个诊断的严重性级别）映射的函数，
                     返回 'statusline' 组件。在这种情况下，高亮必须由
                     用户在 `format` 函数中应用。示例：>lua
                     local signs = {
                     [vim.diagnostic.severity.ERROR] = "A",
                     -- ...
                   }
                   local hl_map = {
                     [vim.diagnostic.severity.ERROR] = 'DiagnosticSignError',
                     -- ...
                   }
                   vim.diagnostic.config({
                     status = {
                       format = function(counts)
                         local items = {}
                         for level, _ in ipairs(vim.diagnostic.severity) do
                           local count = counts[level] or 0
                           table.insert(items, ("%%#%s#%s %s"):format(hl_map[level], signs[level], count))
                         end
                         return table.concat(items, " ")
                       end
                     }
                   })
<

config({opts}, {namespace})                          *vim.diagnostic.config()*
    全局或为特定诊断命名空间配置诊断选项。

    配置可以全局指定、按命名空间指定或临时指定（即仅对单次
    |vim.diagnostic.set()| 或 |vim.diagnostic.show()| 调用有效）。
    临时配置优先级最高，其次是命名空间配置，最后是全局配置。

    例如，如果用户全局启用虚拟文本 >lua

<

    则虚拟文本不会为那些诊断启用。

    参数: ~

                     配置。否则为配置表（参见 |vim.diagnostic.Opts|）。
      • {namespace}  (`integer?`) 更新给定命名空间的选项。省略时，更新
                     全局诊断选项。

    返回: ~
        (`vim.diagnostic.Opts?`) 如果省略 {opts} 则返回当前诊断配置。
        参见 |vim.diagnostic.Opts|。

match({str}, {pat}, {groups}, {severity_map}, {defaults})
    从字符串中解析诊断。

    例如，考虑来自 linter 的一行输出：>
        WARNING filename:27:3: Variable 'foo' does not exist
<

    可以通过以下方式解析为 |vim.Diagnostic| 结构：>lua
        local s = "WARNING filename:27:3: Variable 'foo' does not exist"
        local pattern = "^(%w+) %w+:(%d+):(%d+): (.+)$"
        local groups = { "severity", "lnum", "col", "message" }
        vim.diagnostic.match(s, pattern, groups, { WARNING = vim.diagnostic.WARN })
<

    参数: ~
      • {str}           (`string`) 要从中解析诊断的字符串。
      • {pat}           (`string`) 带有捕获组的 Lua 模式。
      • {groups}        (`string[]`) |vim.Diagnostic| 结构中要与 {pat}
                        的捕获关联的字段列表。
      • {severity_map}  (`table`) 将 {groups} 中的 severity 字段映射到
                        |vim.diagnostic.severity| 中项目的表。
      • {defaults}      (`table?`) {groups} 中未列出的字段的默认值表。
                        省略时，数值默认为 0，"severity" 默认为 ERROR。

    返回: ~
        (`vim.Diagnostic?`) |vim.Diagnostic| 结构，如果 {pat} 未匹配
        {str} 则为 `nil`。
