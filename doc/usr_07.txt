				  编辑多个文件


无论你有多少文件，你都可以不离开 Vim 来编辑它们。定义一个文件列表来逐个处理，
在它们之间跳转。从一个文件复制文本并放到另一个文件中。

*07.1*	编辑另一个文件

到目前为止，你每次要编辑一个文件都必须启动 Vim。有一个更简单的方法。要开始
编辑另一个文件，使用这个命令: >

	:edit foo.txt

你可以使用任何文件名代替 "foo.txt"。Vim 会关闭当前文件并打开新的文件。但是
如果当前文件有未保存的更改，Vim 会显示错误信息而不打开新文件:

	E37: No write since last change (use ! to override) ~

	注意:
	Vim 在每个错误信息的开头放一个错误 ID。如果你不理解该信息或其原因，
	可以在帮助系统中查找这个 ID。在这种情况下: >

		:help E37

此时你有几个选择。你可以用这个命令保存文件: >

	:write

或者你可以强制 Vim 放弃更改并编辑新文件，使用强制（!）字符: >

	:edit! foo.txt

如果你想编辑另一个文件，但还不想保存当前文件中的更改，你可以将它隐藏: >

	:hide edit foo.txt

带有更改的文本仍然在那里，但你看不到它。这在 |22.4| 节中有更详细的解释:
缓冲区列表。

*07.2*	文件列表

你可以启动 Vim 来编辑一系列文件。例如: >

	vim one.c two.c three.c

这个命令启动 Vim 并告诉它你要编辑三个文件。Vim 只显示第一个文件。在你完成
这个文件后，要编辑下一个文件使用这个命令: >

	:next

如果你在当前文件中有未保存的更改，你会收到错误信息，":next" 不会工作。这与
上一节中提到的 ":edit" 的问题相同。要放弃更改: >

	:next!

但大多数时候你想保存更改并继续编辑下一个文件。有一个专门的命令: >

	:wnext

这等同于使用两个单独的命令: >

	:write
	:next


我在哪里？

要查看你正在编辑参数列表中的哪个文件，看窗口标题。它应该显示类似 "(2 of 3)"
的内容。这意味着你正在编辑三个文件中的第二个。
   如果你想看到文件列表，使用这个命令: >

	:args

这是 "arguments" 的缩写。输出可能看起来像这样:

	one.c [two.c] three.c ~

这些是你启动 Vim 时指定的文件。你当前正在编辑的 "two.c" 在方括号中。


移动到其他参数

要回到上一个文件: >

	:previous

这与 ":next" 命令一样，只是移动方向相反。同样，有一个在保存文件后移动的快捷
命令: >

	:wprevious

要移到列表中的最后一个文件: >

	:last

要回到第一个: >

	:first

不过没有 ":wlast" 或 ":wfirst" 命令！

你可以对 ":next" 和 ":previous" 使用计数。要向前跳过两个文件: >

	:2next


自动保存

当在文件之间移动并进行更改时，你必须记住使用 ":write"。否则你会收到错误信息。
如果你确定总是想保存已修改的文件，你可以告诉 Vim 自动保存它们: >

	:set autowrite

当你编辑一个你可能不想保存的文件时，再次关闭它: >

	:set noautowrite


编辑另一个文件列表

你可以重新定义文件列表而不需要退出 Vim 再重新启动。使用这个命令编辑另外三个
文件: >

	:args five.c six.c seven.h

或者使用通配符，就像在 shell 中一样: >

	:args *.txt

Vim 会带你到列表中的第一个文件。同样，如果当前文件有更改，你可以先保存文件，
或者使用 ":args!"（加上 !）来放弃更改。


你编辑了最后一个文件吗？
							*arglist-quit*
当你使用文件列表时，Vim 假设你想编辑所有文件。为了保护你不要太早退出，如果
你还没有编辑列表中的最后一个文件，你会收到这个错误:

	E173: 46 more files to edit ~

如果你真的想退出，再做一次就行了。这次可以退出（但不要在中间执行其他命令）。

*07.3*	在文件间跳转

要在两个文件之间快速跳转，按 CTRL-^（在英语 US 键盘上 ^ 在 6 键上方）。
例如: >

	:args one.c two.c three.c

你现在在 one.c 中。 >

	:next

现在你在 two.c 中。使用 CTRL-^ 回到 one.c。再按一次 CTRL-^ 你又回到
two.c。再按一次 CTRL-^ 你又在 one.c 中。如果你现在执行: >

	:next

你在 three.c 中。注意 CTRL-^ 命令不会改变你在文件列表中位置的概念。只有像
":next" 和 ":previous" 这样的命令才会。

你之前编辑的文件称为 "轮换" 文件。当你刚启动 Vim 时 CTRL-^ 不会工作，因为
还没有前一个文件。


预定义标记

跳到另一个文件后，你可以使用两个非常有用的预定义标记: >

	`"

这会带你到离开文件时光标所在的位置。另一个被记住的标记是你最后做修改的位置:
>
	`.

假设你正在编辑文件 "one.txt"。在文件中间的某处你用 "x" 删除了一个字符。然后
你用 "G" 到最后一行并用 ":w" 保存文件。你编辑了几个其他文件，然后使用
":edit one.txt" 回到 "one.txt"。如果你现在使用 `"，Vim 会跳到文件的最后一行。
使用 `. 则带你到你删除字符的位置。即使你在文件中移动，`" 和 `. 也会带你到
记住的位置。至少在你做另一个修改或离开文件之前。


文件标记

在 |03.10| 节中解释了你可以用 "mx" 在文件中放置标记并用 "`x" 跳到那个位置。
这在一个文件内有效。如果你编辑另一个文件并在那里放置标记，这些标记是特定于
那个文件的。因此每个文件都有自己的一组标记，它们是文件局部的。
   到目前为止我们使用的是小写字母的标记。还有大写字母的标记。这些是全局的，
可以从任何文件中使用。例如，假设我们正在编辑文件 "foo.txt"。移到文件中间
（"50%"）并在那里放置 F 标记（F 代表 foo）: >

	50%mF

现在编辑文件 "bar.txt" 并在最后一行放置 B 标记（B 代表 bar）:
>
	GmB

现在你可以使用 "'F" 命令跳回 foo.txt 的中间位置。或者编辑另一个文件，输入
"'B" 你就跳到 bar.txt 的末尾。

文件标记在被放到其他地方之前会一直被记住。因此你可以放置标记，编辑几个小时，
仍然能跳回到那个标记。
   想出标记字母和它被放置位置之间的简单联系通常很有用。例如，在头文件中使用
H 标记，在 Makefile 中使用 M，在 C 代码文件中使用 C。

要查看某个特定标记在哪里，给 ":marks" 命令一个参数: >

	:marks M

你也可以给多个参数: >

	:marks MCP

不要忘记你可以使用 CTRL-O 和 CTRL-I 跳到更早和更新的位置，而不需要在那里
放置标记。

*07.4*	备份文件

通常 Vim 不生成备份文件。如果你想要一个，你只需要执行以下命令: >

	:set backup

备份文件的名称是原始文件名加上 ~ 。如果你的文件名为 data.txt，则备份文件名
为 data.txt~。
   如果你不喜欢备份文件以 ~ 结尾，你可以更改扩展名: >

	:set backupext=.bak

这将使用 data.txt.bak 代替 data.txt~。
   另一个相关的选项是 'backupdir'。它指定备份文件写在哪里。默认情况下，将备份
写在与原文件相同的目录中，这通常是正确的做法。

	注意:
	当 'backup' 选项未设置但 'writebackup' 已设置时，Vim 仍然会创建备份
	文件。但是，一旦文件成功写入就会被删除。这是一个安全措施，防止在写入
	失败时丢失原文件（磁盘满是最常见的原因; 被闪电击中可能是另一个，
	虽然不太常见）。


保留原始文件

如果你在编辑源文件，你可能想在做任何更改之前保留原来的文件。但每次你写入文件
时备份文件都会被覆盖。因此它只包含上一个版本，而不是第一个。
   要使 Vim 保留原始文件，设置 'patchmode' 选项。这指定用于第一次备份已更改
文件的扩展名。通常你会这样做: >

	:set patchmode=.orig

当你第一次编辑文件 data.txt 并做了更改然后写入文件时，Vim 会将未更改的文件
副本保留在 "data.txt.orig" 下。
   如果你对文件做了更多更改，Vim 会注意到 "data.txt.orig" 已经存在并保持不动。
后续的备份文件将被命名为 "data.txt~"（或你用 'backupext' 指定的名称）。
   如果你将 'patchmode' 留空（这是默认的），原始文件不会被保留。

*07.5*	在文件间复制文本

这解释了如何从一个文件复制文本到另一个文件。让我们从一个简单的例子开始。编辑
包含你想复制的文本的文件。将光标移到文本的开头并按 "v"。这启动可视模式。
现在将光标移到文本的末尾并按 "y"。这复制（yank）了选中的文本。
   要复制上面的段落，你可以这样做: >

	:edit thisfile
	/This
	vjjjj$y

现在编辑你想放入文本的文件。将光标移到你想让文本出现在其后的字符处。使用
"p" 将文本放在那里。 >
	:edit otherfile
	/There
	p

当然你可以使用很多其他命令来复制文本。例如，用 "V" 启动可视模式来选择整行。
或者使用 CTRL-V 来选择矩形块。或者使用 "yy" 复制单行，"yaw" 来复制一个单词
等等。
   "p" 命令将文本放在光标之后。使用 "P" 将文本放在光标之前。注意 Vim 记住了
你是复制了整行还是一个块，并以同样的方式放回。


使用寄存器

当你想从一个文件复制多段文本到另一个文件时，在文件之间切换并保存目标文件会
花很多时间。为了避免这种情况，将每段文本复制到自己的寄存器中。
   寄存器是 Vim 存储文本的地方。这里我们使用名为 a 到 z 的寄存器（稍后你会
发现还有其他的）。让我们将一个句子复制到 f 寄存器（f 代表 First，第一个）: >

	"fyas

"yas" 命令像以前一样复制一个句子。是 "f 告诉 Vim 文本应该被放到 f 寄存器中。
这必须紧接在复制命令之前。
   现在复制三个完整行到 l 寄存器（l 代表 line，行）: >

	"l3yy

计数也可以放在 "l 之前。要将一个文本块复制到 b（代表 block，块）寄存器: >

	CTRL-Vjjww"by

注意寄存器指定 "b 就在 "y" 命令之前。这是必须的。如果你把它放在 "w" 命令
之前，就不会工作。
   现在你有三段文本在 f、l 和 b 寄存器中。编辑另一个文件，移动到你想放文本
的位置: >

	"fp

同样，寄存器指定 "f 在 "p" 命令之前。
   你可以按任意顺序粘贴寄存器。而且文本会留在寄存器中直到你将其他内容复制
进去。因此你可以粘贴任意多次。

当你删除文本时，你也可以指定一个寄存器。用这个来移动多段文本。例如，要删除
一个单词并写入 w 寄存器: >

	"wdaw

同样，寄存器指定在删除命令 "d" 之前。


追加到文件

当收集文本行到一个文件中时，你可以使用这个命令: >

	:write >> logfile

这会将当前文件的文本写到 "logfile" 的末尾。因此它是追加的。这避免了你必须
复制行、编辑日志文件然后把它们放在那里。因此你节省了两个步骤。但你只能追加到
文件末尾。
   要只追加几行，在输入 ":write" 之前用可视模式选择它们。在第 10 章你会学到
选择行范围的其他方法。

*07.6*	查看文件

有时你只想看看文件包含什么内容，而无意写回它。有这样的风险: 你不小心输入了
":w" 并覆盖了原文件。为避免这种情况，以只读模式编辑文件。
   要以只读模式启动 Vim，使用这个命令: >

	vim -R file

在 Unix 上这个命令应该做同样的事: >

	view file

你现在正在以只读模式编辑 "file"。当你尝试使用 ":w" 时你会收到错误信息，
文件不会被写入。
   当你尝试修改文件时 Vim 会给你一个警告:

	W10: Warning: Changing a readonly file ~

不过修改仍然会执行。这允许你格式化文件，例如使其更容易阅读。
   如果你做了更改并忘记了文件是只读的，你仍然可以保存它。在写命令后加上 !
来强制写入。

如果你真的想禁止对文件做任何更改，这样做: >

	vim -M file

现在每次尝试修改文本都会失败。例如帮助文件就是这样的。如果你尝试做修改你会
收到这个错误信息:

	E21: Cannot make changes, 'modifiable' is off ~

你可以使用 -M 参数来设置 Vim 以查看器模式工作。不过这只是自愿的，因为这些
命令会移除保护: >

	:set modifiable
	:set write

*07.7*	更改文件名

一个聪明的方法来开始编辑一个新文件是使用一个包含你所需大部分内容的现有文件。
例如，你开始写一个移动文件的新程序。你知道你已经有一个复制文件的程序，因此
你开始: >

	:edit copy.c

你可以删除不需要的内容。现在你需要用新名称保存文件。":saveas" 命令可以用于
此: >

	:saveas move.c

Vim 会用给定的名称写入文件，并编辑该文件。因此下次你执行 ":write" 时，它会
写入 "move.c"。"copy.c" 保持不变。
   当你想更改正在编辑的文件的名称但不想写入文件时，你可以使用这个命令: >

	:file move.c

Vim 会将文件标记为 "未编辑"。这意味着 Vim 知道这不是你开始编辑的那个文件。
当你尝试写入文件时，你可能会收到这个消息:

	E13: File exists (use ! to override) ~

这保护你不会意外覆盖另一个文件。
