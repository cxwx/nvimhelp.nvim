				编辑带格式的文本


文本很少是每行一个句子的。本章介绍如何断行以使文本适合页面宽度，以及其他格式化
功能。Vim 还有编辑单行段落和表格的实用功能。

*25.1*	断行

Vim 有许多使处理文本更容易的功能。默认情况下，编辑器不执行自动换行。换句话说，
你需要自己按 <Enter>。这在编写程序时很有用，因为你想自己决定行在哪里结束。但当
你编写文档并希望文本宽度最多为 70 个字符时就不那么好了。
   如果你设置 'textwidth' 选项，Vim 会自动插入换行符。例如，假设你想要一个只有
30 个字符宽的非常窄的列。你需要执行以下命令: >

	:set textwidth=30

现在你开始输入（已添加标尺）: >

		 1	   2	     3
	12345678901234567890123456789012345
	I taught programming for a whi

如果你接下来输入 "l"，这使得行超过了 30 字符的限制。当 Vim 看到这种情况时，它会
插入一个换行符，你得到: >

		 1	   2	     3
	12345678901234567890123456789012345
	I taught programming for a
	whil

继续输入，你可以输入段落的其余部分: >

		 1	   2	     3
	12345678901234567890123456789012345
	I taught programming for a
	while. One time, I was stopped
	by the Fort Worth police,
	because my homework was too
	hard. True story.

你不需要输入换行符；Vim 会自动添加。

	备注:
	'wrap' 选项让 Vim 显示时对行进行换行，但这并不会在文件中插入
	换行符。


重新格式化

Vim 编辑器不是文字处理器。在文字处理器中，如果你在段落开头删除了某些内容，换行
符会被重新调整。在 Vim 中不会；所以如果你从第一行中删除了 "programming" 这个
词，你得到的只是一个短行: >

		 1	   2	     3
	12345678901234567890123456789012345
	I taught for a
	while. One time, I was stopped
	by the Fort Worth police,
	because my homework was too
	hard. True story.

这看起来不太好。要让段落恢复整齐，你可以使用 "gq" 操作符。
   让我们先用可视模式来演示。从第一行开始，输入: >

	v4jgq

"v" 开始可视模式，"4j" 移动到段落末尾，然后是 "gq" 操作符。结果是: >

		 1	   2	     3
	12345678901234567890123456789012345
	I taught for a while. One
	time, I was stopped by the
	Fort Worth police, because my
	homework was too hard. True
	story.

备注: 有一种方法可以对特定类型的文本布局进行自动格式化，参见 |auto-format|。

由于 "gq" 是一个操作符，你可以使用三种方式之一来选择它作用的文本: 可视模式、移
动命令和文本对象。
   上面的例子也可以用 "gq4j" 来完成。输入更少，但你需要知道行数。一个更有用的
移动命令是 "}"。它移到段落的末尾。因此 "gq}" 将从光标到当前段落末尾进行格式
化。
   一个非常有用的与 "gq" 配合使用的文本对象是段落。试试: >

	gqap

"ap" 代表 "a-paragraph"（一个段落）。这会格式化一个段落的文本（由空行分隔）。
也包括光标之前的部分。
   如果你的段落由空行分隔，你可以这样格式化整个文件: >

	gggqG

"gg" 移到第一行，"gqG" 格式化到最后一行。
   警告: 如果你的段落没有正确分隔，它们会被合并在一起。一个常见的错误是有一行包
含空格或制表符。那是一个空白行，但不是空行。

Vim 能格式化的不仅仅是纯文本。参见 |fo-table| 了解如何改变格式化行为。参见
'joinspaces' 选项了解如何改变句号后使用的空格数。
   可以使用外部程序进行格式化。当 Vim 的内置命令无法正确格式化你的文本时，这很
有用。参见 'formatprg' 选项。

*25.2*	对齐文本

要将一系列行居中对齐，使用以下命令: >

	:{range}center [width]

{range} 是通常的命令行范围。[width] 是用于居中的可选行宽。如果未指定 [width]，
默认使用 'textwidth' 的值。（如果 'textwidth' 为 0，默认为 80。）
   例如: >

	:1,5center 40

结果如下: >

       I taught for a while. One
       time, I was stopped by the
     Fort Worth police, because my
      homework was too hard. True
		 story.


右对齐

类似地，":right" 命令将文本右对齐: >

	:1,5right 37

结果如下: >

	    I taught for a while. One
	   time, I was stopped by the
	Fort Worth police, because my
	  homework was too hard. True
			       story.

左对齐

最后是这个命令: >

	:{range}left [margin]

不过，与 ":center" 和 ":right" 不同的是，":left" 的参数不是行的长度，而是左边
距。如果省略，文本将靠左放置（使用零边距效果相同）。如果设为 5，文本将缩进 5 个
空格。例如，使用以下命令: >

	:1left 5
	:2,5left

结果如下: >

	     I taught for a while. One
	time, I was stopped by the
	Fort Worth police, because my
	homework was too hard. True
	story.


两端对齐			*justify* *:Justify* *Justify()* *package-justify*

Vim 没有内置的两端对齐功能。但是，有一个整洁的宏包可以完成这项工作。要使用这个
包，执行以下命令: >vim

	:packadd justify

或者在你的 |vimrc| 中加入这一行: >vim

	:packadd! justify

这个 Vim 脚本文件定义了一个新的可视模式命令 "_j"。要对一块文本进行两端对齐，在
可视模式下高亮文本，然后执行 "_j"。
   查看文件以获取更多说明。要打开它，在以下文件名上执行 "gf":
$VIMRUNTIME/pack/dist/opt/justify/plugin/justify.vim。

另一种方法是通过外部程序过滤文本。例如: >

	:%!fmt

*25.3*	缩进和制表符

缩进可以使文本从其余部分中突出。本手册中的示例文本，例如，缩进了八列。你通常在
每行开头输入 <Tab> 来实现。以这段文本为例: >
	the first line
	the second line

这是通过输入 <Tab>、一些文本、<Enter>、<Tab> 和更多文本来实现的。
   'autoindent' 选项会自动插入缩进: >

	:set autoindent

当开始新行时，它会获得与前一行相同的缩进。在上面的例子中，<Enter> 之后的 <Tab>
就不再需要了。


增加缩进

要增加一行的缩进量，使用 ">" 操作符，在普通模式下。通常它被用作 ">>"，为当前行
添加缩进。在插入模式下，使用 <C-t>。
   添加的缩进量由 'shiftwidth' 选项指定。默认值为 8。例如，要让 ">>" 插入四列
缩进，输入: >

	:set shiftwidth=4

在示例文本的第二行上使用时，你会得到: >

	the first line
	    the second line

"4>>" 会增加四行的缩进。


软制表位

如果你想让缩进是 4 的倍数，你将 'shiftwidth' 设为 4。但当按 <Tab> 时你仍然会得
到 8 列的缩进。要改变这一点，设置 'softtabstop' 选项: >

	:set softtabstop=4

Vim 现在会每隔 4 列为你的光标创建不可见的制表位；按 <Tab> 会跳到下一个制表位并
插入所需的空格或制表符的精确组合。

	备注:
	你可以将 'tabstop' 选项设为 4。但是，如果你下次编辑该文件时
	'tabstop' 设回默认值 8，它看起来会不对。在其他程序和打印时
	缩进也会出错。因此建议始终将 'tabstop' 保持为 8。这是类 UNIX
	系统上的标准值。

*25.4*	处理长行

有时你会编辑比窗口列数更宽的文件。当这种情况发生时，Vim 会折行，使所有内容都显
示在屏幕上。
   如果你关闭 'wrap' 选项，文件中的每一行都只显示为屏幕上的一行。这样长行的末
尾就会消失在屏幕右侧之外。
   当你将光标移到看不到的字符上时，Vim 会滚动文本来显示它。这就像在文本上水平
移动一个视口。
   默认情况下，Vim 在 GUI 中不显示水平滚动条。如果你想启用它，使用以下命令: >

	:set guioptions+=b

一个水平滚动条将出现在 Vim 窗口底部。

如果你没有滚动条或不想使用它，可以用以下命令来滚动文本。光标会保持在同一位置，
但必要时会被移回到可见文本中。

	zh		向右滚动
	4zh		向右滚动四个字符
	zH		向右滚动半个窗口宽度
	ze		向右滚动将光标置于末尾
	zl		向左滚动
	4zl		向左滚动四个字符
	zL		向左滚动半个窗口宽度
	zs		向左滚动将光标置于开头

让我们用一行文本来演示。光标在 "which" 的 "w" 上。上方的 "current window" 表示
当前可见的文本。下方的 "window" 表示执行左侧命令后可见的文本。 >

			      |<-- current window -->|
		some long text, part of which is visible in the window
	ze	  |<--	   window     -->|
	zH	   |<--     window     -->|
	4zh		  |<--	   window     -->|
	zh		     |<--     window	 -->|
	zl		       |<--	window	   -->|
	4zl			  |<--	   window     -->|
	zL				|<--	 window     -->|
	zs			       |<--	window	   -->|


关闭 WRAP 时的移动

当 'wrap' 关闭且文本已水平滚动时，你可以使用以下命令将光标移到你能看到的字符
上。这样窗口左右两侧的文本会被忽略。这些命令永远不会导致文本滚动: >

	g0		到本行第一个可见字符
	g^		到本行第一个非空白的可见字符
	gm		到屏幕行的中间
	gM		到本行文本的中间
	g$		到本行最后一个可见字符

		|<--	  window     -->|
	some long    text, part of which is visible in one line
		 g0  g^    gm	   gM g$


在单词处断行					*edit-no-break*

当准备供其他程序使用的文本时，你可能需要制作没有换行符的段落。使用 'nowrap' 的
一个缺点是你看不到正在编写的整个句子。当 'wrap' 开启时，单词会在中间被截断，这
使得它们难以阅读。
   编辑这种段落的一个好方案是设置 'linebreak' 选项。Vim 会在显示时在适当的位置
断行。文件中的文本保持不变。
   没有 'linebreak' 时，文本可能看起来像这样:
>
	+---------------------------------+
	|letter generation program for a b|
	|ank.  They wanted to send out a s|
	|pecial, personalized letter to th|
	|eir richest 1000 customers.  Unfo|
	|rtunately for the programmer, he |
	+---------------------------------+
<
执行: >

	:set linebreak

之后，看起来像这样:
>
	+---------------------------------+
	|letter generation program for a  |
	|bank.  They wanted to send out a |
	|special, personalized letter to  |
	|their richest 1000 customers.    |
	|Unfortunately for the programmer,|
	+---------------------------------+
<
相关选项:
'breakat' 指定可以插入断行的字符。
'showbreak' 指定在被截断行开头显示的字符串。
将 'textwidth' 设为零以避免段落被分割。


按可见行移动

"j" 和 "k" 命令移到下一行和上一行。当用在长行上时，这意味着一次移动很多屏幕
行。
   要只移动一个屏幕行，使用 "gj" 和 "gk" 命令。当一行没有折行时，它们和 "j" 与
"k" 效果相同。当行折行时，它们移到显示在上一行或下一行的字符处。
   你可能想使用这些映射，它们将这些移动命令绑定到光标键: >

	:map <Up> gk
	:map <Down> gj


将段落合并为一行				*edit-paragraph-join*

如果你想将文本导入到像 MS-Word 这样的程序中，每个段落应该是单独一行。如果你的段
落当前由空行分隔，以下方法可以将每个段落合并为一行: >

	:g/./,/^$/join

看起来很复杂。让我们分解一下:

	:g/./		一个 ":global" 命令，找到所有包含至少一个字符的行。
	     ,/^$/	一个范围，从当前行（非空行）到一个空行。
		  join	":join" 命令将范围内的行合并为一行。

从以下文本开始，包含八行，在第 30 列处断行:
>
	+----------------------------------+
	|A letter generation program	   |
	|for a bank.  They wanted to	   |
	|send out a special,		   |
	|personalized letter.		   |
	|				   |
	|To their richest 1000		   |
	|customers.  Unfortunately for	   |
	|the programmer,		   |
	+----------------------------------+
<
你最终得到两行:
>
	+----------------------------------+
	|A letter generation program for a |
	|bank.	They wanted to send out a s|
	|pecial, personalized letter.	   |
	|To their richest 1000 customers.  |
	|Unfortunately for the programmer, |
	+----------------------------------+
<
注意当分隔行是空白行但不是空行时这不起作用；即当它包含空格和/或制表符时。以下命
令可以处理空白行:
>
	:g/\S/,/^\s*$/join

最后一个段落仍然需要文件末尾有一个空白行或空行才能被合并。

*25.5*	编辑表格

假设你在编辑一个有四列的表格: >

	nice table	  test 1	test 2	    test 3
	input A		  0.534
	input B		  0.913

你需要在第三列输入数字。你可以移到第二行，使用 "A"，输入很多空格然后输入文本。
   对于这种编辑有一个特殊选项: >

	set virtualedit=all

现在你可以将光标移到没有任何文本的位置。这被称为 "虚拟空间"。这样编辑表格就容
易多了。
   通过搜索最后一列的表头来移动光标: >

	/test 3

现在按 "j"，你就在可以输入 "input A" 的值的位置。输入 "0.693" 结果是: >

	nice table	  test 1     test 2	 test 3
	input A		  0.534			 0.693
	input B		  0.913

Vim 自动为你在新文本前面填充了空白。现在，要在这一列输入下一个字段，使用 "Bj"。
"B" 移回到以空白分隔的单词的开头。然后 "j" 移到可以输入下一个字段的位置。

	备注:
	你可以在显示中的任何位置移动光标，包括行尾之后。但 Vim 不会
	在那里插入空格，直到你在该位置插入一个字符。


复制一列

你想添加一列，该列应该是第三列的副本，放在 "test 1" 列之前。分七步完成:
1.  将光标移到这列的左上角，例如用 "/test 3"。
2.  按 CTRL-V 开始块可视模式。
3.  用 "2j" 将光标向下移两行。你现在在 "虚拟空间" 中: "input B" 行的 "test 3"
    列。
4.  向右移动光标，将整列以及列间距都包含在选择中。"9l" 应该够了。
5.  用 "y" 复制选中的矩形。
6.  将光标移到 "test 1"，这是新列要放置的位置。
7.  按 "P"。

结果应该是: >

	nice table	  test 3    test 1     test 2	   test 3
	input A		  0.693     0.534		   0.693
	input B			    0.913

注意整个 "test 1" 列向右移动了，包括 "test 3" 列中没有文本的行。

用以下命令回到非虚拟光标移动: >

	:set virtualedit=


虚拟替换模式

使用 'virtualedit' 的缺点是它的 "感觉" 不同。在移动光标时你无法识别行尾之后的
制表符或空格。可以使用另一种方法: 虚拟替换模式。
   假设你的表格中有一行同时包含制表符和其他字符。在第一个制表符上使用 "rx": >

	inp	0.693   0.534	0.693

	       |
	   rx  |
	       V

	inpx0.693   0.534	0.693

布局被破坏了。为了避免这种情况，使用 "gr" 命令: >

	inp	0.693   0.534	0.693

	       |
	  grx  |
	       V

	inpx	0.693   0.534	0.693

"gr" 命令确保新字符占用正确的屏幕空间。多余的空格或制表符会被插入以填补空白。
因此实际发生的是制表符被 "x" 替换，然后添加空白以保持其后的文本位置不变。在这个
例子中插入了一个制表符。
   当你需要替换多个字符时，使用 "R" 命令进入替换模式（参见 |04.9|）。这会破坏
布局并替换错误的字符: >

	inp	0	0.534	0.693

		|
	 R0.786 |
		V

	inp	0.78634	0.693

"gR" 命令使用虚拟替换模式。这会保持布局: >

	inp	0	0.534	0.693

		|
	gR0.786 |
		V

	inp	0.786	0.534	0.693


重新格式化表格中的制表符

你编辑的文件包含表格数据，原作者决定使用制表符来对齐表格数据（而不是空格）。可
惜他使用的制表位间隔为 4 列，而 Vim 默认为 8 列；表格看起来不对！怎么办？
  要修复显示而不修改文件，临时调整设置: >

	:set tabstop=4

这会更新视觉布局，但文件本身保持不变。
  另一种可能是永久地重新格式化文件。为此 Vim 提供了 |:retab| 命令。首先，设置
'tabstop' 以匹配原始布局（如上），然后运行: >

	:retab 8

":retab" 命令会将 'tabstop' 改为 8，同时修改文本使其看起来不变。它为此将空白区
域转换为制表符和空格。现在你可以写入文件了。
   警告: 在程序上使用 ":retab" 时，它可能会改变字符串常量内的空白。因此最好养成
使用 "\t" 而不是真正制表符的习惯。
