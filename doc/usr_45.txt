*45.1*	消息的语言

当你启动 Vim 时，它会检查环境以确定你使用的语言。大多数情况下这应该工作正常，
你可以得到你所用语言的消息 (如果可用的话)。要查看当前使用的语言，使用此命令: >

	:language

如果回复 "C"，这意味着正在使用默认值，即英语。

如果你想要不同语言的消息怎么办？有几种方法。你应该使用哪种取决于你系统的
能力。
   第一种方法是在启动 Vim 之前将环境设置为所需的语言。Unix 的示例: >

	env LANG=de_DE.ISO_8859-1  vim

这仅在你的系统上有该语言时才有效。优点是所有 GUI 消息和库中的内容也都使用
正确的语言。缺点是你必须在启动 Vim 之前完成此操作。如果你想在 Vim 运行时
更改语言，可以使用第二种方法: >

	:language fr_FR.ISO_8859-1

这样你可以尝试多个语言名称。当你的系统不支持时会得到错误消息。当翻译的消息
不可用时不会得到错误。Vim 会静默回退到使用英语。
   要找出你的系统支持哪些语言，找到列出它们的目录。在我的系统上是
"/usr/share/locale"。在某些系统上是 "/usr/lib/locale"。"setlocale" 的手册页
应该能提示你在系统上哪里找到它们。
   注意要精确输入名称。大小写很重要，'-' 和 '_' 字符容易混淆。

你也可以分别为消息、编辑的文本和时间格式设置语言。参见 |:language|。


自己动手翻译消息

如果你的语言没有可用的翻译消息，你可以自己编写。为此，获取 Vim 的源代码和
GNU gettext 包。解压源代码后，可以在目录 src/po/README.txt 中找到说明。
   翻译并不太难。你不需要是程序员。当然，你必须同时了解英语和你要翻译的
语言。
   当你对翻译满意后，考虑将其提供给其他人。上传到
https://github.com/vim/vim 或通过电子邮件发送给 Vim 维护者
<maintainer@vim.org>。或者两者都做。

*45.2*	菜单的语言

默认菜单是英文的。为了能使用你当地的语言，它们必须被翻译。通常，如果环境
已设置为你的语言，这会自动为你完成，就像消息一样。你不需要额外做任何事情。
但这仅在该语言的翻译可用时才有效。
   假设你在德国，语言设置为德语，但更喜欢使用 "File" 而不是 "Datei"。你可以
这样切换回英文菜单: >

	:set langmenu=none

也可以指定一种语言: >

	:set langmenu=nl_NL.ISO_8859-1

像上面一样，"-" 和 "_" 之间的差异很重要。但是，这里大小写差异被忽略。
   'langmenu' 选项必须在菜单加载前设置。一旦菜单被定义，更改 'langmenu'
不会有直接效果。因此，将设置 'langmenu' 的命令放在你的 vimrc 文件中。
   如果你真的想在 Vim 运行时切换菜单语言，可以这样做: >

	:source $VIMRUNTIME/delmenu.vim
	:set langmenu=de_DE.ISO_8859-1
	:source $VIMRUNTIME/menu.vim

有一个缺点: 你自己定义的所有菜单都会消失。你需要重新定义它们。


自己动手翻译菜单

要查看有哪些可用的菜单翻译，查看此目录:

	$VIMRUNTIME/lang ~

文件名为 menu_{language}.vim。如果你没有看到你想使用的语言，你可以自己翻译。
最简单的方法是复制一个现有的语言文件，然后修改它。
   首先用 ":language" 命令找出你的语言名称。使用此名称，但所有字母都改为
小写。然后将文件复制到你自己的运行时目录，如 'runtimepath' 中较早出现的目录。
例如，对于 Unix，你可以这样做: >

	:!cp $VIMRUNTIME/lang/menu_ko_kr.euckr.vim ~/.config/nvim/lang/menu_nl_be.iso_8859-1.vim

你可以在 "$VIMRUNTIME/lang/README.txt" 中找到翻译提示。

*45.3*	使用其他编码

Vim 猜测你将要编辑的文件是以你的语言编码的。对于许多欧洲语言，这是 "latin1"。
每个字节是一个字符。这意味着有 256 种不同的字符。对于亚洲语言这是不够的。
这些语言大多使用双字节编码，提供超过一万个可能的字符。当文本包含几种不同的
语言时，这仍然不够。这就是 Unicode 的用武之地。它被设计为包含常用语言中使用
的所有字符。这是 "取代所有其他编码的超级编码"。但它还没有被广泛使用。
   幸运的是，Vim 支持这三种编码。而且，在一些限制条件下，即使你的环境使用的
语言与文本不同，你也可以使用它们。
   然而，当你只编辑你的语言编码的文件时，默认应该工作正常，你不需要做任何
事情。以下内容仅在你想编辑不同语言时才相关。


在 GUI 中使用 Unicode

Unicode 的好处是其他编码可以转换为它并转换回来而不丢失信息。当你让 Vim
内部使用 Unicode 时，你将能够编辑任何编码的文件。
   不幸的是，支持 Unicode 的系统数量仍然有限。因此你的语言不太可能使用它。
你需要告诉 Vim 你想使用 Unicode，以及如何处理与系统其余部分的接口。
   让我们从 Vim 的 GUI 版本开始，它能显示 Unicode 字符。这应该可以工作: >

	:set encoding=utf-8
	:set guifont=-misc-fixed-medium-r-normal--18-120-100-100-c-90-iso10646-1

'encoding' 选项告诉 Vim 你使用的字符的编码。这适用于缓冲区中的文本
(你正在编辑的文件)、寄存器、Vim 脚本文件等。你可以将 'encoding' 视为
Vim 内部使用的设置。
   此示例假设你的系统上有此字体。示例中的名称是用于 X 窗口系统的。此字体
位于一个用于增强 xterm Unicode 支持的包中。

对于 MS-Windows，某些字体的 Unicode 字符数量有限。尝试使用 "Courier New"
字体。你可以使用 编辑/选择字体... 菜单来选择和试用可用的字体。但只能使用
等宽字体。示例: >

	:set guifont=courier_new:h12

如果效果不好，尝试获取一个字体包。

现在你已经告诉 Vim 内部使用 Unicode 并使用 Unicode 字体显示文本。

在 Unicode 终端中使用 Unicode

有些终端直接支持 Unicode。XFree86 附带的标准 xterm 就是其中之一。
让我们以此为例。
   首先，xterm 必须已编译有 Unicode 支持。
   使用 "-u8" 参数启动 xterm。你可能还需要指定一个字体。示例: >

   xterm -u8 -fn -misc-fixed-medium-r-normal--18-120-100-100-c-90-iso10646-1

现在你可以在此终端中运行 Vim。


在普通终端中使用 Unicode

假设你想使用 Unicode 文件，但没有支持 Unicode 的终端。你可以用 Vim 做到这一
点，虽然终端不支持的字符不会显示。文本的布局会保留。

尝试编辑包含 Unicode 字符的文件。你会注意到 Vim 在终端无法显示的字符位置
放置问号 (或下划线或其他字符)。将光标移动到问号上并使用此命令: >

	ga

Vim 将显示带有该字符代码的行。这给你一个关于它是什么字符的提示。你可以在
Unicode 表中查找它。如果你有很多时间，你确实可以这样查看文件。

	备注:
	由于 'encoding' 用于 Vim 内部的所有文本，更改它会使所有非 ASCII
	文本无效。你会在使用寄存器和 |shada-file| (例如，记住的搜索模式)
	时注意到这一点。建议在你的 vimrc 文件中设置 'encoding'，并保持不变。

*45.4*	编辑不同编码的文件

假设你已经设置 Vim 使用 Unicode，你想编辑一个 16 位 Unicode 的文件。听起来
很简单，对吧？实际上，Vim 内部使用 utf-8 编码，因此 16 位编码必须进行转换，
因为字符集 (Unicode) 和编码 (utf-8 或 16 位) 之间存在差异。
   Vim 将尝试检测你正在编辑的文件类型。它使用 'fileencodings' 选项中的编码
名称。使用 Unicode 时，默认值是: "ucs-bom,utf-8,latin1"。这意味着 Vim 检查
文件以查看它是否是以下编码之一:

	ucs-bom		文件必须以字节序标记 (BOM) 开头。这允许检测
			16 位、32 位和 utf-8 的 Unicode 编码。
	utf-8		utf-8 Unicode。当字节序列在 utf-8 中非法时，此编码
			被拒绝。
	latin1		古老的 8 位编码。总是有效。

当你开始编辑那个 16 位 Unicode 文件，且它有 BOM 时，Vim 会检测到并在读取时
将文件转换为 utf-8。'fileencoding' 选项 (末尾没有 s) 被设置为检测到的值。
在此情况下是 "utf-16le"。这意味着它是 Unicode，16 位且小端序。这种文件格式
在 MS-Windows 上很常见 (例如，注册表文件)。
   写入文件时，Vim 会比较 'fileencoding' 和 'encoding'。如果它们不同，
文本将被转换。
   'fileencoding' 为空值意味着不进行转换。因此文本假定为以 'encoding'
编码的。

如果默认的 'fileencodings' 值对你不好，将其设置为你想让 Vim 尝试的编码。
只有当发现一个值无效时才会使用下一个。将 "latin1" 放在第一位不起作用，因为
它永远不会非法。一个示例，当文件没有 BOM 且不是 utf-8 时回退到日语: >

	:set fileencodings=ucs-bom,utf-8,sjis

参见 |encoding-values| 了解建议的值。其他值也可能有效。这取决于可用的转换。


强制编码

如果自动检测不起作用，你必须告诉 Vim 文件的编码。示例: >

	:edit ++enc=koi8-r russian.txt

"++enc" 部分指定仅用于此文件的编码名称。Vim 将从指定的编码 (本例中是俄语)
转换文件为 'encoding'。'fileencoding' 也将被设置为指定的编码，以便写入文件
时可以进行反向转换。
   写入文件时也可以使用相同的参数。这样你实际上可以使用 Vim 来转换文件。
示例: >

	:write ++enc=utf-8 russian.txt
<
	备注:
	转换可能导致字符丢失。从一种编码转换到 Unicode 再转换回来通常不会
	有这个问题，除非存在非法字符。当文件中有多种语言时，从 Unicode
	转换到其他编码经常会丢失信息。

*45.5*	输入语言文本

计算机键盘只有一百多个键。有些语言有数千个字符，Unicode 有超过十万个。
那么你怎么输入这些字符？
   首先，当你不使用太多特殊字符时，可以使用二合字母。这已经在 |24.9| 中
解释过了。
   当你使用的语言所需字符比键盘上的键多得多时，你需要使用输入法 (IM)。
这需要学习输入键到生成字符的翻译。当你需要输入法时，你的系统可能已经有一个。
它应该像其他程序一样与 Vim 配合工作。


键盘映射

对于某些语言，字符集与拉丁字符不同，但使用类似数量的字符。可以将键映射到
字符。Vim 使用键盘映射来实现。
   假设你想输入希伯来语。你可以这样加载键盘映射: >

	:set keymap=hebrew

Vim 将尝试为你找到键盘映射文件。这取决于 'encoding' 的值。如果没有找到
匹配的文件，你会得到一个错误消息。

现在你可以在插入模式中输入希伯来语。在普通模式和输入 ":" 命令时，Vim 会自动
切换到英语。你可以使用以下命令在希伯来语和英语之间切换: >

	CTRL-^

这仅在插入模式和命令行模式中有效。在普通模式中它做完全不同的事情
(跳转到备用文件)。
   键盘映射的使用在模式消息中指示，如果你设置了 'showmode' 选项的话。在
GUI Vim 中会用不同的光标颜色来指示键盘映射的使用。
   你也可以用 'iminsert' 和 'imsearch' 选项来更改键盘映射的使用。

要查看映射列表，使用此命令: >

	:lmap

要找出有哪些可用的键盘映射文件，在 GUI 中你可以使用 编辑/键盘映射 菜单。
否则你可以使用此命令: >

	:echo globpath(&rtp, "keymap/*.vim")


自己创建键盘映射

你可以创建自己的键盘映射文件。这不太难。从与你要使用的语言相似的键盘映射
文件开始。将其复制到你运行时目录中的 "keymap" 目录。例如，对于 Unix，
你可以使用目录 "~/.config/nvim/keymap"。
   键盘映射文件的名称必须如下:

	keymap/{name}.vim ~
或
	keymap/{name}_{encoding}.vim ~

{name} 是键盘映射的名称。选择一个明显但不同于现有键盘映射的名称 (除非你想
替换现有的键盘映射文件)。{name} 不能包含下划线。可选地，在下划线后添加使用
的编码。示例:

	keymap/hebrew.vim ~
	keymap/hebrew_utf-8.vim ~

文件的内容应该是不言自明的。查看随 Vim 分发的一些键盘映射。详情参见
|mbyte-keymap|。


最后手段

如果所有其他方法都失败了，你可以用 CTRL-V 输入任何字符:

	编码	   输入			范围 ~
	8 位	   CTRL-V 123		十进制 0-255
	8 位	   CTRL-V x a1		十六进制 00-ff
	16 位     CTRL-V u 013b	十六进制 0000-ffff
	31 位	   CTRL-V U 001303a4	十六进制 00000000-7fffffff

不要输入空格。详情参见 |i_CTRL-V_digit|。
