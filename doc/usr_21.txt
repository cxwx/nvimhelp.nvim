*21.1*	挂起和恢复

和大多数 Unix 程序一样，Vim 可以通过按 CTRL-Z 来挂起。这会停止 Vim 并把你带回
启动它的那个 shell。然后你可以执行任何其他命令，直到你厌倦了为止。然后用 "fg"
命令把 Vim 带回来。 >

	CTRL-Z
	{任何 shell 命令序列}
	fg

你会回到离开 Vim 时的状态，一切都没有改变。
   如果按 CTRL-Z 不起作用，你也可以使用 ":suspend"。
别忘了把 Vim 切回前台，否则你会丢失所做的修改！

只有 Unix 支持这个功能。在其他系统上 Vim 会为你启动一个 shell。这也同样有执行
shell 命令的功能。但它是一个新的 shell，不是启动 Vim 的那个。
   当你运行 GUI 时，你无法回到启动 Vim 的那个 shell。CTRL-Z 会将 Vim 窗口
最小化。

*21.2*	执行 shell 命令

要从 Vim 中执行单个 shell 命令，使用 ":!{command}"。例如，查看目录列表: >

	:!ls
	:!dir

第一个用于 Unix，第二个用于 MS-Windows。
   Vim 会执行该程序。程序结束后你会得到一个提示按 <Enter>。这让你有机会在返回
正在编辑的文本之前查看命令的输出。
   "!" 在其他需要运行程序的地方也会被使用。让我们看看概览:

	:!{program}		执行 {program}
	:r !{program}		执行 {program} 并读取其输出
	:w !{program}		执行 {program} 并将文本发送到其输入
	:[range]!{program}	通过 {program} 过滤文本

注意 "!{program}" 前面有无范围的区别很大。没有范围时会正常执行程序，有范围时会
将若干行文本通过该程序过滤。

用这种方式执行一系列程序是可以的。但 shell 更擅长这个。你可以用 |:terminal|
启动一个新的 shell。

这类似于使用 CTRL-Z 来挂起 Vim。不同之处在于会启动一个新的 shell。

*21.3*	记住信息; ShaDa

编辑一段时间后，你的寄存器中会有文本，各个文件中会有标记，命令行历史中充满了
精心构造的命令。当你退出 Vim 时，这些都会丢失。但你可以找回它们！

ShaDa（SHAred DAta 的缩写）文件被设计用于存储状态信息:

	命令行和搜索模式的历史
	寄存器中的文本
	各个文件的标记
	缓冲区列表
	全局变量

每次你退出 Vim 时，它会将这些信息存储在一个文件中，即 ShaDa 文件。当 Vim 再次
启动时，ShaDa 文件被读取，信息被恢复。

'shada' 选项的默认设置会恢复有限数量的项目。你可能想设置它来记住更多信息。
通过以下命令来实现: >

	:set shada=string

这个字符串指定要保存什么。字符串的语法是一个选项字符后跟一个参数。选项/参数对
之间用逗号分隔。
   看看你如何构建自己的 shada 字符串。首先，' 选项用于指定为多少个文件保存
标记 (a-z)。为这个选项选一个合适的整数（例如 1000）。你的命令现在看起来像: >

	:set shada='1000

f 选项控制是否存储全局标记 (A-Z 和 0-9)。如果此选项为 0，则不存储。如果为 1 或
你不指定 f 选项，标记会被存储。你想要这个功能，所以现在你有: >

	:set shada='1000,f1

< 选项控制为每个寄存器保存多少行。默认情况下，所有行都被保存。如果为 0，什么
都不保存。为了避免在 ShaDa 文件中添加数千行（可能永远不会用到并且会使 Vim 启动
变慢），你设置最多 500 行: >

	:set shada='1000,f1,<500
<
你可能想使用的其他选项:
	:	从命令行历史中保存的行数
	@	从输入行历史中保存的行数
	/	从搜索历史中保存的行数
	r	可移动介质，不为其存储标记（可以多次使用）
	!	以大写字母开头且不包含小写字母的全局变量
	h	启动时禁用 'hlsearch' 高亮
	%	缓冲区列表（仅在启动 Vim 时没有文件参数时恢复）
	c	使用 'encoding' 转换文本
	n	ShaDa 文件的名称（必须是最后一个选项）

更多信息请参见 'shada' 选项和 |shada-file|。

当你运行多个 Vim 实例时，最后退出的那个会存储其信息。这可能导致之前退出的 Vim
存储的信息丢失。每个项目只能被记住一次。


回到你停止 VIM 的位置

你编辑文件到一半，是时候去度假了。你退出 Vim 去享受假期，忘掉了所有的工作。几
周后你启动 Vim，输入:
>
	'0

你就回到了离开 Vim 时的位置。这样你就可以继续工作了。
   Vim 在你每次退出时都会创建一个标记。最后一个是 '0。'0 指向的位置变成 '1。'1
变成 '2，以此类推。标记 '9 会被丢弃。
   |:marks| 命令用来查看 '0 到 '9 会带你到哪里。


回到某个文件

如果你想回到最近编辑过的文件，但不是退出 Vim 时的那个，有一种稍微复杂一点的
方法。你可以通过输入以下命令来查看文件列表: >

	:oldfiles
<	1: ~/.config/nvim/init.vim ~
	2: ~/text/resume.txt ~
	3: /tmp/draft ~

现在你想编辑第二个文件，就是列表中前面标着 "2:" 的那个。你输入: >

	:e #<2

除了 ":e" 之外，你可以用任何有文件名参数的命令，"#<2" 的工作方式和 "%"（当前
文件名）以及 "#"（备选文件名）一样。所以你也可以分割窗口来编辑第三个文件: >

	:split #<3

当你只想编辑一个文件时，#<123 这种写法有点复杂。幸运的是有一种更简单的方式: >

	:browse oldfiles
<	1: ~/.config/nvim/init.vim ~
	2: ~/text/resume.txt ~
	3: /tmp/draft ~
	-- More --

你得到和 |:oldfiles| 一样的文件列表。如果你想编辑 "resume.txt"，先按 "q" 停止
列出。你会得到一个提示:

	Type number and <Enter> (empty cancels): ~

输入 "2" 并按 <Enter> 来编辑第二个文件。

更多信息请参见 |:oldfiles|、|v:oldfiles| 和 |c_#<|。


在两个 VIM 之间传递信息

你可以使用 ":wshada" 和 ":rshada" 命令在 Vim 运行时保存和恢复信息。这对于在两
个 Vim 实例之间交换寄存器内容很有用。例如，在第一个 Vim 中执行: >

	:wshada! ~/tmp/shada

在第二个 Vim 中执行: >

	:rshada! ~/tmp/shada

显然，"w" 代表 "write"（写入），"r" 代表 "read"（读取）。
   ":wshada" 使用 ! 字符来强制覆盖已有文件。省略时，如果文件存在，信息会被合并
到文件中。
   ":rshada" 使用 ! 字符表示 ShaDa 文件中的所有信息优先于已有信息，这可能会覆
盖它们。不带 ! 时只使用未设置过的信息。
   这些命令也可以用来存储信息以备后用。你可以建一个目录专门存放 ShaDa 文件，每
个文件包含不同用途的信息。

*21.4*	会话

假设你正在编辑，到了下班时间。你想退出工作，第二天从离开的地方继续。你可以通过
保存编辑会话并在第二天恢复来实现这一点。
   Vim 会话包含你正在编辑的所有信息。这包括文件列表、窗口布局、全局变量、选项
和其他信息。（确切记住什么由 'sessionoptions' 选项控制，如下所述。）
   以下命令创建会话文件: >

	:mksession vimbook.vim

以后如果你想恢复这个会话，你可以使用这个命令: >

	:source vimbook.vim

如果你想在启动 Vim 时恢复特定的会话，你可以使用以下命令: >

	vim -S vimbook.vim

这告诉 Vim 在启动时读取一个特定的文件。'S' 代表 session（实际上，你可以用 -S
加载任何 Vim 脚本，所以它也可以代表 "source"）。

之前打开的窗口会被恢复，包括相同的位置和大小。映射和选项值也和之前一样。
   确切恢复什么取决于 'sessionoptions' 选项。默认值是:
"blank,buffers,curdir,folds,help,options,tabpages,winsize,terminal"。

	blank		保留空窗口
	buffers		所有缓冲区，不只是在窗口中的
	curdir		当前目录
	folds		折叠，包括手动创建的
	help		帮助窗口
	options		所有选项和映射
	tabpages	所有标签页
	winsize		窗口大小
	terminal	包含终端窗口

根据你的喜好来修改。例如，要同时恢复 Vim 窗口的大小，使用: >

	:set sessionoptions+=resize


这里的会话，那里的会话

使用会话的明显方式是在不同项目之间切换。假设你把会话文件存储在目录
"~/.config/nvim" 中。你当前在 "secret" 项目上工作，需要切换到 "boring"
项目: >

	:wall
	:mksession! ~/.config/nvim/secret.vim
	:source ~/.config/nvim/boring.vim

这首先使用 ":wall" 写入所有已修改的文件。然后使用 ":mksession!" 保存当前会话。
这会覆盖之前的会话。下次加载 secret 会话时你可以从这个位置继续。最后加载新的
"boring" 会话。

如果你打开帮助窗口、分割和关闭各种窗口，搞乱了窗口布局，你可以回到最后保存的
会话: >

	:source ~/.config/nvim/boring.vim

这样你就可以完全控制是否要下次从当前位置继续（通过将当前设置保存在会话中），还是
保持会话文件作为起点。
   使用会话的另一种方式是创建一个你喜欢的窗口布局，并将其保存在会话中。然后你
可以随时回到这个布局。
   例如，这是一个好用的布局:
>
        +----------------------------------------+
        |                  VIM - main help file  |
        |                                        |
        |Move around:  Use the cursor keys, or "h|
        |help.txt================================|
        |explorer   |                            |
        |dir        |~                           |
        |dir        |~                           |
        |file       |~                           |
        |file       |~                           |
        |file       |~                           |
        |file       |~                           |
        |~/=========|[No File]===================|
        |                                        |
        +----------------------------------------+
<
上面有一个帮助窗口，你可以阅读本文。左边的窄竖窗口包含一个文件浏览器。这是一个
Vim 插件，列出目录的内容。你可以在那里选择要编辑的文件。更多信息在下一章。
   在刚启动的 Vim 中用以下命令创建这个布局: >

	:help
	CTRL-W w
	:vertical split ~/

你可以根据喜好调整窗口大小。然后用以下命令保存会话:
>
	:mksession ~/.config/nvim/mine.vim

现在你可以用这个布局启动 Vim: >

	vim -S ~/.config/nvim/mine.vim

提示: 要在空窗口中打开浏览器窗口中列出的文件，将光标移到文件名上然后按 "O"。
双击鼠标也可以。


会话和 SHADA

会话存储很多东西，但不存储标记的位置、寄存器的内容和命令行历史。你需要使用
shada 功能来保存这些。
   大多数情况下你会想要把会话和 shada 分开使用。这可以用于切换到另一个会话但
保留命令行历史。在一个会话中复制文本到寄存器，然后在另一个会话中粘贴。
   你也许更喜欢把信息和会话一起保存。那你需要自己来做。例如: >

	:mksession! ~/.config/nvim/secret.vim
	:wshada! ~/.local/state/nvim/shada/secret.shada

要恢复: >

	:source ~/.config/nvim/secret.vim
	:rshada! ~/.local/state/nvim/shada/secret.shada

*21.5*	视图

会话存储整个 Vim 的外观。当你只想存储一个窗口的属性时，使用视图。
   视图的使用场景是当你想以特定方式编辑文件时。例如，你用 'number' 选项启用了行
号显示，并且定义了一些折叠。就像会话一样，你可以记住文件上的这个视图，以后再恢
复它。实际上，当你保存会话时，它会保存每个窗口的视图。
   有两种基本的视图使用方式。第一种是让 Vim 为视图文件选一个名字。你可以在以后
编辑同一个文件时恢复视图。要保存当前窗口的视图: >

	:mkview

Vim 会决定将视图存储在哪里。当你以后编辑同一个文件时，用这个命令恢复视图: >

	:loadview

简单吧？
   现在你想不带 'number' 选项查看文件，或者打开所有折叠，你可以设置选项使窗口
看起来如你所愿。然后用以下命令保存视图: >

	:mkview 1

显然，你可以用以下命令恢复: >

	:loadview 1

现在你可以通过使用带或不带 "1" 参数的 ":loadview" 在同一个文件的两个视图之间
切换。
   你可以用这种方式为同一个文件保存多达十个视图，一个无编号的和九个编号为 1 到
9 的。


带名称的视图

使用视图的第二种基本方式是将视图保存到你选择的名称的文件中。这个视图可以在编辑
另一个文件时加载。Vim 会切换到视图中指定的文件进行编辑。因此你可以用它来快速
切换到另一个文件的编辑，并恢复你保存的所有选项设置。
   例如，保存当前文件的视图: >

	:mkview ~/.config/nvim/main.vim

你可以这样恢复: >

	:source ~/.config/nvim/main.vim

*21.6*	模式行

当编辑特定文件时，你可能会专门为该文件设置选项。每次都输入这些命令很烦。在多人
共享文件时，使用会话或视图来编辑文件也不太合适。
   这种情况的解决方案是在文件中添加模式行。这是一行文本，告诉 Vim 选项的值，仅
用于该文件。
   一个典型的例子是 C 程序，其中缩进是 4 个空格的倍数。这需要将 'shiftwidth'
选项设置为 4。以下模式行可以做到: >

	/* vim:set shiftwidth=4: */ ~

将这一行放在文件的前五行或最后五行之内。当编辑该文件时，你会注意到 'shiftwidth'
被设置为 4。编辑另一个文件时，它会恢复为默认值 8。
   对于某些文件，模式行适合放在文件头部，因此可以放在文件顶部。对于文本文件和其
他模式行会妨碍正常内容的文件，把它放在文件末尾。

'modelines' 选项指定检查文件开头和末尾多少行来寻找模式行。要检查十行: >

	:set modelines=10

'modeline' 选项可以用来关闭这个功能。当你在 Unix 上以 root 身份工作或在
MS-Windows 上以 Administrator 身份工作，或者你不信任正在编辑的文件时，可以这样
做: >

	:set nomodeline

模式行的格式如下: >

	any-text vim:set {option}={value} ... : any-text

"any-text" 表示你可以在 Vim 使用的部分前后放置任何文本。这允许它看起来像注释，
就像上面用 "/*" 和 "*/" 做的那样。
   " vim:" 部分是让 Vim 识别这一行的。"vim" 前面必须有空白字符，或者 "vim" 必须
在行首。因此使用 "gvim:" 之类的不会起作用。
   两个冒号之间的部分是 ":set" 命令。它的工作方式和输入 ":set" 命令一样，只是
你需要在冒号前插入反斜杠（否则它会被视为模式行的结束）。

另一个例子: >

	// vim:set textwidth=72 dir=c\:\tmp:  use c:\tmp here

在第一个冒号前有一个额外的反斜杠，这样它就包含在 ":set" 命令中。第二个冒号后的
文本被忽略，因此可以放置注释。

更多详情请参见 |modeline|。
