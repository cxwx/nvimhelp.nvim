*24.1*	更正输入

<BS> 键前面已经提到过。它删除光标前面的字符。<Del> 键对光标下（后面的）字符做同
样的操作。
   当你输入了一整个错误的单词时，使用 CTRL-W:

	The horse had fallen to the sky ~
				       CTRL-W
	The horse had fallen to the ~

如果你把一整行都搞乱了并想重新开始，使用 CTRL-U 来删除它。这会保留光标之后的文
本和缩进。只有从第一个非空白字符到光标之间的文本被删除。在下面这行中，光标在
"fallen" 的 "f" 上时按 CTRL-U 会得到:

	The horse had fallen to the ~
		      CTRL-U
	fallen to the ~

当你发现几个单词之前有一个错误时，你需要把光标移到那里去更正。例如，你输入了:

	The horse had follen to the ground ~

你需要将 "follen" 改为 "fallen"。光标在末尾时，你可以这样输入来更正: >

					<Esc>4blraA

<	退出插入模式			<Esc>
	往回四个单词			     4b
	移到 "o" 上面			       l
	替换为 "a"			        ra
	重新进入插入模式		          A

另一种方法: >

		<C-Left><C-Left><C-Left><C-Left><Right><Del>a<End>

<	往回四个单词		     <C-Left><C-Left><C-Left><C-Left>
	移到 "o" 上面			<Right>
	删除 "o"			       <Del>
	输入 "a"				    a
	移到行尾				     <End>

这种方式使用特殊键来移动，同时保持在插入模式中。这类似于无模式编辑器中的操作。
记起来更容易，但花费更多时间（你需要把手从字母键移到光标键，而且不看键盘很难按
到 <End> 键）。
   这些特殊键在编写映射时最有用，因为映射不需要离开插入模式。额外的按键在那种情
况下并不重要。
   以下是你可以在插入模式中使用的按键概览:

	<C-Home>	到文件开头
	<PageUp>	向上翻一整屏
	<Home>		到行首
	<S-Left>	左移一个单词
	<C-Left>	左移一个单词
	<S-Right>	右移一个单词
	<C-Right>	右移一个单词
	<End>		到行尾
	<PageDown>	向下翻一整屏
	<C-End>		到文件末尾

还有其他一些，参见 |ins-special-special|。

*24.2*	显示匹配

当你输入 ) 时，如果能看到它和哪个 ( 匹配就好了。要让 Vim 做到这一点，使用以下
命令: >

	:set showmatch

当你现在输入类似 "(example)" 的文本时，一旦你输入 )，Vim 会短暂地将光标移到匹
配的 ( 上，在那里停留半秒钟，然后移回到你正在输入的位置。
   如果没有匹配的 (，Vim 会发出蜂鸣声。这样你就知道可能在某处忘记了 (，或者多
输入了一个 )。
   匹配也会对 [] 和 {} 对显示。你不必等着输入下一个字符，一旦 Vim 看到你输入了
新字符，光标就会移回来，插入操作像之前一样继续。
   你可以用 'matchtime' 选项改变 Vim 等待的时间。例如，要让 Vim 等待一秒半: >

	:set matchtime=15

时间以十分之一秒为单位指定。

*24.3*	补全

Vim 可以在插入时自动补全单词。你输入单词的开头部分，按 CTRL-P，Vim 就会猜出剩
余部分。
   例如，假设你正在编写一个 C 程序，想要输入以下内容:

	total = ch_array[0] + ch_array[1] + ch_array[2]; ~

你开始输入:

	total = ch_array[0] + ch_ ~

这时，你告诉 Vim 用 CTRL-P 命令补全单词。Vim 会搜索以光标前面的内容开头的单
词。在这个例子中，是 "ch_"，它和 ch_array 匹配。所以输入 CTRL-P 会给你:

	total = ch_array[0] + ch_array ~

再多输入一些，你会得到（以一个空格结尾）:

	total = ch_array[0] + ch_array[1] +  ~

如果你现在输入 CTRL-P，Vim 会再次搜索光标前面的单词来补全。由于光标前面什么也
没有，它会向前找到第一个单词，即 "ch_array"。再次输入 CTRL-P 会给你下一个匹配
的单词，这里是 "total"。第三次 CTRL-P 继续向前搜索。如果没有其他匹配了，编辑器
会返回到原始文本，即什么都没有。第四次 CTRL-P 会使编辑器重新从 "ch_array" 开
始。

要向前搜索，使用 CTRL-N。由于搜索会绕回文件末尾，CTRL-N 和 CTRL-P 会找到相同
的匹配，但顺序不同。提示: CTRL-N 是 Next-match（下一个匹配），CTRL-P 是
Previous-match（上一个匹配）。

Vim 编辑器会花很大功夫来寻找要补全的单词。默认情况下，它搜索以下位置:

	1. 当前文件
	2. 其他窗口中的文件
	3. 其他已加载的文件（隐藏缓冲区）
	4. 未加载的文件（非活动缓冲区）
	5. 标签文件
	6. 当前文件通过 #include 包含的所有文件


选项

你可以用 'complete' 选项自定义搜索顺序。

会使用 'ignorecase' 选项。当它被设置时，搜索匹配时忽略大小写差异。

补全的一个特殊选项是 'infercase'。这在忽略大小写（'ignorecase' 必须被设置）搜
索匹配时很有用，但仍然使用你到目前为止输入的单词的大小写。因此，如果你输入
"For" 而 Vim 找到了 "fortunately" 这个匹配，结果将是 "Fortunately"。


补全特定项目

如果你知道要找什么，可以使用以下命令来补全特定类型的项目:

	CTRL-X CTRL-F		文件名
	CTRL-X CTRL-L		整行
	CTRL-X CTRL-D		宏定义（也包含在包含文件中）
	CTRL-X CTRL-I		当前文件和包含文件
	CTRL-X CTRL-K		字典中的单词
	CTRL-X CTRL-R		寄存器内容
	CTRL-X CTRL-T		同义词库中的单词
	CTRL-X CTRL-]		标签
	CTRL-X CTRL-V		Vim 命令行

在每个命令之后，可以使用 CTRL-N 查找下一个匹配，CTRL-P 查找上一个匹配。
   每个命令的更多信息请参见: |ins-completion|。


补全文件名

让我们以 CTRL-X CTRL-F 为例。这会查找文件名。它扫描当前目录中的文件，并显示每
个与光标前面的单词匹配的文件。
   例如，假设当前目录中有以下文件:

	main.c  sub_count.c  sub_done.c  sub_exit.c

现在进入插入模式并开始输入:

	The exit code is in the file sub ~

这时，你输入命令 CTRL-X CTRL-F。Vim 现在通过查看当前目录中的文件来补全当前单词
"sub"。第一个匹配是 sub_count.c。这不是你想要的，所以输入 CTRL-N 来匹配下一个
文件。这个匹配是 sub_done.c。再次输入 CTRL-N 会带你到 sub_exit.c。结果:

	The exit code is in the file sub_exit.c ~

如果文件名以 /（Unix）或 C:\（MS-Windows）开头，你可以在文件系统中查找所有文
件。例如，输入 "/u" 并按 CTRL-X CTRL-F。这将匹配 "/usr"（这是在 Unix 上）:

	the file is found in /usr/ ~

如果你现在按 CTRL-N，你会回到 "/u"。要接受 "/usr/" 并深入一级目录，再次使用
CTRL-X CTRL-F:

	the file is found in /usr/X11R6/ ~

结果当然取决于你的文件系统中有什么。匹配结果按字母顺序排序。


在源代码中补全

源代码文件有良好的结构。这使得可以以智能的方式进行补全。在 Vim 中这被称为全能
补全。在其他一些编辑器中叫做 intellisense，但那是一个商标。

全能补全的按键是 CTRL-X CTRL-O。显然 O 代表 Omni（全能），这样你更容易记住。让
我们以编辑 C 源代码为例: >

	{
	    struct foo *p;
	    p->

光标在 "p->" 后面。现在输入 CTRL-X CTRL-O。Vim 会给你一个备选列表，这些是
"struct foo" 包含的成员。这和使用 CTRL-P 完全不同，后者会补全任何单词，而这里只
有 "struct foo" 的成员才是有效的。

要使全能补全工作，你可能需要做一些设置。至少确保文件类型插件已启用。你的 vimrc
文件应该包含类似这样的行: >
	filetype plugin on
或者: >
	filetype plugin indent on

对于 C 代码，你需要创建标签文件并设置 'tags' 选项。这在 |ft-c-omni| 中有解释。
对于其他文件类型，你可能需要做类似的事情，请查看 |compl-omni-filetypes|。它只对
特定的文件类型有效。检查 'omnifunc' 选项的值可以确定它是否会工作。

*24.4*	重复一次插入

如果你按 CTRL-A，编辑器会插入你上次在插入模式中输入的文本。
   例如，假设你有一个文件，开头是: >

	"file.h" ~
	/* Main program begins */ ~

你通过在第一行开头插入 "#include " 来编辑此文件: >

	#include "file.h" ~
	/* Main program begins */ ~

你用 "j^" 命令移到下一行的开头。现在你开始插入一个新的 "#include" 行。所以你输
入: >

	i CTRL-A

结果如下: >

	#include "file.h" ~
	#include /* Main program begins */ ~

"#include " 被插入了，因为 CTRL-A 插入上一次插入的文本。现在你输入
"main.h"<Enter> 来完成这一行: >


	#include "file.h" ~
	#include "main.h" ~
	/* Main program begins */ ~

CTRL-@ 命令执行 CTRL-A 然后退出插入模式。这是快速重复完全相同的插入操作的方
法。

*24.5*	从另一行复制

CTRL-Y 命令插入光标上方的字符。当你在复制前一行时很有用。例如，你有以下这行 C
代码:

	b_array[i]->s_next = a_array[i]->s_next; ~

现在你需要输入同样的行，但将 "s_next" 改为 "s_prev"。开始新行，按 CTRL-Y 14
次，直到你到达 "next" 的 "n":

	b_array[i]->s_next = a_array[i]->s_next; ~
	b_array[i]->s_ ~

现在输入 "prev":

	b_array[i]->s_next = a_array[i]->s_next; ~
	b_array[i]->s_prev ~

继续按 CTRL-Y 直到下一个 "next":

	b_array[i]->s_next = a_array[i]->s_next; ~
	b_array[i]->s_prev = a_array[i]->s_ ~

现在输入 "prev;" 来完成。

CTRL-E 命令和 CTRL-Y 类似，但插入的是光标下方的字符。

*24.6*	插入寄存器内容

命令 CTRL-R {register} 插入寄存器的内容。这对于避免输入很长的单词很有用。例如，
你需要输入:

	r = VeryLongFunction(a) + VeryLongFunction(b) + VeryLongFunction(c) ~

函数名在另一个文件中定义。编辑那个文件，将光标移到函数名上，然后将它复制到寄存
器 v 中: >

	"vyiw

"v 是寄存器指定，"yiw" 是复制内词。现在编辑需要插入新行的文件，输入开头的字
符:

	r = ~

然后使用 CTRL-R v 来插入函数名:

	r = VeryLongFunction ~

你继续输入函数名之间的字符，再使用两次 CTRL-R v。
   你也可以用补全来完成同样的操作。当有很多以相同字符开头的单词时，使用寄存器会
更有用。

如果寄存器包含 <BS> 或其他特殊字符，它们会像从键盘输入一样被解释。如果你不希望
这样（你确实想要将 <BS> 插入到文本中），请使用命令 CTRL-R CTRL-R {register}。

*24.7*	缩写

缩写是一个代替长词的短词。例如，"ad" 代表 "advertisement"。Vim 使你能输入缩
写，然后自动展开它。
   要告诉 Vim 每次你输入 "ad" 时将其展开为 "advertisement"，使用以下命令: >

	:iabbrev ad advertisement

现在，当你输入 "ad" 时，整个单词 "advertisement" 将被插入到文本中。这是通过输入
一个不能作为单词一部分的字符来触发的，例如空格:

	输入的内容		你看到的结果
	I saw the a		I saw the a ~
	I saw the ad		I saw the ad ~
	I saw the ad<Space>	I saw the advertisement<Space> ~

当只输入 "ad" 时不会发生展开。这样你就可以输入像 "add" 这样的单词而不会被展
开。只有完整的单词才会被检查是否是缩写。


多个单词的缩写

可以定义展开为多个单词的缩写。例如，要将 "JB" 定义为 "Jack Benny"，使用以下命
令: >

	:iabbrev JB Jack Benny

作为程序员，我使用两个相当不寻常的缩写: >

	:iabbrev #b /****************************************
	:iabbrev #e <Space>****************************************/

这些用于创建框式注释。注释以 #b 开始，画出顶部的线。然后我输入注释文本，用 #e
画出底部的线。
   注意 #e 缩写以空格开头。换句话说，前两个字符是空格-星号。通常 Vim 忽略缩写
和展开之间的空格。为了避免这个问题，我把空格拼写为七个字符: <, S, p, a, c, e,
>。

	备注:
	":iabbrev" 是一个很长的命令。":iab" 也一样有效。
	这就是对缩写命令的缩写！


修正输入错误

常常会反复犯同样的输入错误。例如，输入 "teh" 而不是 "the"。你可以用缩写来修
正: >

	:abbreviate teh the

你可以添加一整个这样的列表。每次发现常见错误时就添加一个。


列出缩写

":abbreviate" 命令列出所有缩写: >

	:abbreviate
	i  #e		  ****************************************/
	i  #b		 /****************************************
	i  JB		 Jack Benny
	i  ad		 advertisement
	!  teh		 the

第一列的 "i" 表示插入模式。这些缩写只在插入模式中生效。其他可能的字符是:

	c	命令行模式			:cabbrev
	!	插入模式和命令行模式		:abbreviate

由于缩写在命令行模式中不太常用，你大多会使用 ":iabbrev" 命令。这样可以避免，例
如，当输入以下命令时 "ad" 被展开: >

	:edit ad


删除缩写

要删除一个缩写，使用 ":unabbreviate" 命令。假设你有以下缩写: >

	:abbreviate @f fresh

你可以用以下命令删除它: >

	:unabbreviate @f

当你输入这个命令时，你会注意到 @f 被展开成了 "fresh"。不用担心，Vim 仍然能理解
（除非你有一个 "fresh" 的缩写，但那是非常不可能的）。
   要删除所有缩写: >

	:abclear

":unabbreviate" 和 ":abclear" 也有插入模式的变体（":iunabbreviate" 和
":iabclear"）以及命令行模式的变体（":cunabbreviate" 和 ":cabclear"）。


重映射缩写

定义缩写时有一件事需要注意: 展开后的字符串不应被映射。例如: >

	:abbreviate @a adder
	:imap dd disk-door

当你输入 @a 时，你会得到 "adisk-doorer"。这不是你想要的。要避免这种情况，使用
":noreabbrev" 命令。它的功能和 ":abbreviate" 相同，但避免展开后的字符串被用于
映射: >

	:noreabbrev @a adder

幸运的是，缩写的结果被映射的情况很少见。

*24.8*	输入特殊字符

CTRL-V 命令用于按字面意义插入下一个字符。换句话说，字符的任何特殊含义都会被忽
略。例如: >

	CTRL-V <Esc>

插入一个 escape 字符。因此你不会离开插入模式。（不要输入 CTRL-V 后面的空格，那
只是为了方便阅读）。

	备注:
	在 MS-Windows 上，CTRL-V 用于粘贴文本。请用 CTRL-Q 代替
	CTRL-V。另一方面，在 Unix 上，CTRL-Q 在某些终端上不起作用，
	因为它有特殊含义。

你也可以使用命令 CTRL-V {digits} 来插入十进制数 {digits} 对应的字符。例如，字
符编号 127 是 <Del> 字符（但不一定是 <Del> 键！）。要插入 <Del> 输入: >

	CTRL-V 127

你可以用这种方式输入最大到 255 的字符。当你输入少于两位数字时，一个非数字字符将
终止命令。为了避免需要输入非数字字符，可以在前面加一个或两个零使其成为三位数:
   以下所有命令都插入一个 <Tab> 然后一个点:

	CTRL-V 9.
	CTRL-V 09.
	CTRL-V 009.

要以十六进制输入字符，在 CTRL-V 后面使用 "x": >

	CTRL-V x7f

这也可以到字符 255（CTRL-V xff）。你可以用 "o" 以八进制输入字符，还有两种方法
可以输入最多 16 位和 32 位的数字（例如，用于 Unicode 字符）: >

	CTRL-V o123
	CTRL-V u1234
	CTRL-V U12345678

*24.9*	二合字母

有些字符不在键盘上。例如，版权符号（©）。要在 Vim 中输入这些字符，可以使用二合
字母，用两个字符代表一个字符。例如，要输入 ©，你按三个键: >

	CTRL-K Co

要了解有哪些可用的二合字母，使用以下命令: >

	:digraphs

Vim 会显示二合字母表。以下是其中的三行:

  AC ~_ 159  NS |  160  !I ¡  161  Ct ¢  162  Pd £  163  Cu ¤  164  Ye ¥  165 ~
  BB ¦  166  SE §  167  ': ¨  168  Co ©  169  -a ª  170  << «  171  NO ¬  172 ~
  -- ­  173  Rg ®  174  'm ¯  175  DG °  176  +- ±  177  2S ²  178  3S ³  179 ~

例如，这显示你输入 CTRL-K Pd 得到的字符是（£）。这是字符编号 163（十进制）。
   Pd 是 Pound 的缩写。大多数二合字母都经过选择，能让你猜出它们会产生什么字
符。如果你浏览列表，就能理解其中的逻辑。
   你可以交换第一个和第二个字符，如果没有该组合的二合字母的话。因此 CTRL-K dP
也有效。由于没有 "dP" 的二合字母，Vim 也会搜索 "Pd" 的二合字母。

	备注:
	二合字母取决于 Vim 假定你使用的字符集。始终使用 ":digraphs"
	来查看当前可用的二合字母。

你可以通过指定目标字符的十进制数字来定义自己的二合字母。示例: >

	:digraph a\" 228

这定义了 CTRL-K a" 插入一个 ä 字符。注意: 我们必须转义 " 字符，否则它会被当作
注释字符。

关于二合字母的更多信息请参见: |digraphs|
   插入特殊字符的另一种方法是使用键映射表。更多信息请参见: |45.5|

*24.10*	普通模式命令

插入模式提供的命令数量有限。在普通模式中你有更多命令可用。当你想使用某个普通模
式命令时，通常先用 <Esc> 离开插入模式，执行普通模式命令，然后用 "i" 或 "a" 重
新进入插入模式。
   有一种更快的方法。使用 CTRL-O {command} 你可以从插入模式执行任何普通模式命
令。例如，要从光标处删除到行尾: >

	CTRL-O D

这种方式一次只能执行一个普通模式命令。但你可以指定寄存器或计数。一个更复杂的例
子: >

	CTRL-O "g3dw

这将删除到第三个单词并放入寄存器 g。
