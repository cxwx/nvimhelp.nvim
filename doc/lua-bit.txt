Lua BitOp                                                             *lua-bit*

改编自 https://bitop.luajit.org。

Lua BitOp 是一个 Lua 5.1/5.2 的 C 扩展模块，用于对数字进行位运算操作。

                                       Type |gO| to see the table of contents.

==============================================================================
API 函数                                                         *lua-bit-api*

本 API 函数列表不旨在替代教程。如果你不熟悉所使用的术语，建议先阅读维基百科上
关于位运算的文章 (https://en.wikipedia.org/wiki/Bitwise_operation)。

------------------------------------------------------------------------------
加载 BitOp 模块
                                                               *lua-bit-module*

推荐的使用 BitOp 模块的方式是在每个需要使用其函数的 Lua 文件开头添加以下代码：
>lua
    local bit = require("bit")
<
这样做可以使依赖关系明确，将作用域限制在当前文件内，并且能更快地访问 bit.*
函数。良好的编程习惯是不要依赖全局变量 bit 已被设置（假设应用程序的其他部分
已经加载了该模块）。require 函数确保模块无论如何只会被加载一次。

------------------------------------------------------------------------------
定义快捷方式
                                                            *lua-bit-shortcuts*

将常用的模块函数缓存到局部变量中是一种常见（但非必须的）做法。这相当于一种快捷
方式，可以减少输入量，同时也能加快函数解析速度（仅在被调用数十万次时才有明显
效果）。
>lua
    local bnot = bit.bnot
    local band, bor, bxor = bit.band, bit.bor, bit.bxor
    local lshift, rshift, rol = bit.lshift, bit.rshift, bit.rol
    -- etc...

    -- Example use of the shortcuts:
    local function tr_i(a, b, c, d, x, s)
      return rol(bxor(c, bor(b, bnot(d))) + a + x, s) + b
    end
<

请记住 `and`、`or` 和 `not` 是 Lua 的保留关键字。它们不能用作变量名或字面量
字段名。这就是为什么相应的位运算函数被命名为 `band`、`bor` 和 `bnot`（以及
为了一致性而命名的 `bxor`）。

顺便一提：一个常见的陷阱是使用 bit 作为局部临时变量的名字——不要这样做！ :-)

------------------------------------------------------------------------------
关于示例

以下示例展示的是简短的 Lua 单行代码。它们的预期输出显示在 `-->` 之后。这在
Lua 中被解释为注释标记，因此你可以将整行复制粘贴到 Lua 提示符中进行实验。

请注意，所有位运算都返回有符号的 32 位数字（原因见后文）。默认情况下，它们以
有符号十进制数的形式打印。

为了清晰起见，示例假设定义了一个辅助函数 `printx()`。该函数在所有平台上将
其参数作为无符号 32 位十六进制数打印：
>lua
    function printx(x)
      print("0x"..bit.tohex(x))
    end
<
------------------------------------------------------------------------------
位运算操作
                                                                    *lua-bitop*

bit.tobit({x})                                                    *bit.tobit()*
    将数字规范化到位运算的数值范围并返回。由于所有位运算已经会规范化它们的所有
    输入参数，因此通常不需要此函数。参见 |lua-bit-semantics|。

    示例： >lua
        print(0xffffffff)                --> 4294967295 (see Note)
        print(bit.tobit(0xffffffff))     --> -1
        printx(bit.tobit(0xffffffff))    --> 0xffffffff
        print(bit.tobit(0xffffffff + 1)) --> 0
        print(bit.tobit(2^40 + 1234))    --> 1234
<
    注意：|lua-bit-hex-literals| 解释了为什么前两行打印的数字不同（如果你的
    Lua 安装使用 double 数字类型的话）。

bit.tohex({x} [, {n}])                                            *bit.tohex()*
    将第一个参数转换为十六进制字符串。十六进制位数由可选的第二个参数的绝对值
    给出。1 到 8 之间的正数生成小写十六进制数字。负数生成大写十六进制数字。
    仅使用最低有效的 `4*|n|` 位。默认生成 8 个小写十六进制数字。

    示例： >lua
        print(bit.tohex(1))              --> 00000001
        print(bit.tohex(-1))             --> ffffffff
        print(bit.tohex(0xffffffff))     --> ffffffff
        print(bit.tohex(-1, -8))         --> FFFFFFFF
        print(bit.tohex(0x21, 4))        --> 0021
        print(bit.tohex(0x87654321, 4))  --> 4321
<
bit.bnot({x})                                                      *bit.bnot()*
    返回其参数的按位 `not` 结果。

    示例： >lua
        print(bit.bnot(0))            --> -1
        printx(bit.bnot(0))           --> 0xffffffff
        print(bit.bnot(-1))           --> 0
        print(bit.bnot(0xffffffff))   --> 0
        printx(bit.bnot(0x12345678))  --> 0xedcba987
<
bit.bor({...})                                                      *bit.bor()*
bit.band({...})                                                    *bit.band()*
bit.bxor({...})                                                    *bit.bxor()*
    分别返回所有参数的按位 `or`、按位 `and` 或按位 `xor` 结果。注意允许
    传入两个以上的参数。

    示例： >lua
        print(bit.bor(1, 2, 4, 8))                --> 15
        printx(bit.band(0x12345678, 0xff))        --> 0x00000078
        printx(bit.bxor(0xa5a5f0f0, 0xaa55ff00))  --> 0x0ff00ff0
<
bit.lshift({x}, {n})                                             *bit.lshift()*
bit.rshift{(x}, {n})                                             *bit.rshift()*
bit.arshift{(x}, {n})                                           *bit.arshift()*
    分别返回第一个参数按第二个参数给定的位数进行按位 `逻辑左移`、按位 `逻辑`
    `右移` 或按位 `算术右移` 的结果。

    逻辑移位将第一个参数视为无符号数，并移入 0 位。算术右移将最高有效位视为
    符号位并复制它。仅使用移位计数的低 5 位（缩小到 [0..31] 范围）。

    示例： >lua
        print(bit.lshift(1, 0))              --> 1
        print(bit.lshift(1, 8))              --> 256
        print(bit.lshift(1, 40))             --> 256
        print(bit.rshift(256, 8))            --> 1
        print(bit.rshift(-256, 8))           --> 16777215
        print(bit.arshift(256, 8))           --> 1
        print(bit.arshift(-256, 8))          --> -1
        printx(bit.lshift(0x87654321, 12))   --> 0x54321000
        printx(bit.rshift(0x87654321, 12))   --> 0x00087654
        printx(bit.arshift(0x87654321, 12))  --> 0xfff87654
<
bit.rol({x}, {n})                                                   *bit.rol()*
bit.ror({x}, {n})                                                   *bit.ror()*
    分别返回第一个参数按第二个参数给定的位数进行按位 `左旋转` 或按位 `右旋转`
    的结果。从一侧移出的位会从另一侧移入。

    仅使用旋转计数的低 5 位（缩小到 [0..31] 范围）。

    示例： >lua
        printx(bit.rol(0x12345678, 12))   --> 0x45678123
        printx(bit.ror(0x12345678, 12))   --> 0x67812345
<
bit.bswap({x})                                                    *bit.bswap()*
    交换其参数的字节顺序并返回。可用于将小端序 32 位数字转换为大端序 32 位
    数字，反之亦然。

    示例： >lua
        printx(bit.bswap(0x12345678)) --> 0x78563412
        printx(bit.bswap(0x78563412)) --> 0x12345678
<

示例程序

这是一个（朴素的）埃拉托斯特尼筛法算法的实现。它计算某个最大数字以内的
素数个数。

使用 Lua 表来保存位向量。每个数组索引包含向量的 32 位。使用位运算来访问和
修改它们。注意移位计数不需要掩码处理，因为 BitOp 的移位和旋转函数已经做了
这一步。
>lua
    local bit = require("bit")
    local band, bxor = bit.band, bit.bxor
    local rshift, rol = bit.rshift, bit.rol

    local m = tonumber(arg and arg[1]) or 100000
    if m < 2 then m = 2 end
    local count = 0
    local p = {}

    for i=0,(m+31)/32 do p[i] = -1 end

    for i=2,m do
      if band(rshift(p[rshift(i, 5)], i), 1) ~= 0 then
        count = count + 1
        for j=i+i,m,i do
          local jx = rshift(j, 5)
          p[jx] = band(p[jx], rol(-2, j))
        end
      end
    end

    io.write(string.format("Found %d primes up to %d\n", count, m))
<
Lua BitOp 非常快。此程序在 3 GHz CPU 上使用标准 Lua 安装运行时间不到 90
毫秒，但执行了超过一百万次位运算函数调用。如果你想要更高的速度，请查看
|lua-luajit|。

------------------------------------------------------------------------------
注意事项                                                     *lua-bit-caveats*

有符号结果 ~

从位运算操作返回有符号数字对于来自其他同时具有有符号和无符号类型的编程语言的
程序员来说可能会感到意外。但只要你在所有地方统一处理位运算的结果，这就不会
造成任何问题。

如果你想要可靠的无符号字符串表示，最好使用 `bit.tohex` 格式化结果。避免使用
`string.format` 的 `"%x"` 或 `"%u"` 格式。它们在某些架构上对负数会失败，
在其他架构上可能返回超过 8 个十六进制数字。

你可能还想避免默认的数字到字符串强制转换，因为这是有符号转换。字符串连接和所有
接受字符串参数的标准库函数（如 `print()` 或 `io.write()`）都使用这种强制转换。

条件判断 ~

如果你正在从 C/C++ 转录代码，请注意条件判断中的位运算。在 C/C++ 中，任何非零
值都被隐式视为 `true`。例如这段 C 代码： >c
    if (x & 3) ...
<
不能转换为这样的 Lua 代码： >lua
    if band(x, 3) then ... -- wrong!
<
在 Lua 中，除了 `nil` 和 `false` 之外的所有对象都被视为 `true`。这包括所有
数字。在这种情况下需要与零进行显式比较： >lua
    if band(x, 3) ~= 0 then ... -- correct!

与十六进制字面量比较 ~

将位运算的结果（有符号数字）与十六进制字面量（无符号数字）进行比较需要格外
小心。以下条件表达式可能在你运行的平台上正确或不正确地工作： >lua
    bit.bor(x, 1) == 0xffffffff
<
例如，在使用默认数字类型的 Lua 安装上它永远不会为 true。一些简单的解决方案：

    在比较中永远不要使用大于 0x7fffffff 的十六进制字面量： >lua
        bit.bor(x, 1) == -1
<
    或者在比较之前用 bit.tobit() 转换它们： >lua
        bit.bor(x, 1) == bit.tobit(0xffffffff)
<
    或者使用 bit.bxor() 的通用解决方法： >lua
        bit.bxor(bit.bor(x, 1), 0xffffffff) == 0
<
    或者使用针对特定情况的解决方法： >lua
        bit.rshift(x, 1) == 0x7fffffff
<

运算语义与原理                                            *lua-bit-semantics*


输入和输出范围 ~
                                                          *lua-bit-io-ranges*

位运算不能合理地应用于浮点数（或其底层位模式）。必须先将它们转换为整数进行
运算，然后再转换回浮点数。

定义在所有平台上行为一致的语义是可取的。这决定了所有运算都基于 32 位整数的
最大公约数。`float` 类型仅提供 24 位精度，不适合用于位运算。Lua BitOp 拒绝
在使用此数字类型的 Lua 安装上编译。

位运算仅处理底层位模式，通常忽略符号性（算术右移除外）。不过它们通常被显示
和处理为无符号数。

但 Lua 数字类型必须是有符号的，且可能限制为 32 位。将结果类型定义为无符号数
在跨平台上是不安全的。因此所有位运算都被定义为返回有符号 32 位数字范围内的
结果（转换为 Lua 数字类型）。

                                                        *lua-bit-hex-literals*
十六进制字面量在 Lua 解析器将其转换为 Lua 数字类型之前被视为无符号数。这意味着
如果 Lua 数字类型具有更大的范围，它们可能超出有符号 32 位整数的范围。例如，
0xffffffff 在默认安装中的值为 4294967295，但在嵌入式系统上可能是 -1。非常希望
在位运算中使用时，十六进制字面量在各系统上得到统一处理。所有位运算接受有符号或
无符号 32 位范围内的参数（以及更多，见下文）。具有相同底层位模式的数字在所有
运算中被同等处理。


模运算 ~
                                                        *lua-bit-modular-arith*

n 位整数的算术运算通常基于模 2^n 的模运算规则。当运算的数学结果超出其定义范围
时，数字会回绕。这简化了硬件实现，而且某些算法确实需要这种行为（如许多加密
函数）。

例如，对于 32 位整数：`0xffffffff + 1 = 0`

如果 Lua 数字类型是 32 位整数，则模 2^32 运算可以直接使用。否则必须插入规范化
步骤。模运算应尽可能在所有平台上相同地工作：

- 对于默认的 double 数字类型，参数可以在 ±2^51 范围内，并且仍然可以通过取其
  最低有效 32 位在所有平台上安全地规范化。此限制源自 double 转换为整数的方式。
- 函数 bit.tobit 可用于显式规范化数字以实现模加法或减法。例如 >lua
                bit.tobit(0xffffffff + 1)
  在所有平台上返回 0。
- 参数范围的限制意味着模乘法通常限于将已规范化的数字与小常数相乘。浮点数的
  精度无论如何都限制在 53 位。例如，(2^30+1)^2 在用 double 计算时不会返回
  奇数。

顺便说一下：这里 |lua-bit-shortcuts| 所示的 `tr_i` 函数是（有缺陷的）MD5
加密哈希的非线性函数之一，依赖模运算才能正确运行。其结果被反馈到其他位运算
（未展示），直到最后一步才需要规范化。


受限和未定义行为 ~
                                                      *lua-bit-restrictions*

以下规则旨在给出精确且实用的定义（面向程序员），同时给予实现（解释器和编译器）
最大的灵活性和应用高级优化的自由。强烈建议不要依赖未定义或实现定义的行为。

- 所有类型的浮点数都可以被位运算接受。它们都不会导致错误，但有些可能会触发
  未定义行为：
  - `-0` 在输入时与 `+0` 相同处理，且永远不会作为结果返回。
  - 传入 `±Inf`、`NaN` 或超出 `±2^51` 范围的数字将产生未定义结果。
  - 非整数数字可能以实现定义的方式被舍入或截断。这意味着结果可能在不同的 BitOp
    版本、不同的 Lua 虚拟机、不同的平台甚至解释执行与编译执行之间有所不同
    （如在 LuaJIT 中）。避免将小数传给位运算函数。使用 `math.floor()` 或
    `math.ceil()` 以获得确定的行为。
- Lua 默认提供字符串参数到数字的自动强制转换。此行为在位运算中已被弃用。
