				   从崩溃中恢复


你的电脑崩溃了？而你刚刚花了几个小时在编辑？不要惊慌！Vim 存储了足够的信息来
恢复你的大部分工作。本章向你展示如何找回你的工作，并解释交换文件是如何使用的。

*11.1*	基本恢复

在大多数情况下，恢复文件相当简单，前提是你知道你在编辑哪个文件（并且硬盘仍然
在工作）。用以下命令启动 Vim，加上 "-r" 参数: >

	vim -r help.txt

Vim 将读取交换文件（用于存储你正在编辑的文本）并可能读取原始文件的一些片段。
如果 Vim 恢复了你的修改，你会看到以下信息（当然文件名会不同）:

	Using swap file ".help.txt.swp" ~
	Original file "~/vim/runtime/doc/help.txt" ~
	Recovery completed. You should check if everything is OK. ~
	(You might want to write out this file under another name ~
	and run diff with the original file to check for changes) ~
	You may want to delete the .swp file now. ~

为了安全起见，将这个文件用另一个名字保存: >

	:write help.txt.recovered

将这个文件与原始文件比较，检查你是否得到了预期的结果。Diff 模式在这方面非常
有用 |08.7|。例如: >

	:write help.txt.recovered
	:edit #
	:diffsp help.txt

注意检查原始文件是否包含更新的版本（你在电脑崩溃前刚保存了文件）。还要检查
是否有行丢失（出了问题导致 Vim 无法恢复）。
   如果 Vim 在恢复时产生了警告信息，仔细阅读它们。不过这种情况很少见。

如果恢复的文本和文件内容完全相同，你会得到这个信息:

	Using swap file ".help.txt.swp" ~
	Original file "~/vim/runtime/doc/help.txt" ~
	Recovery completed. Buffer contents equals file contents. ~
	You may want to delete the .swp file now. ~

这通常发生在你已经恢复了修改，或者你在做了修改之后保存了文件。此时可以安全地
删除交换文件。

最后几次修改无法恢复是正常的。Vim 在你大约四秒钟不输入时，或在输入大约两百
个字符后，将修改刷新到磁盘。这由 'updatetime' 和 'updatecount' 选项设置。
因此当系统在 Vim 没来得及保存自己时崩溃，最后一次刷新之后的修改就会丢失。

如果你在编辑时没有文件名，给一个空字符串作为参数: >

	vim -r ""

你必须在正确的目录中，否则 Vim 无法找到交换文件。

*11.2*	交换文件在哪里？

Vim 可以将交换文件存储在多个位置。要找到它，切换到文件所在的目录，然后使用: >

	vim -r

Vim 会列出它能找到的交换文件。它也会在其他目录中查找，这些目录可能包含当前
目录中文件的交换文件。但它不会在其他目录中查找，不会搜索目录树。
   输出可能看起来像这样:

	Swap files found: ~
	   In current directory: ~
	1.    .main.c.swp ~
		  owned by: mool   dated: Tue May 29 21:00:25 2001 ~
		 file name: ~mool/vim/vim6/src/main.c ~
		  modified: YES ~
		 user name: mool   host name: masaka.moolenaar.net ~
		process ID: 12525 ~
	   In directory ~/tmp: ~
	      -- none -- ~
	   In directory /var/tmp: ~
	      -- none -- ~
	   In directory /tmp: ~
	      -- none -- ~

如果有多个看起来可能是你需要的交换文件，会给出一个列表，并请你输入你想使用的
那个的编号。仔细查看日期来决定使用哪一个。
   如果你不知道该使用哪一个，就逐个尝试，检查结果文件是否是你期望的。


使用特定的交换文件

如果你知道需要使用哪个交换文件，可以通过给出交换文件的名字来恢复。Vim 将从
交换文件中找出原始文件的名字。

例如: >
	vim -r .help.txt.swo

当交换文件在与预期不同的目录中时，这也很方便。Vim 将模式为 "*.s[uvw][a-z]"
的文件识别为交换文件。

如果这仍然不起作用，查看 Vim 报告了什么文件名，并相应地重命名文件。检查
'directory' 选项看看 Vim 可能把交换文件放在了哪里。

	注意:
	Vim 尝试通过在 'dir' 选项中的目录中搜索匹配 "filename.sw?" 的文件来
	查找交换文件。如果通配符扩展不起作用（例如当 'shell' 选项无效时），
	Vim 会做最后的尝试来查找文件 "filename.swp"。如果那也失败了，你就必须
	自己给出交换文件的名字才能恢复文件。

*11.3*	是否崩溃了？					*ATTENTION* *E325*

Vim 试图保护你不做蠢事。假设你天真地开始编辑一个文件，期望文件的内容会显示
出来。但 Vim 产生了一条很长的消息:

		E325: ATTENTION ~
	Found a swap file by the name ".main.c.swp" ~
		  owned by: mool   dated: Tue May 29 21:09:28 2001 ~
		 file name: ~mool/vim/vim6/src/main.c ~
		  modified: no ~
		 user name: mool   host name: masaka.moolenaar.net ~
		process ID: 12559 (still running) ~
	While opening file "main.c" ~
		     dated: Tue May 29 19:46:12 2001 ~
 ~
	(1) Another program may be editing the same file. ~
	    If this is the case, be careful not to end up with two ~
	    different instances of the same file when making changes. ~
	    Quit, or continue with caution. ~
 ~
	(2) An edit session for this file crashed. ~
	    If this is the case, use ":recover" or "vim -r main.c" ~
	    to recover the changes (see ":help recovery"). ~
	    If you did this already, delete the swap file ".main.c.swp" ~
	    to avoid this message. ~

你会得到这个消息，是因为 Vim 在开始编辑文件时检查该文件是否已经存在交换文件。
如果有，那一定出了什么问题。可能是以下两种情况之一。

1. 另一个编辑会话正在编辑这个文件。查看消息中 "process ID" 那一行。它可能
   看起来像这样:

		process ID: 12559 (still running) ~

   文本 "(still running)" 表示编辑这个文件的进程运行在同一台电脑上。在非 Unix
   系统上你不会得到这个额外的提示。当通过网络编辑文件时，你可能看不到这个
   提示，因为进程可能运行在另一台电脑上。在这两种情况下你必须自己弄清楚是什么
   情况。
      如果有另一个 Vim 正在编辑同一个文件，继续编辑将导致同一文件有两个版本。
   最后写入的那个将覆盖另一个，导致修改丢失。你最好退出这个 Vim。

2. 交换文件可能是 Vim 或电脑先前崩溃的结果。检查消息中提到的日期。如果交换
   文件的日期比你正在编辑的文件更新，并且出现了这一行:

		modified: YES ~

   那么你很可能有一个值得恢复的崩溃编辑会话。
      如果文件的日期比交换文件的日期更新，那么要么它在崩溃后被修改了（也许你
   之前恢复了它，但没有删除交换文件？），要么文件在崩溃前保存了，但在交换文件
   的最后一次写入之后（那你很幸运: 你甚至不需要那个旧的交换文件）。Vim 会用
   这一额外行来警告你:

      NEWER than swap file! ~


注意在以下情况中 Vim 知道交换文件没有用处，会自动删除它:
- 文件是一个有效的交换文件（魔术数字正确）。
- 文件已修改的标志未设置。
- 进程没有在运行。

你可以用 |FileChangedShell| 自动命令事件来编程处理这种情况。


不可读的交换文件 ~

有时在交换文件名下面会出现这一行

	[cannot be read] ~

这可能是好事也可能是坏事，取决于具体情况。

如果之前的编辑会话崩溃时没有对文件做任何修改，这是好事。那么交换文件的目录
列表会显示它有零字节。你可以删除它然后继续。

如果你没有交换文件的读取权限，这就有点糟糕了。你可能想以只读方式查看文件，
或退出。在多用户系统上，如果你最后的修改是在不同的登录名下做的，注销后用
那个登录名重新登录可能能解决 "读取错误"。或者你可能想找出谁最后编辑（或正在
编辑）这个文件，和他谈谈。

如果这意味着存放交换文件的磁盘有物理读取错误，那就非常糟糕了。幸运的是，
这几乎从不发生。你可能想先以只读方式查看文件（如果可以的话），看看有多少修改
被"忘记"了。如果你是这个文件的负责人，准备好重做你最后的修改。


怎么办？						*swap-exists-choices*

如果支持对话框，你会被要求选择六个选项之一:

  Swap file ".main.c.swp" already exists! ~
  [O]pen Read-Only, (E)dit anyway, (R)ecover, (Q)uit, (A)bort, (D)elete it: ~

O  以只读方式打开文件。当你只想查看文件而不需要恢复时使用。当你知道别人正在
   编辑这个文件，但你只是想看看而不做修改时，可能想使用这个选项。

E  仍然编辑文件。谨慎使用！如果文件正在另一个 Vim 中编辑，你可能最终得到
   两个版本的文件。Vim 会在发生这种情况时尝试警告你，但最好还是小心为妙。

R  从交换文件中恢复文件。当你知道交换文件包含你想要恢复的修改时使用。

Q  退出。这避免了开始编辑文件。当有另一个 Vim 正在编辑同一个文件时使用。
      当你刚启动 Vim 时，这将退出 Vim。当启动 Vim 时在多个窗口中打开文件，
   Vim 仅在第一个文件有交换文件时才退出。当使用编辑命令时，文件不会被加载，
   你会回到之前编辑的文件。

A  中止。和退出类似，但也中止后续的命令。这在加载编辑多个文件的脚本时有用，
   例如有多个窗口的会话。

D  删除交换文件。当你确定不再需要它时使用。例如，当它不包含修改时，或当文件
   本身比交换文件更新时。
      在 Unix 上，只有当创建交换文件的进程看起来没有在运行时才提供这个选项。

如果你没有得到对话框（你运行的 Vim 版本不支持），你必须手动操作。要恢复文件，
使用这个命令: >

	:recover


Vim 不能总是检测到文件的交换文件已经存在。当另一个编辑会话把交换文件放在另一个
目录中，或者在不同的机器上编辑时文件的路径名不同时，就会出现这种情况。因此，
不要依赖 Vim 总是发出警告。

如果你真的不想看到这个消息，可以把 'A' 标志加到 'shortmess' 选项中。但这是
非常不寻常的需求。

有关交换文件的编程访问，见 |swapinfo()|。

*11.4*	深入阅读

|swap-file|	关于交换文件的创建位置和名称的说明。
|:preserve|	手动将交换文件刷新到磁盘。
|:swapname|	查看当前文件的交换文件名。
'updatecount'	在多少次键击后将交换文件刷新到磁盘。
'updatetime'	超时多少时间后将交换文件刷新到磁盘。
'directory'	存储交换文件的目录名列表。
