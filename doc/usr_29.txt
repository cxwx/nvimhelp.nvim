*29.1*	使用标签

什么是标签？它是一个标识符被定义的位置。一个例子是 C 或 C++ 程序中的函数定
义。标签列表保存在标签文件中。Vim 可以利用它从任何位置直接跳转到标签处，即
标识符被定义的位置。
   要为当前目录中所有 C 文件生成标签文件，使用以下命令: >

	ctags *.c

"ctags" 是一个独立的程序。大多数 Unix 系统已经安装了它。如果你还没有，可以
在这里找到 Universal ctags：
	https://ctags.io

推荐使用 Universal ctags，Exuberant ctags 已不再维护。

现在当你在 Vim 中想跳到函数定义时，可以使用以下命令: >

	:tag startlist

这个命令会找到函数 "startlist"，即使它在另一个文件中。
   CTRL-] 命令跳转到光标下的单词所对应的标签。这使得浏览 C 代码变得很方便。
例如，假设你在函数 "write_block" 中。你可以看到它调用了 "write_line"。但
"write_line" 做什么呢？将光标放在 "write_line" 的调用上并按 CTRL-]，你就跳
到了这个函数的定义处。
   "write_line" 函数调用了 "write_char"。你需要弄清楚它做什么。所以你将光标
放在 "write_char" 的调用上并按 CTRL-]。现在你在 "write_char" 的定义处了。
>
	+-------------------------------------+
	|void write_block(char **s; int cnt)  |
	|{				      |
	|   int i;			      |
	|   for (i = 0; i < cnt; ++i)	      |
	|      write_line(s[i]);	      |
	|}	    |			      |
	+-----------|-------------------------+
		    |
	     CTRL-] |
		    |	 +----------------------------+
		    +--> |void write_line(char *s)    |
			 |{			      |
			 |   while (*s != 0)	      |
			 |	write_char(*s++);     |
			 |}	  |		      |
			 +--------|-------------------+
				  |
			   CTRL-] |
				  |    +------------------------------------+
				  +--> |void write_char(char c)		    |
				       |{				    |
				       |    putchar((int)(unsigned char)c); |
				       |}				    |
				       +------------------------------------+
<
":tags" 命令显示你已经经过的标签列表：

	:tags
	  # TO tag	   FROM line  in file/text ~
	  1  1 write_line	   8  write_block.c ~
	  2  1 write_char	   7  write_line.c ~
	> ~
<
现在返回。CTRL-T 命令跳到前一个标签。在上面的例子中，你会回到 "write_line"
函数中调用 "write_char" 的地方。
   这个命令接受一个计数参数，指示向回跳转多少个标签。你已经前进了，现在后
退。让我们再前进。以下命令跳到列表顶端的标签: >

	:tag

你可以在前面加一个计数来向前跳转多个标签。例如：":3tag"。CTRL-T 前面也可以
加计数。
   这些命令允许你用 CTRL-] 沿调用树向下，用 CTRL-T 向上返回。使用 ":tags"
来查看你当前的位置。


分割窗口

":tag" 命令将当前窗口中的文件替换为包含新函数的文件。但假设你不仅想看旧函
数，还想看新函数呢？你可以使用 ":split" 命令分割窗口，然后再使用 ":tag" 命
令。Vim 有一个简写命令可以同时完成这两件事: >
	:stag tagname

要分割当前窗口并跳到光标下的标签，使用以下命令: >

	CTRL-W ]

如果指定了计数，新窗口将为那么多行高。


更多标签文件

当你的文件分布在多个目录中时，你可以在每个目录中创建标签文件。Vim 只能跳转
到该目录中的标签。
   要找到更多标签文件，可以设置 'tags' 选项来包含所有相关的标签文件。例如: >

	:set tags=./tags,./../tags,./*/tags

这会查找与当前文件同目录的标签文件、上一级目录的标签文件以及所有子目录中的
标签文件。
   这已经是相当多的标签文件了，但可能还不够。例如，当你编辑 "~/proj/src" 中
的文件时，你找不到 "~/proj/sub/tags" 标签文件。对于这种情况，Vim 支持在整个
目录树中搜索标签文件。例如: >

	:set tags=~/proj/**/tags


一个标签文件

当 Vim 需要在很多地方搜索标签文件时，你能听到磁盘在转。这可能会有点慢。这
种情况下，最好花时间生成一个大的标签文件。你可以在晚上运行这个任务。
   这需要上面提到的 Universal 或 Exuberant ctags 程序。它提供了搜索整个目录
树的参数: >

	cd ~/proj
	ctags -R .

这样做的好处是 Universal/Exuberant ctags 能识别各种文件类型。因此这不仅适用
于 C 和 C++ 程序，也适用于 Eiffel 甚至 Vim 脚本。参阅 ctags 文档来调整这
个功能。
   现在你只需要告诉 Vim 你的大标签文件在哪里: >

	:set tags=~/proj/tags


多个匹配

当一个函数被定义了多次（或一个方法在多个类中），":tag" 命令会跳到第一个。如
果当前文件中有匹配，那个会被优先使用。
   你现在可以用以下命令跳到同一标签的其他匹配: >

	:tnext

重复这个命令来查找更多匹配。如果有很多，你可以选择跳到哪一个: >

	:tselect tagname

Vim 会给你一个选择列表：

	  # pri kind tag	       file ~
	  1 F	f    mch_init	       os_amiga.c ~
		       mch_init() ~
	  2 F	f    mch_init	       os_mac.c ~
		       mch_init() ~
	  3 F	f    mch_init	       os_msdos.c ~
		       mch_init(void) ~
	  4 F	f    mch_init	       os_riscos.c ~
		       mch_init() ~
	Enter nr of choice (<CR> to abort):  ~

你现在可以输入你想跳到的匹配的编号（在第一列）。其他列中的信息可以帮助你判
断匹配的定义位置。

要在匹配的标签之间移动，可以使用以下命令：

	:tfirst			跳到第一个匹配
	:[count]tprevious	跳到前 [count] 个匹配
	:[count]tnext		跳到后 [count] 个匹配
	:tlast			跳到最后一个匹配

如果省略 [count]，则默认为一。


猜测标签名称

命令行补全是避免输入长标签名的好方法。只需输入开头部分然后按 <Tab>: >

	:tag write_<Tab>

你会得到第一个匹配。如果不是你想要的，继续按 <Tab> 直到找到正确的。
   有时你只知道函数名的一部分。或者你有很多标签以相同字符串开头但结尾不同。
这时你可以告诉 Vim 使用模式来查找标签。
   假设你想跳到包含 "block" 的标签。首先输入: >

	:tag /block

然后使用命令行补全：按 <Tab>。Vim 会找到所有包含 "block" 的标签并使用第一
个匹配。
   标签名前的 "/" 告诉 Vim 后面的不是字面的标签名，而是一个模式。你可以在这
里使用所有搜索模式中的元素。例如，假设你想选择以 "write_" 开头的标签: >

	:tselect /^write_

"^" 指定标签以 "write_" 开头。否则它也会在标签名中间被找到。类似地，末尾的
"$" 确保模式匹配到标签的末尾。


标签浏览器

由于 CTRL-] 会跳转到光标下标识符的定义，你可以使用标识符名称列表作为目录。
这里有一个例子。
   首先创建一个标识符列表（这需要 Universal 或 Exuberant ctags）: >

	ctags --c-types=f -f functions *.c

然后不带文件启动 Vim，在垂直分割的窗口中编辑这个文件: >

	vim
	:vsplit functions

窗口中包含所有函数的列表。还有一些其他内容，但你可以忽略。执行
":setlocal ts=99" 来清理一下。
   在这个窗口中，定义一个映射: >

	:nnoremap <buffer> <CR> 0ye<C-W>w:tag <C-R>"<CR>

将光标移到包含你想跳转的函数的行上。现在按 <Enter>。Vim 会到另一个窗口并跳
到选定的函数。


相关内容

要使标签名忽略大小写，你可以设置 'ignorecase' 同时保持 'tagcase' 为
"followic"，或者将 'tagcase' 设为 "ignore"。

'tagbsearch' 选项告诉标签文件是否已排序。默认假设标签文件已排序，这使标签搜
索快得多，但如果标签文件未排序就不起作用。

'taglength' 选项可以用来告诉 Vim 标签中有效字符的数量。

*29.2*	预览窗口

当你编辑包含函数调用的代码时，你需要使用正确的参数。要知道传递什么值，你可
以查看函数是如何定义的。标签机制在这方面非常好用。最好在另一个窗口中显示定
义。预览窗口可以用于此目的。
   要打开预览窗口来显示函数 "write_char": >

	:ptag write_char

Vim 会打开一个窗口，并跳转到标签 "write_char"。然后它带你回到原来的位置。这
样你就可以继续输入而不需要使用 CTRL-W 命令。
   如果函数名出现在文本中，你可以用以下命令在预览窗口中获取它的定义: >

	CTRL-W }

有一个脚本可以自动显示光标下单词的定义。参见 |CursorHold-example|。

要关闭预览窗口，使用以下命令: >

	:pclose

要在预览窗口中编辑特定文件，使用 ":pedit"。例如，这可以用来编辑头文件: >

	:pedit defs.h

最后，":psearch" 可以用来在当前文件和所有包含的文件中查找一个词，并在预览窗
口中显示匹配。这在使用库函数时特别有用，因为你没有对应的标签文件。例如: >

	:psearch popen

这将在预览窗口中显示 "stdio.h" 文件，其中包含 popen() 的函数原型: >c

	FILE	*popen __P((const char *, const char *));

你可以使用 'previewheight' 选项来指定预览窗口打开时的高度。

*29.3*	在程序中移动

由于程序是结构化的，Vim 可以识别其中的元素。特定的命令可用于在其中移动。
   C 程序通常包含这样的结构: >c

	#ifdef USE_POPEN
	    fd = popen("ls", "r")
	#else
	    fd = fopen("tmp", "w")
	#endif

但可能更长，并且可能嵌套。将光标放在 "#ifdef" 上并按 %。Vim 会跳到 "#else"。
再次按 % 会跳到 "#endif"。再按一次 % 则回到 "#ifdef"。
   当结构嵌套时，Vim 会找到匹配的项。这是检查你是否遗漏了 "#endif" 的好方
法。
   当你在 "#if" - "#endif" 内部的某处时，可以用以下命令跳到起始处: >

	[#

如果你不在 "#if" 或 "#ifdef" 之后，Vim 会发出蜂鸣声。要向前跳到下一个
"#else" 或 "#endif"，使用: >

	]#

这两个命令会跳过它们遇到的任何 "#if" - "#endif" 块。
例如：

	#if defined(HAS_INC_H) ~
	    a = a + inc(); ~
	# ifdef USE_THEME ~
	    a += 3; ~
	# endif ~
	    set_width(a); ~

光标在最后一行时，"[#" 移到第一行。中间的 "#ifdef" - "#endif" 块被跳过。


在代码块中移动

在 C 代码中，代码块用 {} 括起来。这些可以变得很长。要移到外层块的开头，使用
"[[" 命令。使用 "][" 找到结尾。这假设 "{" 和 "}" 在第一列。
   "[{" 命令移到当前块的开头。它跳过同级的 {} 对。"]}" 跳到结尾。
   概览：

			function(int a)
	   +->		{
	   |		    if (a)
	   |	   +->	    {
	[[ |	   |		for (;;)	       --+
	   |	   |	  +->	{			 |
	   |	[{ |	  |	    foo(32);		 |     --+
	   |	   |   [{ |	    if (bar(a))  --+	 | ]}	 |
	   +--	   |	  +--		break;	   | ]}  |	 |
		   |		}		 <-+	 |	 | ][
		   +--		foobar(a)		 |	 |
			    }			       <-+	 |
			}				       <-+

当编写 C++ 或 Java 时，外层 {} 块是类。下一层 {} 是方法。在类内部的某处使用
"[m" 查找方法的前一个起始处。"]m" 查找方法的下一个起始处。

另外，"[]" 向后移到函数的结尾，"]]" 向前移到下一个函数的起始处。函数的结尾
定义为第一列的 "}"。

				int func1(void)
				{
					return 1;
		  +---------->  }
		  |
	      []  |		int func2(void)
		  |	   +->	{
		  |    [[  |		if (flag)
	start	  +--	   +--			return flag;
		  |    ][  |		return 2;
		  |	   +->	}
	      ]]  |
		  |		int func3(void)
		  +---------->	{
					return 3;
				}

别忘了你还可以使用 "%" 在匹配的 ()、{} 和 [] 之间移动。即使它们相隔很多行
也可以。


在括号中移动

"[(" 和 "])" 命令与 "[{" 和 "]}" 类似，但它们针对 () 对而不是 {} 对。
>
				  [(
<		    <--------------------------------
			      <-------
		if (a == b && (c == d || (e > f)) && x > y) ~
				  -------------->
			  --------------------------------> >
				       ])

在注释中移动

要向后移到注释的开头，使用 "[/"。向前移到注释的结尾，使用 "]/"。这只适用于
`/* - */` 注释。
>
	  +->	  +-> /*
	  |    [/ |    * A comment about      --+
       [/ |	  +--  * wonderful life.	| ]/
	  |	       */		      <-+
	  |
	  +--	       foo = bar * 3;	      --+
						| ]/
		       /* a short comment */  <-+
<

*29.4*	查找全局标识符

你正在编辑一个 C 程序，想知道一个变量是声明为 "int" 还是 "unsigned"。一种快
速的方法是使用 "[I" 命令。
   假设光标在单词 "column" 上。输入: >

	[I

Vim 会列出它能找到的所有匹配行。不仅在当前文件中，还在所有包含的文件（以及
它们包含的文件，等等）中。结果看起来像这样: >

	structs.h
	 1:   29     unsigned     column;    /* column number */

与使用标签或预览窗口相比，好处是会搜索包含的文件。在大多数情况下，这能找到
正确的声明。即使标签文件过期了也没关系。即使你没有包含文件的标签也行。
   不过，要让 "[I" 工作，有几件事必须正确。首先，'include' 选项必须指定文件
是如何被包含的。默认值适用于 C 和 C++。对于其他语言你需要更改它。


定位包含文件

   Vim 会在 'path' 选项指定的位置查找包含文件。如果缺少某个目录，某些包含文
件就找不到。你可以用以下命令发现这个问题: >

	:checkpath

它会列出找不到的包含文件。也包括能找到的文件所包含的找不到的文件。输出示例：

	--- Included files not found in path --- ~
	<io.h> ~
	vim.h --> ~
	  <functions.h> ~
	  <clib/exec_protos.h> ~

"io.h" 文件被当前文件包含但找不到。"vim.h" 能找到，因此 ":checkpath" 会检查
它包含的文件。"functions.h" 和 "clib/exec_protos.h" 文件（被 "vim.h" 包含）
找不到。

	备注：
	Vim 不是编译器。它不识别 "#ifdef" 语句。这意味着每个 "#include" 语句
	都会被使用，即使它在 "#if NEVER" 之后。

要修复找不到的文件，向 'path' 选项添加目录。Makefile 是查找相关信息的好地
方。注意包含 "-I" 项的行，例如 "-I/usr/local/X11"。要添加这个目录，使用: >

	:set path+=/usr/local/X11

当有很多子目录时，可以使用 "*" 通配符。例如: >

	:set path+=/usr/*/include

这会找到 "/usr/local/include" 以及 "/usr/X11/include" 中的文件。

当项目有一整棵嵌套的包含文件树时，"**" 项很有用。这会搜索所有子目录。例如:
>

	:set path+=/projects/invent/**/include

这会找到以下目录中的文件：

	/projects/invent/include ~
	/projects/invent/main/include ~
	/projects/invent/main/os/include ~
	等等。

还有更多可能性。查看 'path' 选项的信息。
   如果你想查看实际找到了哪些包含文件，使用以下命令: >

	:checkpath!

你会得到一个（很长的）包含文件列表，它们包含的文件，等等。为了缩短列表，
Vim 对之前已经找到的文件显示 "(Already listed)" 并且不再列出其中的包含文件。


跳转到匹配

"[I" 产生一个只有一行文本的列表。当你想仔细查看第一个项时，可以用以下命令跳
到那一行: >

	[<Tab>

你也可以使用 "[ CTRL-I"，因为 CTRL-I 和按 <Tab> 相同。

"[I" 产生的列表在每行开头有一个数字。当你想跳到第一个以外的其他项时，先输入
数字: >

	3[<Tab>

将跳到列表中的第三项。记住你可以使用 CTRL-O 跳回到你出发的地方。


相关命令

	[i		只列出第一个匹配
	]I		只列出光标以下的项
	]i		只列出光标以下的第一项


查找已定义的标识符

"[I" 命令查找任何标识符。要只查找用 "#define" 定义的宏，使用: >

	[D

同样，这会搜索包含的文件。'define' 选项指定 "[D" 查找的行的格式。你可以更
改它使其适用于 C 或 C++ 以外的语言。
   与 "[D" 相关的命令：

	[d		只列出第一个匹配
	]D		只列出光标以下的项
	]d		只列出光标以下的第一项

*29.5*	查找局部标识符

"[I" 命令搜索包含的文件。要只在当前文件中搜索，并跳到光标下的词首次被使用的
地方: >

	gD

提示：跳到定义（Goto Definition）。这个命令在查找局部声明的变量或函数时非常
有用（C 术语中的 "static"）。例如（光标在 "counter" 上）：
>
	   +->   static int counter = 0;
	   |
	   |     int get_counter(void)
	gD |     {
	   |	     ++counter;
	   +--	     return counter;
		 }
<
要将搜索范围进一步缩小，只在当前函数中查找，使用以下命令: >

	gd

这会回到当前函数的开头，查找光标下的词的第一次出现。实际上，它向后搜索第一
列 "{" 上方的空行。然后从那里向前搜索标识符。例如（光标在 "idx" 上）：
>
		int find_entry(char *name)
		{
	   +->	    int idx;
	   |
	gd |	    for (idx = 0; idx < table_len; ++idx)
	   |		if (strcmp(table[idx].name, name) == 0)
	   +--		    return idx;
		}
<
