==============================================================================
1. 文件类型					*filetypes* *file-types*

Vim 可以检测正在编辑的文件类型。这通过检查文件名来完成，有时也通过检查文件内容
中的特定文本来完成。

							*:filetype* *:filet*
要启用文件类型检测，在你的 vimrc 中使用此命令: >
	:filetype on
每次编辑新文件或现有文件时，Vim 会尝试识别文件类型并设置 'filetype' 选项。
这将触发 FileType 事件，可用于设置语法高亮、设置选项等。

详细信息: ":filetype on" 命令将加载以下文件:
		$VIMRUNTIME/filetype.lua
		$VIMRUNTIME/filetype.vim
	filetype.lua 创建一个自动命令，在所有 BufNewFile 和 BufRead 事件上
	触发。它尝试根据文件的扩展名或名称来检测文件类型。

	filetype.vim 是一个 Vim 脚本，为 BufNewFile 和 BufRead 事件定义
	自动命令。与 filetype.lua 不同，此文件为每个文件类型模式创建单独的
	BufNewFile 和 BufRead 事件。

	如果通过文件名未找到文件类型，则使用文件
	$VIMRUNTIME/scripts.vim 从文件内容来检测。
	当 GUI 正在运行或即将启动时，|menu.vim| 脚本也会被加载。

要添加你自己的文件类型，参见下面的 |new-filetype|。要搜索文件类型的帮助，
在前面加上 "ft-" 并可选地在后面追加 "-syntax"、"-indent" 或 "-plugin"。
例如: >
	:help ft-vim-indent
	:help ft-vim-syntax
	:help ft-man-plugin

如果文件类型未被自动检测到，或者找到了错误的类型，你可以手动设置 'filetype'
选项，或在文件中添加模式行。例如，对于 IDL 文件使用命令: >
	:set filetype=idl

或在文件中添加此 |modeline|: >
	/* vim: set filetype=idl : */
<
						*:filetype-plugin-on*
你可以用以下命令启用为特定文件类型加载插件文件: >
	:filetype plugin on
如果文件类型检测尚未开启，它也会被开启。
这实际上加载了 'runtimepath' 中的文件 "ftplugin.vim"。
结果是当编辑文件时，其插件文件会被加载（如果对检测到的文件类型有对应的插件
文件）。|filetype-plugin|

						*:filetype-plugin-off*
你可以用以下命令再次禁用: >
	:filetype plugin off
文件类型检测不会被关闭。但如果你关闭了文件类型检测，插件也不会被加载。
这实际上加载了 'runtimepath' 中的文件 "ftplugof.vim"。

						*:filetype-indent-on*
你可以用以下命令启用为特定文件类型加载缩进文件: >
	:filetype indent on
如果文件类型检测尚未开启，它也会被开启。
这实际上加载了 'runtimepath' 中的文件 "indent.vim"。
结果是当编辑文件时，其缩进文件会被加载（如果对检测到的文件类型有对应的缩进
文件）。|indent-expression|

						*:filetype-indent-off*
你可以用以下命令再次禁用: >
	:filetype indent off
文件类型检测不会被关闭。但如果你关闭了文件类型检测，缩进文件也不会被加载。
这实际上加载了 'runtimepath' 中的文件 "indoff.vim"。
这会禁用你将要打开的文件的自动缩进。对已打开的文件仍然有效。重置 'autoindent'、
'cindent'、'smartindent' 和/或 'indentexpr' 来禁用已打开文件中的缩进。

						*:filetype-off*
要禁用文件类型检测，使用此命令: >
	:filetype off
这将保留 "plugin" 和 "indent" 的标志，但由于不再检测文件类型，它们在下一次
":filetype on" 之前不会起作用。


概览:						*:filetype-overview*

command				detection	plugin		indent ~
:filetype on			on		unchanged	unchanged
:filetype off			off		unchanged	unchanged
:filetype plugin on		on		on		unchanged
:filetype plugin off		unchanged	off		unchanged
:filetype indent on		on		unchanged	on
:filetype indent off		unchanged	unchanged	off
:filetype plugin indent on	on		on		on
:filetype plugin indent off	unchanged	off		off

要查看当前状态，输入: >
	:filetype
输出看起来像这样: >
	filetype detection:ON  plugin:ON  indent:OFF

文件类型也用于语法高亮。如果使用了 ":syntax on" 命令，文件类型检测也会被安装。
无需在 ":syntax on" 之后执行 ":filetype on"。

要禁用某个文件类型，在你的文件类型文件中添加一行，参见 |remove-filetype|。

							*filetype-detect*
要重新检测文件类型: >
	:filetype detect
当你从空文件开始并输入了可以检测文件类型的文本时使用此命令。例如，当你在
shell 脚本中输入了: "#!/bin/csh"。
   当文件类型检测关闭时，它会先像使用了 "on" 参数一样被启用。

	file name	variable ~

						|ft-aspvbs-syntax|
	`*.asm`		g:asmsyntax		|ft-asm-syntax|

						|ft-aspvbs-syntax|

	`*.cls`		g:filetype_cls
	`*.csh`		g:filetype_csh		|ft-csh-syntax|
	`*.dat`		g:filetype_dat
	`*.def`		g:filetype_def
	`*.dsp`		g:filetype_dsp
	`*.f`		g:filetype_f		|ft-forth-syntax|
	`*.frm`		g:filetype_frm		|ft-form-syntax|
	`*.fs`		g:filetype_fs		|ft-forth-syntax|
	`*.h`		g:c_syntax_for_h	|ft-c-syntax|
	`*.i`		g:filetype_i		|ft-progress-syntax|
	`*.inc`		g:filetype_inc
	`*.int`		g:filetype_int
	`*.lsl`		g:filetype_lsl
	`*.m`		g:filetype_m		|ft-mathematica-syntax|
	`*.mac`		g:filetype_mac

对于少数文件类型，全局变量仅在无法检测到文件类型时使用:
	`*.r`		g:filetype_r	|ft-rexx-syntax|

							*filetype-ignore*
为避免某些文件被检查，使用 g:ft_ignore_pat 变量。默认值设置如下: >
	:let g:ft_ignore_pat = '\.\(Z\|gz\|bz2\|zip\|tgz\)$'
这意味着不检查压缩文件的内容。

							*new-filetype*
如果你想使用的文件类型尚未被检测到，有几种方法可以添加它。推荐的方法是使用
|vim.filetype.add()| 将其添加到 Nvim 的内置文件类型检测机制。如果你想手动
处理检测，请按以下步骤操作:

A. 如果你想覆盖所有默认文件类型检查。
   这通过为每个文件类型编写一个文件来实现。缺点是可能有很多文件。优点是你可以
   简单地将此文件放入正确的目录即可使其工作。
							*ftdetect*
   1. 创建你的用户运行时目录。你通常使用 'runtimepath' 选项的第一项。然后在
      其中创建 "ftdetect" 目录。Unix 示例: >
	:!mkdir -p ~/.config/nvim/ftdetect
<
   2. 创建一个包含检测文件类型的自动命令的文件。示例: >
	au BufRead,BufNewFile *.mine		set filetype=mine
<     注意这里没有 "augroup" 命令，这在加载你的文件时已经完成了。你也可以使用
      模式 "*" 然后检查文件内容来识别它。
      将此文件作为 "mine.vim" 写入你的用户运行时目录中的 "ftdetect" 目录。
      例如，对于 Unix: >
	:w ~/.config/nvim/ftdetect/mine.vim

<  3. 要使用新的文件类型检测你必须重启 Vim。

   "ftdetect" 目录中的文件在所有默认检查之后使用，因此它们可以覆盖之前检测
   到的文件类型。但你也可以使用 |:setfiletype| 来保留之前检测到的文件类型。

B. 如果你想在默认文件类型检查之后检测你的文件。

   这与上面的 A 类似，但使用 ":setfiletype" 而不是无条件设置 'filetype'。
   这只在尚未检测到文件类型时设置 'filetype'。示例: >
	au BufRead,BufNewFile *.txt		setfiletype text
<
   你也可以在命令中使用已检测到的文件类型。例如，当检测到 "pascal" 时使用
   文件类型 "mypascal": >
	au BufRead,BufNewFile *		if &ft == 'pascal' | set ft=mypascal
								       | endif

C. 如果你的文件类型可以通过文件名或扩展名来检测。
   1. 创建你的用户运行时目录。你通常使用 'runtimepath' 选项的第一项。
      Unix 示例: >
	:!mkdir -p ~/.config/nvim
<
   2. 创建一个包含检测文件类型的自动命令的文件。示例: >
	" my filetype file
	if exists("did_load_filetypes")
	  finish
	endif
	augroup filetypedetect
	  au! BufRead,BufNewFile *.mine		setfiletype mine
	  au! BufRead,BufNewFile *.xyz		setfiletype drawing
	augroup END
<
      将此文件作为 "filetype.vim" 写入你的用户运行时目录。例如，对于 Unix: >
	:w ~/.config/nvim/filetype.vim

<   3. 要使用新的文件类型检测你必须重启 Vim。

   你的 filetype.vim 将在安装默认 FileType 自动命令之前被加载。你的自动命令
   将首先匹配，":setfiletype" 命令将确保之后不会再有其他自动命令设置
   'filetype'。
							*new-filetype-scripts*
D. 如果你的文件类型只能通过检查文件内容来检测。

   1. 创建你的用户运行时目录。你通常使用 'runtimepath' 选项的第一项。
      Unix 示例: >
	:!mkdir -p ~/.config/nvim
<
   2. 创建一个 Vim 脚本文件来完成此操作。示例: >
	if did_filetype()	" 文件类型已设置..
	  finish		" ..不做这些检查
	endif
	if getline(1) =~ '^#!.*\<mine\>'
	  setfiletype mine
	elseif getline(1) =~? '\<drawing\>'
	  setfiletype drawing
	endif
<     更多示例参见 $VIMRUNTIME/scripts.vim。
      将此文件作为 "scripts.vim" 写入你的用户运行时目录。例如，对于 Unix: >
	:w ~/.config/nvim/scripts.vim
<
   3. 检测将立即生效，无需重启 Vim。

   你的 scripts.vim 在默认文件类型检查之前加载，这意味着你的规则覆盖
   $VIMRUNTIME/scripts.vim 中的默认规则。

							*remove-filetype*
如果检测到的文件类型对你来说是错误的，你可以将 'filetype' 设置为一个不存在的
名称如 `ignored` 来避免之后仍然被设置。

						     *g:did_load_filetypes*
Nvim 提供的内置文件类型检测可以通过设置 `did_load_filetypes` 全局变量来禁用。
如果此变量存在，默认的 `$VIMRUNTIME/filetype.lua` 将不会运行。

							*plugin-details*
"plugin" 目录可以在 'runtimepath' 选项中的任何目录中。所有这些目录都将被
搜索插件，它们都会被加载。例如，如果此命令: >

	set runtimepath

产生此输出: >

	runtimepath=/etc/vim,~/.config/nvim,/usr/local/share/vim/vim82

则 Vim 将加载以下目录及其子目录中的所有插件: >

	/etc/vim/plugin/
	~/.config/nvim/plugin/
	/usr/local/share/vim/vim82/plugin/

注意最后一个是 $VIMRUNTIME 的值，已被展开。

注意当使用插件管理器或 |packages| 时，许多目录会被添加到 'runtimepath'。
这些插件各自需要自己的目录，不要直接将它们放在 ~/.config/nvim/plugin 中。

如果看起来你的插件没有被加载怎么办？你可以通过使用 |-V| 参数来找出 Vim 启动
时发生了什么: >

	vim -V2

你会看到很多消息，其中有关于加载插件的说明。它以这样的内容开始: >

	Searching for "plugin/**/*.vim" in

在那里你可以看到 Vim 在哪里寻找你的插件脚本。

2. 文件类型插件					*filetype-plugins*

当已启用加载文件类型插件 |:filetype-plugin-on| 时，选项将被设置并定义映射。
这些都是缓冲区局部的，它们不会用于其他文件。

为文件类型定义映射可能会妨碍你自己定义的映射。有几种方法可以避免这种情况:
1. 将 "maplocalleader" 变量设置为你想要映射开头的键序列。示例: >
	:let maplocalleader = ","
<  所有映射将以逗号开头，而不是默认的反斜杠。也参见 |<LocalLeader>|。

2. 定义你自己的映射。示例: >
	:map ,p <Plug>MailQuote
<  你需要查看下面插件文件的描述来了解它提供的功能和要映射到的字符串。
   你需要在插件加载之前（在编辑该类型的文件之前）定义你自己的映射。然后插件
   将跳过安装默认映射。
					*no_mail_maps* *g:no_mail_maps*
3. 通过设置一个包含文件类型名称的变量来禁用特定文件类型的映射定义。对于
   "mail" 文件类型这将是: >
	:let no_mail_maps = 1
<				*no_plugin_maps* *g:no_plugin_maps*
4. 通过设置一个变量来禁用所有文件类型的映射定义: >
	:let no_plugin_maps = 1
<

							*ftplugin-overrule*
如果全局文件类型插件不完全符合你的要求，有三种方法可以更改:

1. 添加一些设置。
   你必须在 'runtimepath' 中较早的目录中创建新的文件类型插件。对于 Unix，
   例如你可以使用此文件: >
	vim ~/.config/nvim/ftplugin/fortran.vim
<   你可以设置你想添加的设置和映射。注意全局插件将在此之后加载，它可能覆盖
   你在这里做的设置。如果是这种情况，你需要使用以下两种方法之一。

2. 复制插件并更改。
   你必须将副本放在 'runtimepath' 中较早的目录中。对于 Unix，例如你可以
   这样做: >
	cp $VIMRUNTIME/ftplugin/fortran.vim ~/.config/nvim/ftplugin/fortran.vim
<   然后你可以根据喜好编辑复制的文件。由于 b:did_ftplugin 变量将被设置，
   全局插件将不会被加载。
   这种方法的缺点是当分发的插件改进时，你必须再次复制和修改。

3. 在加载全局插件之后覆盖设置。
   你必须在 'runtimepath' 末尾的目录中创建新的文件类型插件。对于 Unix，
   例如你可以使用此文件: >
	vim ~/.config/nvim/after/ftplugin/fortran.vim
<   在此文件中你只更改你想更改的设置。

3.  默认文件类型插件的文档。			*ftplugin-docs*


					*plugin_exec* *g:plugin_exec*
启用执行外部命令。这在历史上是为了例如 perl 文件类型插件（和其他一些）来设置
搜索路径而做的。出于安全原因默认禁用: >
	:let g:plugin_exec = 1
也可以仅为某些文件类型启用: >
	:let g:<filetype>_exec = 1
因此要仅为 ruby 启用，设置以下变量: >
	:let g:ruby_exec = 1

如果全局 `plugin_exec` 和 `<filetype>_exec` 特定变量都已设置，文件类型特定
变量应优先。


ASCIIDOC						*ft-asciidoc-plugin*

要启用 |folding| 使用: >
	let g:asciidoc_folding = 1

要禁用折叠标题的嵌套使用: >
	let g:asciidoc_foldnested = 0

要禁用折叠标题下的所有内容使用: >
	let asciidoc_fold_under_title = 0


ARDUINO							*ft-arduino-plugin*

默认设置以下选项，符合 Arduino IDE 的默认设置: >

	setlocal expandtab tabstop=2 softtabstop=2 shiftwidth=2

要禁用此行为，在你的 vimrc 中设置以下变量: >

	let g:arduino_recommended_style = 0


AWK							*ft-awk-plugin*

可以通过设置以下内容来启用对 GNU Awk 特有功能（如 @include）的支持: >
	:let g:awk_is_gawk = 1


CHANGELOG						*ft-changelog-plugin*

允许在 Changelog 文件中轻松输入 Changelog 条目。有一些值得探索的命令、映射和
变量:

选项:
'comments'		被设为空以不打乱格式。
'textwidth'		被设为 78，这是标准的。
'formatoptions'		添加 't' 标志以在插入文本时换行。

命令:
NewChangelogEntry	以智能方式添加新的 Changelog 条目（见下文）。

局部映射:
<Leader>o		以同样智能的方式开始新的 Changelog 条目（见下文）。

全局映射:
			注意: 全局映射通过先加载 ftplugin/changelog.vim 文件来
			访问，例如在你的 |init.vim| 中使用 >
				runtime ftplugin/changelog.vim
<
<Leader>o		切换到为当前目录打开的 ChangeLog 缓冲区，如果它存在于
			当前目录中则在新缓冲区中打开。然后执行与上述局部
			<Leader>o 相同的操作。

变量:
g:changelog_timeformat  已弃用；改用 g:changelog_dateformat。
g:changelog_dateformat	ChangeLog 条目中使用的日期（和时间）格式。
			接受的格式与 |strftime()| 函数相同。
			默认是 "%Y-%m-%d"，这是许多 ChangeLog 布局的标准格式。
g:changelog_username	用户的名称和电子邮件地址。
			默认从环境变量和系统文件推导。它搜索 /etc/passwd 中
			当前用户的注释部分，该部分非正式地包含用户的真实姓名
			直到第一个分隔逗号。然后检查 $NAME 环境变量，最后
			运行 `whoami` 和 `hostname` 来构建电子邮件地址。
			最终形式是 >
				Full Name  <user@host>
<
g:changelog_new_date_format
			创建新日期条目时使用的格式。以下表格描述了字符串中的
			特殊标记:
				%%	插入单个 '%' 字符
				%d	插入上面的日期
				%u	插入上面的用户
				%p	插入 b:changelog_entry_prefix 的结果
				%c	完成后光标定位的位置
			默认是 "%d  %u\n\n\t* %p%c\n\n"，产生类似以下的内容
			（| 是光标将在的位置，除非在行首它表示行的开始）>
				|2003-01-14  Full Name  <user@host>
				|
				|        * prefix|
<
g:changelog_new_entry_format
			创建新条目时使用的格式。以下表格描述了字符串中的特殊
			标记:
				%p	插入 b:changelog_entry_prefix 的结果
				%c	完成后光标定位的位置
			默认是 "\t*%c"，产生类似以下的内容 >
				|        * prefix|
<
g:changelog_date_entry_search
			搜索日期条目时使用的搜索模式。
			可以使用与 g:changelog_new_date_format 相同的标记。
			默认是 '^\s*%d\_s*%u'，匹配以下形式的行 >
				|2003-01-14  Full Name  <user@host>
<			以及一些类似格式。

g:changelog_date_end_entry_search
			搜索日期条目结尾时使用的搜索模式。
			可以使用与 g:changelog_new_date_format 相同的标记。
			默认是 '^\s*$'，匹配只包含空白或完全为空的行。

b:changelog_name					*b:changelog_name*
			要查找的 ChangeLog 文件名。默认是 'ChangeLog'。

b:changelog_path

标签折叠带来一些困难。许多元素（如 `blockquote`）总是由开始和结束标签界定；
某些元素（如 `p`）的结束标签在某些上下文中可以省略；空元素（如 `hr`）没有

作用域中的元素。假设语法正确，结束标签可以与其在作用域中可发现的最近匹配的

计算: >

<
要强制另一次重新计算，执行: >
	unlet! b:foldsmap
	normal zx

在 Nvim 中查看手册页。支持高亮、补全、语言环境和导航。也参见 |find-manpage|。

SHADA							*ft-shada*

允许以友好的方式编辑二进制 |shada-file|。打开的二进制文件以以下格式显示: >

    Type with timestamp YYYY-mm-ddTHH:MM:SS:
      % Key__  Description___  Value
      + fooba  foo bar baz fo  {msgpack-value}
      + abcde  abc def ghi jk  {msgpack-value}
    Other type with timestamp YYYY-mm-ddTHH:MM:SS:
      @ Description__  Value
      - foo bar baz t  {msgpack-value}
      # Expected more elements in list
    Some other type with timestamp YYYY-mm-ddTHH:MM:SS:
      # Unexpected type: type instead of map
      = {msgpack-value}

文件类型插件定义所有 |Cmd-event|。定义的 |SourceCmd| 事件使
"source file.shada" 等价于 "|:rshada| file.shada"。|BufWriteCmd|、
|FileWriteCmd| 和 |FileAppendCmd| 事件受以下设置影响:

*g:shada#keep_old_header*	布尔值，如果设为 false 则写入时忽略所有头部
				条目。默认为 1。
*g:shada#add_own_header*	布尔值，如果设为 true 则第一个写入的条目将
				始终是头部条目，在映射中带有两个值的附加
				数据: |v:version| 附加到 "version" 键，
				"shada.vim" 附加到 "generator" 键。默认为 1。

格式说明:

1. `#` 开始注释。以空格字符开头然后 `#` 的行被忽略。插件可能只添加注释行来
   指示 ShaDa 格式中的某些错误。不包含非空白字符的行也被忽略。
2. 每个条目以格式为 "{type} with timestamp {timestamp}:" 的行开始。
   {timestamp} 是表示实际 Unix 时间戳值的 |strftime()| 格式化字符串。第一个
   strftime() 参数等于 `%Y-%m-%dT%H:%M:%S`。写入时此时间戳使用
   |msgpack#strptime()| 解析，带缓存（它记住哪个时间戳产生了特定的
   strftime() 输出，如果你没有更改时间戳则使用此值）。{type} 是以下之一
    1 - Header
    2 - Search pattern
    3 - Replacement string
    4 - History entry
    5 - Register
    6 - Variable
    7 - Global mark
    8 - Jump
    9 - Buffer list
   10 - Local mark
   11 - Change
    * - Unknown (0x{type-hex})

   每种类型都可以使用 Unknown 条目表示: "Jump with timestamp ..." 与
   "Unknown (0x8) with timestamp ...." 相同。
3. 头部之后是以下行之一:
   1. "  % Key__  Description__  Value": 映射头部。映射头部后面是一个表格，
      可以包含注释和由 "  +"、键、描述和 |{msgpack-value}| 组成的行。键与
      描述之间至少有两个空格分隔，描述与值之间至少有两个空格分隔。映射中的
      每个键最多与 "Key__" 头部一样宽: "Key" 允许最多 3 字节的键，"Key__"
      允许最多 5 字节的键。如果键实际占用更少字节则其余用空格填充。键不能为
      空、以空格结尾、包含两个连续空格或包含多字节字符（如果需要请使用 "="
      格式）。描述对宽度和内容有相同的限制，但允许空描述。描述列可以省略。

      写入时描述被忽略。值与默认值 |msgpack#equal| 的键被忽略。键的顺序被
      保留。所有键被视为字符串（不是二进制字符串）。

      注意: 特别是对于缓冲区列表条目，允许有多个映射头部。每个映射头部在
      缓冲区列表内开始一个新的映射条目，因为 ShaDa 缓冲区列表条目是映射
      的数组。即 >

        Buffer list with timestamp 1970-01-01T00:00:00:
          % Key  Description  Value
          + f    file name    "/foo"
          + l    line number  1
          + c    column       10
<
      等价于 >

        Buffer list with timestamp 1970-01-01T00:00:00:
          = [{="f": "/foo", ="c": 10}]
<
      而 >

        Buffer list with timestamp 1970-01-01T00:00:00:
          % Key  Description  Value
          + f    file name    "/foo"

          % Key  Description  Value
          + f    file name    "/bar"
<
      等价于 >

        Buffer list with timestamp 1970-01-01T00:00:00:
          = [{="f": "/foo"}, {="f": "/bar"}]
<
      注意 2: 特别是对于寄存器条目，设计了特殊的数组语法: >

        Register with timestamp 1970-01-01T00:00:00:
          % Key  Description  Value
          + rc   contents     @
          | - "line1"
          | - "line2"
<
      这等价于 >

        Register with timestamp 1970-01-01T00:00:00:
          % Key  Description  Value
          + rc   contents     ["line1", "line2"]
<
      如果数组表示看起来太长，将自动使用这种语法。
   2. "  @  Description__  Value": 数组头部。与映射相同，但省略了键且描述
      不能省略。数组条目以 "  -" 开头。示例: >

        History entry with timestamp 1970-01-01T00:00:00:
          @ Description_  Value
          - history type  SEARCH
          - contents      "foo"
          - separator     '/'
<
      等价于 >

        History entry with timestamp 1970-01-01T00:00:00:
          = [SEARCH, "foo", '/']
<
      注意: 这里不识别寄存器条目的特殊数组语法。
   3. "  = {msgpack-value}": 原始值。此处的 |{msgpack-value}| 可以有任何
      类型。这里也不识别寄存器条目的特殊数组语法。

TEX						*ft-tex-plugin* *g:tex_flavor*

如果 `*.tex` 文件的第一行形如 >
	%&<format>
则这决定了文件类型: plaintex（用于 plain TeX）、context（用于 ConTeXt）或
tex（用于 LaTeX）。否则，搜索文件中的关键字来选择 context 或 tex。如果未找到
关键字，默认为 plaintex。你可以通过定义变量 g:tex_flavor 为你最常用的格式
（不是文件类型）来更改默认值。使用以下之一: >
	let g:tex_flavor = "plain"
	let g:tex_flavor = "context"
	let g:tex_flavor = "latex"
目前不识别其他格式。

ZIG							*ft-zig-plugin*

						*g:zig_recommended_style*
默认根据 Zig 的推荐风格
(https://ziglang.org/documentation/master/) 设置以下缩进选项: >

	setlocal expandtab shiftwidth=4 softtabstop=4 tabstop=8
<
要禁用此行为，将 |g:zig_recommended_style| 设为 0: >

	let g:zig_recommended_style = 0
<
							*g:zig_std_dir*
Zig 标准库的路径。Zig |ftplugin| 读取 |g:zig_std_dir| 并将其追加到 Zig 文件
的 'path'。Zig 标准库的位置取决于系统和安装方法。

可以使用 `zig env` 自动设置 |g:zig_std_dir|: >

	let g:zig_std_dir = json_decode(system('zig env'))['std_dir']
<
这可以例如放在 FileType |:autocmd| 或用户 |ftplugin| 中，以仅在打开 Zig 文件
时加载。
