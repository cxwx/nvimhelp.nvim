*30.1*	编译

Vim 有一组被称为 "quickfix" 的命令。它们让你可以在 Vim 内编译程序，然后逐一
查看生成的错误并修复它们（希望如此）。然后你可以重新编译并修复发现的新错误，
直到最终你的程序编译通过没有任何错误。

以下命令运行 "make" 程序（传入你给的参数）并捕获结果: >

	:make {arguments}

如果产生了错误，它们会被捕获，编辑器会将你定位到第一个错误发生的位置。
   让我们看一个 ":make" 会话的例子。（典型的 :make 会话产生的错误更多，愚蠢
的错误更少。）输入 ":make" 后，屏幕看起来像这样：

	:!make | &tee /tmp/vim215953.err ~
	gcc -g -Wall -o prog main.c sub.c ~
	main.c: In function 'main': ~
	main.c:6: too many arguments to function 'do_sub' ~
	main.c: At top level: ~
	main.c:10: parse error before '}' ~
	make: *** [prog] Error 1 ~

	2 returned ~
	"main.c" 11L, 111C ~
	(3 of 6): too many arguments to function 'do_sub' ~
	Press ENTER or type command to continue ~

从中你可以看到文件 "main.c" 中有错误。当你按 <Enter> 时，Vim 显示文件
"main.c"，光标定位在第 6 行，即第一个有错误的行。你不需要指定文件或行号，
Vim 通过查看错误信息就知道该去哪里。
>
		+---------------------------------------------------+
		|int main()					    |
		|{						    |
		|	int i=3;				    |
      cursor -> |	do_sub("foo");				    |
		|	++i;					    |
		|	return (0);				    |
		|}						    |
		|}						    |
		| ~						    |
		|(3 of 12): too many arguments to function 'do_sub' |
		+---------------------------------------------------+
<
以下命令跳到下一个错误发生的位置: >

	:cnext

Vim 跳到第 10 行，文件的最后一行，那里有一个多余的 '}'。
   当空间不够时，Vim 会缩短错误信息。要看完整的信息，使用: >

	:cc

你可以用 ":clist" 命令获得所有错误信息的概览。输出看起来像这样: >

	:clist
<	3 main.c: 6:too many arguments to function 'do_sub' ~
	5 main.c: 10:parse error before '}' ~

这里只列出了 Vim 识别出文件名和行号的行。它假设这些是有意义的行，其余的只是
无聊的信息。但有时未识别的行确实包含你想看的内容。例如链接器输出的关于未定
义函数的信息。要看所有信息，在命令后加 "!": >

	:clist!
<	1 gcc -g -Wall -o prog main.c sub.c ~
	2 main.c: In function 'main': ~
	3 main.c:6: too many arguments to function 'do_sub' ~
	4 main.c: At top level: ~
	5 main.c:10: parse error before '}' ~
	6 make: *** [prog] Error 1 ~

Vim 会高亮当前错误。要回到前一个错误，使用:
>
	:cprevious

其他在错误列表中移动的命令：

	:cfirst		跳到第一个错误
	:clast		跳到最后一个错误
	:cc 3		跳到第 3 个错误


使用其他编译器

执行 ":make" 命令时运行的程序名由 'makeprg' 选项定义。通常设为 "make"，但
Visual C++ 用户应通过执行以下命令将其设为 "nmake": >

	:set makeprg=nmake

你也可以在此选项中包含参数。特殊字符需要用反斜杠转义。例如: >

	:set makeprg=nmake\ -f\ project.mak

你可以在命令规格中包含特殊的 Vim 关键字。% 字符扩展为当前文件名。所以如果你
执行以下命令: >
	:set makeprg=make\ %:S

当你编辑 main.c 时，":make" 会执行以下命令: >

	make main.c

这不太有用，所以你可以用 :r（root，根名）修饰符来改进: >

	:set makeprg=make\ %:r:S.o

现在执行的命令如下: >

	make main.o

关于这些修饰符的更多信息: |filename-modifiers|。


旧的错误列表

假设你 ":make" 一个程序。一个文件中有一个警告信息，另一个文件中有一个错误信
息。你修复了错误并再次使用 ":make" 来检查是否真的修好了。现在你想查看那个警
告信息。它不会出现在最新的错误列表中，因为有警告的文件没有被重新编译。你可
以用以下命令回到前一个错误列表: >

	:colder

然后使用 ":clist" 和 ":cc {nr}" 跳到有警告的位置。
   要前进到下一个错误列表: >

	:cnewer

Vim 记住十个错误列表。


切换编译器

你需要告诉 Vim 你的编译器产生的错误信息格式。这通过 'errorformat' 选项来完
成。这个选项的语法相当复杂，可以适配几乎任何编译器。你可以在这里找到说明:
|errorformat|。

你可能使用各种不同的编译器。每次设置 'makeprg' 选项，尤其是 'errorformat'
并不容易。Vim 为此提供了一个简单的方法。例如，要切换到使用 Microsoft Visual
C++ 编译器: >

	:compiler msvc

这会找到 "msvc" 编译器的 Vim 脚本并设置适当的选项。
   你可以编写自己的编译器文件。参见 |write-compiler-plugin|。


输出重定向

":make" 命令将执行的程序的输出重定向到一个错误文件。这如何工作取决于各种因
素，例如 'shell'。如果你的 ":make" 命令不能捕获输出，检查 'makeef' 和
'shellpipe' 选项。'shellquote' 和 'shellxquote' 选项可能也有关系。

如果你无法让 ":make" 重定向文件，另一种方法是在另一个窗口中编译程序并将输出
重定向到一个文件。然后让 Vim 用以下命令读取这个文件: >

	:cfile {filename}

跳转到错误的功能与 ":make" 命令相同。

*30.2*	C 风格文本缩进

当行被正确缩进时，程序更容易理解。Vim 提供了多种方式来减少这方面的工作量。
对于 C 或 C 风格的程序如 Java 或 C++，设置 'cindent' 选项。Vim 对 C 程序有
很多了解，会努力自动为你设置缩进。将 'shiftwidth' 选项设为你想要的每一层缩
进的空格数。四个空格就很好。一个 ":set" 命令就够了: >

	:set cindent shiftwidth=4

启用此选项后，当你输入类似 "if (x)" 的内容时，下一行会自动增加一级缩进。

				    if (flag)
	自动缩进       --->		do_the_work();
	自动反缩进     <--	    if (other_flag) {
	自动缩进       --->		do_file();
	保持缩进			do_some_more();
	自动反缩进     <--	    }

当你在花括号 ({}) 中输入内容时，文本会在开始处缩进，在结尾处反缩进。反缩进
在你输入 '}' 之后发生，因为 Vim 无法猜到你要输入什么。

自动缩进的一个副作用是它帮助你及早发现代码中的错误。当你输入 } 来结束一个函
数时，却发现自动缩进给出的缩进比预期多，那么可能缺少了一个 }。使用 "%" 命
令来找出你输入的 } 对应的 {。
   缺少 ) 和 ; 也会导致额外的缩进。因此如果你得到的空白比预期多，检查前面的
行。

当你的代码格式很乱，或者你插入和删除了行，你需要重新缩进这些行。"=" 操作符
可以做到这一点。最简单的形式是: >

	==

这将缩进当前行。像所有操作符一样，有三种使用方式。在可视模式下 "=" 缩进选
中的行。一个有用的文本对象是 "a{"。这选择当前的 {} 块。因此，要重新缩进光标
所在的代码块: >

	=a{

如果你的代码缩进真的很糟糕，你可以用以下命令重新缩进整个文件:
>
	gg=G

不过，不要对那些已经仔细手动缩进的文件这样做。自动缩进做得很好，但在某些情
况下你可能想要覆盖它。


设置缩进风格

不同的人有不同的缩进风格。默认情况下 Vim 的缩进方式适合 90% 的程序员。但也
有不同的风格；如果你想要，可以用 'cinoptions' 选项来自定义缩进风格。
   默认情况下 'cinoptions' 为空，Vim 使用默认风格。你可以添加各种项来改变你
想要的地方。例如，要让花括号像这样放置：

	if (flag) ~
	  { ~
	    i = 8; ~
	    j = 0; ~
	  } ~

使用这个命令: >

	:set cinoptions+={2

有很多这样的项。参见 |cinoptions-values|。

*30.3*	自动缩进

你不想每次编辑 C 文件时都手动打开 'cindent' 选项。以下是让它自动工作的方
法: >

	:filetype indent on

实际上，这不仅仅是为 C 文件打开 'cindent'。首先，它启用文件类型检测。这和
语法高亮使用的是同样的机制。
   当文件类型已知时，Vim 会搜索该文件类型的缩进文件。Vim 发行版包含许多不同
编程语言的缩进文件。这个缩进文件会为该文件类型专门准备自动缩进。

如果你不喜欢自动缩进，可以再次关闭它: >

	:filetype indent off

如果你不喜欢某个特定文件类型的缩进，以下是避免它的方法。创建一个只包含这一
行的文件: >

	:let b:did_indent = 1

现在你需要将这个文件保存为具有特定名称的文件：

	{directory}/indent/{filetype}.vim

{filetype} 是文件类型的名称，如 "cpp" 或 "java"。你可以用以下命令查看 Vim
检测到的确切名称: >

	:set filetype

在这个文件中输出是：

	filetype=help ~

因此你应使用 "help" 作为 {filetype}。
   对于 {directory} 部分，你需要使用你的运行时目录。查看以下命令的输出: >

	set runtimepath

然后使用第一项，即第一个逗号之前的名称。如果输出看起来像这样：

	runtimepath=~/.config/nvim,/usr/local/share/vim/vim60/runtime,~/.config/nvim/after ~

你应使用 "~/.config/nvim" 作为 {directory}。那么最终的文件名就是：

	~/.config/nvim/indent/help.vim ~

你也可以编写自己的缩进文件来替代关闭缩进。如何做请参见: |indent-expression|。

*30.4*	其他缩进

最简单的自动缩进形式是使用 'autoindent' 选项。它使用上一行的缩进。稍微聪明
一些的是 'smartindent' 选项。它对没有缩进文件的语言很有用。'smartindent' 没
有 'cindent' 那么聪明，但比 'autoindent' 聪明。
   设置 'smartindent' 后，每个 { 增加一级缩进，每个 } 减少一级。'cinwords'
选项中的任何词也会增加一级缩进。以 # 开头的行被特殊对待：移除所有缩进。这
样做是为了让预处理指令都从第一列开始。下一行的缩进会恢复。


修正缩进

当你使用 'autoindent' 或 'smartindent' 来获取上一行的缩进时，很多时候你需要
增加或减少一个 'shiftwidth' 的缩进。一种快速方法是在插入模式下使用 CTRL-D
和 CTRL-T 命令。
   例如，你正在输入一个 shell 脚本，它应该看起来像这样：

	if test -n a; then ~
	   echo a ~
	   echo "-------" ~
	fi ~

先设置以下选项: >

	:set autoindent shiftwidth=3

你开始输入第一行，<Enter> 和第二行的开头：

	if test -n a; then ~
	echo ~

现在你发现需要额外的缩进。输入 CTRL-T。结果：

	if test -n a; then ~
	   echo ~

CTRL-T 命令在插入模式下增加一个 'shiftwidth' 的缩进，无论你在行中的什么位
置。
   你继续输入第二行，<Enter> 和第三行。这次缩进是正确的。然后 <Enter> 和最
后一行。现在你有了这些：

	if test -n a; then ~
	   echo a ~
	   echo "-------" ~
	   fi ~

要移除最后一行多余的缩进，按 CTRL-D。这会删除一个 'shiftwidth' 的缩进，无
论你在行中的什么位置。
   在普通模式下，你可以使用 ">>" 和 "<<" 命令来移动行。">" 和 "<" 是操作
符，因此你有通常的三种方式来指定要缩进的行。一个有用的组合是: >

	>i{

这为当前 {} 内的行增加一级缩进。{ 和 } 行本身不变。">a{" 包含它们。在这个
例子中光标在 "printf" 上：

	原始文本		">i{" 后		">a{" 后

	if (flag)		if (flag)		if (flag) ~
	{			{			    { ~
	printf("yes");		    printf("yes");	    printf("yes"); ~
	flag = 0;		    flag = 0;		    flag = 0;  ~
	}			}			    } ~

*30.5*	制表符和空格

关于制表符的简要历史

`vi`（Vim 的前身）由 Bill Joy 创建。当时他使用的 PDP-11 内存和 I/O 操作能力
有限。那时通常用以下技巧来优化源代码的大小。
  ASCII 表最初是为远程控制电传打字机设计的。当控制字符 9（水平制表符，脱字符
表示：^I）被发送到电传打字机时，它会将托架移到下一个制表位。假设制表位每隔
8 列（一个典型标准），这意味着一个控制字符可以产生最多 8 个空格字符的视觉效
果。例如，以下两行显示效果相同 >

	1234^I9
	1234    9

使用 <Tab> 键也比多次按 <Space> 快；<BS> 也一样。


制表符和缩进的问题

在 Vim 中，两个（虚拟）水平制表位之间的列数由 'tabstop' 控制，默认为八。虽
然你可以更改它，但以后很快会遇到麻烦。其他程序不知道你使用的 tabstop 值。它
们可能使用默认值八，你的文本看起来会突然不同。另外，大多数打印机使用固定的
tabstop 值八。因此最好不要改 'tabstop'；如果你编辑一个使用不同 tabstop 设置
的文件，参见 |25.3| 了解如何修复。
   对于程序中的行缩进，使用八列的倍数会让你很快到达窗口的右边界。使用一个空
格又没有足够的视觉差异。很多人喜欢用四个空格，这是一个很好的折中。
   由于行首的制表符在视觉上表示为八个空格，而你想使用四个空格的缩进，你就不
能用制表符来做缩进。
  为了补救这个问题，`vi` 有 'shiftwidth' 选项。设为 4 时，在新行上，在插入
模式下按 <C-t> 会缩进 4 个空格，这是用 <Tab> 键和 'tabstop' 设为 8 无法得
到的结果。
 为了优化空间，`vi` 还会静默地移除成组的空格并替换为制表符。以下显示多次按
<C-t> 的效果。
  "." 代表空格字符，"------->" 代表制表符。

	type				result ~
	<C-t>				....
	<C-t><C-t>			------->
	<C-t><C-t><C-t>			------->....

  类似地，在插入模式下按 <C-d> 会减少缩进。因此使用 `set tabstop=8
shiftwidth=2` 时有

	type				result ~
	<C-t><Tab><C-t>			..----->..
	<C-t><Tab><C-t><C-d>		------->

  `vi` 中可以设置的第三个选项是 'autoindent'。它复制前一行的缩进级别，

	type				result ~
	<Space><Tab>hello		.------>hello
	<Space><Tab>hello<Enter>	.------>hello
					------->

但新行是通过优化使用字符数量产生的。


仅使用空格

但以 8 列分隔制表位并非通用标准：IBM 的标准是 10 列，如今一些 Go 开发者使用
`tabstop=4` 编写代码。每当文本以不同的 'tabstop' 值显示时，就有文本对齐出错
的风险，特别是文件被共享并在另一台机器上打开时。
  与此同时，计算机变得更好了，使用制表符节省的几个字节已经没有实际意义了。可
以只使用空格从而保证在任何地方得到相同的结果。但在 `vi` 中不牺牲功能的情况
下只使用空格是不可能的。记住 'autoindent' 会在可能时系统地尝试插入制表符。
  Vim 4.0 通过引入 'expandtab' 选项，使得只使用空格和只使用制表符（或混合使
用）一样方便。设置后，Vim 会将它通常要插入的任何水平制表符替换为等效数量的
空格，以得到相同的视觉效果。<BS> 继续一次只删除一个字符。

	type				result ~
	<Tab>				........
	<Tab><BS>			.......


将制表符改为空格（及反向操作）

设置 'expandtab' 不会立即影响现有的制表符。为了清除文件中所有的水平制表符，
Vim 5.3 引入了 |:retab| 命令。使用以下命令: >

	:set expandtab
	:retab

这有一点危险，因为它也可能改变字符串中的制表符。要检查是否存在这种情况，可
以使用: >

	/"[^"\t]*\t[^"]*"

建议不要在字符串中使用实际的制表符。用 "\t" 替换它们以避免问题。

  反向操作也同样有效: >

	:set noexpandtab
	:retab!


软制表位

当只使用空格或混合使用空格和水平制表符时，你会有 <Tab> 和 <BS> 两个键不像只
使用制表符时那样镜像工作的不愉快感觉。
  Vim 5.4 引入了 'softtabstop' 选项。在用于显示文本中水平制表符的（硬）制表
位之上，Vim 增加了仅用于光标的额外软制表位。当 'softtabstop' 设为正值时，
<Tab> 键会将光标推到下一个软制表位。Vim 会插入正确组合的制表符和空格来实现
视觉效果。同样按 <BS> 会让光标尝试到达最近的软制表位。以下例子使用
`:set softtabstop=4`

	type			result ~
	<Tab>			....
	<Tab><Tab>a		------->a
	<Tab><Tab>a<Tab>	------->a...
	<Tab><Tab>a<Tab><BS>	------->a

  要保持全局一致性，可以 `:set softtabstop=-1` 这样 'shiftwidth' 的值就被用
作两个软制表位之间的列数。

  如果你更喜欢 'shiftwidth' 和 'softtabstop' 使用不同的值，你仍然可以这样做
并使用 <C-t> 以 'shiftwidth' 缩进。或者你可以使用 'smarttab' 选项，它提供
统一的 <Tab> 键，知道在不同情况下该做什么。


可变制表位

如前所述，ASCII 表设计用于远程控制电传打字机。一台电传打字机可以配置为物理
制表位具有可变间距。毕竟，^I 控制字符只是规定：移到下一个制表位，无论它在哪
里。
  Vim 7.3 引入了 'vartabstop' 来模拟同样的功能。例如如果 Vim 编译时带有
`+vartabs` 并且 `:set vartabstop=2,4` 则有

	actual character	result ~
	^I			->
	^I^I			->--->
	^I^I^I			->--->--->

  类似地，'varsofttabstop' 也被引入，用于可变间距的软制表位。使用
`:set varsofttabstop=2,4` 则有

	type			  result ~
	<Tab>			  ..
	<Tab><Tab>		  ......
	<Tab><Tab><Tab>		  ------->....


配置示例

默认情况下，Vim 配置为只使用制表符: >

	:set tabstop=8
	:set shiftwidth=8
	:set noexpandtab
	:set softtabstop=0
	:set nosmarttab
<
  如果你想像写 Python 一样编写 C 代码（只用空格，缩进 4 个空格），可以使用:
>

	:set shiftwidth=4
	:set softtabstop=-1
	:set expandtab
<
  如果你想要相同的行为但对对齐有更好的控制（例如以 2 个空格的倍数对齐参数或
注释），使用: >

	:set shiftwidth=4
	:set softtabstop=2
	:set expandtab
	:set smarttab
<
  如果你更愿意像 Bram Moolenaar 那样编写 C 代码（使用制表符和空格的混合），
可以使用 >

	:set shiftwidth=4
	:set softtabstop=-1
<

*30.6*	格式化注释

Vim 的一个优点是它能理解注释。你可以让 Vim 格式化注释，它会正确处理。
   例如，假设你有以下注释: >c

	/*
	 * This is a test
	 * of the text formatting.
	 */

然后你让 Vim 格式化它，将光标定位在注释的开头并输入: >

	gq]/

"gq" 是格式化文本的操作符。"]/" 是将你带到注释末尾的移动命令。结果是: >c

	/*
	 * This is a test of the text formatting.
	 */

注意 Vim 正确处理了每行的开头。
  另一种方法是在可视模式下选择要格式化的文本，然后输入 "gq"。

要向注释添加新行，将光标定位在中间行上并按 "o"。结果看起来像这样: >c

	/*
	 * This is a test of the text formatting.
	 *
	 */

Vim 自动为你插入了一个星号和一个空格。现在你可以输入注释文本。当文本超过
'textwidth' 时，Vim 会断行。同样，星号会被自动插入: >c

	/*
	 * This is a test of the text formatting.
	 * Typing a lot of text here will make Vim
	 * break
	 */

要使此功能工作，'formatoptions' 中必须存在一些标志：

	r	在插入模式下输入 <Enter> 时插入星号
	o	在普通模式下使用 "o" 或 "O" 时插入星号
	c	根据 'textwidth' 断开注释文本

更多标志参见 |fo-table|。


定义注释

'comments' 选项定义了注释的样子。Vim 区分单行注释和有不同开头、结尾和中间部
分的注释。
   许多单行注释以特定字符开头。在 C++ 中使用 //，在 Makefile 中使用 #，在
Vim 脚本中使用 "。例如，要让 Vim 理解 C++ 注释: >

	:set comments=://

冒号将项目的标志与注释的识别文本分开。项目的一般形式是：

	{flags}:{text}

{flags} 部分可以为空，如本例。
   多个这样的项可以用逗号连接。这允许同时识别不同类型的注释。例如，让我们编
辑一封电子邮件。回复时，别人写的文本前面有 ">" 和 "!" 字符。这个命令可以工
作: >

	:set comments=n:>,n:!

有两个项，一个用于以 ">" 开头的注释，一个用于以 "!" 开头的注释。两者都使用
"n" 标志。这意味着这些注释可以嵌套。因此以 ">" 开头的行可以在 ">" 之后有另
一个注释。这允许格式化这样的消息：

	> ! Did you see that site? ~
	> ! It looks really great. ~
	> I don't like it.  The ~
	> colors are terrible. ~
	What is the URL of that ~
	site? ~

试着将 'textwidth' 设为不同的值，例如 80，然后在可视模式下选择文本并输入
"gq" 来格式化。结果是：

	> ! Did you see that site?  It looks really great. ~
	> I don't like it.  The colors are terrible. ~
	What is the URL of that site? ~

你会注意到 Vim 没有将文本从一种注释移到另一种。第二行中的 "I" 可以放到第一
行的末尾，但由于那行以 "> !" 开头而第二行以 ">" 开头，Vim 知道这是不同类型
的注释。


三段式注释

C 注释以 "/*" 开头，中间有 "*"，以 "*/" 结尾。'comments' 中对应的条目看起来
像这样: >

	:set comments=s1:/*,mb:*,ex:*/

起始部分用 "s1:/*" 定义。"s" 表示三段式注释的开头。冒号将标志与注释的识别文
本 "/*" 分开。有一个标志："1"。这告诉 Vim 中间部分有一个空格的偏移。
   中间部分 "mb:*" 以 "m" 开头，表示它是中间部分。"b" 标志表示文本后面必须
有空白。否则 Vim 会把像 "*pointer" 这样的文本也当作注释的中间部分。
   结尾部分 "ex:*/" 用 "e" 标识。"x" 标志有特殊含义。它意味着在 Vim 自动插
入星号后，输入 / 会移除多余的空格。

更多细节参见 |format-comments|。
