Nvim 和 Vim 之间的差异                                        *vim-differences*

Nvim 在许多方面与 Vim 不同，尽管编辑器和 Vimscript（非 Vim9script）功能
大体相同。本文档是差异的完整集中参考。

                                      输入 |gO| 查看目录。

==============================================================================
配置                                                        *nvim-config*

用户配置和数据文件位于标准 |base-directories| 中（另见 |$NVIM_APPNAME|）。
特别注意：

- 使用 `$XDG_CONFIG_HOME/nvim/init.vim` 代替 `.vimrc` 作为你的 |config|。
- 使用 `$XDG_CONFIG_HOME/nvim` 代替 `.vim` 存储配置文件。
- 使用 `$XDG_STATE_HOME/nvim/shada/main.shada` 代替 `.viminfo` 存储持久
  会话信息。|shada|

默认鼠标设置
                                                *default-mouse* *disable-mouse*
默认启用鼠标。这意味着 |scroll-mouse-wheel| 将滚动窗口而非移动光标；
<LeftMouse> 点击放置光标；<RightMouse> 点击打开带有标准操作的默认
|popup-menu|。

鼠标在 |Cmdline-mode| 或 |more-prompt| 中不启用，因此你可以通过输入 ":"
来临时禁用它。或者如果你想部分或完全禁用鼠标或弹出菜单，执行以下任一操作：

- 通过取消设置 'mouse' 选项完全禁用鼠标： >vim
  set mouse=
- 更改 'mousemodel'，使 <RightMouse> 扩展选择而非显示弹出菜单： >vim
  set mousemodel=extend
- 映射 <A-LeftMouse> 使其临时禁用鼠标直到光标移动： >vim
  nnoremap <A-LeftMouse> <Cmd>
    \ set mouse=<Bar>
    \ echo 'mouse OFF until next cursor-move'<Bar>
    \ autocmd CursorMoved * ++once set mouse&<Bar>
    \ echo 'mouse ON'<CR>
<
要移除默认弹出菜单但不禁用鼠标： >vim
  aunmenu PopUp
  autocmd! nvim.popupmenu

要仅移除 "How-to disable mouse" 菜单项（及其分隔符）： >vim
  aunmenu PopUp.How-to\ disable\ mouse
  aunmenu PopUp.-2-

默认自动命令
                                                        *default-autocmds*
默认自动命令存在于以下组中。使用 ":autocmd! {group}" 移除它们，
使用 ":autocmd {group}" 查看它们的定义。

nvim.terminal:
- BufReadCmd：将 "term://" 缓冲区视为 |terminal| 缓冲区。|terminal-start|
- TermClose：以无参数启动（因此使用 'shell'）且无错误退出的 |terminal|
  缓冲区会自动关闭。
- TermClose：显示 "[Process exited]" 虚拟文本。
- TermRequest：终端模拟器响应 OSC 背景和前景请求，当 Nvim 选项
  'background' 为 "dark" 时指示 (1) 黑色背景和白色前景，当 'background'
  为 "light" 时指示 (2) 白色背景和黑色前景。虽然这可能不反映实际的前景/
  背景颜色，但它允许在终端模拟器中运行的嵌套 Nvim 实例保留 'background'。
- TermRequest：Nvim 将为使用 OSC 133 转义序列标注提示的 shell 创建
  extmark，使用户能够使用 |[[| 和 |]]| 在提示之间快速导航。
- TermOpen：为 |terminal| 缓冲区设置默认选项和映射：
    - 'nomodifiable'
    - 'undolevels' 设置为 -1
    - 'textwidth' 设置为 0
    - 'nowrap'
    - 'nolist'
    - 'nonumber'
    - 'norelativenumber'
    - 'signcolumn' 设置为 "no"
    - 'foldcolumn' 设置为 "0"
    - 'winhighlight' 使用 |hl-StatusLineTerm| 和 |hl-StatusLineTermNC|
      代替 |hl-StatusLine| 和 |hl-StatusLineNC|
    - |[[| 和 |]]| 在 shell 提示之间导航

nvim.cmdwin:
- |CmdwinEnter|：在 |cmdwin| 中限制语法同步为 maxlines=1。

nvim.swapfile:
- |SwapExists|：当交换文件属于运行中的 Nvim 进程时跳过交换文件提示
  （将 |v:swapchoice| 设置为 "e"）。显示 |W325| "忽略交换文件..." 消息。

nvim.exrc:
- |VimEnter|：扩展 'exrc' 以在所有父目录中搜索项目本地配置文件。

nvim.progress:
- |Progress|：使用 OSC 9;4 转义序列在 TUI 中显示原生进度条。

用户体验

直观且一致地工作是 Nvim 的主要目标。

                                                        *feature-compile*
- Nvim 始终包含所有功能，与 Vim（附带各种 100 多个可选功能的组合）不同。
  |feature-compile| 可以将其视为 Vim "HUGE" 构建的精简版本。这减少了 bug
  的表面积，并消除了用户常见的困惑和摩擦来源。

- Nvim 避免无法在所有平台上提供的功能；相反将其委托给外部插件/扩展。
  例如 `-X` 平台特定选项在 Vim 中"有时"可用（可能带来意外：
  https://stackoverflow.com/q/14635295）。

- Vim 的内部测试函数（test_autochdir()、test_settime() 等）不会被暴露
  （也不会实现）；相反 Nvim 有一个健壮的 API。

- 如果行为、选项、文档花费用户的时间多于节省的时间，则会被移除。

在收益大于向后兼容性成本的地方改进了可用性细节。一些示例：

- 'directory' 和 'undodir' 的目录会自动创建。
- 终端功能如 'guicursor' 在可能的情况下启用。
- 各种 "nvim" |cli-arguments| 已重新设计。

一些原本需要外部插件的功能已内置：

- 高亮复制区域，参见 |vim.hl|。

架构

Nvim UI 与核心编辑器"解耦"：所有 UI，包括内置的 |TUI| 都只是连接到 Nvim
服务器的插件（通过 |--server| 或 |--embed|）。多个 Nvim UI 客户端可以连接
到同一个 Nvim 编辑器服务器。

外部插件在独立进程中运行。|remote-plugin| 这提高了稳定性，并允许这些插件
在不阻塞编辑器的情况下工作。即使是使用旧 Vim 接口（|if_pyth|、|if_ruby|）
的"旧版" Python 和 Ruby 插件也在进程外运行，因此它们不会导致 Nvim 崩溃。

平台和 I/O 设施建立在 libuv 之上。Nvim 受益于 libuv 的功能和 bug 修复，
其他项目也受益于 Nvim 开发者对 libuv 的改进。

提供者：
- 如果 Python 解释器在你的 `$PATH` 中可用，|:python| 和 |:python3|
  始终可用。参见 |provider-python|。

Shell：
- Shell 输出（|:!|、|:make| 等）始终通过 UI 路由，因此它不会"搞乱"
  屏幕。（如果你想搞乱屏幕，仍然可以使用 "chansend(v:stderr,...)" :)
- Nvim 节流（跳过）来自 shell 命令（|:!|、|:grep|、|:make|）的消息，
  如果输出太多。不会丢失数据，这只影响显示并提高性能。|:terminal| 输出
  从不节流。
- |:!| 不支持"交互式"命令。请使用 |:terminal|。
  （GUI Vim 有类似的限制，参见 Vim 中的 ":help gui-pty"。）
- :!start 在 Windows 上不是特殊情况。
- |system()| 不支持写入/读取"后台"命令。|E5677|

标记：
- 'signcolumn' 可以显示多个标记。
- 如果关联的行被删除，标记会被移除。
- 使用相同标识符在同一组中放置两次的标记会被移动。

启动：
- |-e| 和 |-es| 调用与 -E 和 -Es 相同的"改进的 Ex 模式"。

其他更改                                                 *nvim-changed*

本节记录各种底层行为更改。

|mkdir()| 行为更改：
- 1. 假设 /tmp/foo 不存在且 /tmp 可写
     mkdir('/tmp/foo/bar', 'p', 0700) 将以 0700 权限创建 /tmp/foo 和
     /tmp/foo/bar。Vim 的 mkdir 将以 0755 创建 /tmp/foo。
- 2. 如果你尝试使用 `'p'` 创建已存在的目录（例如 mkdir('/', 'p')），
     mkdir() 将静默退出。在 Vim 中这是一个错误。
- 3. mkdir() 错误消息现在在 mkdir 失败时包含 strerror() 文本。

|string()| 和 |:echo| 行为更改：
- 1. 对嵌套容器结构不应用最大递归深度限制。
- 2. |string()| 在遇到嵌套容器时立即失败，而非在超过递归限制时。
- 3. 当 |:echo| 遇到重复容器时，如 >vim
       let l = []
       echo [l, l]
<     它不使用 "[...]"（原来是："[[], [...]]"，现在是："[[], []]"）。
     "..." 仅用于递归容器。
- 4. |:echo| 打印嵌套容器时在 "..." 后添加 "@level" 表示递归容器
     被打印的级别：|:echo-self-refer|。同样适用于 |string()|（虽然它
     使用类似 "{E724@level}" 的构造），但这不可靠，因为 |string()|
     继续报错。
- 5. 字符串化的无穷和 NaN 值现在使用 |str2float()| 并且可以被 eval 回来。
- 6. （内部）在 Vim 中尝试打印或字符串化 VAR_UNKNOWN 不会产生任何结果，
     E908，在 Nvim 中是内部错误。

|json_decode()| 行为更改：
- 1. 它可能输出 |msgpack-special-dict|。
- 2. 在键重复的情况下也发出 |msgpack-special-dict|，而 Vim 会报错。
- 3. 它只接受有效的 JSON。不接受尾随逗号。

|json_encode()| 行为略有更改：现在接受 |msgpack-special-dict| 值，
但不接受 |v:none|。

Viminfo 文本文件已被二进制（messagepack）|shada| 文件替代。
其他差异：

- |shada-c| 无效。
- |shada-s| 现在限制每个项目的大小，而不仅仅是寄存器。
- 'viminfo' 选项已重命名为 'shada'。旧选项作为兼容性别名保留。
- |:wviminfo| 已重命名为 |:wshada|，|:rviminfo| 已重命名为 |:rshada|。
  旧命令仍然保留。
- ShaDa 文件格式在设计时考虑了前向和后向兼容性。|shada-compatibility|
- 某些错误使 ShaDa 代码将临时文件保留在原位让用户决定如何处理。
  Vim 在这些情况下删除临时文件。|shada-error-handling|
- ShaDa 文件保留搜索方向（|v:searchforward|），viminfo 不保留。

|printf()| 使用 `%p` 参数时返回有意义的内容：在 Vim 中它过去返回字符串的
无用地址（字符串在各处被复制到新分配的内存中）并在无法强制转换为字符串的
类型上失败。详见 |id()|，目前内部使用 `printf("%p", {expr})`。

|c_CTRL-R| 将非特殊寄存器粘贴到 |cmdline| 时省略最后的 <CR>。

|CursorMoved| 在窗口之间移动时触发。

Lua 接口（|lua.txt|）：

  Nvim 不发出此类序列，始终使用 7 位控制序列。

 vim:tw=78:ts=8:sw=2:et:ft=help:norl:
