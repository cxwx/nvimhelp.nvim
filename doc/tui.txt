终端用户界面					*TUI* *tui*

默认情况下，当你运行 `nvim`（不带 |--embed| 或 |--headless|）时，它会启动内置
的"终端用户界面"（TUI）。这个默认的 UI 是可选的：你可以将 Nvim 作为"无头"
服务器运行，也可以使用 |GUI|。

                                      输入 |gO| 查看目录。

==============================================================================
启动						*startup-tui* *startup-terminal*

Nvim 采用客户端-服务器架构：默认情况下当你运行 `nvim` 时，这会启动内置的
UI 客户端，该客户端会启动一个 `nvim --embed` 服务器（子）进程，然后 UI
客户端连接到该服务器。连接到服务器后，UI 客户端会调用
|nvim_set_client_info()|（按照所有 UI 的建议 |dev-ui|），并在其通道上设置
以下字段： >

  client = {
    attributes = {
      license = 'Apache 2',
      pid = …,
      website = 'https://neovim.io',
    },
    name = 'nvim-tui',
    type = 'ui',
    version = { … },
  }

Nvim 在启动时猜测终端类型（|--embed| 和 |--headless| 模式除外）。|$TERM|
环境变量是确定终端类型的主要依据。

					*terminfo* *E557* *E558* *E559*
为了显示其用户界面，Nvim 从系统 terminfo 数据库读取"终端能力"列表（如果
找不到 terminfo 则使用内置默认值）。如果信息有误，屏幕可能会混乱或按键
可能无法被识别。

Unibilium 库（用于读取 terminfo）允许你用 "$HOME/.terminfo/" 目录中的
terminfo 覆盖系统 terminfo。构建你自己的 terminfo 通常很简单，只需运行：
>
  curl -LO https://invisible-island.net/datafiles/current/terminfo.src.gz
  gunzip terminfo.src.gz
  tic -x terminfo.src
<
								*$TERM*
$TERM 环境变量必须与你正在使用的终端匹配！否则 Nvim 无法知道你的终端
期望什么序列，可能会产生奇怪或次优的行为（滚动异常、颜色错误等）。

$TERM 也很重要，因为它会通过 SSH 转发到远程会话，不像大多数其他环境变量。

>
  此终端                     设置 $TERM 为                    |builtin-terms|
  -------------------------------------------------------------------------
  ansi                        (unknown)                           Y
  Ghostty                     ghostty, xterm-ghostty              Y
  iTerm (original)            iterm, iTerm.app                    N
  iTerm2 (new capabilities)   iterm2, iTerm2.app                  Y
  Konsole                     konsole-256color                    N
  libvte-based                vte, vte-256color                   Y
   (e.g. GNOME Terminal)      (aliases: gnome, gnome-256color)
  Linux virtual terminal      linux, linux-256color               Y
  PuTTY                       putty, putty-256color               Y
  rxvt                        rxvt, rxvt-256color                 Y
  screen                      screen, screen-256color             Y
  simple terminal (st)        st, st-256color                     Y
  Terminal.app                nsterm                              N
  tmux                        tmux, tmux-256color                 Y
  Windows/ConEmu              conemu                              Y
  Windows/Cygwin-built Nvim   cygwin                              Y
  Windows/Interix             interix                             Y
  Windows/legacy console      win32con                            Y
  Windows/VTP console         vtpcon                              Y
  xterm or compatible         xterm, xterm-256color               Y
<

					*builtin-terms* *builtin_terms*
Nvim 会根据上表将 |$TERM| 映射到内置条目，如果：

- 系统上没有可用的 |terminfo| 数据库
- 找不到当前检测到的终端的 terminfo 条目
- Nvim 构建时没有 terminfo 支持（`has('terminfo')==0`）

内置 terminfo 不会与任何外部 terminfo 数据库合并，也不能优先于外部
数据库使用。因此你可以通过提供具有该终端类型条目的外部数据库来完全
覆盖内置 terminfo 数据库中的任何遗漏或过时信息。

例如，"TERM=putty-256color" 将映射到内置的 "putty" 条目。
另见 |tui-colors|。

依赖终端的设置				*term-dependent-settings*

如果你想设置依赖于终端的选项或映射，可以在 init.vim 中这样做。
示例： >vim

    if $TERM =~ '^\(rxvt\|screen\|interix\|putty\)\(-.*\)\?$'
        set notermguicolors
    elseif $TERM =~ '^\(tmux\|iterm\|vte\|gnome\)\(-.*\)\?$'
        set termguicolors
    elseif $TERM =~ '^\(xterm\)\(-.*\)\?$'
        if $XTERM_VERSION != ''
            set termguicolors
        elseif $KONSOLE_PROFILE_NAME != ''
            set termguicolors
        elseif $VTE_VERSION != ''
            set termguicolors
        else
            set notermguicolors
        endif
    elseif $TERM =~ ...
        ... and so forth ...
    endif
<
					*scroll-region* *xterm-scroll-region*
Nvim 会尽可能使用终端的滚动区域设置能力，以便在窗口滚动时更快地重绘。
如果终端的 terminfo 描述中有设置顶部和底部滚动边距的能力，就会使用它。

这不会加速非全宽终端窗口中的滚动。Xterm 有一个额外的能力，terminfo
中没有描述，可以同时设置左右滚动边距。如果 Nvim 检测到终端是 Xterm，
它将利用此功能加速非全宽的滚动。

								*tui-input*
历史上，终端模拟器无法区分某些控制键修饰符和其他键。例如，<C-I> 和 <Tab>
的表示方式相同，<Esc> 和 <C-[>、<CR> 和 <C-M>、以及 <NL> 和 <C-J> 也是
如此。

现代终端模拟器能够通过不同方式编码控制修饰符来区分这些键对。有两种常见
但不同的方式，称为 "modifyOtherKeys" 和 "CSI u"。Nvim 支持这两种编码
方法，并在启动时告诉终端模拟器它理解这些键编码。如果你的终端模拟器支持
的话，这将允许你分别映射上面列出的键对。|<Tab>|

Nvim 使用 libtermkey 将终端转义序列转换为键码。首先使用 |terminfo|，
不在 |terminfo| 中的 CSI 序列（包括扩展键，即 "modifyOtherKeys" 或
"CSI u"）也可以被解析。

例如，在 tmux 中运行 Nvim 时，这会使 Nvim 离开插入模式并转到下面的
窗口： >
        tmux send-keys 'Escape' [ 2 7 u 'C-W' j
其中 `'Escape' [ 2 7 u` 是 <Esc> 键的无歧义 "CSI u" 序列。

kitty 键盘协议 https://sw.kovidgoyal.net/kitty/keyboard-protocol/
得到部分支持，包括 Unicode 私有使用区中的小键盘键。
例如，此序列被 Nvim 识别为 <C-kEnter>： >
        CSI 57414 ; 5 u
可以在映射中与 <C-CR> 不同地使用。

						*tui-modifyOtherKeys* *tui-csiu*
启动时，Nvim 会通过写入以下序列来查询你的终端是否支持 "CSI u" 编码 >
        CSI ? u CSI c
如果你的终端模拟器响应 >
        CSI ? <flags> u
这意味着你的终端支持 "CSI u" 编码，Nvim 将通过写入以下序列告诉你的
终端启用它 >
        CSI > 1 u
如果你的终端不支持 "CSI u"，那么 Nvim 将改为通过写入以下序列启用
"modifyOtherKeys" 编码 >
        CSI > 4 ; 2 m

当 Nvim 正常退出时，它会发送相应的序列来禁用特殊键编码。如果 Nvim
没有正常退出，你的终端模拟器可能处于不良状态。如果发生这种情况，
只需运行 "reset"。

							*tui-colors*
默认情况下，Nvim 使用 256 色，忽略大多数终端类型的 |terminfo|，包括
"linux"（其虚拟终端自 4.8 以来就支持 256 色）和任何声称是 "xterm" 的
终端。当 $COLORTERM 或 $TERM 包含字符串 "256" 时也是如此。

Nvim 同样假定任何将 $COLORTERM 设置为任意值的终端模拟器至少能够
进行 16 色操作。

						*true-color* *xterm-true-color*
如果设置了 'termguicolors'，Nvim 会在终端中输出真彩色（24 位）。

它使用 "setrgbf" 和 "setrgbb" |terminfo| 扩展（由 Rudiger Sonderfeld
在 2013 年提出）。如果你的 terminfo 定义缺少它们，Nvim 将决定是否将
它们添加到你的 terminfo 定义中，使用 ISO 8613-6:1994/ITU T.416:1993
控制序列来设置 RGB 颜色（但修改为使用分号而不是冒号，除非已知终端
遵循标准）。

另一个惯例是 tmux 在 2016 年首创的 "Tc" terminfo 扩展。如果 terminfo
具有此标志，Nvim 将添加构造的 "setrgbf" 和 "setrgbb" 能力，就好像
它们在 terminfo 定义中一样。

如果 terminfo 还没有此标志，Nvim 将回退到 $TERM 和其他环境变量。
对于 "rxvt"、"linux"、"st"、"tmux" 和 "iterm" 终端类型，或者当检测到
Konsole、真正的 Xterm、0.36 或更高版本的 libvte 终端模拟器、或将
COLORTERM 环境变量设置为 "truecolor" 的终端模拟器时，它将添加构造的
"setrgbf" 和 "setrgbb" 能力。

							*xterm-resize*
Nvim 可以在一些实现了 dtterm 首创的扩展的终端上调整终端显示大小。
|terminfo| 没有此扩展的标志。因此 Nvim 简单地假定（所有）"dtterm"、
"xterm"、"teraterm"、"rxvt" 终端类型和 Konsole 都具备此功能。

							*tui-cursor-shape*
Nvim 会在插入模式下将光标形状从块状调整为线状（或按 'guicursor' 选项
指定），在支持此功能的终端上。它使用与 tmux 首创的相同 |terminfo|
扩展："Ss" 和 "Se"。
类似地，如果你将光标高亮组设置为 blend=100，Nvim 会通过 "cvvis" 和
"civis" 扩展隐藏光标。

如果你的 terminfo 定义缺少它们，Nvim 将通过查看 $TERM 和其他环境
变量来决定是否将它们添加到你的 terminfo 定义中。对于 "rxvt"、"putty"、
"linux"、"screen"、"teraterm" 和 "iterm" 终端类型，或者当检测到
Konsole、基于 libvte 的终端模拟器或真正的 Xterm 时，它将添加构造的
"Ss" 和 "Se" 能力。

							*tui-cursor-tmux*
在 tmux 中，Nvim 似乎没有改变光标，但实际上是 tmux 从 Nvim 接收到
改变光标的指令，却不知道该如何处理。tmux 必须将从 Nvim 收到的内容
转换为适合宿主终端的控制序列。它与 Nvim 共享相同的机制，即使用
terminfo 中的 "Ss" 和 "Se" 能力（用于输出终端），如果它们存在的话。
与 Nvim 不同，如果它们不在 terminfo 中，你必须通过在 ~/.tmux.conf
中设置 "terminal-overrides" 来添加它们。

请参阅 tmux(1) 手册页了解如何在 tmux 配置文件中操作的详细信息。
它看起来类似于： >bash
        set -ga terminal-overrides '*:Ss=\E[%p1%d q:Se=\E[ q'
或者（唉！）对于 Konsole 18.07.70 或更早版本，可能更复杂，类似于： >bash
        set -ga terminal-overrides 'xterm*:\E]50;CursorShape=%?%p1%{3}%<%t%{0}%e%{1}%;%d\007'
<

窗口大小						*window-size*

[这里说的是 Vim 使用的整个窗口的大小，不是用 ":split" 命令创建的窗口。]

在 Unix 系统上，会尝试三种方法获取窗口大小：

- ioctl 调用（TIOCGSIZE 或 TIOCGWINSZ，取决于你的系统）
- 环境变量 "LINES" 和 "COLUMNS"
- 来自 |terminfo| 的 "lines" 和 "columns" 条目

如果所有方法都失败，则假定默认大小为 24 行 80 列。如果收到窗口调整
大小信号，大小将被重新设置。如果窗口大小有误，你可以使用 'lines' 和
'columns' 选项来设置正确的值。参见 |:mode|。

慢速和快速终端					*slow-fast-terminal*
						*slow-terminal*

如果你的终端很慢，你可能想要重置 'showcmd' 和 'ruler' 选项。命令
字符和光标位置将不会在状态行中显示（这涉及到每次按键或移动时大量
的光标移动和属性更改）。如果终端滚动非常慢，可以将 'scrolljump'
设置为 5 或更多。如果光标移出屏幕（例如，使用 "j"），Vim 将一次
滚动 5 行。另一种可能性是使用命令 "z{height}<CR>" 减少 Vim 使用
的行数。

如果终端的字符到达间隔超过 1 秒，你可能想要设置 'timeout' 和/或
'ttimeout' 选项。

如果你使用的彩色终端在显示缓冲区结束后的行时很慢，这是因为 Nvim
用两组颜色和属性绘制了两次空白。为了防止这种情况，使用此命令： >vim
        hi NonText cterm=NONE ctermfg=NONE
这将使用默认颜色和属性绘制空格，从而允许第二次绘制被优化掉。
注意：虽然理论上空白的颜色无关紧要，但在实践中它们会改变穿过它们
的光标和选区的颜色。这可能会在某些 UI 上产生可见但微小的影响。
