*change.txt*    Nvim


		  VIM 参考手册	  able Bram Moolenaar


本文件描述删除或修改文本的命令。在此上下文中，修改文本是指
删除文本并用其他文本替换，通过一个命令完成。你可以撤销所有
这些命令。非 Ex 命令可以用 "." 命令重复。

插入文本见 |insert.txt|。

                                      输入 |gO| 查看目录。

==============================================================================
1. 删除文本					*deleting* *E470*

["x]<Del>	或					*<Del>* *x* *dl*
["x]x			删除光标下及之后的 [count] 个字符
			[到寄存器 x]（非 |linewise|）。与 "dl" 相同。
			<Del> 键不接受 [count]。它删除计数的最后
			一位数字。
			关于删除换行符（合并行）见 'whichwrap'。

							*X* *dh*
["x]X			删除光标前的 [count] 个字符 [到寄存器 x]
			（非 |linewise|）。与 "dh" 相同。
			另见 'whichwrap'。

							*d*
["x]d{motion}		删除 {motion} 移过的文本 [到寄存器 x]。
			例外情况见下文。

							*dd*
["x]dd			删除 [count] 行 [到寄存器 x] |linewise|。

							*D*
["x]D			删除光标下的字符直到行尾及 [count]-1 行
			[到寄存器 x]；"d$" 的同义词。
			（非 |linewise|）

{Visual}["x]x	或					*v_x* *v_d* *v_<Del>*
{Visual}["x]d   或
{Visual}["x]<Del>	删除高亮文本 [到寄存器 x]（{Visual} 见
			|Visual-mode|）。

{Visual}["x]CTRL-H   或					*v_CTRL-H* *v_<BS>*
{Visual}["x]<BS>	在选择模式中：删除高亮文本 [到寄存器 x]。

{Visual}["x]X	或					*v_X* *v_D* *v_b_D*
{Visual}["x]D		删除高亮行 [到寄存器 x]（{Visual} 见
			|Visual-mode|）。在块状可视模式中，
			"D" 删除高亮文本加上该行剩余所有文本。

					*:d* *:de* *:del* *:delete* *:dl* *:dp*
:[range]d[elete] [x]	删除 [range] 行（默认：当前行）[到寄存器 x]。
			注意这些奇怪的缩写：
			   :dl		删除并列出
			   :dell	同上
			   :delel	同上
			   :deletl	同上
			   :deletel	同上
			   :dp		删除并打印
			   :dep		同上
			   :delp	同上
			   :delep	同上
			   :deletp	同上
			   :deletep	同上

:[range]d[elete] [x] {count}
			删除 {count} 行，从 [range] 开始
			（默认：当前行 |cmdline-ranges|）[到寄存器 x]。

这些命令删除文本。你可以用 `.` 命令重复它们
（`:d` 除外）并撤销它们。用可视模式删除文本块。
寄存器的解释见 |registers|。
							*d-special*
d{motion} 命令的一个例外：如果移动不是按行的，移动的起点和
终点不在同一行，且起点之前只有空白，移动终点之后没有非空白，
则删除变为按行的。这意味着删除也会移除你可能期望保留的空白行。
使用 |o_v| 操作符强制移动为按字符的。

尝试删除空文本区域（例如在第一列中 "d0"）在 'cpoptions'
包含 'E' 标志时是一个错误。

							*J*
J			合并 [count] 行，最少两行。删除缩进并
			插入最多两个空格（见下文）。在缓冲区最后
			一行时失败。
			如果 [count] 太大，会减少到可用行数。

							*v_J*
{Visual}J		合并高亮行，最少两行。删除缩进并插入
			最多两个空格（见下文）。

							*gJ*
gJ			合并 [count] 行，最少两行。不插入或删除
			任何空格。

							*v_gJ*
{Visual}gJ		合并高亮行，最少两行。不插入或删除
			任何空格。

							*:j* *:join*
:[range]j[oin][!] [flags]
			合并 [range] 行。与 "J" 相同，但有 [!] 时
			合并不插入或删除任何空格。
			如果 [range] 的起始和结束值相同，此命令
			不做任何事。默认行为是将当前行与下面
			的行合并。
			[flags] 见 |ex-flags|。

:[range]j[oin][!] {count} [flags]
			合并 {count} 行，从 [range] 开始（默认：
			当前行 |cmdline-ranges|）。与 "J" 相同，
			但有 [!] 时合并不插入或删除任何空格。
			[flags] 见 |ex-flags|。

这些命令删除行之间的 <EOL>。效果是将多行合并为一行。你可以
重复这些命令（`:j` 除外）并撤销它们。

这些命令（"gJ" 除外）在 <EOL> 位置插入一个空格，除非有尾随
空白或下一行以 ')' 开头。这些命令（"gJ" 除外）删除下一行的
前导空白。如果 'joinspaces' 选项打开，这些命令在 '.'、'!'
或 '?' 后插入两个空格。
'formatoptions' 中的 'B' 和 'M' 标志改变在多字节字符前后
插入空格的行为 |fo-table|。

|'[| 标记设在被合并的第一行末尾，|']| 在结果行末尾。

2. 删除并插入				*delete-insert* *replacing*

							*R*
R			进入替换模式：你输入的每个字符替换一个
			已有字符，从光标下的字符开始。将输入的
			文本重复 [count]-1 次。更多细节见
			|Replace-mode|。

							*gR*
gR			进入虚拟替换模式：你输入的每个字符在
			屏幕空间中替换已有字符。所以一个 <Tab>
			可能一次替换多个字符。
			将输入的文本重复 [count]-1 次。更多细节见
			|Virtual-Replace-mode|。

							*c*
["x]c{motion}		删除 {motion} 文本 [到寄存器 x] 并开始
			插入。当 'cpoptions' 包含 'E' 标志且没有
			文本要删除时（例如光标刚好在 'x' 后面的
			"cTx"），会发生错误且不开始插入模式
			（这是 Vi 兼容的）。
			当 'cpoptions' 不包含 'E' 标志时，"c" 命令
			总是开始插入模式，即使没有文本要删除。

							*cc*
["x]cc			删除 [count] 行 [到寄存器 x] 并开始
			插入 |linewise|。如果 'autoindent' 打开，
			保留第一行的缩进。

							*C*
["x]C			从光标位置删除到行尾及 [count]-1 行
			[到寄存器 x]，并开始插入。c$ 的同义词
			（非 |linewise|）。

							*s*
["x]s			删除 [count] 个字符 [到寄存器 x] 并开始
			插入（s 代表 Substitute）。"cl" 的同义词
			（非 |linewise|）。

							*S*
["x]S			删除 [count] 行 [到寄存器 x] 并开始
			插入。"cc" 的同义词 |linewise|。

{Visual}["x]c	或					*v_c* *v_s*
{Visual}["x]s		删除高亮文本 [到寄存器 x] 并开始插入
			（{Visual} 见 |Visual-mode|）。

							*v_r*
{Visual}r{char}		用 {char} 替换所有选定字符。
			CTRL-C 将按字面插入。

							*v_C*
{Visual}["x]C		删除高亮行 [到寄存器 x] 并开始插入。
			在块状可视模式中行为不同 |v_b_C|。
							*v_S*
{Visual}["x]S		删除高亮行 [到寄存器 x] 并开始插入
			（{Visual} 见 |Visual-mode|）。
							*v_R*
{Visual}["x]R		目前与 {Visual}["x]S 相同。在下一版本中
			可能行为不同。

注意：
- 你可以用 <Esc> 结束插入和替换模式。
- 关于这些模式中的其他特殊字符，见 "插入和替换模式"
  |mode-ins-repl| 一节。
- [count] 的效果在 Vim 退出插入或替换模式后生效。
- 当 'cpoptions' 选项包含 '$' 且更改在一行内时，Vim 继续
  显示要删除的文本并在最后一个被删除的字符处放一个 '$'。

寄存器的解释见 |registers|。

替换模式就像插入模式，只是你输入的每个字符删除一个字符。
如果你到了行尾，Vim 追加更多字符（就像插入模式）。在替换
模式中，退格键恢复原始文本（如果有的话）。（见 "插入和
替换模式" |mode-ins-repl| 一节）。

						*cw* *cW*
特殊情况：当光标在单词中时，"cw" 和 "cW" 不包含单词后的
空白，它们只修改到单词末尾。这是因为 Vim 将 "cw" 解释为
change-word（修改单词），而单词不包含后面的空白。

如果你希望 "cw" 包含单词后的空格，见 |cpo-_| 来改变行为。
或者，使用 "caw"（见 |aw|）。

							*:c* *:ch* *:change*
:{range}c[hange][!]	用一些不同的文本替换文本行。
			输入只包含 "." 的行来停止替换。
			没有 {range} 时，此命令只修改当前行。
			添加 [!] 在此命令执行期间切换 'autoindent'。

3. 简单修改				*simple-change* *changing*

							*r*
r{char}			用 {char} 替换光标下的字符。
			如果 {char} 是 <CR> 或 <NL>，换行替换该
			字符。要用真正的 <CR> 替换，使用 CTRL-V
			<CR>。CTRL-V <NL> 用 <Nul> 替换。

			如果 {char} 是 CTRL-E 或 CTRL-Y，使用
			下一行或上一行的字符，就像 |i_CTRL-E| 和
			|i_CTRL-Y|。这也适用于计数，因此 `10r<C-E>`
			从下一行复制 10 个字符。

			如果你给出 [count]，Vim 用 [count] 个 {char}
			替换 [count] 个字符。但当 {char} 是 <CR>
			或 <NL> 时，Vim 只插入一个 <CR>："5r<CR>"
			用一个换行替换五个字符。
			当 {char} 是 <CR> 或 <NL> 时，Vim 执行
			自动缩进。这就像删除被替换的字符然后
			执行 "i<CR><Esc>"。
			{char} 可以作为二合字母输入 |digraph-arg|。
			|:lmap| 映射应用于 {char}。插入模式中的
			CTRL-^ 命令可用于开关此功能 |i_CTRL-^|。
			当 'encoding' 是 Unicode 时使用组合字符见
			|utf-8-char-arg|。

							*gr*
gr{char}		用 {char} 替换光标下的虚拟字符。这在
			屏幕空间中替换，而不是文件空间。
			更多细节见 |gR| 和 |Virtual-Replace-mode|。
			与 |r| 一样可以给出计数。
			{char} 可以像 |r| 一样输入，但在插入模式中
			有特殊含义的字符（如大多数 CTRL 键）不能使用。

							*gr-default*
			Nvim 创建 |lsp-defaults| 映射，可能会抑制
			|gr| 的内置行为。使用此命令恢复内置行为： >
				nnoremap <nowait> gr gr
<

						*digraph-arg*
普通模式命令（如 |r| 和 |t|）的参数是单个字符。
当 'cpo' 不包含 'D' 标志时，此字符也可以像 |digraphs| 一样
输入。先输入 CTRL-K 然后输入两个二合字母字符。

						*case*
以下命令改变字母的大小写。使用当前活动的 |locale|。
见 |:language|。LC_CTYPE 的值在此处很重要。

							*~*

			将光标向右移动。
			如果给出 [count]，对那么多字符执行。

~{motion}		'tildeop' 选项：切换 {motion} 文本的大小写。

							*g~*
g~{motion}		切换 {motion} 文本的大小写。

g~g~							*g~g~* *g~~*
g~~			切换当前行的大小写。

							*v_~*
{Visual}~		切换高亮文本的大小写（{Visual} 见
			|Visual-mode|）。

							*v_U*
{Visual}U		将高亮文本转为大写（{Visual} 见
			|Visual-mode|）。

							*gU* *uppercase*
gU{motion}		将 {motion} 文本转为大写。
			示例： >
				:map! <C-F> <Esc>gUiw`]a

gUgU							*gUgU* *gUU*
gUU			将当前行转为大写。

							*v_u*
{Visual}u		将高亮文本转为小写（{Visual} 见

							*gu* *lowercase*
gu{motion}		将 {motion} 文本转为小写。

gugu							*gugu* *guu*
guu			将当前行转为小写。

							*g?* *rot13*
g?{motion}		对 {motion} 文本进行 Rot13 编码。

							*v_g?*
{Visual}g?		对高亮文本进行 Rot13 编码（{Visual} 见

g?g?							*g?g?* *g??*

CTRL-A			将 [count] 加到光标处或之后的数字或

							*v_g_CTRL-A*
{Visual}g CTRL-A	将 [count] 加到高亮文本中的数字或字母字符

			[count]（因此实际上创建一个 [count] 递增

			例如，如果你有以下数字列表： >
				1.
				1.
				1.
				1.
<			移到第二个 "1." 并可视选择三行，
			按 g CTRL-A 结果为： >
				1.

							*CTRL-X*
CTRL-X			从光标处或之后的数字或字母字符中减去
			[count]。

							*v_CTRL-X*
{Visual}CTRL-X		从高亮文本中的数字或字母字符中减去
			[count]。

							*v_g_CTRL-X*
{Visual}g CTRL-X	从高亮文本中的数字或字母字符中减去
			[count]。如果多行被高亮，每个值将减去
			额外的 [count]（因此实际上创建一个 [count]
			递减序列）。

CTRL-A 和 CTRL-X 命令适用于（有符号的）十进制数、无符号的
二进制/八进制/十六进制数和字母字符。

这取决于 'nrformats' 选项：
- 当 'nrformats' 包含 "bin" 时，Vim 假定以 '0b' 或 '0B'
  开头的数字是二进制。
- 当 'nrformats' 包含 "octal" 时，Vim 将以 '0' 开头的数字
  视为八进制，除非数字包含 '8' 或 '9'。其他数字是十进制，
  可能有前导负号。
  如果光标在数字上，命令应用于该数字；否则 Vim 使用光标
  右边的数字。
- 当 'nrformats' 包含 "hex" 时，Vim 假定以 '0x' 或 '0X'
  开头的数字是十六进制。数字中最右边字母的大小写决定
  结果十六进制数的大小写。如果当前数字中没有字母，Vim
  使用之前检测到的大小写。
- 当 'nrformats' 包含 "alpha" 时，Vim 将改变光标下或
  之后的字母字符。这对制作带字母索引的列表很有用。

对于十进制数，前导负号用于递增或递减，对于二进制、八进制和
十六进制值则不考虑。要忽略符号，在使用 CTRL-A 或 CTRL-X
之前可视选择该数字。

对于前导零的数字（包括所有八进制和十六进制数），Vim 尽可能
保留数字中的字符数。CTRL-A 对 "0077" 结果为 "0100"，CTRL-X
对 "0x100" 结果为 "0x0ff"。
有一个例外：当以零开头的数字被发现不是八进制（包含 '8' 或 '9'），
但 'nrformats' 包含 "octal" 时，删除前导零以避免结果被
识别为八进制数。

注意当 'nrformats' 包含 "octal" 时，带前导零的十进制数会
导致错误，因为它们可能与八进制数混淆。

类似地，当 'nrformats' 同时包含 "bin" 和 "hex" 时，带前导
'0x' 或 '0X' 的二进制数可能被解释为十六进制而不是二进制，
因为 '0b' 是有效的十六进制数字。CTRL-A 对 "0x0b11" 结果为
"0x0b12"，而不是 "0x0b100"。
当 'nrformats' 包含 "bin" 而不包含 "hex" 时，CTRL-A 对
"0x0b11" 中的 "0b11" 结果为 "0x0b100"。

当光标下的数字太大无法放入 64 位时，它将被四舍五入到最近的
可表示数字，并跳过加/减。例如 CTRL-X 对 18446744073709551616
结果为 18446744073709551615。更大的数字也是如此。

CTRL-A 命令在宏中非常有用。示例：使用以下步骤制作编号列表。

1. 创建第一个列表条目，确保它以数字开头。
2. qa	     - 开始录制到寄存器 'a'
3. Y	     - 复制条目
4. p	     - 粘贴条目的副本到下面
5. CTRL-A    - 递增数字
6. q	     - 停止录制
7. <count>@a - 重复复制、粘贴和递增 <count> 次


行左移或右移					*shift-left-right*

							*<*
 <{motion}		将 {motion} 行向左移一个 'shiftwidth'。

			如果 'shiftwidth' 选项设为零，缩进量在
			行中第一个非空白字符处计算。
							*<<*
 <<			将 [count] 行向左移一个 'shiftwidth'。

							*v_<*
{Visual}[count]<	将高亮行向左移 [count] 个 'shiftwidth'
			（{Visual} 见 |Visual-mode|）。

							*>*
 >{motion}		将 {motion} 行向右移一个 'shiftwidth'。

			如果 'shiftwidth' 选项设为零，缩进量在
			行中第一个非空白字符处计算。
							*>>*
 >>			将 [count] 行向右移一个 'shiftwidth'。

							*v_>*
{Visual}[count]>	将高亮行向右移 [count] 个 'shiftwidth'
			（{Visual} 见 |Visual-mode|）。

							*:<*
:[range]<		将 [range] 行向左移一个 'shiftwidth'。
			重复 '<' 以移多个 'shiftwidth'。

:[range]< {count}	将 {count} 行向左移一个 'shiftwidth'，从
			[range] 开始（默认当前行 |cmdline-ranges|）。
			重复 '<' 以移多个 'shiftwidth'。

:[range]le[ft] [indent]	将 [range] 中的行左对齐。将行中缩进
			设为 [indent]（默认 0）。

							*:>*
:[range]> [flags]	将 [range] 行向右移一个 'shiftwidth'。
			重复 '>' 以移多个 'shiftwidth'。
			[flags] 见 |ex-flags|。

:[range]> {count} [flags]
			将 {count} 行向右移一个 'shiftwidth'，从
			[range] 开始（默认当前行 |cmdline-ranges|）。
			重复 '>' 以移多个 'shiftwidth'。
			[flags] 见 |ex-flags|。

">" 和 "<" 命令对于在程序中改变缩进很方便。使用 'shiftwidth'
选项设置这些命令插入或删除的空白大小。通常 'shiftwidth' 选项
是 8，但你可以设为 3 以使缩进更小。左移在没有缩进时停止。
右移不影响空行。

如果 'shiftround' 选项打开，缩进四舍五入到 'shiftwidth' 的
倍数。

如果 'smartindent' 选项打开，或 'cindent' 打开且 'cinkeys'
包含值为零的 '#'，右移不影响以 '#' 开头的行（这些应该是
必须保留在第 1 列的 C 预处理器行）。
这可以用 'cino' 选项改变，见 |cino-#|。

打开，Vim 只使用空格。这时你可以用 ">><<" 将缩进中的 <Tab>
替换为空格（或使用 `:retab!`）。

要将一行移多个 'shiftwidth'，使用可视模式或 `:` 命令。
例如： >
	Vjj4>		将三行向右移 4 个缩进
	:<<<		将当前行向左移 3 个缩进
	:>> 5		将 5 行向右移 2 个缩进
	:5>>		将第 5 行向右移 2 个缩进

4.1 过滤命令					*filter*

过滤器是一个程序，它在标准输入接受文本，以某种方式改变它，
然后将结果发送到标准输出。你可以使用下面的命令将一些文本
通过过滤器发送，使其被过滤器输出替换。
过滤器的例子有 "sort"（按字母排序）和 "indent"（格式化
C 程序文件；你需要一个作为过滤器工作的 indent 版本；
不是所有版本都可以）。'shell' 选项指定 Vim 用来执行
过滤命令的 shell。你可以用 "." 重复过滤命令。Vim 不识别
`:!` 命令后的注释（以 '"' 开头）。

							*!*
!{motion}{filter}	通过外部程序 {filter} 过滤 {motion} 文本行。

							*!!*
!!{filter}		通过外部程序 {filter} 过滤 [count] 行。

							*v_!*
{Visual}!{filter}	通过外部程序 {filter} 过滤高亮行
			（{Visual} 见 |Visual-mode|）。

:{range}![!]{filter} [!][arg]				*:range!*
			执行外部命令见 |:!|

			Vim 将可选的感叹号替换为最近给出的命令
			并追加可选的 [arg]。
			Vim 将过滤命令的输出保存到临时文件中，
			然后将该文件读入缓冲区 |tempfile|。
			Vim 使用 'shellredir' 选项将过滤器输出
			重定向到临时文件。
			但如果 'shelltemp' 选项关闭，则在可能时
			使用管道（在 Unix 上）。
			当 'cpoptions' 中包含 'R' 标志时，过滤行中
			的标记被删除，除非使用 |:keepmarks| 命令。
			示例： >
				:keepmarks '<,'>!sort
<			当过滤后的行数少于之前时，缺少行中的
			标记无论如何都会被删除。

						*tempdir* *tempfile* *setuid*
Nvim 使用临时文件进行过滤和生成差异。插件也通常使用
|tempname()| 用于自己的目的。在第一次请求临时文件时，
Nvim 创建一个公共目录（"Nvim tempdir"），用作存储当前
会话中所有临时文件（包括 `stdpath("run")` 文件
|$XDG_RUNTIME_DIR|）的存储。

Nvim tempdir 在第一个可用的系统临时目录中创建：
	Unix：    $TMPDIR、/tmp、当前目录、$HOME。
	Windows： $TMPDIR、$TMP、$TEMP、$USERPROFILE、当前目录。

在 unix 上 tempdir 以权限 0700 创建（仅当前用户可访问）
以避免安全问题（例如符号链接攻击）。退出时，Nvim 删除
tempdir 及其内容。
							*E5431*
如果你看到这样的错误或 |log| 消息： >
	E5431: tempdir disappeared (2 times)
这意味着你系统上的外部进程删除了 Nvim tempdir。
通常这是由"杀毒软件"或配置错误的清理服务导致的。

如果 Nvim 设置了 setuid 位，可能导致问题：临时文件由 setuid
用户拥有，但过滤命令可能以原始用户身份运行。

用表达式替换			*sub-replace-expression*
					*sub-replace-\=* *s/\=*
当替换字符串以 "\=" 开头时，其余部分被解释为表达式。

|sub-replace-special| 提到的字符特殊含义不适用，"<CR>" 除外。
<NL> 字符用作换行符，你可以用双引号字符串获得一个："\n"。
在前面加反斜杠可得到真正的 <NL> 字符（在文件中将是 NUL）。

"\=" 表示法也可以在 |substitute()| 函数的第三个参数 {sub}
内使用。此时，|sub-replace-special| 提到的字符特殊含义
完全不适用。特别是 <CR> 和 <NL> 不被解释为换行符，而分别
解释为回车和新行。

当结果是 |List| 时，项目用换行分隔符连接。因此每个项目
成为一行，但它们本身可以包含换行符。

|submatch()| 函数可用于获取匹配的文本。整个匹配文本可以
用 "submatch(0)" 访问。第一对 () 匹配的文本用 "submatch(1)"。
后续子匹配类推。

注意：分隔字符不能出现在表达式中！
考虑使用如 "@" 或 ":" 的字符。如果表达式结果包含分隔字符
则没有问题。

示例： >
	:s@\n@\="\r" .. expand("$HOME") .. "\r"@
这将行尾替换为包含 $HOME 值的新行。 >

	s/E/\="\<Char-0x20ac>"/g
这将每个 'E' 字符替换为欧元符号。更多信息见 |<Char->|。

  :auto BufNewFile	*.xx	set ts=4

你可以使用这些命令将文本从一个地方复制到另一个地方。先用
复制、删除或修改命令将文本放入寄存器，然后用粘贴命令插入
寄存器内容。你也可以使用这些命令在文件之间移动文本，因为
Vim 在切换缓冲区时保留所有寄存器（CTRL-^ 命令是在两个
文件之间快速切换的方式）。

你可以用 "." 重复粘贴命令（:put 除外）并撤销它们。如果
用来将文本放入寄存器的命令是 |linewise| 的，Vim 在光标所在
行的下方（"p"）或上方（"P"）插入文本。否则 Vim 在光标之后
（"p"）或之前（"P"）插入文本。使用 ":put" 命令时，Vim
总是在下一行插入文本。你可以用命令序列 "xp" 交换两个字符。
你可以用命令序列 "ddp" 交换两行。你可以用命令序列 "deep"
交换两个单词（从第一个单词前的空格开始）。你可以在粘贴命令
之后使用 |']| 或 |`]| 命令将光标移到插入文本的末尾，
或使用 |'[| 或 |`[| 将光标移到开头。

							     *put-Visual-mode*
在可视模式中使用 |p| 或 |P| 等粘贴命令时，Vim 将尝试用
寄存器的内容替换选定的文本。工作方式取决于选区类型和文本。
对于块状选区还取决于块的大小和角是否在现有字符上。
（实现细节：它实际上先将寄存器放在选区之后，然后删除选区。）
									 *v_p*
可视模式中的 |p| 粘贴文本并将默认寄存器（无名、选择或
剪贴板）设为之前选定的文本。如果你想将那个文本放在其他
地方很有用。但你不能重复相同的更改。
									 *v_P*
可视模式中的 |P| 粘贴文本但不设置默认寄存器。你可以重复
更改，但删除的文本不能使用。如果你确实需要它，可以用 |p|
配合另一个寄存器。例如，复制要粘贴的文本，可视选择要替换
的文本并使用 "0p。你可以根据需要重复多次，每次无名寄存器
都会被更改。
							*blockwise-put*
当寄存器包含来自一行的文本（按字符），使用块状可视选区时，
粘贴该寄存器将在每个选定行中重复粘贴该文本，从而用寄存器
文本的多个副本替换块状选定区域。例如：
	- 用 `yw` 将单词 "TEXT" 复制到寄存器
	- 选择一个可视块，在此文本中用 "v" 标记：
	    aaavvaaa
	    bbbvvbbb
	    cccvvccc
	- 按 `p`，结果为：
	    aaaTEXTaaa
	    bbbTEXTbbb
	    cccTEXTccc

							*blockwise-register*
如果你使用块状可视模式命令将文本放入寄存器，文本块将被
插入到光标列之前（"P"）或之后（"p"），在当前和后续行中。
Vim 使整个文本块从相同列开始。因此插入的文本看起来与
复制或删除时相同。Vim 可能将一些 <Tab> 字符替换为空格来
实现这一点。但是，如果块的宽度不是 <Tab> 宽度的倍数且
插入块之后的文本包含 <Tab>，那些文本可能会对不齐。

使用 |zP|/|zp| 粘贴块状复制的寄存器而不追加尾随空格。

注意在按字符复制命令后，Vim 将光标留在最接近缓冲区开头的
第一个被复制字符上。这意味着 "yl" 不移动光标，但 "yh" 将
光标向左移一个字符。
理由：	在 Vi 中 "y" 命令后跟向后移动有时不会将光标
	移到第一个被复制字符，因为跳过了重绘。在 Vim 中
	它总是移到第一个字符，如 Posix 所指定。
对于按行复制命令，光标放在第一行，但列不变，因此可能
不在第一个被复制字符上。

寄存器				       *registers* *{register}* *E354*

有十种类型的寄存器：
1. 无名寄存器 ""
2. 10 个编号寄存器 "0 到 "9
3. 小删除寄存器 "-
4. 26 个命名寄存器 "a 到 "z 或 "A 到 "Z
5. 三个只读寄存器 ":、".、"%
6. 备用缓冲区寄存器 "#
7. 表达式寄存器 "=
8. 选择寄存器 "* 和 "+
9. 黑洞寄存器 "_
10. 上次搜索模式寄存器 "/

-----------------------------------------------------------------------------
1. 无名寄存器 ""			    *quote_quote* *quotequote*

Vim 用 "d"、"c"、"s"、"x" 命令删除的或用复制 "y" 命令
复制的文本填充此寄存器，无论是否指定了特定寄存器
（例如 "xdd）。这就像无名寄存器指向最后使用的寄存器。
因此当使用大写寄存器名追加时，无名寄存器包含与命名
寄存器相同的文本。
一个例外是 '_' 寄存器："_dd 不将删除的文本存储在任何
寄存器中。
Vim 使用无名寄存器的内容用于任何不指定寄存器的粘贴命令
（p 或 P）。此外你可以用名称 '"' 访问它。这意味着你
必须输入两个双引号。写入 "" 寄存器会写入寄存器 "0。

-----------------------------------------------------------------------------
2. 编号寄存器 "0 到 "9				*quote_number*
			 *quote0* *quote1* *quote2* *quote3* *quote4* *quote9*

Vim 用复制和删除命令的文本填充这些寄存器。
编号寄存器 0 包含最近复制命令的文本，除非命令用 ["x]
指定了另一个寄存器。

编号寄存器 1 包含最近删除或修改命令删除的文本（即使命令
指定了另一个寄存器），除非文本少于一行（此时使用小删除
寄存器）。对于使用这些移动命令的删除操作符有例外：|%|、
|(|、|)|、|`|、|/|、|?|、|n|、|N|、|{| 和 |}|。

此时总是使用寄存器 "1（这是 Vi 兼容的）。如果删除在一行
内，"- 寄存器也会被使用。注意这些字符可能被映射。例如
|%| 被 matchit 插件映射。

每次连续的删除或修改，Vim 将寄存器 1 的先前内容移到
寄存器 2，2 到 3，依此类推，丢失寄存器 9 的先前内容。
							*yankring*
要将复制（不仅是删除）也存储到寄存器 1-9，试试这个： >lua
    -- 复制环：将复制的文本存储到寄存器 1-9。
    vim.api.nvim_create_autocmd('TextYankPost', {
      callback = function()
        if vim.v.event.operator == 'y' then
          for i = 9, 1, -1 do -- 移动所有编号寄存器。
            vim.fn.setreg(tostring(i), vim.fn.getreg(tostring(i - 1)))
          end
        end
      end,
    })
<
-----------------------------------------------------------------------------
3. 小删除寄存器 "-                                 *quote_-* *quote-*

此寄存器包含删除少于一行的命令的文本，
除非命令用 ["x] 指定了寄存器。

-----------------------------------------------------------------------------
4. 命名寄存器 "a 到 "z 或 "A 到 "Z             *quote_alpha* *quotea*

Vim 仅在你指定时才填充这些寄存器。指定小写字母以替换
其先前内容，或指定大写字母以追加到其先前内容。
当 'cpoptions' 中有 '>' 标志时，追加文本前会插入换行。

-----------------------------------------------------------------------------
5. 只读寄存器 ":、". 和 "%

这些是 '%'、':' 和 '.'。你只能用 "p"、"P" 和 ":put"
命令以及 CTRL-R 使用它们。

						*quote_.* *quote.* *E29*
   - ".	包含最后插入的文本（与插入模式命令 CTRL-A 和 CTRL-@
	插入的相同）。注意：这在命令行的 CTRL-R 上不起作用。
	它的工作方式略有不同，像是插入文本而不是放置它
	（'textwidth' 和其他选项影响插入的内容）。
							*quote_%* *quote%*
   - "%	包含当前文件的名称。
						*quote_:* *quote:* *E30*
   - ":	包含最近执行的命令行。示例：使用 "@:" 重复上一个
	命令行命令。命令行仅在至少输入了一个字符时才存储到
	此寄存器。因此如果命令完全由映射执行，它保持不变。

-----------------------------------------------------------------------------
6. 备用文件寄存器 "#                               *quote_#* *quote#*

包含当前窗口的备用文件名。它将改变 |CTRL-^| 命令的
工作方式。此寄存器可写，主要允许在插件更改后恢复它。

它接受缓冲区号： >
     let altbuf = bufnr(@#)
     ...
     let @# = altbuf

如果你传递了缓冲区号但该缓冲区不存在，将报错 |E86|。

它也可以接受与现有缓冲区名匹配的内容： >
     let @# = 'buffer_name'

如果有多个缓冲区匹配给定名称则报错 |E93|，
如果没有缓冲区匹配则报错 |E94|。

-----------------------------------------------------------------------------
7. 表达式寄存器 "=                            *quote_=* *quote=* *@=*

这不是真正存储文本的寄存器，而是在使用寄存器的命令中
使用表达式的方式。表达式寄存器是可读写的。

- 当在 " 或 CTRL-R 之后输入 '=' 时，光标移到命令行，
  你可以输入任何表达式（见 |expression|）。所有正常
  命令行编辑命令可用，包括表达式的特殊历史。
  当你用 <CR> 结束命令行时，Vim 计算表达式结果。
  如果你用 <Esc> 结束，Vim 放弃表达式。如果你没有
  输入表达式，Vim 使用上一个表达式（类似 "/" 命令）。
- 表达式必须求值为 String。Number 总是自动转换为 String。
  对于 "p" 和 ":put" 命令，如果结果是 Float 则转为
  String。如果结果是 List，每个元素转为 String 并用作
  一行。Dictionary 转为 String。Funcref 导致错误消息
  （使用 string() 转换）。
- 如果 "= 寄存器用于 "p" 命令，String 在 <NL> 字符处
  分割。如果 String 以 <NL> 结尾，它被视为按行寄存器。

-----------------------------------------------------------------------------
8. 选择寄存器 "* 和 "+

使用这些寄存器存储和检索 GUI 的选定文本。
见 |quotestar| 和 |quoteplus|。当剪贴板不可用或不工作时，
使用无名寄存器代替。对于 Unix 系统和 Mac OS X，
见 |primary-selection|。

-----------------------------------------------------------------------------
9. 黑洞寄存器 "_					      *quote_*

写入此寄存器时什么都不发生。这可以用来删除文本而不影响
正常寄存器。从此寄存器读取时什么都不返回。

-----------------------------------------------------------------------------
10. 上次搜索模式寄存器 "/			    *quote_/* *quote/*

包含最近的搜索模式。用于 "n" 和 'hlsearch'。
可以用 `:let` 写入，你可以更改它使 'hlsearch' 高亮其他
匹配而不实际搜索。你不能复制或删除到此寄存器。
搜索方向在 |v:searchforward| 中可用。注意从函数返回时
该值会被恢复 |function-search-undo|。

							*@/*
你可以用 `:let` 命令写入寄存器 |:let-@|。示例： >
	:let @/ = "the"

如果你使用粘贴命令而不指定寄存器，Vim 使用最后填充的
寄存器（这也是无名寄存器的内容）。如果你混淆了，
使用 `:dis` 命令查看 Vim 将粘贴什么（此命令显示所有
命名和编号寄存器；无名寄存器标记为 '"'）。

以下三个命令总是对整行操作。

:[range]co[py] {address}				*:co* *:copy*
			将 [range] 给出的行复制到 {address} 给出的
			行下面。

							*:t*
:t			copy 的同义词。

:[range]m[ove] {address}			*:m* *:mo* *:move* *E134*
			将 [range] 给出的行移动到 {address} 给出的
			行下面。

6. 格式化文本					*formatting*

:[range]ce[nter] [width]				*:ce* *:center*
			将 [range] 中的行居中于 [width] 列之间
			（默认 'textwidth' 或 80，当 'textwidth' 为 0 时）。

:[range]ri[ght] [width]					*:ri* *:right*
			将 [range] 中的行右对齐于 [width] 列

							*:le* *:left*

							*gq*
gq{motion}		格式化 {motion} 移过的行。
			格式化使用三种方法之一：
			1. 如果 'formatexpr' 非空则求值表达式。
			   这对每个缓冲区可以不同。
			2. 如果 'formatprg' 非空则使用外部程序。
			3. 否则使用内部格式化。

gqgq							*gqgq* *gqq*

			|Visual-mode|）。

							*gw*
gw{motion}		格式化 {motion} 移过的行。与 |gq| 类似
			但将光标放回文本中的相同位置。
			但不使用 'formatprg' 和 'formatexpr'。

gwgw							*gwgw* *gww*
gww			像 "gw" 一样格式化当前行。

							*v_gw*
{Visual}gw		像 "gw" 一样格式化高亮文本。（{Visual}
			见 |Visual-mode|）。

格式化当前段落的示例：					*gqap*  >
	gqap

"gq" 命令将光标留在移动命令将光标带到的行。这允许你
用 "." 重复格式化。这对 "gqj"（格式化当前行和下一行）
和 "gq}"（格式化到段落末尾）很有效。注意：当设置了
'formatprg' 时，"gq" 将光标留在第一个格式化行（与使用
过滤命令一样）。

如果你想格式化当前段落并继续在原来的位置，使用： >
	gwap
如果你总想保持段落已格式化，你可能想在 'formatoptions' 中
添加 'a' 标志。见 |auto-format|。

如果 'autoindent' 选项打开，Vim 使用第一行的缩进用于
后续行。

格式化不改变空行（但它确实改变只有空白的行！）。

合并行时使用 'joinspaces' 选项。

你可以将 'formatexpr' 选项设为表达式或将 'formatprg' 选项
设为外部程序名供 Vim 使用。'textwidth' 和其他选项对外部
程序格式化无效。

                                                        *format-formatexpr*
'formatexpr' 选项可以设为执行缓冲区重格式化的 Vim 脚本函数。
这通常应在 |ftplugin| 中完成，因为格式化高度依赖于文件类型。
使用 |autoload| 脚本有意义，这样相应的脚本只在实际需要时
才加载，脚本应命名为 <filetype>format.vim。

例如，随 Vim 分发的 XML 文件类型插件在
$VIMRUNTIME/ftplugin 目录中，将 'formatexpr' 选项设为： >

   setlocal formatexpr=xmlformat#Format()

这意味着你可以在文件 `$VIMRUNTIME/autoload/xmlformat.vim`
中找到定义 xmlformat#Format() 函数的相应脚本

以下示例脚本从选定文本中删除尾随空白。将其放在你的
autoload 目录中，例如 ~/.vim/autoload/format.vim：
>vim
  func! format#Format()
    " 仅在显式 gq 命令时重格式化
    if mode() != 'n'
      " 回退到 Vim 内部重格式化
      return 1
    endif
    let lines = getline(v:lnum, v:lnum + v:count - 1)
    call map(lines, {key, val -> substitute(val, '\s\+$', '', 'g')})
    call setline('.', lines)

    " 不运行内部格式化器！
    return 0
  endfunc

然后你可以通过执行以下命令来启用格式化： >
  setlocal formatexpr=format#Format()

注意：此函数在从插入模式调用时（基本上意味着文本插入超过
'textwidth' 限制时）显式返回非零。这使 Vim 回退到使用
内部格式化器重格式化文本。

但是，如果使用 |gq| 命令重格式化文本，函数将接收选定行，
修剪这些行的尾随空白并将它们放回原位。如果你要将单行
拆分为多行，注意不要覆盖任何内容。

如果你想允许从插入或替换模式重格式化文本，必须非常小心，
因为函数可能被递归调用。用于调试时设置 'debug' 选项很有帮助。

							*right-justify*
Vim 中没有右对齐文本的命令。你可以用外部命令来做，
如 "par"（例如：`:.,}!par` 格式化到段落末尾）或将
'formatprg' 设为 "par"。

							*format-comments*
注释格式化概览在用户手册 |30.6| 节中。

Vim 可以自动以特殊方式插入和格式化注释。Vim 通过行开头
的特定字符串（忽略空白）来识别注释。可以使用三种注释类型：

- 在每行开头重复的注释字符串。例如 shell 脚本中使用的
  以 "#" 开头的注释。
- 只在第一行出现，后续行没有的注释字符串。例如此列表中
  使用的破折号。
- 三件式注释，有开始字符串、结束字符串和可选的中间行。
  开始、中间和结束的字符串不同。例如 C 风格注释： >
	/*
	 * this is a C comment
	 */

'comments' 选项是逗号分隔的部分列表。每个部分定义一种
注释字符串类型。一个部分由以下组成：
	{flags}:{string}

{string} 是必须出现的字面文本。

{flags}:
  n	嵌套注释。允许混合部分嵌套。如果 'comments' 是
	"n:),n:>" 则以 "> ) >" 开头的行是注释。

  b	{string} 后需要空白（<Space>、<Tab> 或 <EOL>）。

  f	只有第一行有注释字符串。不在下一行重复注释，
	但保留缩进（例如项目符号列表）。

  s	三件式注释的开始

  m	三件式注释的中间

  e	三件式注释的结束

  l	左对齐。与 's' 或 'e' 一起使用，开始或结束的
	最左字符与中间的最左字符对齐。
	这是默认值，可以省略。更多细节见下文。

  r	右对齐。与上面相同但是最右而不是最左。
	更多细节见下文。

  O	不为 "O" 命令考虑此注释。

  x	允许三件式注释在新行上只输入结束注释字符串的
	最后一个字符就结束，当中间注释字符串已自动
	插入时。更多细节见下文。

  {digits}
	与 's' 或 'e' 一起使用：给自动插入的中间或结束
	注释前导添加 {digit} 偏移量。偏移从左对齐开始。
	更多细节见下文。

  -{digits}
	类似 {digits} 但减少缩进。这仅在开始或结束部分
	有一些可以删除的缩进时有效。

当字符串没有 'f'、's'、'm' 或 'e' 标志时，Vim 假定注释
字符串在每行开头重复。{flags} 字段可以为空。

文本中 {string} 前后的任何空白是 {string} 的一部分，
所以不要包含前导或尾随空白，除非空白是注释字符串的
必需部分。

当一个注释前导是另一个的一部分时，在整体之后指定部分。
例如，要同时包含 "-" 和 "->"，使用 >
	:set comments=f:->,f:-

三件式注释必须始终作为 开始,中间,结束 给出，中间没有
其他部分。三件式注释的示例是 >
	sr:/*,mb:*,ex:*/
用于 C 注释。为避免 "*ptr" 被识别为注释，中间字符串
包含 'b' 标志。对于三件式注释，Vim 在开始和中间字符串
之后检查结束字符串。如果 Vim 找到结束字符串，注释不
在下一行继续。三件式注释必须有中间字符串，因为否则
Vim 无法识别中间行。

注意在上面的三件式注释定义中使用了 "x" 标志。当你在
C 注释中按 Return 时，Vim 将为新行插入中间注释前导：
" * "。要关闭此注释，你只需在新行上输入任何其他内容前
输入 "/"。这将用结束注释前导替换中间注释前导并应用
指定的对齐，只留下 `" */"`。不需要先按退格键。

当有中间部分的匹配，但也有更长的匹配结束部分时，使用
结束部分。这使得 C 风格注释在不要求中间部分以空格结尾
的情况下也能工作。

以下是对齐标志工作的示例（看起来有点像 1）。
考虑注释字符串： >vim
	:set comments=sr:/***,m:**,ex-2:******/
>
                                   /***
                                     **<--从 "r" 标志右对齐
                                     **
 "-2" 标志偏移 2 空格-->            **
                                   ******/
在此例中，第一个注释被输入，然后按了 4 次回车，
然后按 "/" 结束注释。

以下是三件式注释的一些细节。有三种情况考虑对齐和
偏移标志：在开始注释后打开新行、在结束注释前打开
新行以及自动结束三件式注释。结束对齐标志有向后的
视角；结果是用 "s" 和 "e" 使用相同的对齐标志将
导致开始和结束部分相同的缩进。每个注释部分只能使用
一种对齐方式，但偏移数会覆盖 "r" 和 "l" 标志。

启用 'cindent' 在许多情况下会覆盖对齐标志。
使用不同方法如 |gq| 或 |=| 重新缩进也不会参考
对齐标志。相同的行为可以在那些其他格式化选项中定义。
一个考虑因素是 'cindent' 有基于上下文的注释缩进的
额外选项，但无法复制许多三件式缩进对齐。然而，
'indentexpr' 能更好地处理三件式注释。

其他示例： >
   "b:*"	包含以 "*" 开头的行，但如果 "*" 后跟
		非空白则不包含。这避免像 "*str" 这样的
		指针解引用被识别为注释。
   "n:>"	包含以 ">"、">>"、">>>" 等开头的行。
   "fb:-"	格式化以 "- " 开头的列表。

默认情况下包含 "b:#"。这意味着以 "#include" 开头的行
不会被识别为注释行。但以 "# define" 开头的行会被识别。
这是一种折衷。

							*fo-table*
你可以使用 'formatoptions' 选项来影响 Vim 如何格式化文本。
'formatoptions' 是一个字符串，可以包含下面的任何字母。
你可以用逗号分隔选项字母以提高可读性。

字母	 存在于 'formatoptions' 中的含义    ~
							*fo-t*
t	使用 'textwidth' 自动换行文本
							*fo-c*
c	使用 'textwidth' 自动换行注释，自动插入当前
	注释前导。
							*fo-r*
r	在插入模式中按 <Enter> 后自动插入当前注释前导。
							*fo-o*
o	在普通模式中按 'o' 或 'O' 后自动插入当前注释前导。
	如果在特定位置不想要注释，使用 CTRL-U 快速删除。
	|i_CTRL-U|
							*fo-/*
/	当包含 'o' 时：语句后不插入 // 注释的注释前导，
	只有当 // 在行首时才插入。
							*fo-q*
q	允许用 "gq" 格式化注释。
	注意格式化不会改变空行或只包含注释前导的行。
	这样的行后或注释前导改变时开始新段落。
							*fo-w*
w	尾随空白表示段落在下一行继续。
	以非空白字符结尾的行结束段落。
							*fo-a*
a	自动格式化段落。每次插入或删除文本时段落将被
	重格式化。见 |auto-format|。
	当有 'c' 标志时，只对识别的注释发生。
							*fo-n*
n	格式化文本时识别编号列表。这实际上使用 'formatlistpat'
	选项，因此可以使用任何类型的列表。数字后文本的
	缩进用于下一行。默认是查找数字，后面可选跟
	'.'、':'、')'、']' 或 '}'。注意 'autoindent' 也
	必须设置。与 "2" 不能很好地一起工作。
	示例： >
		1. the first item
		   wraps
		2. the second item
<							*fo-2*
2	格式化文本时，使用段落第二行的缩进用于段落其余
	部分，而不是第一行的缩进。这支持第一行与其余
	部分缩进不同的段落。注意 'autoindent' 也必须设置。
	示例： >
			first line of a paragraph
		second line of the same paragraph
		third line.
<	这在注释内部也适用，忽略注释前导。
							*fo-v*
v	Vi 兼容的插入模式自动换行：仅在你在当前插入命令
	期间输入的空白处断行。（注意：这不是 100% Vi 兼容。
	Vi 在此领域有一些"意外功能"或缺陷。它使用屏幕列
	而不是行列。）
							*fo-b*
b	类似 'v'，但仅在你在换行边距处或之前输入空白时
	自动换行。如果开始插入时行已经比 'textwidth' 长，
	或你在到达 'textwidth' 之前没有在插入中输入空白，
	Vim 不执行自动换行。
							*fo-l*
l	长行在插入模式中不被断开：当插入命令开始时行已经
	比 'textwidth' 长，Vim 不自动格式化它。
							*fo-m*
m	也在 255 以上的多字节字符处断开。这对每个字符
	都是一个单词的亚洲文本很有用。注意也可能在
	冒号等标点字符后添加换行以匹配 CJK 断行规则。
							*fo-M*
M	合并行时，不在多字节字符前后插入空格。覆盖 'B' 标志。
							*fo-B*
B	合并行时，不在两个多字节字符之间插入空格。
	被 'M' 标志覆盖。
							*fo-1*
1	不在单字母单词后断行。而是在它之前断开
	（如果可能）。
							*fo-]*
]	严格遵守 'textwidth'。使用此标志，任何行不能比
	'textwidth' 更长，除非断行禁止规则使这不可能。
	主要用于 CJK 脚本，仅当 'encoding' 为 "utf-8" 时有效。
							*fo-j*
j	在有意义时，合并行时删除注释前导。例如，合并：
		int i;   // the index ~
			 // in the list ~
	变为：
		int i;   // the index in the list ~
							*fo-p*
p	不在句号后的单个空格处断行。这旨在补充
	'joinspaces' 和 |cpo-J|，用于以两个空格分隔
	句子的散文。例如，'textwidth' 设为 28 时： >
		Surely you're joking, Mr. Feynman!
<	变为： >
		Surely you're joking,
		Mr. Feynman!
<	而不是： >
		Surely you're joking, Mr.
		Feynman!


使用 't' 和 'c' 你可以指定 Vim 何时执行自动换行：
值	动作	~
""	不自动格式化（你可以用 "gq" 手动格式化）
"t"	自动格式化文本，但不格式化注释
"c"	自动格式化注释，但不格式化文本（适合 C 代码）
"tc"	同时自动格式化文本和注释

注意当 'textwidth' 为 0 时，Vim 无论如何不会自动格式化
（但确实根据 'comments' 选项插入注释前导）。当 'a' 标志
存在时例外。|auto-format|

注意 'textwidth' 可以非零即使 Vim 从不执行自动换行；
'textwidth' 对用 "gq" 格式化仍然有用。

如果 'comments' 选项包含 "/*"、"*" 和/或 "*/"，Vim 有一些
内置功能来更智能地处理这些类型的注释。
在 "/*" 或 "*/" 之前或之后打开新行（'formatoptions' 中有
'r' 或 'o'）会自动给出正确的行开头。格式化和自动换行
也是如此。在以 "/*" 或 "*" 开头且包含 "*/" 的行之后打开行，
不会插入注释前导，新行的缩进取自包含注释开始的行。
例如： >
    /*
     * Your typical comment.
     */
    The indent on this line is the same as the start of the above
    comment.

所有这些应该非常酷，特别是与新的 :autocmd 命令结合，
为不同类型的文件准备不同的设置。

一些示例：
  对于 C 代码（只格式化注释）： >
	:set fo=croq
< 对于 Mail/news（全部格式化，不用 "o" 命令开始注释）： >
	:set fo=tcrq
<

自动格式化				*auto-format* *autoformat*

当 'formatoptions' 中有 'a' 标志时，在插入或删除文本时
自动格式化文本。这对编辑文本段落效果很好。使用提示：

- 你需要正确定义段落。最简单的是用空行分隔的段落。
  当没有分隔空行时，考虑使用 'w' 标志并在段落每行末尾
  添加空格（最后一行除外）。

- 你可以根据文件类型 |filetype| 或用 |modeline| 针对特定
  文件设置 'formatoptions'。

- 将 'formatoptions' 设为 "aw2tq" 以制作这样缩进的文本：

	    bla bla foobar bla
	bla foobar bla foobar bla
	    bla bla foobar bla
	bla foobar bla bla foobar

- 添加 'c' 标志以只自动格式化注释。对源代码有用。

- 将 'textwidth' 设为所需宽度。如果为零则使用 79，
  如果屏幕更窄则使用屏幕宽度。

一些警告：

- 当部分文本未正确分为段落时，在此文本中做更改将
  导致它被格式化。考虑执行 >

	:set fo-=a

- 当使用 'w' 标志（尾随空格表示段落继续）并用 |dd|
  删除段落的最后一行时，段落将与下一个合并。

- 更改的文本为撤销保存。格式化也是更改。因此每次
  格式化动作保存用于撤销的文本。这可能消耗相当多的内存。

- 格式化长段落和/或复杂缩进可能较慢。

7. 排序文本					*sorting*

Vim 有排序函数和排序命令。排序函数在这里：|sort()|、|uniq()|。
另见 |:uniq|。

							*:sor* *:sort*
:[range]sor[t][!] [b][f][i][l][n][o][r][u][x] [/{pattern}/]
			排序 [range] 中的行。未给范围时排序所有行。

			使用 [!] 时顺序反转。

			使用 [i] 时忽略大小写。
							*:sort-l*
			使用 [l] 时用当前排序区域设置排序。
			实现细节：使用 strcoll() 比较字符串。
			见 |:language| 检查或设置排序区域设置。
			示例： >
				:language collate en_US.UTF-8
				:%sort l
<			|v:collate| 也可用于检查当前区域设置。
			使用区域设置排序通常忽略大小写。
			在 Mac 上不能正常工作。

			选项 [n][f][x][o][b] 互斥。

			使用 [n] 时按行中第一个十进制数排序
			（在 {pattern} 匹配之后或内部）。
			一个前导 '-' 包含在数字中。

			使用 [f] 时按行中的 Float 排序。
			Float 的值确定方式类似于将文本
			（在 {pattern} 匹配之后或内部）传递给
			str2float() 函数。

			使用 [x] 时按行中第一个十六进制数排序
			（在 {pattern} 匹配之后或内部）。
			前导 "0x" 或 "0X" 被忽略。
			一个前导 '-' 包含在数字中。

			使用 [o] 时按行中第一个八进制数排序
			（在 {pattern} 匹配之后或内部）。

			使用 [b] 时按行中第一个二进制数排序
			（在 {pattern} 匹配之后或内部）。
							*:sort-u* *:sort-uniq*
			使用 [u]（u 代表 unique）时只保留相同行
			序列中的第一行（使用 [i] 时忽略大小写）。
			没有此标志时，相同行的序列保持原始顺序。
			注意前导和尾随空白可能导致行不同。
			当你只想去重时，使用 |:uniq|。

			当指定了 /{pattern}/ 且没有 [r] 标志时，
			跳过与 {pattern} 匹配的文本，使你对匹配
			之后的内容排序。
			'ignorecase' 适用于模式，但不使用 'smartcase'。
			可以使用任何非字母代替斜杠。
			例如，按第二个逗号分隔字段排序： >
				:sort /[^,]*,/
<			按虚拟第 10 列的文本排序（忽略制表符和
			空格的差异）： >
				:sort /.*\%10v/
<			按行中第一个数字排序，无论前面是什么： >
				:sort /.\{-}\ze\d/
<			（解释：".\{-}" 匹配任何文本，"\ze" 设置
			匹配的末尾，\d 匹配数字。）
			使用 [r] 时按匹配的 {pattern} 排序，
			而不是如上所述跳过它。
			例如，只按每行的前三个字母排序： >
				:sort /\a\a\a/ r

<			如果使用了 {pattern}，任何没有 {pattern}
			匹配的行保持当前顺序，但与匹配 {pattern}
			的行分开。如果你反向排序，它们将在排序行
			之后以反向顺序出现，否则它们将以原始顺序
			出现在排序行之前。

			如果 {pattern} 为空（例如指定了 //），
			使用上次搜索模式。这允许先尝试模式。

注意将 `:sort` 与 `:global` 一起使用不会排序匹配行，
它相当无用。

`:sort` 不使用当前区域设置，除非使用 l 标志。
Vim 执行"稳定"排序。

排序可以中断，但如果你在过程中太晚中断，你可能会得到
重复行。这也取决于使用的系统库函数。

8. 去重文本				*deduplicating* *unique*

Vim 有去重函数和去重命令。去重函数在这里：|uniq()|。
另见 |:sort-uniq|。

							*:uni* *:uniq*
:[range]uni[q][!] [i][l][r][u] [/{pattern}/]
			删除 [range] 中相邻的重复行。未给范围时
			处理所有行。

			使用 [i] 时比较行时忽略大小写。

			使用 [l] 时比较使用当前排序区域设置。
			更多细节见 |:sort-l|。

			使用 [r] 时比较基于匹配 /{pattern}/ 的文本
			而不是整行。

			使用 [u] 时只保留不重复的行（即不紧跟
			相同行的行）。

			使用 [!] 时只保留紧跟重复行的行。

			如果同时给出 [!] 和 [u]，忽略 [u]，
			[!] 生效。

			当指定了 /{pattern}/ 且不使用 [r] 时，
			跳过与 {pattern} 匹配的文本，比较在匹配
			之后的内容。
			'ignorecase' 适用于模式，但不使用 'smartcase'。
			可以使用任何非字母代替斜杠。

			例如，基于第二个逗号分隔字段删除相邻
			重复行： >
				:uniq /[^,]*,/
<			或只保留忽略前 5 个字符的唯一行： >
				:uniq u /.\{5}/
<			如果 {pattern} 为空（例如使用了 //），
			使用上次搜索模式。

			注意前导和尾随空白可能导致行被视为不同。
			要删除所有重复（无论位置），使用
			|:sort-u| 或外部工具。
