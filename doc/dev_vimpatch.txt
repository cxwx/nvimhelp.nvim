从 Vim 合并补丁                                             *dev-vimpatch*


Nvim 从 Vim 7.4.160 分叉而来；它与相关的 Vim 补丁保持同步以避免重复工作。
运行 `vim-patch.sh`
https://github.com/neovim/neovim/blob/master/scripts/vim-patch.sh 查看
Vim 补丁的状态：
>bash
    ./scripts/vim-patch.sh -l
<
欢迎所有人为相关的 Vim 补丁提交 |dev-vimpatch-pull-requests|，但某些类型
的补丁 |dev-vimpatch-not-applicable|。
参见 |dev-vimpatch-quickstart| 立即开始。


                                         输入 |gO| 查看目录。

快速入门                                              *dev-vimpatch-quickstart*

1. 拉取 Nvim 源码： >bash
     git clone https://github.com/neovim/neovim.git
2. 运行 `./scripts/vim-patch.sh -l` 查看缺失的 Vim 补丁列表。
3. 从列表中选择一个补丁（通常是最旧的那个），例如 `8.0.0123`。
   - 检查已打开的 vim-patch PR
     https://github.com/neovim/neovim/pulls?q=is%3Apr+is%3Aopen+label%3Avim-patch。
4. 运行 `./scripts/vim-patch.sh -p 8.0.0123`
5. 按照脚本给出的指示操作。

注意 ~

- 强烈建议从最旧的缺失补丁开始工作，因为后续的补丁可能依赖于这些更改。
- 使用 `git log --grep` 或 `git log -G` 搜索 Nvim/Vim 源码历史
  （包括已删除的代码）。例如查找 `reset_option_was_set`： >bash

    git log -p -G reset_option_was_set
<
- 将 `git log` 选项（如 `--grep` 和 `-G`）传递给 `./scripts/vim-patch.sh -L`
  来过滤未合并的 Vim 补丁。例如查找 `+quickfix` 补丁： >bash

    ./scripts/vim-patch.sh -L --grep quickfix -- src
<

NA（不适用）补丁                               *dev-vimpatch-not-applicable*

许多 Vim 补丁不适用于 Nvim。如果你发现 NA 补丁，访问已打开的
"version.c: update" 拉取请求
https://github.com/neovim/neovim/pulls?q=is%3Apr+author%3Aapp%2Fgithub-actions+version.c+is%3Aopen
并在评论中提及 NA 补丁（请编辑/更新一条评论，而不是为每个补丁添加新评论）。

如果没有打开的 `version.c: update` 拉取请求，在提交消息中以以下格式包含
NA 补丁：
>
    vim-patch:<version-or-commit>
    vim-patch:<version-or-commit>
    ...
<
其中 `<version-or-commit>` 是有效的 Vim 版本号（如 `8.0.0123`）或
commit-id (SHA)。每个补丁占一行。

推荐将 NA 补丁通过压缩合入适用的 Vim 补丁中，特别是当这些 Vim 补丁
相互关联时。提交消息的第一行应来自适用的 Vim 补丁。
>
    ./scripts/vim-patch -p <na-patch>
    ./scripts/vim-patch -p <na-patch>
    ...
    ./scripts/vim-patch -P <patch>
    git rebase -i master
<
示例：
https://github.com/neovim/neovim/commit/00f60c2ce78fc1280e93d5a36bc7b2267d5f4ac6

"不适用" VIM 补丁的类型 ~

- Vim9script 功能以及与 `:scriptversion` 相关的所有内容。（Nvim 仅支持
  Vimscript 版本 1。）请注意，标记为 `Vim9:` 的补丁可能仍包含适用于
  代码库其他部分的修复，因此这些补丁需要逐个检查。
- `testdir/Makefile` 的更新通常是 NA，因为该 Makefile 隐式发现
  https://github.com/neovim/neovim/commit/8a677f8a4bff6005fa39f090c14e970c3dfdbe6e#diff-b3c6ad6680a25a1b42095879e3a87104R52
  所有 `test_*.vim` 文件。
- 编译器警告修复：Nvim 致力于完全没有警告，且其构建系统与 Vim 非常不同。
    - 注意：Vim 中的 Coverity 修复与 Nvim 相关。
- `*.proto` 更改：Nvim 自动生成函数原型
- `#ifdef` 调整：例如，Vim 决定为所有平台启用 `FEAT_VISUAL` - 但 Nvim
  已经这样做了。添加新的 `FEAT_` 保护也与 Nvim 无关。
- 旧系统支持：对 Amiga、OS/2 Xenix、Mac OS 9、Windows XP SP2 之前版本等
  旧系统的修复不需要，因为 Nvim 不支持它们。
    - NA 文件：`src/Make_*`、`src/testdir/Make__*`
- `if_*.c` 更改：`if_python.c` 等已被移除。
- 大多数 `term.c` 更改：Nvim TUI 使用 `libtermkey` 读取终端序列；
  注意：`replace_termcodes()` 适用且已移至 `src/nvim/keycodes.c`。
- `job` 补丁：不兼容的 API 和实现
    - NA 文件：`src/channel_*`、`src/job_*`、`src/testdir/test_channel_*`、
      `src/testdir/test_job_*`
- 修改 NA 文件的 `:terminal` 补丁：不兼容的 API 和实现
    - NA 文件：`src/terminal_*`、`src/testdir/test_terminal_*`
- `defaults.vim` 补丁
- 大多数 GUI 相关更改：Nvim GUI 实现在核心 C 代码库之外。
    - NA 文件：`src/gui_*`、`src/gvim_*`、`src/GvimExt/*`、
      `src/testdir/test_gui*`
- `balloon` 更改：Nvim 不支持 balloon 功能
    - NA 文件：`src/beval_*`、`src/testdir/test_balloon_*`
- 来自 `test_popupwin.vim`、`test_popupwin_textprop.vim` 的屏幕截图测试：
  https://github.com/neovim/neovim/pull/12741#issuecomment-704677141
- json 更改：不兼容的 API https://github.com/neovim/neovim/pull/4131
    - NA 文件：`src/json*`、`src/testdir/test_json.vim`
- `test_restricted.vim` 受限模式已在
  https://github.com/neovim/neovim/pull/11996 中移除
- `test_prompt_buffer.vim` 中的许多测试需要不兼容的 Vim 功能（如
  `channel`）；它们仍应被包含，但应被跳过
- 非运行时文档：已移至 `BUILD.md`、`INSTALL.md`。
    - NA 文件：`Filelist`、`README`、`INSTALL`
- 其他任何内容都可能是相关的；谨慎行事，如果不确定请提交 issue。

VERSION.C                                          *dev-vimpatch-version.c*

`src/nvim/version.c` 中的 Vim 补丁列表是自动更新的
https://github.com/neovim/neovim/pull/7780，基于 Nvim git 日志中
`vim-patch:xxx` 标记的存在。

- 不要自行更新 `src/nvim/version.c`。
    - `scripts/vim-patch.sh -p` 有意省略 `version.c` 以避免合并冲突
      并在移植补丁时节省时间。
- 自动化脚本（`scripts/vimpatch.lua`）只识别类似 `vim-patch:8.0.1206`
  的标记，不识别 `vim-patch:<hash>`。

https://github.com/neovim/neovim/pull/7708/ 中更改。有一个针对"旧"用法的
lint，但以下是最重要的更改。

表中的声明

- `list_T list`：一个列表
- `listitem_T li`：`list` 的一个项目
- `int val` 用于 `lv_copyID` 的值

>

  list->lv_last                   tv_list_last(list)
  li->li_next                     TV_LIST_ITEM_NEXT(list, li)          尽可能避免使用，必须使用 li 所属的 list。
  li->li_prev                     TV_LIST_ITEM_PREV(list, li)          尽可能避免使用，必须使用 li 所属的 list。

文件类型检测                                   *dev-vimpatch-filetype*

Nvim 的文件类型检测行为与 Vim 匹配，但实现为 |vim.filetype| 的一部分
（参见 `$VIMRUNTIME/lua/vim/filetype.lua`）。逻辑编码在三个表中，按优先级
排列（返回第一个匹配）：
1. `filename` 用于字面完整路径或基本名称查找；
2. `pattern` 用于将文件名或路径与 |lua-pattern| 匹配，针对快速查找优化；
3. `extension` 用于字面扩展名查找。

需要检查文件内容或缓冲区变量的逻辑在
`$VIMRUNTIME/lua/vim/filetype/detect.lua` 中实现。

从 Vim 移植文件类型补丁时，请注意以下几点：

优先使用显式文件名或扩展名而非模式，特别是对于不区分大小写的匹配
（参见 https://github.com/neovim/neovim/pull/29800）： >
    "*[mM]akefile" regex -> "makefile", "Makefile" filenames
    "*.js\c"       regex -> "js", "jS", "Js", "jS" extensions

模式匹配有几个差异：
- 使用显式的 Lua 模式（无隐式锚定）而非 Vim 正则表达式： >
    "*/debian/changelog" -> "/debian/changelog$"
    "*/bind/db.*"        -> "/bind/db%."
<
- 文件类型模式按其父模式分组以提高匹配性能：如果父模式不匹配，则跳过
  测试所有子模式。请注意，与叶模式不同，如果父模式包含 `/`，则没有特殊
  匹配行为。

  添加带模式匹配的新文件类型时，请考虑以下几点：
  - 如果已有一个带有合适父模式的组，请使用它。
  - 如果能有一个足够快速和特定的模式来分组至少 3 个文件类型模式，
    则将其作为单独的分组条目添加。

  新的父模式应该是
  - 快速的：经验法则是它应该是一个简短的显式字符串
  （即没有量词或字符集）；
  - 特定的：经验法则，按顺序：
    - 完整的目录名（例如 `"/etc/"`、`"/log/"`）；
    - 足够罕见的目录名的一部分（例如 `"/conf"`、`"git/"`）；
    - 在真实完整路径中很少使用的字符串（例如 `"nginx"`）。

  示例：
  - 文件类型模式：`".*/etc/a2ps/.*%.cfg"`
  - 好的父模式：`"/etc/"` 或 `"%.cfg$"`
  - 坏的父模式：`"%."` （快速但不特定）或 `"/a2ps/.*%."` （特定但慢）

  修改现有常规模式时，请确保它仍然适合其组。
