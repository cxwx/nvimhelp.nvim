Vim 有一些通用功能使得输入命令更加容易。冒号命令可以被缩写、编辑和重复。几乎
所有地方都可以使用补全。

*20.1*	命令行编辑

当你使用冒号 (:) 命令或者用 / 或 ? 搜索字符串时，Vim 会将光标放到屏幕底部。
在那里你输入命令或搜索模式。这被称为命令行。即使在输入搜索命令时也是如此。

编辑已输入命令的最直接方法是按 <BS> 键。这会删除光标前的字符。要删除更早输入
的另一个字符，先用光标键移动光标。
   例如，你输入了这个: >

	:s/col/pig/

在按 <Enter> 之前，你注意到 "col" 应该是 "cow"。要修正这个错误，你按 <Left>
五次。光标现在正好在 "col" 之后。输入 <BS> 和 "w" 来修正: >

	:s/cow/pig/

现在你可以直接按 <Enter> 了。在执行命令之前不需要把光标移到行尾。

命令行中最常用的移动键:

	<Left>			左移一个字符
	<Right>			右移一个字符
	<S-Left> 或 <C-Left>	左移一个单词
	<S-Right> 或 <C-Right>	右移一个单词
	CTRL-B 或 <Home>	移到命令行开头
	CTRL-E 或 <End>		移到命令行末尾

	备注:
	<S-Left>（按住 Shift 再按左光标键）和 <C-Left>（按住 Control 再按左光标
	键）不是在所有键盘上都有效。其他的 Shift 和 Control 组合键也一样。

你也可以用鼠标来移动光标。


删除

如前所述，<BS> 删除光标前的字符。要删除整个单词用 CTRL-W。

	/the fine pig ~

		     CTRL-W

	/the fine ~

CTRL-U 删除所有文本，让你可以从头开始。


改写

<Insert> 键在插入字符和替换已有字符之间切换。从这段文本开始:

	/the fine pig ~

用 <S-Left> 两次（或 <Left> 八次，如果 <S-Left> 不起作用）将光标移到 "fine" 的
开头。现在按 <Insert> 切换到改写模式并输入 "great":

	/the greatpig ~

哎呀，我们丢失了空格。现在不要用 <BS>，因为它会删除 "t"（这和替换模式不同）。
换一种方法，按 <Insert> 从改写切换回插入模式，然后输入空格:

	/the great pig ~


取消

你想执行一个 : 或 / 命令，但改变了主意。要丢弃已经输入的内容而不执行它，按
CTRL-C 或 <Esc>。

	备注:
	<Esc> 是通用的 "退出" 键。不幸的是，在传统的 Vi 中，在命令行按 <Esc>
	会执行命令！由于这可以被认为是一个 bug，Vim 使用 <Esc> 来取消命令。但
	通过 'cpoptions' 选项可以使其兼容 Vi。当使用映射（可能是为 Vi 编写的）
	时 <Esc> 也按 Vi 兼容方式工作。因此，使用 CTRL-C 是一种始终有效的方法。

如果你在命令行的开头，按 <BS> 会取消命令。就像删除了行首的 ":" 或 "/" 一样。

*20.2*	命令行缩写

有些 ":" 命令确实很长。我们已经提到 ":substitute" 可以缩写为 ":s"。这是一种
通用机制，所有的 ":" 命令都可以被缩写。

一个命令最短能缩到多短？共有 26 个字母，但命令要多得多。例如，":set" 也以 ":s"
开头，但 ":s" 并不会启动 ":set" 命令。实际上 ":set" 可以缩写为 ":se"。
   当一个缩写形式可能用于两个命令时，它只代表其中一个。这背后没有什么逻辑，你
需要记住它们。在帮助文件中会提到能用的最短形式。例如: >

	:s[ubstitute]

这意味着 ":substitute" 的最短形式是 ":s"。后面的字符是可选的。因此 ":su" 和
":sub" 也能用。

在用户手册中，我们会使用命令的全名或仍可辨认的缩写形式。例如，":function" 可以
缩写为 ":fu"。但由于大多数人不理解它代表什么，我们将使用 ":fun"。（Vim 没有
":funny" 命令，否则 ":fun" 也会令人困惑。）

建议在 Vim 脚本中使用命令的全名。这使你以后修改时更容易阅读。经常使用的命令
除外，如 ":w" (":write") 和 ":r" (":read")。
   特别容易混淆的是 ":end"，它可以代表 ":endif"、":endwhile" 或 ":endfunction"。
因此，始终使用全名。


简短选项名

在用户手册中使用的是选项的长名。很多选项也有短名。与 ":" 命令不同，只有一个短名
有效。例如，'autoindent' 的短名是 'ai'。因此这两个命令效果相同: >

	:set autoindent
	:set ai

你可以在这里找到长名和短名的完整列表: |option-list|。

*20.3*	命令行补全

这是 Vim 的功能之一，仅此一项就足以成为从 Vi 切换到 Vim 的理由。一旦你用过这个
功能，就再也离不开了。

假设你有一个目录包含这些文件:

	info.txt
	intro.txt
	bodyofthepaper.txt

要编辑最后一个，你使用命令: >

	:edit bodyofthepaper.txt

这很容易打错。一种更快的方法是: >

	:edit b<Tab>

这会得到相同的命令。发生了什么？<Tab> 键对光标前的单词进行补全。在这里是 "b"。
Vim 在目录中查找，发现只有一个文件以 "b" 开头。那一定就是你要找的文件，所以 Vim
为你补全了文件名。

现在输入: >

	:edit i<Tab>

Vim 会发出蜂鸣声，并给出: >

	:edit info.txt

蜂鸣声表示 Vim 找到了多个匹配项。然后它使用找到的第一个匹配（按字母顺序）。如果
你再按 <Tab>，你会得到: >

	:edit intro.txt

因此，如果第一次 <Tab> 没有给出你想要的文件，再按一次。如果有更多匹配项，你会
一个接一个看到它们。
   如果你在最后一个匹配项上按 <Tab>，你会回到最初输入的内容: >

	:edit i

然后重新开始循环。Vim 在匹配列表中循环。使用 CTRL-P 反方向遍历列表:

	      <------------------- <Tab> -------------------------+
								  |
		  <Tab> -->		       <Tab> -->
	:edit i		      :edit info.txt		   :edit intro.txt
		  <-- CTRL-P		       <-- CTRL-P
	   |
	   +---------------------- CTRL-P ------------------------>


上下文

当你输入 ":set i" 而不是 ":edit i" 并按 <Tab> 时，你得到的是: >

	:set icon

嘿，为什么你没得到 ":set info.txt"？那是因为 Vim 有上下文相关的补全。Vim 会根据
命令来决定查找什么类型的单词。Vim 知道在 ":set" 命令后面不能使用文件名，但可以
使用选项名。
   同样，如果你反复按 <Tab>，Vim 会在所有匹配中循环。匹配项很多，最好先多输入
几个字符: >

	:set isk<Tab>

得到: >

	:set iskeyword

现在输入 "=" 并按 <Tab>: >

	:set iskeyword=@,48-57,_,192-255

这里发生的是 Vim 插入了选项的旧值。现在你可以编辑它了。
   <Tab> 补全的内容是 Vim 在该位置期望的东西。试试看它是怎么工作的。在某些情况
下你不会得到你想要的。那要么是因为 Vim 不知道你想要什么，要么是因为那种情况下的
补全还没有实现。在这种情况下你会得到一个 <Tab>（显示为 ^I）。


列出匹配

当有很多匹配项时，你想要查看一个概览。按 CTRL-D 即可。例如，在以下命令后按
CTRL-D: >

	:set is

结果是: >

	:set is
	incsearch  isfname    isident    iskeyword  isprint
	:set is

Vim 列出匹配项然后回到你输入的文本。你现在可以查看列表中是否有你想要的项目。如果
没有，你可以用 <BS> 来修改。如果匹配项很多，在按 <Tab> 补全之前多输入几个字符。
   如果你仔细观察，你会注意到 "incsearch" 并不是以 "is" 开头。在这里 "is" 代表
"incsearch" 的短名。（很多选项有长名和短名。）Vim 很聪明，知道你可能想要将选项
的短名展开为长名。


更多

CTRL-L 命令将单词补全到最长的无歧义字符串。如果你输入 ":edit i" 而有文件
"info.txt" 和 "info_backup.txt"，你会得到 ":edit info"。

'wildmode' 选项可以用来改变补全的工作方式。
'wildmenu' 选项可以用来获取菜单式的匹配列表。
用 'suffixes' 选项指定不太重要的文件，它们出现在文件列表的末尾。
'wildignore' 选项指定完全不列出的文件。

更多相关信息请参见: |cmdline-completion|

*20.4*	命令行历史

在第 3 章中我们简要提到了历史记录。基本用法是用 <Up> 键调出旧的命令行。<Down>
则回到较新的命令。

实际上有五种历史记录。这里要提到的是 ":" 命令和 "/" 及 "?" 搜索命令的历史。"/"
和 "?" 命令共享同一个历史，因为它们都是搜索命令。其他三种历史用于表达式、调试
模式命令和 input() 函数的输入行。|cmdline-history|

假设你执行了一个 ":set" 命令，之后又输入了十个冒号命令，现在想重复那个 ":set"
命令。你可以按 ":" 然后按十次 <Up>。有一种更快的方法: >

	:se<Up>

Vim 会回到以 "se" 开头的上一个命令。你很有可能找到你想要的 ":set" 命令。至少
你不需要按太多次 <Up>（除非你执行的全是 ":set" 命令）。

<Up> 键会将你目前输入的文本与历史中的行进行比较。只有匹配的行才会被使用。
   如果你没找到想要的行，使用 <Down> 回到你输入的内容并修改它。或者使用 CTRL-U
重新开始。

要查看历史中的所有行: >

	:history

这是 ":" 命令的历史。搜索历史用这个命令显示: >

	:history /

CTRL-P 的工作方式与 <Up> 类似，但不考虑你已经输入的内容。CTRL-N 和 <Down> 类似。
CTRL-P 代表 previous（上一个），CTRL-N 代表 next（下一个）。

*20.5*	命令行窗口

在命令行中输入文本与在插入模式中输入文本的方式不同。它不允许使用很多修改文本的
命令。对于大多数命令来说这没问题，但有时你需要输入一个复杂的命令。这时命令行
窗口就有用了。

用这个命令打开命令行窗口: >

	q:

Vim 会在底部打开一个（小的）窗口。它包含命令行历史，以及最后的一个空行:
>
	+-------------------------------------+
	|other window			      |
	|~				      |
	|file.txt=============================|
	|:e c				      |
	|:e config.h.in			      |
	|:set path=.,/usr/include,,	      |
	|:set iskeyword=@,48-57,_,192-255     |
	|:set is			      |
	|:q				      |
	|:				      |
	|command-line=========================|
	|				      |
	+-------------------------------------+
<
你现在在普通模式中。你可以使用 "hjkl" 键来移动。例如，用 "5k" 向上移到
":e config.h.in" 行。输入 "$h" 移到 "in" 的 "i" 上，然后输入 "cwout"。现在你
将该行改成了:

	:e config.h.out ~

现在按 <Enter>，该命令就会被执行。命令行窗口将关闭。
   <Enter> 命令会执行光标所在行。无论 Vim 是在插入模式还是普通模式都一样。
   命令行窗口中的修改会被丢弃。它们不会导致历史记录被改变。只是你执行的命令
会像所有被执行的命令一样被添加到历史末尾。

当你想要概览历史记录，查找一个类似的命令，稍作修改后执行时，命令行窗口非常有用。
可以使用搜索命令来查找内容。
   在前面的例子中，"?config" 搜索命令可以用来查找包含 "config" 的上一个命令。
这有点奇怪，因为你在用命令行来搜索命令行窗口中的内容。在输入搜索命令时你不能
再打开另一个命令行窗口，只能有一个。
