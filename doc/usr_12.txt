*12.1*	替换一个单词

替换命令可以用来将一个单词的所有出现替换为另一个单词: >

	:%s/four/4/g

"%" 范围表示在所有行中替换。末尾的 "g" 标志使一行中的所有单词都被替换。
   如果你的文件还包含 "thirtyfour"，这将不能正确工作。它会被替换为 "thirty4"。
要避免这种情况，使用 "\<" 来匹配单词的开头: >

	:%s/\<four/4/g

显然，这在 "fourteen" 上仍然会出错。使用 "\>" 来匹配单词的结尾: >

	:%s/\<four\>/4/g

如果你正在编程，你可能只想替换注释中的 "four"，而不是代码中的。由于这难以
指定，可以加上 "c" 标志让替换命令在每次替换前询问你确认: >


	:%s/\<four\>/4/gc


在多个文件中替换

假设你想在多个文件中替换一个单词。你可以逐个编辑每个文件然后手动输入命令。
使用录制和回放要快得多。
   假设你有一个包含 C++ 文件的目录，所有文件都以 ".cpp" 结尾。有一个函数叫
"GetResp"，你想把它重命名为 "GetAnswer"。

	vim `*.cpp`		启动 Vim，将参数列表定义为包含所有 C++ 文件。
				你现在在第一个文件中。
	qq			开始录制到寄存器 q。
	:%s/\<GetResp\>/GetAnswer/g
				在第一个文件中进行替换。
	:wnext			保存这个文件并移到下一个。
	q			停止录制。
	@q			执行寄存器 q。这将回放替换和 ":wnext"。
				你可以验证这不会产生错误信息。
	999@q			在剩余文件上执行寄存器 q。

在最后一个文件上你会得到一个错误信息，因为 ":wnext" 无法移到下一个文件。这会
停止执行，一切就完成了。

	注意:
	回放录制的序列时，错误会停止执行。因此，确保你在录制时不会得到错误
	信息。

有一个注意事项: 如果某个 .cpp 文件不包含 "GetResp" 这个词，你会得到一个错误，
替换将停止。要避免这种情况，给替换命令加上 "e" 标志: >

	:%s/\<GetResp\>/GetAnswer/ge

"e" 标志告诉 ":substitute" 没有找到匹配不是一个错误。

*12.2*	把 "Last, First" 改为 "First Last"

你有一个如下形式的名字列表:

	Doe, John ~
	Smith, Peter ~

你想把它改为:

	John Doe ~
	Peter Smith ~

这只需一个命令就能完成: >

	:%s/\([^,]*\), \(.*\)/\2 \1/

让我们逐部分来分析。显然它以一个替换命令开始。"%" 是行范围，代表整个文件。因此
替换在文件的每一行上进行。
   替换命令的参数是 "/from/to/"。斜杠分隔 "from" 模式和 "to" 字符串。"from"
模式包含的内容如下: >
							\([^,]*\), \(.*\)
<
	\( \) 之间的第一部分匹配 "Last"		\(     \)
	    匹配除逗号之外的任意字符			  [^,]
	    任意多次					      *
	按字面值匹配 ", "					 ,
	\( \) 之间的第二部分匹配 "First"		   \(  \)
	    任意字符					     .
	    任意多次					      *

在 "to" 部分我们有 "\2" 和 "\1"。这些叫做反向引用。它们引用模式中 "\( \)"
部分匹配的文本。"\2" 引用第二个 "\( \)" 匹配的文本，即 "First" 名。"\1" 引用
第一个 "\( \)"，即 "Last" 名。
   你最多可以在替换命令的 "to" 部分使用九个反向引用。"\0" 代表整个匹配的模式。
替换命令中还有一些更多的特殊项，见 |sub-replace-special|。

*12.3*	排序列表

在 Makefile 中你经常有一个文件列表。例如:

	OBJS = \ ~
		version.o \ ~
		pch.o \ ~
		getopt.o \ ~
		util.o \ ~
		getopt1.o \ ~
		inp.o \ ~
		patch.o \ ~
		backup.o ~

要排序这个列表，通过外部 sort 命令过滤文本: >

	/^OBJS
	j
	:.,/^$/-1!sort

这先定位到以 "OBJS" 开头的第一行。然后向下一行，过滤到下一个空行之前的行。
你也可以用可视模式选择这些行然后使用 "!sort"。这样输入更容易，但当行数很多时
需要更多操作。
   结果是:

	OBJS = \ ~
		backup.o ~
		getopt.o \ ~
		getopt1.o \ ~
		inp.o \ ~
		patch.o \ ~
		pch.o \ ~
		util.o \ ~
		version.o \ ~


注意每行末尾的反斜杠用于表示行的延续。排序后，这就不对了！"backup.o" 那行
原来在最后，没有反斜杠。现在它排到了其他位置，必须加上反斜杠。
   最简单的解决办法是用 "A \<Esc>" 加上反斜杠。你可以保留最后一行的反斜杠，
只要确保在它后面有一个空行。这样你就不会再遇到这个问题了。

*12.4*	反转行序

|:global| 命令可以和 |:move| 命令组合使用，将所有行移到第一行之前，从而反转
文件。命令是: >

	:global/^/move 0

缩写形式: >

	:g/^/m 0

"^" 正则表达式匹配行首（即使行是空的）。|:move| 命令将匹配的行移到虚拟的第零
行之后，因此当前匹配的行成为文件的第一行。由于 |:global| 命令不会被行号变化
所困扰，|:global| 继续匹配文件的所有剩余行，并将每一行放在第一行。

这也适用于行范围。先移到要反转的第一行上方并用 "mt" 标记它。然后将光标移到
范围中的最后一行并输入: >

	:'t+1,.g/^/m 't

*12.5*	计算字数

有时你需要写一篇有最大字数限制的文本。Vim 可以帮你计算字数。
   当你想计算整个文件的字数时，使用这个命令: >

	g CTRL-G

不要在 g 后面输入空格，这里只是为了使命令更容易阅读。
   输出看起来像这样:

	Col 1 of 0; Line 141 of 157; Word 748 of 774; Byte 4489 of 4976 ~

你可以看到你在第几个单词（748），以及文件中的总字数（774）。

当文本只是文件的一部分时，你可以移到文本的开头，输入 "g CTRL-G"，然后移到
文本的末尾，再次输入 "g CTRL-G"，然后用你的脑子计算两个单词位置之间的差。
这是一个好的练习，但有更简单的方法。用可视模式选择你想要计算字数的文本。
然后输入 g CTRL-G。结果:

	Selected 5 of 293 Lines; 70 of 1884 Words; 359 of 10928 Bytes ~

关于计算单词、行和其他项目的其他方法，见 |count-items|。

*12.6*	查找 man 手册页					*find-manpage*

在编辑 shell 脚本或 C 程序时，你正在使用一个命令或函数，想要查找它的 man 手册
页（这在 Unix 上适用）。先用一个简单的方法: 将光标移到你想要查找帮助的单词上
然后按 >

	K

Nvim 将在该单词上运行 |:Man|。如果找到了 man 手册页，它会被显示出来。你也可以
使用 |:Man| 命令在一个窗口中打开 man 手册页: >

	:Man csh

你可以滚动浏览，文本会被高亮显示。这让你可以找到你要找的帮助。使用 CTRL-W w
跳到你正在编辑的文本所在的窗口。
   要查找特定章节的 man 手册页，将章节号放在前面。例如，要查看第 3 节的
"echo": >

	:Man 3 echo

要跳转到另一个 man 手册页——它在文本中以典型的 "word(1)" 形式出现——在上面按
CTRL-]。后续的 ":Man" 命令将使用同一个窗口。

要显示光标下单词的 man 手册页，使用: >

	K

例如，你想在编辑以下这行时知道 "strstr()" 的返回值:

	if ( strstr (input, "aap") == ) ~

将光标移到 "strstr" 上的某个位置，输入 "K"。一个窗口会打开显示 strstr() 的
man 手册页。

*12.7*	去除空白

有些人认为行尾的空格和制表符是无用的、浪费的和丑陋的。要删除每行末尾的空白，
执行以下命令: >

	:%s/\s\+$//

使用行范围 "%"，因此这作用于整个文件。":substitute" 命令匹配的模式是
"\s\+$"。这匹配空白字符 (\s)，一个或多个 (\+)，在行尾 ($) 之前。
后面会解释如何写这样的模式，见 |usr_27.txt|。
   替换命令的 "to" 部分为空: "//"。因此它替换为空，实际上是删除了匹配的空白。

另一种浪费空格的方式是在制表符前放置空格。通常这些可以在不改变空白量的情况下
删除。但并不总是这样！因此，你最好手动处理。使用这个搜索命令: >

	/

你看不到，但在这个命令中的制表符前有一个空格。因此它是 "/<Space><Tab>"。
现在用 "x" 删除空格并检查空白量没有变化。你可能需要插入一个制表符如果它发生了
变化。输入 "n" 找到下一个匹配。重复此操作直到找不到更多匹配。

*12.8*	查找一个单词的使用位置

如果你是一个 Unix 用户，你可以使用 Vim 和 grep 命令的组合来编辑所有包含给定
单词的文件。如果你正在编写程序并想查看或编辑包含特定变量的所有文件，这非常
有用。
   例如，假设你想编辑所有包含 "frame_counter" 这个词的 C 程序文件。你可以使用
这个命令: >

	vim `grep -l frame_counter *.c`

让我们详细看看这个命令。grep 命令在一组文件中搜索给定的单词。因为指定了 -l
参数，该命令只会列出包含该单词的文件，而不打印匹配的行。搜索的单词是
"frame_counter"。实际上，这可以是任何正则表达式。（注意: grep 使用的正则
表达式和 Vim 使用的不完全相同。）
   整个命令用反引号 (`) 括起来。这告诉 Unix shell 运行这个命令并假装结果是在
命令行上输入的。因此发生的是 grep 命令运行并产生一个文件列表，这些文件被放在
Vim 命令行上。这使得 Vim 编辑 grep 输出的文件列表。然后你可以使用 ":next" 和
":first" 等命令浏览这些文件。


查找每一行

上面的命令只查找包含该单词的文件。你仍然需要在文件中查找该单词。
   Vim 有一个内置命令可以用来在一组文件中搜索给定的字符串。例如，如果你想查找
所有 C 程序文件中 "error_string" 的所有出现，输入以下命令: >

	:grep error_string *.c

这使 Vim 在所有指定的文件 (`*.c`) 中搜索字符串 "error_string"。编辑器现在会
打开找到匹配的第一个文件，并将光标定位在第一个匹配的行上。要跳到下一个匹配行
（无论在哪个文件中），使用 ":cnext" 命令。要跳到上一个匹配，使用 ":cprev" 命令。
使用 ":clist" 查看所有匹配及其位置。
   ":grep" 命令使用外部命令 grep（在 Unix 上）或 findstr（在 Windows 上）。
你可以通过设置 'grepprg' 选项来改变这一点。
