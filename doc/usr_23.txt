*23.1*	DOS、Mac 和 Unix 文件

在早期，老式电传打字机使用两个字符来开始新的一行。一个用于将打印头移回到第一个
位置（回车，<CR>），另一个用于将纸张上移（换行，<LF>）。
   当计算机出现时，存储空间很昂贵。有些人决定不需要两个字符来表示行尾。Unix 开
发者决定只使用 <New Line> 或 <NL> 来表示行尾。Apple 开发者则采用了 <CR> 作为标
准。Microsoft Windows 的开发者决定保留旧有的 <CR><NL>（在帮助文本中我们用 <NL>
表示换行）。
   这意味着如果你试图在不同系统之间移动文件，就会遇到换行符问题。Vim 编辑器能
自动识别不同的文件格式，并在后台正确处理。
   'fileformats' 选项包含了编辑新文件时会尝试的各种格式。例如，以下命令告诉 Vim
先尝试 Unix 格式，然后尝试 MS-DOS 格式: >

	:set fileformats=unix,dos

编辑文件时，你会在提示消息中注意到文件格式。如果你编辑的是本地格式的文件，则不
会看到任何提示。因此在 Unix 上编辑 Unix 文件不会有任何提示。但当你编辑 dos 文件
时，Vim 会通知你:

	"/tmp/test" [dos] 3L, 71C ~

对于 Mac 文件，你会看到 "[mac]"。
   检测到的文件格式存储在 'fileformat' 选项中。要查看当前使用的格式，执行以下
命令: >

	:set fileformat?

Vim 使用的三个名称是:

	unix		<NL>
	dos		<CR><NL>
	mac		<CR>


使用 MAC 格式

在 Unix 上，<NL> 用于换行。在一行的中间出现 <CR> 字符并不罕见。巧合的是，这在
Vi（和 Vim）脚本中经常发生。
   在 Macintosh 上，由于 <CR> 是换行字符，在一行的中间出现 <NL> 字符也是可能
的。
   结果是，对于同时包含 <CR> 和 <NL> 字符的文件，无法百分之百确定它是 Mac 文件
还是 Unix 文件。因此，Vim 假设在 Unix 上你可能不会编辑 Mac 文件，所以不会检查这
种文件类型。要强制检查这种格式，请将 "mac" 添加到 'fileformats' 中: >

	:set fileformats+=mac

这样 Vim 会猜测文件格式。注意 Vim 可能会猜错的情况。


覆盖格式设定

如果你使用传统的 Vi 并尝试编辑 MS-DOS 格式的文件，你会发现每行末尾都有一个 ^M
字符。（^M 就是 <CR>）。自动检测功能可以避免这种情况。假设你确实想要以那种方式
编辑文件，那么你需要覆盖格式设定: >

	:edit ++ff=unix file.txt

"++" 字符串是一个特殊标记，表示后面跟着一个选项名称，它将覆盖本次命令的默认值。
"++ff" 用于 'fileformat'。你也可以使用 "++ff=mac" 或 "++ff=dos"。
   这不是对任何选项都有效，目前只实现了 "++ff" 和 "++enc"。完整名称
"++fileformat" 和 "++encoding" 也可以使用。


格式转换

你可以使用 'fileformat' 选项将文件从一种格式转换为另一种格式。例如，假设你有一
个 MS-DOS 文件名为 README.TXT，你想将它转换为 Unix 格式。首先编辑这个 MS-DOS
格式的文件: >
	vim README.TXT

Vim 会将它识别为 dos 格式文件。现在将文件格式改为 Unix: >

	:set fileformat=unix
	:write

文件将以 Unix 格式写入。

*23.2*	互联网上的文件

有人给你发了一封电子邮件，其中通过 URL 引用了一个文件。例如:

	你可以在这里找到相关信息: ~
		https://ftp.nluug.nl/pub/vim/README

你可以启动一个程序来下载文件，将它保存到本地磁盘，然后启动 Vim 来编辑它。
   有一种更简单的方法。将光标移到 URL 的任意字符上。然后使用以下命令: >

	gf

如果运气好，Vim 会找到合适的程序来下载文件，下载它并编辑副本。要在新窗口中打开
文件，使用 CTRL-W f。
   如果出现问题，你会收到错误消息。可能是 URL 错误，你没有读取权限，网络连接中
断等。不幸的是，很难判断错误的原因。你可能需要尝试手动下载文件。

通过互联网访问文件使用的是 netrw 插件。目前可以识别以下格式的 URL:

	`ftp://`	使用 ftp
	`rcp://`	使用 rcp
	`scp://`	使用 scp
	`http://`	使用 wget（仅限读取）

Vim 本身不进行通信，它依赖于你计算机上已安装的上述程序。在大多数 Unix 系统上
"ftp" 和 "rcp" 已经存在。"scp" 和 "wget" 可能需要安装。

Vim 在每个开始编辑新文件的命令中都会检测这些 URL，包括 ":edit" 和 ":split" 等
命令。写入命令也同样有效，但 `http://` 除外。

更多信息（包括密码相关内容），请参见 |netrw|。

*23.3*	二进制文件

你可以用 Vim 编辑二进制文件。Vim 本来不是为此设计的，所以有一些限制。但你可以读
取文件、修改一个字符并写回，结果是只有那一个字符被改变，文件的其他部分完全不
变。
   为了确保 Vim 不会以错误的方式使用其智能技巧，启动 Vim 时要加上 "-b" 参数: >

	vim -b datafile

这会设置 'binary' 选项。其效果是关闭一些意外的副作用。例如，'textwidth' 被设为
零，以避免自动格式化行。文件始终以 Unix 文件格式读取。

二进制模式可用于修改程序中的消息文本。注意不要插入或删除任何字符，否则程序可能
无法正常工作。使用 "R" 进入替换模式。

文件中的许多字符可能是不可打印的。要以十六进制格式查看它们: >

	:set display=uhex

也可以使用 "ga" 命令查看光标下字符的值。当光标在 <Esc> 上时，输出如下:

	<^[>  27,  Hex 1b,  Octal 033 ~

文件中可能没有太多换行符。要获得一些概览，可以关闭 'wrap' 选项: >

	:set nowrap


字节位置

要查看你在文件中的字节位置，使用以下命令: >

	g CTRL-G

输出信息很详细:

    Col 9-16 of 9-16; Line 277 of 330; Word 1806 of 2058; Byte 10580 of 12206 ~

最后两个数字是文件中的字节位置和总字节数。这会考虑 'fileformat' 对换行符使用字
节数的影响。
    要移动到文件中的特定字节位置，使用 "go" 命令。例如，要移动到第 2345 个字
节: >

	2345go


使用 XXD

真正的二进制编辑器会以两种方式显示文本: 原始文本和十六进制格式。你可以在 Vim 中
通过 "xxd" 程序来实现这一点。这个程序随 Vim 一起提供。
   首先以二进制模式编辑文件: >

	vim -b datafile

然后用 xxd 将文件转换为十六进制转储: >

	:%!xxd

文本将如下所示:

	0000000: 1f8b 0808 39d7 173b 0203 7474 002b 4e49  ....9..;..tt.+NI ~
	0000010: 4b2c 8660 eb9c ecac c462 eb94 345e 2e30  K,.`.....b..4^.0 ~
	0000020: 373b 2731 0b22 0ca6 c1a2 d669 1035 39d9  7;'1.".....i.59. ~

现在你可以随意查看和编辑文本。Vim 将这些信息视为普通文本。修改十六进制部分不会
导致可打印字符部分的改变，反之亦然。
   最后用以下命令转换回来:
>
	:%!xxd -r

只有十六进制部分的修改会被采用。右侧可打印文本部分的修改会被忽略。

更多信息请参阅 xxd 的手册页。

*23.4*	压缩文件

这很简单: 你可以像编辑其他文件一样编辑压缩文件。"gzip" 插件会在你编辑时负责解
压文件，在你写入时重新压缩。
   目前支持以下压缩方式:

	.Z	compress
	.gz	gzip
	.bz2	bzip2

Vim 使用上述程序来执行实际的压缩和解压。你可能需要先安装这些程序。
